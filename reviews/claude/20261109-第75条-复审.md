# 第 75 条复审（启动方式和测试账号）

复审对象：第 75 条这一批的改动（未提交时的 diff 和三个新文件），改法见 [feedback-20261109-2.md](../../docs/feedback-20261109-2.md)。

复审者：子代理，模型 Sonnet（实现是 Opus 5.5）。只读，没跑会起服务的测试；第 1—4 条它用 node 直接试过 `lib/login.js` 的正则和 `JSON.parse` 的报错。每条下面的"核实"是实现者看代码、补测试核实的。

## 问题

### 1. 口令从坏 JSON 的报错里漏进上下文（确认）

- 证据：`kit/lib/login.js` 的 `read` 把 `e.message` 拼进 `error`。口令没加引号时，Node 24 的报错引出错处附近的原文（`..."assword": S3cret!x9,"...`），经 `summary` 进会话开始的上下文，经 `login.js list/check` 打印，经 `resolve` 的报错进场景结果。
- 核实：成立。修了：不拼报错原文，只说"有语法错"（报错里有位置的再说第几行）。测试加了带口令的坏 JSON，查汇总、`login.js list` 都不带口令。

### 2. 账号提醒误报（确认）

- 证据：`views/login 登录页没样式`、`pages/login 登录页面的按钮` 被"admin/… 登录"那条认成账号；`密码错误，账号 admin 登不上`、`accounting 模块的 password 校验` 被"账号 … 密码 …"那条认成账号。
- 核实：成立。修了：一对 `x/y` 前后还连着斜杠的、两头是 src、views、login 这类目录名的不算；"登录页""登录接口"这类里的登录不算；"账号""密码"后面要跟英文、数字、符号写的值，`account`、`password` 要整个词。测试加了这几句和 `改一下 api/user/list 接口的登录校验`。

### 3. 账号提醒漏报（确认）

- 证据：`用户名/密码是 admin/123456`、`账户 admin 密码 123456` 不提醒。
- 核实：成立。修了："账户"加进去，"密码"也能当一对前面的词。测试加了这两句和 `用 admin/admin 登录`。

### 4. 问"怎么启动"也提醒"说到了怎么启动"（确认）

- 核实：成立。修了：去掉"怎么启动""如何启动"，问句（问号、吗、么、呢结尾）不提醒。测试加了 `怎么启动这个项目`、`启动方式是什么？`。

### 5. 命令里带着的口令写进项目说明（可能）

- 证据：只对 `--env` 的键打码，`-- mvn … -Dspring.datasource.password=xxx`、`--token xxx` 原样写进 `.vibe/project.md`。
- 核实：成立（项目里的口令对模型是放开的，不算越线，但每个会话开头都带一遍）。修了：`password=…`、`token: …`、`--token …` 这类的值换成"<口令照原来的给>"。测试加了。

### 6. 写下的命令原样执行不一定是同一个（可能）

- 证据：单参数用双引号只转义 `"`，Git Bash 里 `$VAR` 会展开；多参数用的 `quote()` 白名单含反斜杠，`C:\proj\run.bat` 不加引号会被 bash 吃掉。
- 核实：成立。修了：只含安全字符的不加引号，别的加单引号（Git Bash、PowerShell 里都不展开），本身带单引号的才用双引号。测试加了：带 `$`、空格、反斜杠的参数，写下的命令拿去 Git Bash 原样跑，认出是同一个服务（"已经在跑"）。

### 7. GBK 的项目说明会被写坏（可能）

- 核实：成立。修了：读出来带替换字符（U+FFFD）的不动。测试加了 GBK 的项目说明，字节不变。

### 8. BOM 被去掉没还原（确认）

- 核实：成立。修了：原来带 BOM 的写回去照样带。测试加了 BOM + CRLF 的项目说明。

### 9. 不在仓库里的目录也建 .vibe（可能）

- 证据：往上 12 层没有项目说明、没有 .git，落到 `--dir`；桌面、下载目录里跑也会建 `.vibe/project.md`。`~/.claude` 本身没拦。
- 核实：成立。修了：往上找也认 `.svn`；都没有时运行目录或 `--dir` 像个项目（有构建文件）才写，否则不写；`~/.claude` 本身也拦。测试加了不像项目的目录不建、加了 package.json 的照写。

### 10. tmp 里的账号文件按名字拦，太宽（可能）

- 证据：`用户故事.md`、`login-bug-notes.md`、`accounting.csv` 会被拦一次；`PWD_HINT` 的 `pass` 命中 bypass、passport。
- 核实：成立（拦一次、原样再写放行，只是打断）。修了：去掉"用户"，`account` 要整个词；名字像账号、内容里还写着密码才拦；`pass` 改成 `passw`。测试加了这三个文件名不拦。

### 11. 没有会话号时每次都拦（确认）

- 核实：成立（`blockOnce` 没会话号返回"该拦"，原样再写放不了行）。修了：`keepCheck` 没会话号不拦。测试加了。

### 12. 项目说明里那一行靠键长躲开自动探索（确认不冲突，脆弱）

- 核实：成立。`lib/onboard.js` 的 `LINE` 旁边加了注释：要放宽键长先把"跑通的启动"排除。

### 13. markOk 重排 login.json；拿不到锁也照写（确认，影响小）

- 核实：重排成立，JSON 没有注释，不丢内容，不改。拿不到锁照写成立，修了：拿不到锁不记。
