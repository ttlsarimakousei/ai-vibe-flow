## 复审报告原文

### R1　P1　`vibe-kit/kit/lib/big-task.js:139`、`vibe-kit/kit/hooks/verify-gate.js:414-420`（调用在 `:858`）　确认（跑过）

- 输入：单个 change `c1`，`tasks.md` 有 3 项没勾、0 项已勾，用户说"开工 c1"，`apply` 已开始（`stage=apply`），模型这一轮还没勾任何一项就收工。
- 错误结果：`phaseOf` 把"有待办且一项都没勾"判成 `plan`。`nextStepTodo` 看到 `ph.phase==='plan' && st.stage==='apply'`，把它当成"接下一个 change"：`setFlow(...,'plan')` 把流程退回写需求那一段，并发提示。人工模式问"要不要接着做 c1"；自动模式同一条收工消息里两条互相矛盾的指令。`stage` 退回 plan 后源码改动会被拦；第一项勾上之前每次收工都重复退回。
- `dev/test-multi-change.js:103-121` 只测了"c1 做完再接 c2"。
- 建议：只在当前要做的 change 不是正在 apply 的那个时才退回 plan。补测例。

### R2　P2　`vibe-kit/kit/lib/review-runner.js:379-386,388-403`、`flow-policy.js:105,120,138`、`config-fields.js:34`　确认（跑过）

- 输入：第一轮 3 个角度，3 个子代理都被 Esc 打断（2.1.120 前台），下一次收工 `sweep`。
- 错误结果：`failLens` 对每个角度各调一次 `noteFail`，一轮就是 `failStreak=3`，`halted=true`。手册、README、配置页都写"连续 3 次"，代码实际是"3 个角度各 1 次"。自动模式下这一点没审成就往下走，一次 Esc 就触发。
- 建议：一次 `prepare` 产生的失败角度合起来只算 1 次。

### R3　P2　`vibe-kit/kit/lib/guard-mcp.js:17,53-60`　确认（拦截逻辑跑过）；真实 MCP 工具是否接受目录外的绝对路径是"可能"

- 硬规矩 6：第 1、4 层只对 `PATH_KEYS` 白名单里的字段名生效。`{directoryToSearch: <套件目录>}`、`{directoryPath: <~/.claude>}`、`{folder: <套件目录>}`、`{directoryToSearch: <用户主目录>}` 都放行。IDEA 的 `search_in_files_by_text`、`list_directory_tree`、`find_files_by_glob` 就用这类名字。第 2 层原文匹配只认文件名，目录级认不出。
- 相对路径按会话 `cwd` 解析，不按同一个 `tool_input` 里的 `projectPath`。
- `mcp__x__apply_patch` 这类补丁文本里的路径不在任何字段里，能放行（P3，只涉及 kitLock）。
- 建议：去掉字段名白名单，所有字符串值里像路径的都查，两种基准都解析。

### R4　P2　`vibe-kit/kit/hooks/session-start.js:36-43,250`、`router-retire.js:66-75,77-91`　可能
