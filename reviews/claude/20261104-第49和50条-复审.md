## 复审报告原文

### R1　P1　确认　`kit/lib/big-task.js:111`，成因在 `kit/lib/apply-scope.js:54`

`grant` 给表外或没有 plan.md 的单个 change 记了 `current`，一直留着，`forSession` 把它排在 `st.task` 之前检查。之后同会话开新大任务，`forSession` 一直返回 null。

输入：项目没有 plan.md，说"开工"，对 small-x 执行 `grant`（`current='small-x'`）；small-x 归档；建 plan.md 和探索记录，大任务（c1、c2），c1 开工；之后开工只说"开工"、不点名。

结果：`forSession` 返回 null（旧版返回大任务）；状态栏没有"探索✓"和 (1/2)；`nextStepTodo` 退出，c1 做完后不提示落地偏差、接 c2、全面自测和人工核验；`automaticApply`、`planOk` 失效；`guard-git` 的 task 为 null（读代码）。`/vk-resume <表外变更名>` 同样触发。

### R2　P2　确认　`kit/lib/big-task.js:116`（`if (dirs.length) return null;`）

`dirs` 不分目录还在不在、做没做完。会话碰过老 change，新大任务在"探索完、第一个 change 还没碰"这段拿不到 task。结果：开口提示对着完整的探索记录说"还没有探索记录"；写需求的自动不生效；步骤条为空。

同根的旧问题：`flowChanges` 从不清已归档的目录，`/vk-resume 探索中的大任务` 紧接着被 decideFlow 的 flowDone 关掉流程（新旧版一样）。

### R3　P2　确认（机制）、可能（触发条件）　`kit/hooks/verify-gate.js:593-613`（`autoModeTodo`）

不看 `phaseFor`/`current`，按 tasks.md 修改时间倒序取第一个有剩余任务的 change。自动模式下 c1 刚做过还剩一项，用户 `/vk-resume c2`，收工催的是 c1，和切换对着干。

### R4　P3　确认　`kit/lib/big-task.js:144-149`、`kit/hooks/guard-spec.js:137`

`current` 指的 change 做完后不清，之后回改加了任务，它重新抢到最优先，打勾顺序继续豁免。

### R5　P3　确认　`kit/hooks/task-anchor.js:124-130`

README 写"`/vk-resume` 不写名字也回到表的顺序"，实际只有恰好一个没做完的大任务时才清。

### R6　P3　确认　`kit/hooks/task-anchor.js:119-126`

名字精确大小写匹配；`/vk-resume c2 继续做` 整串算名字。大任务名和别的任务里的 change 重名时大任务优先。

### R7　P3　可能　`kit/hooks/verify-gate.js:417-421`、`kit/lib/big-task.js:171-184`

新任务里被跳过的行写进"后面还有 X"，它在表里排在前面。`prev` 可能是被跳过的行，会说"c1 做完了"。

### R8　P3　确认　`vibe-kit/README.md:68`、`kit/ui/ui.html:349`

新任务"后面还有没做完的才跳过，做完了又回来算"没写进文档。

### 查了没发现问题的

- `phaseOf`、`goneRow`、`progressText` 的状态判断：13 个场景（新旧任务、各种归档、重名行）。
- `phaseFor` 和 `phaseOf` 的 plan、apply 口径等价，指向已归档或全勾完时正确回退。
- `resumeOutside` 和主路径：表内、表外、无 plan.md、已归档、任务勾完、不存在。
- 新代码抛错、没定义的名字：逐个核对；guard-spec 的新判断在 try 里，`resumeTask` 有 try/catch。
- 标题正则只匹配单行；`grant` 自己调自己时不误删；`setFlow(false)` 的三处调用都是真退出。
