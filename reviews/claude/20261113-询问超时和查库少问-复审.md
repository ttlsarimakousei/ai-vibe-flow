## 问题

### R1（P2，可能）权限确认框到点放行后，查库工具会把这次当"有人在"，还原不了的删可能没人确认就执行

- 位置：`vibe-kit/claude/skills/vk-db-crud/scripts/db.py:1320`（`auto_mode`）、`db.py:1884`（第二步有人在的分支）、`vibe-kit/kit/hooks/ask-timeout.js:103`。
- 现象：自动实施时模型跑 `db.py exec … --ack X`，Claude Code 弹了确认框，没人点，10 分钟后 `ask-timeout` 按允许放行。这时 PreToolUse 留的条子（`state/tool-flow.json`）已经超过 120 秒，`auto_mode()` 返回 False，第二步走"有人在"的分支，只看确认串登记里的 note，照样执行。第一步也被同样拖到条子过期的话，能拿到要人确认的串，整条路没人确认。redis 的 `autoMode()`（`redis.js:65`）同理。
- 依据：`auto_mode` 只认 120 秒内的条子，过期按有人在算；以前没有这个钩子，框要等真人点。
- 建议：放行 Bash 时命令含 `db.py`、`redis.js` 的按不允许收掉；或者让 `auto_mode` 认出"条子在、但过期了"。
- 核实：成立（读代码确认）。触发要两步都弹框：套件的权限规则放行了 Bash，跑 `db.py` 一般不弹，只有 Claude Code 自己的检查（cd 串着别的命令这类）会弹。概率低，但这条路是新钩子带来的。

### R2（P2，确认）认"自己建的"只比对象名，不比 schema

- 位置：`db.py:1674`（`_bare`）、`db.py:1717`（`has`）。
- 现象：工具在 A 建了 `T`（或者没写 schema 建的 `T`），之后 `DELETE FROM B.T`、`TRUNCATE B.T`、`DROP TABLE B.T` 都被认成自己建的，不问就做。
- 依据：`_bare` 取 `split(".")[-1]`，两边都只比裸名。
- 建议：比带 schema 的全名；补两个 schema 里同名表的测试。
- 核实：成立。`_ddl_undo` 记的 `created.name` 是语句里的原样写法（带不带 schema 照写的），比的时候被去掉了。

### R3（P3，确认）用户答了、会话记录里却找不到这次调用时，钩子活到点、往报告里写假条目

- 位置：`ask-timeout.js:50`（`settled`）、`ask-timeout.js:86`（`decide`）。
- 现象：`transcript_path` 为空、调用还没写进会话记录、被挤出最后 800KB 时，`settled()` 一直是 false。用户早处理了，钩子照样等满，到点往全自动报告里写"替你点了允许""没让它跑"。另外每 3 秒读一次 800KB、逐行解析。
- 建议：找不到调用时不写报告条目，或者再看一次会话有没有往下走；先比文件大小，没变就不解析。
- 核实：成立。决定本身不起作用（实测后到的决定被忽略），假的是报告条目。

### R4（P3，确认）`op.json` 的 `auto` 意思变了，有人在时不问就做的也会被全自动报告列出

- 建议：另记一个"用户在不在"的字段，报告按它筛。
- 核实：成立。

## 看过没问题的（审的人列的，核实时抽看了前三条）

- `_removes`：WITH 开头按会删算；MERGE 带 DELETE 要问；CREATE OR REPLACE TABLE、ALTER 里的 DROP/TRUNCATE、`/*!` 都认。
- 多语句一次只收一条；`DROP TABLE a, b` 不匹配 `_DROP_ONE`，要问。
- 全自动下先 `write_policy` 再 `pending_take`，被拒不消耗确认串；行数变了重给串时重算。
- IDS_UNKNOWN 重试：第一次回滚了，不重复执行。
- 旧版给的确认串没有 note，按要人确认算，方向是保守的。
- redis 的 `del` 只收字面 key，没有通配展开。
- `ask-timeout` 出错什么都不说；`invocation.run` 对同步函数直接返回；同名调用取最后一次；7500 秒大于 120 分钟；`process.kill(pid, 0)` 在 Windows 上能查存在。
- 安装、卸载收回有测试；归档、推送的确认不靠 Claude Code 的确认框，放行绕不过它们。
- 配置页说明和 `ask-timeout.js`、`config-fields.js` 的取值一致。
