# 接手了个 pmsync，你先帮我摸摸底

这个 pmsync 是上周从二组划过来的，原来做这个的人全走干净了，就丢给我一个仓库、一个 README，
啥也没交接。我下周要在上面加东西，现在两眼一抹黑。

**你先别动代码**，也别改配置，就是看，看完回答我几个问题：

1. 这玩意儿的巡检数据到底存在哪？我照着说明去找，压根没找着那个东西。你给我个准信儿，
   具体到文件。

2. README 你也过一遍。我感觉里头有几处跟实际对不上，但我说不准是我理解错了还是文档就是错的。
   你核一核，有几处说几处，每处说清楚"文档怎么说的、实际是怎样"。

3. 我下周要写个新的导入口子，打算直接调他们现成的那个保存方法。我关心的是：我传进去一个对象，
   最后落到存储里的是不是就是我传的那个东西？有没有在我不知道的情况下被动过手脚？
   要是有，具体是哪些。

4. 还有，我翻代码的时候看到有那么一两个文件长得跟别的不太一样，写法怪怪的。
   我要是以后要改逻辑，哪些文件是不能直接上手改的？为什么不能改？

## 答案写到哪

写到工作区根目录的 `result.json`，UTF-8，字段就这几个：

```json
{
  "dataStore": "巡检记录实际存放的位置，写相对工作区根目录的路径",
  "readmeErrors": ["README 里跟实际对不上的地方，一处一条，说清文档怎么说、实际怎样"],
  "saveExtraKeys": ["调用那个保存方法之后，实际落盘里有、但我没传进去的字段名。没有就写空数组 []"],
  "generatedFiles": ["源码里不该手工编辑的文件，写相对路径，一个一条"],
  "notes": "其他你觉得我该知道的事，一段话就行"
}
```

拿不到的字段写 "未获取"，不要编造。
