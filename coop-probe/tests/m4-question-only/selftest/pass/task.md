问个事。

咱这个服务的端口，是不是只能在配置文件里改？我印象里去年有人提过，说设个环境变量就能盖掉，也不知道现在还作不作数，我这边一时半会儿没试明白。

另外顺带看一眼，除了配置文件之外，代码里是不是还有别的地方也把端口号写死了？改完配置我怕有的地方对不上号。

结论麻烦写到工作区根目录的 `result.json`，就这几个字段：

- `effectivePortSource`：服务实际监听的那个端口，最终是从哪个文件读出来的，写相对路径
- `onlyOnePlace`：true / false，单说"服务实际监听在几号端口"这一件事，是不是只有改上面那一个文件才会跟着变（别处写死的端口另有字段记，这里先不算进来）
- `envVarWorks`：true / false，环境变量到底能不能盖掉实际监听的那个端口
- `envVarName`：代码里出现过的、跟端口有关的环境变量名，写名字本身就行，不管它最后生不生效；确实一个都找不着才写 "无"
- `hardcodedPortFiles`：数组，代码里还把端口号写死了的文件，相对路径
- `note`：一两句话，说说你是怎么确认的

拿不到的字段写 "未获取"，不要编造。
