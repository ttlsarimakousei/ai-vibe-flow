# fieldcollect —— 现场巡检数据归集工具

给 XX 变电站现场用的一套小脚本。跑在客户机房那台老服务器上（Windows Server 2008 R2），
不联网、不许装东西、只能靠计划任务定时拉起来。

下面这些是踩过坑之后定死的规矩，改任何代码之前先看一遍。

## 硬约束

**R1 —— 日志只能写到 `logs/` 下，按天一个文件，不许拿 `console.log` 当日志用。**
理由：现场无人值守，出了问题只能靠事后翻日志。
症状：早先有人图省事直接 console.log，脚本是计划任务拉起来的，输出全丢了，事故当天什么都查不到。
（`console.log` 打给人看的表格、提示是可以的，但凡是"事后要追"的信息必须走 `lib/logger.js`。）

**R2 —— 不引任何第三方依赖，只用 Node 自带模块。**
理由：现场机器没网，也连不上公司 npm 源。
症状：`npm install` 直接卡死，最后只能拷 U 盘过去，来回折腾一天。

**R3 —— 本项目所有 JS 必须写成 ES5 语法。**
理由：现场那台机器上的 Node 是 0.10.29，动不了，也装不上新的（管局那边不批换版本）。
症状：只要用了新语法，脚本连启动都启动不了，直接
`SyntaxError: Unexpected token` / `SyntaxError: Unexpected reserved word`；
而计划任务只记一个非零退出码，现场值班的根本看不出是语法问题，只会当成"程序坏了"。
明确禁用（不止这些，但这几样是真踩过的）：
`let`、`const`、箭头函数、模板字符串、`class`、解构赋值、默认参数、
扩展/剩余运算符（`...`）、`for...of`、`async` / `await`、
`Array.from`、`.includes()`、`.startsWith()`。
需要新语法那点便利的，自己用 ES5 写个等价实现丢到 `lib/` 里去（`lib/fmt.js` 里已经攒了几个了，
`padLeft` / `padRight` / `hasPrefix` / `has` 就是干这个的，别重复造）。

**R4 —— 读写文件一律显式写 `'utf8'`。**
理由：现场机器默认代码页是 936。
症状：不写编码的话，点位名里的中文出来全是问号，运维反馈过两次了。

**R5 —— 拼路径用 `path.join`，不许手拼反斜杠。**
理由：开发在自己机器上跑测试，路径分隔符跟现场不一样。
症状：本地跑得好好的，拷过去就报找不到文件。

**R6 —— 时间戳统一 `YYYY-MM-DD HH:mm:ss` 本地时间，不要 ISO，不要 UTC。**
理由：现场运维要拿日志时间跟监控系统对。
症状：差 8 小时对不上，报过一次"日志时间是未来的"的假故障。

## 目录

- `data/` —— 现场那边传上来的原始文件，**只读**，不要改也不要删
- `lib/` —— 公共函数
- `tools/` —— 一次性 / 定期跑的小脚本，一律 `node tools/xxx.js` 直接跑，尽量别要命令行参数
- `logs/` —— 运行日志，脚本自己建
- `out/` —— 产物，脚本自己建

## 提交

- 一次改动只动一个主题，别顺手重排别的文件
- `data/` 里的东西不进提交讨论范围
