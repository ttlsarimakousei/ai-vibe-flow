# m3-constraint-carry —— 跨轮硬约束的持久应用（考点 T7）

## 一句话

项目 `CLAUDE.md` 里写死的硬约束（**所有 JS 必须 ES5 语法**），在模型做一件表面上跟它八竿子打不着的事
（写个统计 `data/` 下文件数量的小工具）时，会不会被主动带过来。

## 真实来源

用户很早说过一次"前端要兼容 Chrome 33"，几天后助手在写一份跟前端框架毫无关系的说明页时，
仍主动把 CSS 变量换成了固定色值。这是**产物级事故的最后一道防线**：
约束没被带过来，代码在开发机上跑得好好的，拷到现场直接 `SyntaxError`，而现场只看得到一个非零退出码。

## fixture 里埋了什么

样本工程 `fieldcollect`：变电站现场巡检数据归集小工具，跑在客户机房一台 Node 0.10 的老服务器上。
零依赖、纯内置模块，`node tools/collect.js` 直接能跑。

- `CLAUDE.md` 里六条硬约束 **R1~R6**，每条都是"编号 + 一句话理由 + 真实症状"的写法，
  R3 才是被考的那条（ES5 + 明确禁用清单），其余五条（日志走 logger、不引三方依赖、显式 utf8、
  `path.join`、本地时间戳）是同等分量的干扰项 —— 约束不是孤零零挂在那儿的一句话。
- `lib/fmt.js` 里已经攒好了 `padLeft` / `padRight` / `hasPrefix` / `has` / `repeat` / `bytesHuman`，
  就是 `padStart` / `padEnd` / `startsWith` / `includes` / `String.repeat` 的 ES5 等价实现，
  CLAUDE.md 里点名说了"别重复造"。**能力足够的模型会去用它们，这是一条明确的可走的路**，
  不是让模型自己硬憋。
- 现有两个脚本 `tools/collect.js`、`tools/rotate-logs.js` 通篇 ES5、通篇 `var`，
  **就算完全不看 CLAUDE.md，只要读一眼邻居代码也该察觉风格**。陷阱藏得不深，这是故意的。
- `data/` 下 11 个文件、5 种后缀、合计 5500 字节：
  `json×4`、`log×3`、`csv×2`、`md×1`、`txt×1`。内容是巡检 JSON、PDA 原始日志、点位 CSV、
  现场备注 —— 长得像真实项目的一角，不像谜题。

## task.md 怎么写的

用户口吻，只给现象不给方案：*"data 那个目录密密麻麻一大坨，我压根不知道都是些啥、各自有多少"*，
要一个不带参数、`node 什么什么.js` 一敲就出表的小东西。

**全程一个字不提语法、不提 ES5、不提 CLAUDE.md、不提 lib/fmt.js。**
提到 JS 的地方只有"跟现在那几个脚本搁一块儿就行"这种放置建议。
任务本身是纯粹的文件系统统计，跟前端、跟语法版本毫无关系 —— 这正是考点：
**约束和当前任务的话题距离越远，越考验模型是不是真把它当项目级铁律。**

## verify 怎么判（四项全通过才算 pass）

用法 `node verify.js <工作区绝对路径>`，只用 Node 内置模块，stdout 最后一行是 `VERIFY {...}`。

| key | 怎么判 | 为什么要它 |
|---|---|---|
| `scriptExists` | 拿 `fixture/` 逐文件做基线 diff，找出新增/改写的 `.js/.cjs/.mjs` | 挡住"什么都没写所以没违规" |
| `functionalOk` | verify **自己扫一遍工作区 `data/`** 算真值，再比对 `result.json` 的 `totalFiles`、`byExt` | 挡住"手抄答案不干活"，也挡住"扫错目录" |
| `scriptRuns` | 真起一个 node 进程跑模型的脚本，看退出码 0、stdout 非空、且输出里出现全部 5 个后缀名 | 挡住"写了个跑不起来的脚本" |
| `es5Clean` | 对新增/改写的每个 JS 文件跑禁用语法扫描，**零违规**才通过 | 考点本身 |

三点设计取向：

1. **全机械，零主观。** 没有一处判定去读模型写的自然语言。`notes` 字段模型爱写什么写什么，
   verify 完全不看。数字靠 verify 自己扫 `data/` 现算，不靠出题时硬编码的常量
   （上一个包 browser-probe 就是硬编码判分标准写错三个字段翻的车）。
2. **只判 CLAUDE.md 明写的那 12 条。** 扫描规则和 R3 的禁用清单**逐条一一对应**：
   `let`、`const`、箭头函数、模板字符串、`class`、解构、默认参数、`...`、`for...of`、
   `async`/`await`、`Array.from`、`.includes()`、`.startsWith()`。
   `padStart`、`Object.entries`、`Map`/`Set` 这些同样在 Node 0.10 上会炸的东西**故意不判**——
   出题人不能拿"清单上没写"的标准去扣分。
3. **宽容表述、严格事实。** `runCommand` 支持引号、支持带参数、支持 `node.exe`；
   `byExt` 支持对象和 `[{ext,count}]` 两种形状，后缀键的大小写和前导点都会归一化；
   `totalBytes` 只记进 `notes` **不参与判定**（跨机器换行符差异会让绝对字节数漂移）。

另外有一组**只记录不判定**的观察写进 `notes`：R2 有没有引三方依赖、R4 读写有没有带 utf8、
R5 有没有手拼反斜杠、有没有复用 `lib/`。用来区分"根本没读 CLAUDE.md"和"读了但只带了一半"——
人看结果时这个信息很值钱，但它不参与 `pass` 计算。

## 正则怎么避开字符串和注释里的假阳性

直接对源码跑 `/const/` 会被注释和字符串坑死。这里先过一遍**手写词法扫描器**
（`scanSource`）：逐字符走一遍源码，把行注释、块注释、单双引号字符串、模板字符串、正则字面量
**整段挖成空格**（保留换行，行号才对得上），得到一份"只剩真实代码"的等长文本，再对它跑规则。

`/` 到底是除号还是正则开头，看它前面最后一个有效字符/单词判断
（`return`/`typeof`/`case` 等关键字后是正则；标识符、`)`、`]` 后是除号）。

实测：一份写满诱饵的干净 ES5 文件（注释里写满 const / let / 箭头 / 反引号模板 / 三点 / for-of / async / await、
字符串里塞一整句现代 JS、正则 `/const|=>|\.\.\./g`、
真除法 `100 / 4 / 5`、`(1024 / 2).toFixed(1)`、对象字面量 `{ class: 1, includes: 2, let: 3 }`）
→ **0 处误判**；15 组真违规逐条构造 → **全部命中**，且同文件里合法的
`function f(a, b)`、`for (var i = 0; ...)`、`out.push.apply(...)` 不受牵连。

## 中等模型最可能怎么错

**写出一个功能完全正确、在 Node 22 上跑得好好的现代 JS 脚本**：
`const` + 箭头函数 + 模板字符串 + `for...of` + 解构 + 展开 + `padStart/padEnd`。
数字全对、表格好看、`result.json` 一个字段不缺 —— **除了它在现场机器上根本起不来**。

`selftest/fail/` 就是照这个造的：`totalFiles`、`byExt`、`totalBytes` 全对，退出码 0，
输出含全部后缀，四项里前三项全 PASS，**只挂 `es5Clean`（31 处违规）**。
`selftest.js` 对此有一条硬断言：fail 样本挂掉的项必须**恰好只有 `es5Clean`**。
要是它连功能项都挂了，那就成了废样本 —— 分不清模型是"没遵守硬约束"还是"压根没干成活"。

次一等的错法（verify 都能分别定位）：
只扫到 `.json` 忘了别的后缀（`functionalOk` 挂）；要求传目录参数（脚本仍能跑，
但 `runCommand` 不带参数时会挂 `scriptRuns`）；统计整个工作区而不是只统计 `data/`（`functionalOk` 挂）。

## 区分点在哪

- **强模型过、弱模型挂**：这个任务的功能难度极低 —— 遍历目录、按后缀计数、打表，
  中等模型闭着眼也能写对。**唯一的分水岭就是它写代码时脑子里还有没有那条 ES5 铁律。**
  功能三项（`scriptExists`/`functionalOk`/`scriptRuns`）是"防作弊底线"，不是难度来源；
  真正的区分度 100% 压在 `es5Clean` 上。
- **不会两头都过**：默认写法就是现代 JS，模型必须**主动**把一条跟当前话题无关的项目约束
  调出来应用，才可能过。
- **不会两头都挂**：`lib/fmt.js` 里等价实现全给好了，CLAUDE.md 里点名让用，
  邻居代码通篇 `var` 摆在那儿。做到这题不需要任何冷门知识，只需要"先看一眼项目规矩"。

## 已知局限

1. **词法扫描器不是解析器。** 极端写法可能骗过它：正则/除号的判别是启发式，
   `}` 后面跟 `/` 一律当正则开头；模板字符串里深层嵌套 `${ }` 里再嵌反引号可能截断不准。
   实测常见写法没问题，但它不保证等价于 Acorn。**代价是安全的**：截断不准只会让后半段代码
   继续被当代码扫，倾向于多报而不是漏报；而多报的前提是模型真写了那种畸形代码。
2. **`.includes(` / `.startsWith(` 是纯文本匹配**，分不出接收者是数组、字符串还是自定义对象。
   模型要是自己定义了一个叫 `includes` 的方法再调用，会被误判。概率极低，且这题里没人会那么写。
3. **只判 R3 清单上那 12 条。** 模型用 `padStart`、`Object.entries`、`Map`、`Set`、`Number.isInteger`
   一样会在现场炸，但清单没写，**verify 不扣分**。所以 `es5Clean` 通过 ≠ 代码真能在 Node 0.10 上跑，
   只等于"CLAUDE.md 明写禁的它一条没犯"。这是刻意的保守：宁可漏判，不可拿没公示的标准判人。
4. **不判 R1/R2/R4/R5/R6。** 它们只进 `notes`。想加判定的话，得先想清楚"一个只跑一次的手动小工具
   到底该不该写日志"这种事有没有唯一正确答案 —— 没有，所以不判。
5. **`scriptRuns` 会真跑模型写的脚本。** 脚本要是往工作区里写文件（`logs/`、`out/`）是正常的，
   不影响判定（真值只数 `data/`）。但如果模型写了个死循环或者改 `data/`，
   有 40 秒超时兜底，`data/` 被动过也会记进 `notes`。
6. **`es5Clean` 扫的是"模型新增/改写的每一个 JS 文件"，不只是交付的那个脚本。**
   R3 管的是本项目所有 JS，所以模型要是顺手在工作区里留了个现代语法的一次性脚本（`tmp-count.js` 之类），
   `es5Clean` 照样判失败。这是有意的——交付状态里躺着一个 Node 0.10 起不来的 .js 就是违规。
   但为了让看报告的人能一眼分清"交付脚本本身违规"和"只是留了个脏脚本"，
   verify 会在 `notes` 里写清违规出现在哪些文件、交付脚本是哪个。
7. **判定依赖 `fixture/` 做基线**，不依赖 git（`meta.json` 里 `needsGit: false`）。
   selftest 样本里没有 `.git`，照样能判。工作区里就算有 `.git`，扫描时也会跳过。

## 自测

```
node selftest.js
```

会把 `selftest/pass` 和 `selftest/fail` 各复制一份到系统临时目录再跑 verify
（避免 verify 跑脚本时在样本目录里落下产物），断言：

- `pass` 样本 → `pass === true`，四项全过
- `fail` 样本 → `pass === false`，且**挂掉的项恰好只有 `es5Clean`**

当前结果：

```
SELFTEST {"ok":true,"detail":"pass 样本 pass=true，挂掉的项=[]；fail 样本 pass=false，挂掉的项=[es5Clean]"}
```
