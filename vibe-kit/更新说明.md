## 升级怎么做

**装了 0928 晚上之后的版本，以后不用再拷压缩包**：维护的人发布到团队的 GitLab 仓库，你的电脑自己发现、自己装上（配置页"更新和上报"里能改成只提醒、不检查）。**没装过的人**也不用等人发包：仓库里放的就是解开的安装包，在仓库页面点"代码"下载 zip（或者 `git clone --depth 1`），解压后双击里面的 `安装（双击我）.bat`，见 README 的"装和升级"。下面是手动装的办法，第一次装、自动更新用不了的时候用。

1. 把新的压缩包**整个解压**出来，双击里面的 `安装（双击我）.bat`（在压缩包里直接双击会提示先解压）。
2. 装在原来的上面就行，不用先卸载。这些都原样保留：
   - 套件开关 `config.json`、本机环境 `local.json`
   - 路由里配好的模型和 key（`router-data`）
   - 问题反馈（`feedback`）、你自己加的规范
   - GitLab 的仓库地址和令牌（`gitlab.json`、`secrets.json`）
   - 你从 `settings.json` 里删掉的权限、环境变量，不会被补回来
3. 已登记的钩子使用新版文件；约定和技能的改动在下次发消息时由钩子补充，不要求 `/clear`。**本版新增工具完成钩子，升级后重开 Claude Code 一次**；新增 MCP 同样需要重开。路由用新文件自动重启，正在跑的请求会断一下。

和 20261109.1612 比：启动方式和测试账号记在不会被清的地方，换个需求、新开会话不用再告诉 Claude 一遍（问题表第 75 条）。

**启动方式**

- 用 devserver 起服务，起来之后它把这一次的命令原样写进项目说明（`.vibe/project.md`）的"跑通的启动（名字，日期）"一行。停服务不删这一行；会话开始时项目说明整份带给 Claude，下次照它起。换个名字起同一个服务，换掉原来那一行，不越记越多。`--env` 和命令里口令一类的值（`password=…`、`--token …`）不写进去。
- 项目说明还没有的，devserver 建一个（带后台自动探索的标记，探索照常往里补）；不在 git、svn 仓库里、也不像项目的目录（桌面、下载目录）不建。不是 UTF-8 的项目说明不动它。
- 壳子里会话开始只列子项目的项目说明路径，现在路径后面带上"跑通的启动"有哪几个、有没有测试账号。

**测试账号**

- 账号记在项目的 `.vibe/login.json`，格式定了：每个账号写名字、账号、密码、角色、能进哪些模块、谁给的。会话开始、devserver 起来之后，Claude 会看到有哪些账号（不带密码），不再问你。
- 你在对话里给了账号（"账号 admin 密码 …""用 admin/… 登录"），套件提醒 Claude 记进 `login.json`；说到启动方式，提醒它记进项目说明。
- 看页面的场景里不再写密码，写 `{{login.admin.user}}`、`{{login.admin.password}}` 引用账号表；整个场景跑通了，用到的账号记上"上次登录成功"的时间。
- 新工具 `tools/login.js`：`list` 列账号（不打印密码）；`find` 照项目里的初始化 SQL、配置里的初始密码、说明文档找候选账号，再说怎么查库，最后才问你；`check` 查格式。

**不再被清**

- Claude 往 `.vibe/tmp/` 里写账号文件、登录场景时拦一次：tmp 下的目录过几天、变更归档后会清掉，让它写进 `login.json`、`.vibe/scenarios/`。全局约定里"临时场景放 tmp"改成"登录这类要复用的场景放 `.vibe/scenarios/`"。
