# vibe-kit

让内网的 Claude Code（配私有模型）用起来顺手的一小套东西。挂在 OpenSpec 上用，不另起一套流程。

## 里面有什么

| 东西 | 作用 |
|---|---|
| 全局约定 | 五十来行。第一条是"不想当然"；然后是先用现成的能力、被打断之后怎么办、直接动手、说话直说（带着官方给新模型的那句 "Please remove all mannered prose."）、改完要验、省着用（不自己开子代理、先定位再读文件、到线就交接） |
| 规范 | 每条规范一个文件，启用的自动并进全局约定。现在带了 OpenSpec 的用法（含"一个模块一个提案"）和 git 提交规范 |
| 后台自动探索 | **进到没探索过的项目不用你说**：套件在后台查清是什么工程、怎么编译、启动命令和端口、什么编码，把**开发环境**的数据库和 redis 连接配好，写进那个项目的 `.vibe/`。不用模型、不花额度、不挡你打字；依据的文件改了跟着改（见"后台自动探索"一节） |
| `/ttls-onboard` | 自动探索不够用的时候用：认不出的工程、要实际跑一遍命令量时间、要补登录账号。团队都一样的部分（命令、编码、坑、产出位置），问过你再写进项目 `CLAUDE.md` 的"项目说明（团队共享）"一节，跟着仓库提交，同事不用再查一遍 |
| `/ttls-db-crud` | 查库、改库：达梦、神通、MySQL、Oracle、人大金仓。按关键字找表、看结构、看数据不用写 SQL；写操作先算影响面、留改前快照、要你确认；全自动模式下不等你确认，留得下改前快照和还原脚本才执行，新增的记下表和主键。要 Python 3 和 java 8 以上；驱动在配置页"数据库驱动"里管（见"查库和查 redis"一节） |
| `/ttls-redis` | 查 redis、改 redis 里的数据。客户端只用 Node 自带的模块，什么都不用装。连接信息按连接名从项目的配置里取，口令不上命令行 |
| `/ttls-see-page` | 看页面：起服务、照步骤操作、读页面上的值和页面结构。还原原型时，原型和页面各导出一份"每个元素的位置、尺寸、颜色"按数字比，不靠读截图。**接口场景**：改了后端的，直接调接口、查状态码和返回的字段（和页面共用登录状态；只调接口时不开浏览器） |
| `/ttls-cross-review` | 换个模型审一遍：审查代理用 sonnet 这个角色，经路由落到另一个模型上。每个变更审两次：提案一次（apply 之前）、代码一次（归档之前）；开了多轮审查按轮数 |
| `/ttls-handover` | 写交接记录。上下文到交接线时，这一轮说完后 Claude 会用它的提问框问你"现在交接吗"；选"现在交接"它就写交接记录，你敲 `/clear`，再说一句"继续"，新会话先读交接记录再接着干。配置页可以开"/clear 之后自动接着干"（要较新的 Claude Code，默认关），开了不用说话 |
| 收工检查 | **自动触发就靠它**：模型准备收工时，脚本检查这一轮改了代码有没有验证、改了页面有没有看、这一轮把变更的最后一项任务打了勾有没有审、这一轮改的文件有没有提交，漏了就拦一次让它补上 |
| 自动提交 | 一项任务（最小的一件事）完成了就提交一次。完成 = 验证过 + 提交前它自己把这一项的 diff 过一遍。只 `git add` 它这一轮改的和新建的文件（新建的漏了 add，提交时会被拦下点名），你工作区里原来就有的改动不会被带上；在当前分支上提交，**从不 push**。换个模型的交叉审查不是每项任务都做（每次要开一个子代理），整个变更做完审一次，审出来的问题修掉再补一个 fix 提交。四档可选：每项任务提交 / 一个阶段做完提交（tasks.md 里同一个大编号的任务）/ 整个变更做完再提交 / 我说了才提交 |
| 开工前拉代码 | 你提了需求、敲了 `/opsx:…`、接着交接记录做的那一句话，先把会话所在的仓库和下面的子项目拉到最新，再开始分析、写代码。只快进：分叉了、和没提交的改动碰到同一些文件，就不拉，告诉 Claude 要合并先问你。同一个仓库 2 小时里只拉一次（见"开工前拉代码"一节） |
| 会话开始 | 自动把项目说明、交接记录带给模型；当前目录是一层壳子（下面套着各个子项目）时，列出子项目，提醒 git 要进到各自的子项目里执行；`.vibe/` 一出现就把它加进那个仓库的 `.gitignore` |
| 打断后的提醒 | 你打断它、聊了几句之后，自动带上"你刚才在执行哪条指令、做到第几项"（只提这个会话动过的变更，壳子里 git pull 下来的同事的变更不算；后台任务的通知那一轮不提，免得你按了 Esc 它又回去接着做）；上下文过了交接线，每条消息带一句"该交接了" |
| 状态栏 | 三行。第一行：警告、模型、目录和分支、上下文进度条、进行中的 OpenSpec 变更。第二行：全自动开没开（开着时写明这个会话在不在流程里）、用到多少 Claude Code 自己压缩、放松了的保护、经验待确认、更新。第三行：今天经过路由的请求次数和 token，用得最多的三个模型各自的数，到公司提醒线的 75% 变黄。上下文上限默认按 100 万 token 算，交接线默认 70%，到线变红并把"该交接了"放最前面；用量过了上限（Claude Code 没压缩）时说敲 `/compact` 或者交接。没有新消息时 30 秒刷新一次。这些都在配置页里改，改完不用重开会话 |
| 编码钩子 | 拦住会把中文写坏的修改：GBK 文件、两种编码混着的文件、往 GBK 目录里写带中文的新文件 |
| 提交检查 | 提交时它这个会话里新建的文件还没 `git add`（git 不会自动带上新文件）就点名拦一次，属于这次提交的一起 add，测试用的不提交；提交信息不符合 `类型: 内容`（例：`feat: 新增修改页面`）就拦下；`git add -A`、`git add .`、`git add -u`、`git commit -a` 一律拦（会把你工作区里原来就有的改动一起带进去），壳子里 add 子项目目录也拦（会提交成 gitlink）；新建的仓库第一次入仓（还没有任何提交）不拦。`for r in a b; do git -C "$r" …` 这种循环按每个取值各查一遍；目录写在变量里算不出来的，提示里说清是算不出是哪个仓库。用临时 index 提交的（`GIT_INDEX_FILE=…`），新文件加没加看那份 index。提交前查这次新加的内容里有没有密码、key、token、私钥，查到了弹框等你确认。**git push 不管怎么写都弹确认**：权限规则 `Bash(git push:*)` 按前缀匹配，实测 `git -C 子项目 push` 能绕过它；写在 if / try / 循环 / 子 shell / 函数 / 脚本文件里的也认得出 |
| 别停在确认框上 | Bash 里 cd 和别的命令串在一条里（`cd 子项目 && mvn …`），Claude Code 会停下来等人点确认，开着跳过权限模式（`--dangerously-skip-permissions`）也照样问，全自动时就一直挂着。套件当场拦下，按后面跟的命令给出不用 cd 的写法：`git -C`、`mvn -f`、`npm --prefix`、`devserver.js --cwd`，脚本和文件写完整路径，搜代码读文件用 Grep、Read。单独一条 cd 不拦。会话开始时也先说一句；后台自动探索写的命令不再写"进到某目录里" |
| 产出位置 | DDL 脚本、功能说明、分析报告、表格这类代码之外的产出，放哪要是你定过的：项目说明"产出位置"里记着的，或者你这次说过的路径。没定过就拦下先问你，定了记进项目说明，以后同类的不再问；全自动模式下不问，先放 `.vibe/pending/` 等你回来定 |
| 溯源 | 做完、归档之后才发现问题：`tools/trace.js <文件>[:行号]` 列出当初是哪个变更、哪项任务、哪个提交改的这里，再决定是直接修还是新开变更改规格 |
| .vibe 整理 | 临时脚本放 `.vibe/tmp/<事由>/`，一件事一个目录。事由是变更名的留到变更归档，没归档之前删它会被拦下，归档后套件自己清；别的事由做完就删，七天没动的自动清掉；以前堆着的用 `tools/vibe-tidy.js` 挪进 tmp（不直接删） |
| 起服务 | `tools/devserver.js` 记着起过的服务：已经在跑就复用，改过代码就在同一个端口重启，端口被别的程序占着就说清是谁，不会换端口另起一个；直接起服务的命令会被拦下 |
| 经验规则 | **同样的问题不再犯第二遍**：审查代理报的问题，审查之后那个文件确实改了的，收工时脚本自动收下来（Claude 也可以自己记一句）。同一条在不同的变更里出现两次，就变成那个项目的规则，写进项目的 `.claude/rules/`，跟着仓库提交，同事的 Claude 也能看到；几个项目里都成了规则的，你点一下升成用户级。规则按文件类型分组，读到那类文件时才带上，平时不占上下文；每条限长、每组限条数（见"经验规则"一节） |
| 自动更新 | 团队的 GitLab 仓库里放着安装包。用着 Claude Code 的时候，后台隔一阵问一次仓库，有新版就下载，等路由空闲时装上，装完自检，不过就装回上一版。全程没有窗口。维护的人双击"发布到 GitLab"就发出去了，不用再拷压缩包 |
| 问题上报 | 本机记下的问题反馈自动建成仓库里的 issue，别的电脑报过的不重复建；配置页"更新和上报"那一页列着每条上报成了哪一条 issue。维护的那台电脑在那一页上一键导出开放中的 issue，由浏览器下载，你确认文件存下来了再关掉这一批 |
| 使用情况上报 | 每天用套件的次数（开口、进流程、各道检查拦了几次、放行几次、上下文涨到多少、审了几轮、拉代码成没成、各个模型的请求和失败），第二天传到仓库里这台电脑的"[使用情况]" issue 下面。只有次数和版本号，不传路径、代码、提示词。给改套件的人看哪里能优化；配置页上能看要传的内容，能关（见"使用情况上报"一节） |
| 问题反馈 | 套件拦错了、报错、卡住：Claude 当场记一条，钩子出错也自动记，都在 `~/.claude/vibe-kit/feedback/`，自动上报。不是问题的不记：同一条理由反复拦、在配置页改开关、全自动模式下的放行，另外记数。被拦住走不下去的流程类检查，它可以申请放行那一步（默认要你点同意，全自动模式下不用） |
| 全自动报告 | 全自动模式下收工时，套件把这一轮的情况合成一份报告：做到哪、留给你做的、库里改过的、想问没问成的、没验证的、放行的检查、自己定的事。存在项目的 `.vibe/reports/` |
| 模型路由 | 跟套件一起装，在后台运行，没有窗口，登录后自动启动。限流、熔断、key 失效自动换模型；带一个本机配置页，加模型、换 key、看用量、配本机环境、管数据库驱动、开关上面这些自动触发，都不需要 AI。装了路由时，改文件、跑命令、收工这几个检查也在它里面跑（见"检查在哪里跑"） |

没有编号、状态文件、闸门文档。需求和任务归 OpenSpec 管。

## 安装

需要 Node 18 以上。安装包从两个地方拿，装法一样：

| 从哪拿 | 怎么做 |
|---|---|
| 团队的 GitLab 仓库（里面放的就是解开的安装包，总是最新发布的那一版） | 浏览器里打开仓库页面 `http://scm.skytech.io/nb-2026/p1/ai-engineering/90-personal/3139/vibe-kit`，点"代码"，下载 zip。要能登录内网 GitLab 的账号 |
| 同上，有 git 的电脑用命令行 | `git clone --depth 1 http://scm.skytech.io/nb-2026/p1/ai-engineering/90-personal/3139/vibe-kit.git %USERPROFILE%\vibe-kit-setup`，然后 `node "%USERPROFILE%\vibe-kit-setup\install.js"`。装完这个目录可以删 |
| 别人发来的压缩包 | 第一次装、或者连不上仓库时用 |

把拿到的目录（或者压缩包**整个解压**出来的目录）里的 `安装（双击我）.bat` 双击一下，或者在那个目录里 `node install.js`。装完以后不用再管仓库：你的电脑会自己发现新版、自己装上（见"自动更新和问题上报"）。每一版和上一版有什么不同、怎么看自己装的是哪一版，见同目录的《更新说明.md》。一次装好两样东西：

1. **套件**：约定、规范、技能、钩子、状态栏，装进 `~/.claude`。
2. **模型路由**：在后台启动，**没有窗口，任务栏里没有东西**；登录后自动启动，同样没有窗口；装完安装器自己验证一遍配置页打得开，并把地址打印出来。

全新的机器上还没有配模型，安装器会直接帮你把配置页 **http://127.0.0.1:15730/ui** 在浏览器里打开。两步：

1. 点"添加模型"，填网关地址和 key（一个模型一条）。点"按常用的分三个角色"，再按需要把审查（sonnet）改到另一个模型上，保存。
2. 点页面最上面的 **"接上"**。全新的机器上，Claude Code 并不知道有这个路由；这一下会把 `~/.claude/settings.json` 里的 `ANTHROPIC_BASE_URL` 指到路由（改之前自动备份，"断开"时原样恢复）。这一步不自动做，是怕这台机器上的 Claude Code 本来连着别处，自动改了会让它用不了。

然后新开一个 claude 会话就能用了。项目说明、开发环境的数据库和 redis 连接，套件在后台自己探索，不用你说。在壳子目录里启动的，告诉它这次要动哪个子项目。

以前单独装过 `urai-db-crud`、`redis` 两个技能的：装在用户目录里的，安装器删掉（先备份，自带的驱动挪进套件）；装在项目里的不动，会话开始时 Claude 提醒你一次。

**装完、改完开关，不用重开 Claude Code，也不用 `/clear`。** 在内网 2.1.259 上实测：会话开着的时候，钩子脚本和新登记的钩子立刻生效；全局约定和新装的技能，Claude Code 自己要等 `/clear` 才重新读。所以由钩子来送：会话开始时记下模型拿到的版本，你每次发消息时比一下，变了就把变了的那几段（或者"约定改了很多，先读一遍全文"）随这条消息带给它，只送一次。路由在安装时自动重启。全自动模式下它用提问框问你会被直接拦下，不会整夜停在那里等回答。

安装器先检查后动手：`settings.json` 读不懂、全局 `CLAUDE.md` 不是 UTF-8（比如用 cmd 的 echo 往里追加过中文），就什么都不动，并说清是哪几行、怎么转。只往 `~/.claude` 里添加东西：`CLAUDE.md` 只动两行标记之间的内容；你已有的同名技能（技能目录里改过任何一个文件都算）、改过的约定和审查代理，覆盖或删除前都会备份到 `~/.claude/vibe-kit/backup/`（只留最近 20 份）。你从 `settings.json` 里删掉的权限、环境变量（比如把 push 的确认挪到了 deny），升级时不会再补回来。重复运行就是更新（路由会用新文件重新启动，配好的模型和 key 不动）。不想装路由：`node install.js --no-router`（以前装过的路由不更新、原样留着照常运行）。做到一半出错（文件只读、被占用、没权限）时，用中文说清是哪个文件、现在是什么状态、怎么办，不甩英文堆栈；关掉占着文件的程序再运行一次就会补上。

安装器在 `settings.json` 里放行 Bash、PowerShell、Read、Edit、Write、Glob、Grep，这几样工具平时不弹确认；git push 照样弹，由钩子管，怎么写都认得出。你从放行里删掉的，再装不会补回来。另外写一项 `permissions.disableAutoMode`，把新版 Claude Code 自带的"自动模式"关掉（见"Claude Code 自带的自动模式默认关掉"一节）。

卸载：`node "%USERPROFILE%\.claude\vibe-kit\install.js" --uninstall`。会停掉这一份安装自己的路由（端口上跑的是别的安装的路由就不碰）、取消登录后自动启动，收回安装时加的权限、环境变量、钩子（命令方式和 HTTP 方式的都收）、状态栏；配好的模型和 key（`router-data`）、本机环境、你自己的规范、问题反馈留着。在配置页点过"接上"的，卸载时会替你点一次"断开"：Claude Code 连的地址恢复成接上之前的（不然路由停了 Claude Code 就连不上了）；不是配置页"接上"改的地址（比如你自己配的）不动，只提醒你改。

## 模型路由

配置页 **http://127.0.0.1:15730/ui**：

- **模型**：接上 / 断开 Claude Code；加模型、换 key、停用、测试；看每个模型现在是正常还是在冷却（以及原因）。保存前会先测一次；测不通也能存，因为路由碰到它失败会自动换别的，不会让 Claude 用不了。每次保存前自动备份，能一键恢复。
- **用量**：今天的请求数（对着公司 4000 次的线）、每个模型的 token、最近的请求和失败原因。
- **本机环境**：各版本 JDK、Tomcat，以及好几套 Maven（不同的 settings.xml、本地仓库、版本，各起一个名字，指定一套默认的）。先点"自动探测"，没找到的点"选…"去硬盘上点选，不用手打路径；弹窗会告诉你"这里是一个 JDK"，免得选错层级。保存后写进全局约定，所有项目、所有会话都能看到。只存在本机。
- **套件开关**：上下文上限和交接线（改完自动保存，正在开着的会话下一次刷新就按新值算，还能看到各个会话现在用了多少）、到线后问不问、三个自动触发（关掉"看页面"那个，全局约定和 OpenSpec 规范里也不再让它自己起服务看页面，页面任务的验法改写"人工看页面"）、提交检查、检查在哪里跑（HTTP / 命令，以及路由最近一次收到检查调用的时间）。
- **数据库驱动**：每种数据库现在用的是哪个 jar，手动换、自动搜索（见"查库和查 redis"一节）。

改配置改坏了也不会让 Claude 用不了：配置文件不是合法 JSON，路由继续用上一份好的；某一个模型没填 key、地址不对、key 里混进了看不见的字符，只跳过那一个，并在页面上标出来。两个页面同时开着、或者你手改过 config.json，拿页面上的旧内容保存会被拒绝（页面刷新成最新的，重做这次修改），不会把别处的改动冲掉。

它怎么转发：

- 按请求里的模型名分角色：主会话 opus、审查代理 sonnet、后台小任务 haiku，各自交给你指定的模型
- 熔断（5xx）、key 失效（401/403）、连不上、等 300 秒没回应，都自动换下一个模型。熔断和 key 失效冷却 30 分钟，连接层面的错误只避开 1 分钟（所有模型走同一个网关，多半不是那一个模型的问题）。每次换下一个之前都重新看一眼冷却：别的请求刚把某个模型打进冷却的，这次直接跳过它
- **限流（429）、过载（529）、带 retry-after 的 503 先等再换**：在同一个模型上按它说的 retry-after 等（没说就 5、5、10 秒地试，总共不超过 20 秒，页面可调），等不到再换模型；冷却多久也听它的 retry-after（10 秒到 5 分钟），它没说就按配置。换模型意味着另一个模型要把整个上下文从头算一遍：缓存全丢，还占着它，让别人等
- **额度用完**（网关回"每日额度超限……将于 <时间> 重置"、insufficient_quota 这类）和限流不一样，等几秒没用：不等，直接换模型；这个模型停用到回复里说的重置时间（读 reset_at 这类字段、"将于 … 重置"这句话、很长的 retry-after；每日额度没说时间的，停到本地明天 0 点），到点自动恢复，停用记录存在 `router-data/quota.json`，路由重启也不会忘。配置页上显示"额度用完，几点自动恢复"，旁边有"手动恢复"：你找管理员加了额度，点一下立刻启用（其实没恢复的话，下一次请求被拒，路由会再停用一次）。所有模型都额度用完时，请求直接回 429 并说清几点恢复，不再发给网关
- 任何等待都封顶在 Claude Code 自己的超时减 20 秒：它先放弃了，路由再换模型就来不及了
- 所有模型都在冷却时，一个请求最多再多试一个（最快到期的那个），然后带着 Retry-After 回给 Claude Code，让它按节奏退避，不把整个会话轮着发给每一个模型
- 大请求（默认 30 万字节以上，约 7 万 token）慢是正常的：等到 Claude Code 自己的超时之前，到点、或者网关先回了 502 / 504，也不换模型，回给 Claude Code 让它自己重试；同一个模型连续两次这样才当它卡住了
- 你按 Esc 取消的请求不算模型的错，不冷却任何模型，用量里记成"客户端取消"
- 先回了 200、又在流里报错（overloaded_error）的，记成失败并让那个模型冷却；没收到结束标记就断了的，记成传输中断
- 同一个会话换过模型后 10 分钟内留在新模型上不来回切，按角色分别记，审查代理不受影响；在页面上点首选模型的"现在就试"立即回首选
- 数 token 的接口（count_tokens）上游回过 404，之后六小时就不再把整个会话传过去
- 回复边收边转，不攒包；传到一半上游断了，把客户端的连接也断开让它自己重试，不把半截回复装成正常结束
- 413 翻译成看得懂的提示；边转发边记 token 用量（先写临时文件再改名，退出前保存）；数 token 之类的杂项请求只问一个模型，成败不影响模型的状态
- 只监听本机；不理 Host 不是本机的请求；配置页的接口只接受本机连接，别的网站的页面发来的不收（它页面里的 `<img>`、`<script>` 这类不带 Origin 的请求也挡，按 Sec-Fetch-Site 认）；**网页发来的请求一律不转**（带 Origin、Sec-Fetch 头或者不是 JSON 的），免得网页借路由、带着真实的 key 往网关发请求
- 网关用 https 的：默认不校验证书（内网常见自签证书），网关的证书是正规机构签发的，在模型设置里勾上"校验证书"更安全
- 停路由时先带令牌请它自己保存用量再退出，等不到才结束进程；只认监听着 `127.0.0.1:端口` 的那个进程，不会误杀别的程序

它在哪、怎么管：

| | |
|---|---|
| 程序 | `~/.claude/vibe-kit/router/` |
| 数据（config.json、用量、日志、备份） | `~/.claude/vibe-kit/router-data/`，更新和卸载都不动 |
| 登录后自动启动 | "启动"文件夹里的 `vibe-kit-router.vbs`，删掉它就不再自动启动。不需要管理员权限，不建计划任务 |
| 手动管 | `node "%USERPROFILE%\.claude\vibe-kit\router\service.js" status`（还有 start、stop、restart、autostart、no-autostart） |

有的公司会禁用 .vbs 脚本。安装器放之前会先实际跑一个试试，跑不了就不放（免得以后每次登录弹一个报错框），并告诉你。那种情况也不用管：打开 Claude Code 时，"会话开始"的钩子发现路由没在跑，会悄悄在后台把它拉起来；路由进程被杀了也是同样兜底。

### 配置页打不开

先看状态：

```
node "%USERPROFILE%\.claude\vibe-kit\router\service.js" status
```

- 说"没在运行"：`service.js start`。起不来的话它会把路由的输出打印出来；启动时就崩掉的报错在 `router-data\router.out.log`，平时的日志在 `router-data\router.log`（满 5 MB 轮换）。
- 说"端口 15730 被别的程序占着"：在 `router-data\config.json` 里把 `listen.port` 换一个，再 `service.js start`；然后在配置页里"断开"再"接上"一次，让 Claude Code 跟着换端口。
- 说"在运行"但浏览器打不开：用的是 `127.0.0.1` 不是别的地址；浏览器或系统代理要对本机地址直连。

## 检查在哪里跑（HTTP / 命令）

套件的检查都是钩子：Claude Code 在改文件、跑命令、收工这些时刻调它们。以前每个检查都起一个 node 进程，每次 0.3～0.9 秒，改一次文件、跑一条命令都要等它。现在装了路由时（配置页"检查在哪里跑"选"自动"，默认），改文件、跑命令、提问框和调技能、搜文件内容、收工检查这五个登记成 HTTP 钩子，由路由在后台线程里跑，同一份代码、同样的判断，一次几毫秒（实测平均 5 毫秒）。会话开始、你发消息时的两个检查一直用命令方式，它们负责下面的兜底。

HTTP 方式的代价：路由没在跑时，Claude Code 调不通就当放行，不报错，这几个检查会悄悄失效。所以：

- 会话开始时，钩子发现登记的是 HTTP 方式、路由却没在跑，就在后台把它拉起来。
- 你每次发消息时自检一次：上一轮改过文件或跑过命令，路由却没收到这个会话的检查调用 → 路由没在跑就拉起来；登记的端口和路由的端口对不上就重新登记；路由在跑也收不到，就自动切回命令方式。三种情况都会告诉 Claude"上一轮的改动没经过检查，自己核对一遍"。
- 路由启动时核对一次：settings.json 里登记的端口和它现在的端口对不上，就重新登记。
- 模型常顺手用 `taskkill /IM node.exe`、`Stop-Process -Name node` 杀卡住的开发服务，这会把路由（和接上了路由的 Claude Code 的模型连接）一起杀掉。装了路由时这类命令一律拦下，让它按端口找 PID 再停；结束路由自己的进程也拦。
- 钩子代码更新了（装了新版），路由下一次调用就换新代码，不用重启。一个检查 25 秒没结果、或者出错，当放行（和命令方式一样），出错记在配置页上。

对这个代价不放心，在配置页把"检查在哪里跑"改成"命令"：每次慢零点几秒，但不依赖路由。

## 上下文上限、交接线和网关

**路由不会破坏提示缓存**：实测过，Claude Code 发出的请求原样过路由，上游收到的字节和发出的逐字节一致（system、tools、messages、cache_control 的位置、请求头都不动，只把 key 换成那个模型自己的；配了模型名改写的，只有 model 一个字段变）。同一个会话始终落在同一个模型上，缓存该命中就命中。

真正会让缓存失效、让小模型被占住的是三件事：换模型（另一个模型要把整个上下文从头算一遍）、请求被放弃后重发（原来那个模型多半还在算）、上下文本身太长（内网实测：5 万 token 时同前缀第二次只要 0.25 秒；30 万 token 时热请求 16 秒比冷请求 6.5 秒还慢，缓存已经不起作用，每一轮都要重付预填充）。前两件路由已经尽量避免（见上一节）；第三件只能靠早点交接、把交接线设低一点。

配置页"用量"页最上面有按模型算的缓存命中率（缓存命中 ÷ 全部输入，来自模型在回复里报的数）、换模型次数、限流等待次数，拿去和网关那边对数。命中率一直是 0、而同一个会话的第二条请求又明显比第一条快，说明网关没把这个数传回来，不是没命中。

- 进度条 = 已经用的 token ÷ 上下文上限。上限默认 100 万（模型的标称值），填 0 表示跟着 Claude Code 自己报的窗口走。用到交接线（默认 70%）就提醒交接。
- **模型的上下文长度和网关能接受的请求大小是两回事。** 内网网关对单次请求的大小可能有上限（之前实测约 1 MB，合二十三四万 token），超了直接拒绝（413），根本到不了模型，换模型、`/compact` 都没用。
- 这个上限套件不写死、不猜：路由真的被拒过一次，才记下当时的请求大小；之后快到那个大小的 85% 时，状态栏会提前警告，不管上限填的是多少。之后要是有更大的请求成功了（管理员把上限调大了），这条记录自动作废。配置页上能看到这条记录，也能手动忘掉。
- 想真正用满 100 万，要请网关管理员把请求体上限调大（nginx 的 `client_max_body_size`）。

### Claude Code 自己的"自动压缩"和套件的交接是什么关系

Claude Code 自带自动压缩（`/compact`，或者用到一定量时自动把对话总结成一段再接着聊）。它和套件的交接是前后两道线：

- 套件的交接线（默认 70%）在前：到线问你一句，写交接记录，`/clear` 之后新会话从干净的上下文接着干。交接记录是文件，人能看、能交给同事，新会话还会用 git status、tasks.md 核对一遍再动手。
- Claude Code 的自动压缩在后，当兜底用。压缩之后钩子会重新注入项目说明和壳子结构。

**压缩线由套件替你设好**（配置页"上下文和交接"里的"自动压缩线"，默认 90%）。2026-10-01 有人用到 1001% 都没压缩，查下来是这样（读过两个版本的代码，又用真的 Claude Code 加假模型实测过）：

| Claude Code | 没设压缩窗口时 | 设了之后 |
|---|---|---|
| 2.1.259 这类新版 | 不按用量压缩，只等模型接口报"请求太长"才补救。内网模型报的错它认不出，上下文一直涨，过了 100% 也不压缩 | 在"窗口 − 3.3 万"处压缩 |
| 2.1.120 | 按它认为的模型窗口压缩（默认的模型按 20 万算，约 16.7 万压缩） | 同上，窗口不超过它认为的模型窗口 |
| 2.1.289 | 又按用量压缩了（实测上报 99 万时压缩） | 同上（实测窗口 93.3 万、上报 91 万时压缩） |

- 套件把窗口写进 `settings.json` 的 `autoCompactWindow`：窗口 = 上下文上限 × 自动压缩线 + 3.3 万，最小 10 万、最大 96 万。上限 100 万、压缩线 90% 时窗口是 93.3 万，用到约 90 万压缩。三个版本都认这一项。
- 为什么最大 96 万：2.1.259 上实测，窗口设到 97.7 万以上，Claude Code 还没压缩就先报 `Prompt is too long`。压缩线填 95%、上限填得比 100 万大的，都按 96 万算，最晚用到 92.7 万压缩。
- 改了之后新开的会话生效。开着的会话在 Claude Code 里敲 `/autocompact <窗口>` 马上生效，这个数配置页上算好了写着。
- 压缩线填 0：套件不设，照 Claude Code 自己的。你装套件之前自己设过 `autoCompactWindow` 的，填 0、卸载时还给你；在 Claude Code 里用 `/autocompact` 改过的，下次保存开关、升级时换回配置页算出来的值。`settings.json` 的 `env` 里设了 `CLAUDE_CODE_AUTO_COMPACT_WINDOW` 的，Claude Code 以它为准，安装时会提醒。
- 状态栏第二行写着"到 900k 自动压缩"；用量还是过了上限，第一行说"Claude Code 没自动压缩：敲 /compact 压缩，或者 /ttls-handover 交接"。

用内网这个版本（2.1.259）实测过的另外两件事：

- 不指定模型时它发出去的模型名是 `claude-opus-5`（2.1.289 是 `claude-opus-5-5`），按 100 万的窗口算。要是把 Claude Code 的模型名改成它不认识的（比如内网模型的真名），它会按 20 万窗口算，而且强制执行：用到 19 万左右直接报 `Prompt is too long`，不压缩也不发。这时要在 settings.json 的 env 里加 `CLAUDE_CODE_MAX_CONTEXT_TOKENS=1000000` 告诉它真实窗口。路由里配的"模型名改写"不影响这一条，Claude Code 自己看到的还是 `claude-opus-5`。
- 以前这里写"脚本方式（`claude -p`）不会自动压缩"，其实是没设压缩窗口的缘故，设了之后脚本方式也照样压缩。

### 已知问题：2.1.259 / 2.1.263 用 `claude -p` 时答完不退出

这两个版本在脚本方式（`claude -p`）下，只要 SessionStart 钩子跑得慢一点（几百毫秒）、同时又配了命令方式的 Stop 钩子，答完就一直不退出，要手动杀掉。用两个只是 sleep 一下的空脚本就能复现，和套件里钩子的内容无关；2.1.231、2.1.215 没有这个问题。平时交互着用不受影响。装了路由、收工检查走 HTTP 时（默认），在 2.1.259 上实测四场都能正常退出；检查改成命令方式、又要在脚本里调 `claude -p` 的，给它加超时。

## OpenSpec：先探索、提案的门槛、修订记录

公司用 OpenSpec 1.2 的流程：`/opsx:explore` 想清楚（可选）→ `/opsx:propose` 一次生成 proposal、specs、design、tasks → `/opsx:apply` 逐项做、逐项打勾 → `/opsx:archive` 合并规格、归档。OpenSpec 自己偏向"往前推"，产物细到什么程度全看模型。套件在这上面加了三道确定性的检查（开关：配置页"OpenSpec 提案不细就拦"）：

- **先探索再提案**：你提一条需求，钩子提醒它先在项目里读代码、表、接口，把现状写给你看，确认了再出提案；不用提案的小改动直接改。这一条也是硬的：这个会话里没读过项目里的东西就写 proposal.md，不让写；探索和写提案在同一轮也不让写（你自己敲 /opsx:propose 的除外）——只认你提需求之后的探索，会话里更早读过的不相干的文件不算；接着交接记录干的新会话（读过一天内的交接记录）不要求分轮；设计 Context 里说读过的文件，会话里得真的读过。
- **提案的门槛**：写 proposal / specs / design / tasks 的那一刻检查，不过就拦回去改。不许"待定、后续完善、开发阶段再、视情况、TBD"（同一行写了"默认按…做"的决策项才放行）；模板占位注释不能留；每个文件不超过 250 行；每条需求至少一个 WHEN/THEN 场景；设计和任务里提到的路径要真实存在（新建的写明"新建"）、设计的现状一节不能空；每项任务要写文件路径和"验：…"，不许"联调、完善"这种任务。只判这次新加、改过的行，老变更不追究，打勾不算改。
- **打勾前要跑过验法**：把任务从 `[ ]` 改成 `[x]` 时，钩子在会话记录里查有没有跑过这项任务写的验法，没跑过不让打勾。`openspec status` 和套件自己的工具不算验证。第一次写 tasks.md 就带着 `[x]` 的也按打勾查。
  - 从哪开始算：这项任务写的文件最后一次改成功之后。这段会话记录里没改过这些文件的，整段都算。任务没写文件的，从最后一次改代码之后算。
  - 验法按分句看。写明的命令、脚本、场景文件，每个都要跑过。只提了工具名的（mvn、curl、playwright），跑过其中一个就行。
  - 验法里提到的结果文件（`.vibe/out/…/result.json`、`report.json`）不是要跑的东西，不查。
  - 验法写"同 3.1""同上"的，查的是那一项写的验法；被拦时提示里写明是哪条命令。
  - "人工看"的分句不查。
  - 现在验不了的部分写成"……本次不做（原因）"，这一句不查，别的照查。全自动模式下会记进报告的"没验证的"。
- **要用户动手的任务**（要账号、改 redis 里的数据、查库的工具不肯执行的改库操作）：在任务行里写 `（留给用户：原因）`。全自动模式下不催它做，也不算"还有活没干"。归档时照样算没打勾。
- **规格增量的标题**：需求要写在 `## ADDED Requirements`、`## MODIFIED Requirements`、`## REMOVED Requirements`、`## RENAMED Requirements` 下面。写成别的标题，归档时 OpenSpec 会报 no deltas found，所以写的那一刻就拦。
- **归档之后主规格跟上了没有**：用 `--skip-specs` 归档、手工 mv 归档的，主规格不会自己更新。收工时钩子对一遍，缺了哪几条需求提醒一次。
- **改了要有记录**：需求 → 规格 → 设计 → 任务是一条链，后面一环改了，上面的要跟着看。你开口时钩子记下各产物的指纹，收工时比对：产物变了（或者同一轮里写了后面的产物又回头改前面的）却没动 `revisions.md`，拦一次让它补记：起因（主观 / 客观 / 用户要求 / 需求变化 / 审查 / 自动模式决定）、改了什么、上层哪些跟着改了哪些不用改。提案里列的能力没有对应的规格文件也会拦。
- **所有产出都审**：提案写好（四个产物齐了）、apply 之前，收工钩子要求它跑一次 /ttls-cross-review 的提案模式（换个模型专挑想当然、没说清、场景漏、任务不可验证、上下文不对齐），最多催两轮，之后每条消息带一句"提案还没审"；最后一项任务打勾后要求跑一次代码模式，后端前端都在内。`openspec archive` 或者把变更目录挪进 archive 的命令，任务没全打勾、代码没审过的一律拦下。
- 提交节奏跟着"改完并验证过之后，提交吗"那个开关写进规范：每项任务提交（默认）时，提案写好提交一次、每完成一项任务提交一次、修订和记录一起提交、归档提交一次；一个阶段做完提交时，tasks.md 里同一个大编号的任务（1.x、2.x……）全部打勾才提交一次，信息写这一组做了什么，一组做到一半不提交（每项太碎、整个变更太大时选它；收工检查只在刚做完一个阶段时催）；整个变更做完再提交时，apply 中途不提交；我说了才提交时，都等你说。只提交不 push。
- 交给审查代理的提示第一行固定写"模式：提案 / 代码 / 复审提案 / 复审代码"，第二行写变更目录；审查者最后一行固定报"结论：问题 N 条"。钩子只认这样的真审查：没带结论行的、调用出错的，不算"审过"。第一行没照约定写的，钩子看提示前几行里的说法（"审一遍提案（不是审代码）"）和变更的任务打没打勾来认；还认不出的不记到任何一边，流水账里留一句。
- **审查在后台跑也认**：2.1.259 起 Agent 默认在后台跑，调用当场只回一句"已经在后台跑了"，审查结论后来作为通知送回。钩子两处都看（调用结果、后来的通知），通知在排队、还没送给模型时也认；审查还在跑、结论没回来时，打勾会被拦下并告诉它"等通知"，收工检查也不会再催它审一遍（免得开第二个）。技能里让它调审查时 `run_in_background` 传 `false`，直接等结论。后台任务的通知不是你说的话：不会被当成新需求、不会被当成"接着交接"，里面提到的目录也不算你定过的产出位置。
- 拦一次的边界：收工钩子每轮只拦一次（否则会死循环）。模型被拦后要是照样收工，钩子把"没做"的事实说出来了，最后一道是你看到它。这就是"不靠自觉"能做到的极限。

### 禁止 Claude 自己改套件（开关，默认开）

实际发生过：Claude 嫌钩子碍事，自己去改 `~/.claude/vibe-kit` 里的钩子。套件是你的，它只能用不能改。开着时：

- 用 Edit / Write 改这些东西一律拦：`~/.claude/vibe-kit` 整个目录（钩子、规范、配置、状态、路由）、`settings.json`（钩子登记在这里）、全局 `CLAUDE.md`、套件装进去的技能和代理。
- 命令行也拦：rm、del、Remove-Item、cp、mv、sed -i、`find -delete`、`>` 重定向（`2>&1`、`2>$null` 不算写入）、管道后面的写入、跑 `install.js` / `service.js`，只要一段命令里出现了套件的路径（`~`、`$HOME`、`%USERPROFILE%`、`$env:CLAUDE_CONFIG_DIR` 这些写法都认，`cd` 过去再改也认，`.claude` 挪到别的盘再建目录联接的也认）。直接调路由的 `/api`、钩子入口也拦（端口写成 `015730`、`0x3d72`，地址写成 `127.1`、`[::1]`，带路由的请求头，都认得出）。
- 不许写 `disableAllHooks`：往任何 `settings*.json`（包括项目里的 `settings.local.json`，它能把所有钩子一起关掉）里写，都拦；`grep`、提交信息里提到这个词不拦。
- **套件代码改了能发现**：安装时记下 hooks、lib、tools、page 下每个脚本的指纹（`state/kit-hash.json`），每个会话开始时比一遍；对不上的（被改过、删了、多出来的）告诉 Claude 先跟你说、别去"修"，状态栏挂红字"套件代码被改过"，并记一条问题反馈。重新运行安装包就恢复。禁改拦的是写入那一下，路径藏在变量里的拦不住，这一道是兜底。
- **开关防篡改**：关掉"禁改"、打开"让它自己放行"这两个放松保护的开关，只认配置页（和安装器）改的——配置页保存时同时写一个封条（`state/config-seal.json`）。绕开配置页直接改 `config.json` 的，封条对不上，钩子按安全的值算，状态栏显示红字"套件开关文件被直接改过"，并自动记一条问题反馈。在配置页关掉禁改、打开自动放行、打开全自动模式，也各记一条，方便事后查是谁什么时候开的。
- 不拦的：只读命令（cat、type、Get-Content、ls、dir、grep…）；跑套件自带的工具（`page/`、`tools/` 里的脚本，看页面、清点技能用的）；项目里的东西（`.vibe/`、代码、openspec）。
- 拦下时的话让它把原因和想改成什么告诉你，由你来改。你确实想让它帮你调钩子、改规范，先在配置页关掉这个开关，改完再打开。路径藏在变量里算不出来的会放过去，误拦比漏拦更糟。

### Claude Code 自带的"自动模式"默认关掉（开关）

这里说的不是套件的"全自动模式"，是 Claude Code 自己的一种权限模式（auto mode）：有风险的命令先交给一个分类模型判断放不放。2.1.284 起，没配过权限模式的话 Claude Code 默认进这个模式。经网关用内网模型时它只添麻烦，2.1.289 上实测：

| 情况 | 结果 |
|---|---|
| `node -e`、`curl` 这类有风险的命令 | 每条先多发一个分类请求：系统提示约 14 万字符，经网关的照常算用量。`echo`、`git status`、在项目里读写文件不发 |
| 分类模型答得不合它要的格式（内网的模型多半这样） | 重试十次，然后把这条命令拦下，说"Auto mode could not evaluate this action" |
| 套件的流程 | 命令被它拦下、审查代理跑不起来，端到端测试 31 项不过；关掉之后 190 项全过 |

所以套件默认把它关掉：在 `settings.json` 的 `permissions` 里写 `disableAutoMode: "disable"`。关掉之后权限照原来的走（套件放行的那几样工具、你自己选的权限模式），不多发请求。2.1.120、2.1.259 不认识这一项，不受影响。

- 想用它：配置页"套件开关"那一页"保护"里的"Claude Code 自带的自动模式"改成"不管它"，重新打开 Claude Code 生效。
- 你自己在 `settings.json` 里写过这一项的，套件不动，卸载时也不收回。
- 你自己把 `permissions.defaultMode` 设成 `auto` 的，套件不加这一项，安装时提醒一句经网关用的代价。
- 没有选"写 `defaultMode`"这个办法：只写 `defaultMode: "default"` 的话，交互界面会弹一次"要不要把自动模式设成默认"，默认选中的是 Yes，一回车就又进去了。

### 交接记录什么时候写、会不会过期

- 普通模式：到交接线这一轮说完后问你"现在交接吗"，你选了才写。全自动模式：到交接线自动写一份再继续（开关"全自动模式下到交接线自动写交接记录"，默认开；关掉就只靠 Claude Code 自己的自动压缩）。
- 过期判断：交接记录写完之后，有变更归档了、或者有变更的任务全部打勾了，说明那件事后来做完了（比如全自动挂了一夜）。这种记录新会话不会再照着接：会话开头只提一句"已过期，不要照它的下一步做"，你说"继续"它会先看 git log 和 openspec 里现在的状态再问你做什么。

### 大需求拆成几个变更：怎么知道哪些做完了

已归档的变更在 `openspec/changes/archive/日期-名字/`，它的规格已经合并进 `openspec/specs/`，这是 OpenSpec 自己的机制。套件在这上面加了一张表 `openspec/plan.md`（`| 模块 | 变更名 | 状态 | 说明 |`）：拆变更的时候让它把清单写进去，状态列不用任何人维护，钩子按 changes/ 和 archive/ 的实际情况刷新（未开始 / 提案中 / 已提案 0/n / 进行中 x/n / 已完成待归档 / 已归档 日期），会话开头带上汇总"共几个、归档几个、进行中哪些、下一个是谁"。

- 做到一半、还没有 plan.md 的：会话开头发现有好几个变更却没有 plan.md，会提醒它建表（三天最多提一次）。建表用 `node "%USERPROFILE%\.claude\vibe-kit\tools\plan.js" <项目目录>`：已归档的和进行中的变更按时间排好、状态填好，它再补模块、说明和还没开始的模块。还没开始的模块只在当初拆分时的聊天或 PRD 里，要你给它清单或者告诉它 PRD 在哪。
- 中途加了新功能：它新建的变更不在 plan.md 里，收工时提醒一次加一行；会话开头的汇总里也会列出"不在计划里的变更"。不属于这个大需求的变更不用加。

### 多轮审查（开关，默认关）

默认每种审查只跑一轮。开了"多轮审查"：审查者每次回复末尾有一行"结论：问题 N 条"，钩子读它。一轮报了问题、Claude 改了东西，收工时要求再审改动点（只给上一轮的问题清单和这次改的文件，话里点名是哪个变更），直到报"问题 0 条"。报了问题但这一轮没改（比如停下来问你），下次改了再催复审。问题核实下来全都不成立、它只在这个变更的 `revisions.md` 里逐条记了理由的，算这一轮处理完（以前这种情况会永远审不完，打勾、归档一直被拦）。最多几轮可配（默认 3）；轮数用完还有问题，不管这一轮改没改，停下来用提问框问你：再修一轮、就这样先提交、还是你自己看。提案和代码两种审查都走这个规则；没审完不让开工、不让归档。审完再审就重新计轮。只看这个会话、当前目录里的审查：别的项目没审完的，不会在这里催。

### 全自动模式（开关，默认关）

你开会、不在的时候用。原则一条：**一切自动，不等你，做了什么收工时交一份报告**。

**只在走 OpenSpec 流程的会话里算数**。开关开着，每个会话各自算自己在不在流程里：

| 你说的话 | 这个会话 |
|---|---|
| 敲 `/opsx:…`、`/openspec-…`；提一条要走提案的需求；接着交接记录做；点名让它做某个没归档的变更 | 进流程 |
| 已经在流程里，又说一句不是问句的话（"3.3 我执行过了，接着归档"）；敲 `/ttls-cross-review`、`/ttls-see-page`、`/ttls-handover` | 还在流程里 |
| "继续""好"；"不要停，把剩下的做完""别等我""不用问我" | 跟上一轮一样。上一轮是插进来的一句问话，就跟再上一轮 |
| 让它出一份代码之外的东西（说明、报告、清单，"生成一个文件记一下"） | 不在流程里：放哪照常问你，全自动不作数 |
| 问句；别的斜杠命令（`/ttls-onboard`……）；让它停的话 | 不在流程里 |

让它停的话只认两种：开头就是"停""暂停""等等""等一下"（"等等，先别提交"）；或者短短一句"不用了""别做了""算了""取消"。开头是"不要""别"的长句子不算停，照这句话本身的意思来（"不要用 Excel，做成 CSV 导出"是需求）。

它自己调了 OpenSpec 的技能、建了变更（你用大白话让它出提案），从那一刻起也算进了流程。不在流程里的会话照有人在的样子来：能弹提问框，收工时不催它接着做变更，不出全自动报告。所以开着全自动再开一个窗口做检索、跑 `/ttls-onboard`，那个窗口不会去接着做别的窗口正在做的变更。

开关关着的时候，每一轮在不在流程里也照样记着。做到一半才去配置页打开全自动再离开，照这一轮开头你说的那句话算：开头是 `/opsx:apply` 的接着全自动做下去，开头是一句问话的不算。

在流程里时：

- 会话开头和全局约定最前面都写着"我不在"。别的约定、技能里写"问我""等我"的地方，以全自动那一节为准。
- 你提需求它探索完直接出提案，提案审过直接 apply，做完审过代码直接归档。做了一半停下来，钩子催它接着做下一项。有进展才再催，没进展就放行，不会空转。
- **不弹提问框**。它想用提问框问你的，钩子拦下，把问题和选项记进报告。它按"影响面最小、不破坏现有功能"自己定，定了的记进 `revisions.md`，起因写"自动模式决定"。
- **被检查拦住不等你点**。能申请放行的检查，它写明原因申请，当场放行。30 分钟内对同一个文件、同一件事的这道检查都放行，每次记进报告。一个会话最多 60 次。
- **改库不等你确认**。照 `/ttls-db-crud` 的两步走，第二步不用等你。只做留得下备份的写操作：改、删要取得全改前快照、生成得出还原脚本，新增要记得下表和主键，建表、建索引、加字段要写得出对应的 DROP；备份不了的工具不执行，留给你。每一次都列在报告"库里改过的"一节（见"查库和查 redis"一节）。
- **过程文件先留着**。`.vibe/tmp`、`.vibe/out` 里的东西，流程没走完（这个会话做的变更还没归档）之前不删，删的命令会被拦下；变更归档后套件自己清。
- **要你动手的事不卡住整条链**。要账号、改 redis 里的数据、工具不肯执行的改库操作这类任务，它在任务行里标 `（留给用户：原因）`，跳过去做别的。一个变更只剩这种任务时不归档。
- **push 不弹确认框**，直接拦下留给你，报告里列出没推的提交。提交里有像密码的内容：放行，记进报告。
- 到交接线不弹提问框。收工时还有活要干就先写一份交接记录再继续，每涨 10 个百分点一次。
- 多轮审查用完轮数仍有问题，它按上面的原则自己定，记进 `revisions.md`。
- 只推进这个会话在流程里动手做过的变更（写过它的产物、打过勾、命令里点了名）。只是读过的、壳子里 git pull 下来的同事的变更不碰。

**收工时的报告**。它说"做完了"时，钩子把这一轮的情况合成一份报告，存到项目的 `.vibe/reports/全自动报告-日期-时间.md`，再让它照着写最后的交代。它的交代接在报告后面。一轮交一次；交完又有新情况再交，最多三次。

| 报告里的一节 | 内容 |
|---|---|
| 数 | 各类事情各有几件 |
| 变更做到哪 | 每个变更任务几比几、审没审完、归没归档 |
| 留给你做的 | 标了留给用户的任务、等你定位置的产出、没推的提交、没让它改的文件 |
| 库里改过的 | 这一轮全自动改过的库：哪张表、几行、新增的主键、改前快照和还原脚本在哪、怎么还原 |
| 它想问你、没问成的 | 问题和选项 |
| 没验证的 | 验法里写了本次不做的、要你看一眼的 |

| 它自己定的事 | `revisions.md` 里这一轮记的"自动模式决定"。这一轮没有新定的，会说清以前几轮定过几条、在哪个变更里 |
| 这一轮的提交 | 提交列表 |
| 套件问题 | 这个会话记的问题反馈 |
| AI 最后的交代 | 它照着报告写的七节 |

**全自动模式下仍然拦、不能放行的**：

| 拦什么 | 拦下之后 |
|---|---|
| 改套件的文件、读令牌和模型的 key、结束路由进程 | 这一步不做，换个做法 |
| 整仓 add、`commit -a` | 改成只 add 这一轮改的文件 |
| 改非 UTF-8 的文件 | 留给你，记进报告 |
| push | 留给你，报告里列出没推的提交 |
| 删 `.vibe/tmp`、`.vibe/out` 里的过程文件（流程没走完时） | 先留着，接着做下一步 |

提示里都写着"不要停下等我"。配置页把"被检查拦住、它又确信是套件拦错了"选成"不许放行"的，全自动模式下别的检查也不放行。

改 redis 里的数据、改公共配置、动 git 历史、查库的工具不肯执行的改库操作：约定里要求它标成留给用户，不做。快到网关请求上限时必须停，那是硬墙：收工检查只让它写交接记录然后停下，你回来 /clear 接上。它不会自己开新的变更、不会做需求之外的事。

## 代码之外的产出放哪（开关，默认开）

DDL 脚本、功能说明、性能分析报告、导出的清单这类文件，放哪由你定，不由模型自己挑。三道：

- **约定**：开工前先定好放哪，项目说明（`.vibe/project.md`）的"产出位置"里有的照着放，没有的先用提问框问你（选项写实际目录），你定了记进项目说明，以后同类的不再问。/ttls-onboard 接手项目时就会问一遍，把现成的目录（sql/、docs/ 这类）列给你选。
- **开工前提醒**：你的消息里要的东西像是这类产出（"写一份报告""出个 DDL"），这句话就带上"先定好放哪"。
- **写文件时兜底**：新建 `.sql`、`.md`、`.txt`、`.docx`、`.xlsx`、`.csv`、`.pdf` 这类文件时，位置没确认过就拦下，让它先问你。"确认过"只认两种：会话开始时就记在"产出位置"里的；你这次会话里亲口说过、在提问框里选过的路径。它在会话里自己往项目说明里加一条、却没问过你的，不算。
- 不管的：改已有的文件（不是在选位置）；openspec、`.vibe`、`.claude`、临时目录；README、CHANGELOG 这类；源码目录里的 `.sql`（迁移脚本、测试数据）；代码目录（resources、test、public、static、assets、i18n、mapper……）里的所有文件，比如 `banner.txt`、测试数据 csv、`robots.txt`、国际化文案；技能工程、文档工程里的文档（那就是工程本身）。
- 全自动模式下你不在：不问，也不自己挑，先放 `.vibe/pending/`（不进仓库），最后交代时列在"等你回来定的事"里；项目里现成的同类目录（同一目录里已经有两个以上同类文件）直接用。
- 到哪找定过的位置：按会话启动的那个目录算，不按现在所在的目录（它中途 `cd` 进了子项目的 `ui/` 也一样）。壳子的 `CLAUDE.md`、壳子下面各个子项目的项目说明都看；记在子项目里、目录却在壳子里的也认。
- 写法不用死板：`docs/<需求编号>/<需求编号>-<需求名>/`、`reports/{日期}/` 里的占位当通配符；没写"产出位置"四个字，写成"代码之外的产出放 docs/…"也认；"不要放在 src/ 下"这种否定的不算。

"产出位置"的写法，写在项目说明里（只在本机），也可以由团队写进项目的 `CLAUDE.md`（一起提交，大家通用）：

```markdown
- 产出位置：
  - DDL 脚本：sql/ddl/
  - 功能说明、分析报告：docs/
  - 性能测试报告：`D:\共享\性能报告\`
```

## 起服务自测：不重复起、不换端口（开关，默认开）

以前的毛病：它起服务自测，忘了之前起过、或者上次没关，改完再测时端口被占，就换个端口又起一个——前端代理、配置里写的还是原来的端口，测的就不是它改的那一份，机器上还挂着一堆旧进程。现在起服务一律经过 `tools/devserver.js`：

```
node "%USERPROFILE%\.claude\vibe-kit\tools\devserver.js" start --name backend --port auto --avoid 8080 -- mvn spring-boot:run
node "%USERPROFILE%\.claude\vibe-kit\tools\devserver.js" status
node "%USERPROFILE%\.claude\vibe-kit\tools\devserver.js" stop --all
```

- **端口它自己挑**（`--port auto`）：在 30000 到 39999 里挑一个空着的，离 `--avoid` 给的端口（项目配置里写的）至少 1000，所以你自己在 IDE 里按配置的端口起同一个服务不会撞上，这一类项目端口顺着编（8080、8081……）的也撞不上。起点按项目目录和服务名算，同一个服务每次挑到同一个端口，场景文件里写的地址不用改。挑到的端口交给服务：命令里的 `{port}` 换成它，环境变量 `PORT`、`SERVER_PORT` 也设成它（Spring Boot 认 `SERVER_PORT`，Vue CLI、Next、CRA 认 `PORT`，命令不用改；Vite、webpack-dev-server 不认，命令里写 `npm run dev -- --port {port}`）。起来之后最后一行说用的是哪个端口。前端代理写死了后端端口这类情况，还可以 `--port <端口>` 指定。
- `start` 的意思是"确保这个服务在跑，而且跑的是现在的代码"：记着的服务还在跑、启动之后代码没改过（或者它会热更新，加 `--hot`），直接用；改过代码就停掉、在**同一个端口**重启；起好（端口通了）才返回，起不来把日志最后几十行打出来。进程号、端口、启动时间记在项目的 `.vibe/run/` 里，日志也在那里。
- 服务起得慢（大型 Spring Boot）：进程还在、端口还没通，算"还在启动"——`status` 只报告，再 `start` 同一个服务会接着等，不会把它结束掉重起。壳子里用 `--cwd 子项目` 起的，按子项目自己的 git 仓库判断代码改没改；`-- "npm run dev"` 整条带引号也认；启动失败的日志按 UTF-8 解不开就按 GBK 解（cmd 的中文报错不再是乱码）。
- 端口被占着、又没有记录：看占着的进程是谁。命令行里有这个项目目录的（以前起了忘了关），停掉重起；别的程序，说清是谁、不动它，也不换端口。停的时候连子进程一起停（mvn → java 这种），模型路由无论如何不停；Windows 会重用进程号，所以停之前先核对进程的创建时间，对不上的不碰。
- 服务要在子目录里起的（壳子里的子项目、工程里的前端目录）：`start` 后面加 `--cwd <子目录>`，不要先 `cd` 进去。记录留在当前目录的 `.vibe/run/` 里，`stop`、`status` 不用带参数。以前 `cd` 进去起的服务，记录在那个目录里，用 `--dir <那个目录>` 指过去。
- 直接敲 `mvn spring-boot:run`、`gradle bootRun`、`npm run dev`、`vite`、`catalina run`、`java -jar target/xxx.jar` 这类命令会被拦下，让它改用 `devserver.js`（`npm start` 只有 package.json 里的 start 是开发服务器时才拦）。
- 会话开始时，以前起了没关的服务会告诉它；交接时它会看一眼、停掉或写进交接记录。
- **最后一行就是结果**。`start` 的最后一行是"起来了：名字，端口，用了几秒，听这个端口的是谁"或者"没起来：……"，前一行是"测完停掉用：……"。`stop` 的最后一行是"停了：……端口空出来了"或者"没停干净：……"。`stop && start` 串在一条命令里也一样。
- 停的时候把它起的进程都清掉（包括不听端口的帮手进程），端口空出来才返回。启动命令把服务甩到后台就退出的（`startup.bat` 那种），等 15 秒看端口通不通。
- 服务在后台跑、**不弹窗口**：Windows 上直接甩开（detached）起的进程没有控制台，它再起的 node、java 会自己开一个窗口（Win11 默认终端是 Windows Terminal，服务被停掉后窗口还一直留着）。所以先起一个没有窗口的看管进程，由它给服务一个看不见的控制台，服务的输出写进 `.vibe/run/<名字>.log`。Tomcat 的 `startup.bat` 会自己用 `start` 另开窗口，用 `catalina.bat run` 就不会。

## 验后端：接口场景

以前后端改动的"验证"基本等于"能编译"。现在 /ttls-see-page 的场景执行器能直接调接口、查返回，规格里"当……则……"的场景，结果在接口返回里的就写成接口场景跑：

```json
{ "name": "下单并查回", "steps": [
  { "request": "POST /api/orders", "json": { "customer": "张三" } },
  { "expectStatus": 201 },
  { "readJson": "data.id", "as": "orderId" },
  { "request": "GET /api/orders/{{orderId}}" },
  { "expectJson": "data.status", "equals": "待支付" }
] }
```

- `request` 调接口（`json`、`form`、`params`、`headers`），`expectStatus` 查状态码，`expectJson` 查返回的字段（`equals`、`contains`、`exists`、`gte`、`lte`），`readJson` 读出来给后面的步骤用（`{{名字}}`）。
- 和页面步骤混着用时，接口请求带着页面的登录状态；页面上点按钮发出的请求用 `waitResponse` 等它返回再查。场景里全是接口步骤时不开浏览器，几秒跑完。
- 跑过接口场景算"验证过"（收工检查、打勾检查都认）。模型路由自己的地址（配置页、套件的接口）执行器不让打开、调用。
- **断言可以和动作写在同一步里**：`{ "request": "POST /api/login", "json": {…}, "expectStatus": 200, "expectJson": "code", "equals": 0 }`。登录这类"失败也返回 200"的接口，要查返回的内容。
- 页面步骤多了 `upload`（给文件输入框传文件）、`onFileChooser`（下一次弹文件选择框时用这个文件应答）；`click` 加 `"force": true` 可以点被别的元素盖住的控件。
- 一步里写了两个动作，只做第一个，结果的 `warnings` 里会提醒。

## 开工前拉代码（开关，默认开）

同事推了新代码，这边照着旧的分析、写，到提交时才发现对不上。所以开工前先拉一次。

**什么时候拉**：会话要开始走 OpenSpec 流程的那一句话。

| 你说的 | 拉不拉 |
|---|---|
| 提了一条需求（接下来要探索、分析现有代码） | 拉 |
| 敲了 `/opsx:…`（explore、propose、apply、archive） | 拉 |
| 接着交接记录做 | 拉 |
| 已经在流程里，说"继续""好""不要停" | 不拉，做到一半不换底下的代码。中间插了一句问话再说"继续"，也不拉 |
| 问问题、让它检索、跑别的技能 | 不拉 |

同一个仓库 2 小时里只拉一次（拉没拉成都算）：需求分析前拉过，紧接着 propose、apply 就不再拉；隔了半天再 apply 会再拉一次。

**拉哪些**：会话启动目录所在的仓库；启动目录是壳子的，加上它下面的子项目仓库。一次最多 12 个，一起拉；多出来的先拉最久没拉过的，剩下的这次不拉，告诉 Claude 要动它们之前自己先拉。不是壳子的目录（一堆不相干的项目放在一起的上级目录）不带下面的仓库。

**怎么拉**：只快进。先 `git fetch`，再 `git merge --ff-only` 跟踪的远端分支。不做合并提交、不变基、不动你没提交的改动（你配了 `merge.autoStash` 也一样：这一次不把改动藏起来再放回去）。

| 情况 | 结果 |
|---|---|
| 远端有新提交、本地没有没推的 | 拉下来，告诉 Claude 之前读过的代码可能变了，用到的地方重新读 |
| 本来就是最新的 | 不说，不占上下文（钩子的流水账里有） |
| 本地有没推的提交，远端也有新的（分叉了） | 不拉，告诉 Claude 要合并先问你；全自动模式下照本地的做，写进报告"留给你做的" |
| 没提交的改动和远端改的是同一些文件 | git 自己拒绝，什么都不变，同上 |
| 连不上、没权限、连远端 15 秒没下完 | 没拉成，照本地的做；全自动模式下写进报告 |
| 合并要很久（文件多、杀毒软件逐个扫、git-lfs 下大文件） | 等它做完，做到一半不结束它。中途结束会留下 `.git/index.lock` 和改了一半的工作区，之后这个仓库里的 git 命令都报错 |
| 合完了，仓库自己的 post-merge 钩子还在跑（装依赖这类） | 等 20 秒，还没完就结束钩子。代码照样算拉到了，告诉 Claude 钩子没跑完 |
| 没有跟踪的远端分支、分离头指针、合并或变基做到一半 | 不拉，不提 |

- git 一律不交互：不弹登录框、不问口令。用的是这台电脑上 git 自己的登录（SSH 密钥或者凭据管理器），和套件的 GitLab 令牌无关。登不上就算没拉成，不会拿别的东西当口令去试。
- 要等多久：一般一两秒。连远端最多 15 秒；合并等它做完。Claude Code 对"用户开口"的钩子默认只等 30 秒（官方文档写的），到点就结束钩子、丢掉这一轮的提醒，所以安装器给这个钩子写明等 300 秒。
- 关掉：配置页"套件开关"那一页"拉代码和提交"里的"开工前拉代码"。

## 提交前查密码、key

提交检查（开关"提交不合规范 → 拦下"）顺带扫一遍这次提交新加的内容（暂存的改动，和这条命令里一起 add 的新文件）：配置里的 `password=`、`secret`、`api-key`、`access-token` 这类键、jdbc 连接串里的密码、`用户:密码@`、私钥、`AKIA…`、`sk-…`、`ghp_…`、中文"密码：…"。写成占位符的（`${DB_PASSWORD}`、`<密码>`、`******`、`changeme`）不算。查到了弹 Claude Code 的确认框，说清哪个文件第几行，值遮掉了；你点同意才提交。仓库里原来就有、这次没动的不查。

## 过程文件都放 .vibe（开关，默认开）

`.vibe/`（不进仓库）只放套件长期要用的：项目说明 `project.md`、交接记录 `handover.md`、账号 `login.json`、快检的中间文件（`cp.txt`、`javac.args`、`*baseline*`，别的名字要写进项目说明）、看页面的 `scenarios/`、`out/`、`design/`、起服务的记录 `run/`，全自动模式下放哪还没定的产出 `pending/`。

- 过程文件（备份、临时脚本、草稿、测试数据、日志、导出的中间结果）放 `.vibe/tmp/<事由>/`，一件事一个目录（做 OpenSpec 变更时事由就是变更名，否则写日期加一两个词）。往 `.vibe` 里别处新建文件会被拦下，告诉它放哪。
- 什么时候删：事由是变更名的（`.vibe/tmp/<变更名>/`、`.vibe/tmp/<变更名>-xxx/`，`.vibe/out/` 里的一样）留到变更归档，没归档之前 `rm`、`Remove-Item`、`find -delete` 删它会被拦下，归档之后套件自己清（收工时、会话开始时）；归档之后又动过的目录不清，那是归档后接着修问题用的。别的事由，那件事做完就把整个目录删掉。全自动模式下，这个会话做的变更还没归档之前，`.vibe/tmp`、`.vibe/out` 里的都先留着。
- 往项目里留过程文件也拦：用 Write 写，或者用 `cp`、`mv`、`Copy-Item`、`> 文件`、`| tee` 这类命令生成，都让它改放 `.vibe/tmp/<事由>/`。改文件之前不用另存备份：已提交的 git 里有，没提交的先复制到 `.vibe/tmp`。`git add` 过程文件也拦（不该提交）。怎么认：
  - 名字一看就是的：`A.java.bak`、`A_bak.java`、`x.orig`、`x.old`、`build.log`、`x.tmp`、`A - 副本.java`、`A (2).java`；
  - 旁边有原文件才算的：`A_old.java`、`A-backup.js`、`A备份.sql`（旁边有 `A.java`、`A.js`、`A.sql` 才是备份；`drop_old.sql`、`数据备份.sql` 这种是正经名字，不管）；
  - 目录：`bak/`、`backup/`、`备份/`、`tmp/`、`temp/`、`src_bak/` 这类，而且是项目里原来没有的；代码目录（src、views、common……）下面的不算，那里的 `com/demo/backup/`、`views/system/backup/` 是业务名字，只按文件名判断。
  - 拦错了（比如测试要读的样例日志 `sample.log`）：它原样再做一次就放行，同一个文件只拦一次。
- 必须放在项目里才能用的临时文件（比如测试页面得放在 webapp 下才能访问）：测完就删，不提交。收工时点名它这个会话里新建了、还没进 git 的文件，和这个会话里在项目里冒出来的备份、日志、备份目录（你自己原来就有的不算；改过的文件旁边的备份，被 `.gitignore` 忽略了也查得到）：要交的提交，测试用的删掉；同一批只提一次，它说"做完了"时还留着的再提一次。
- 会话开始时自动清理：`.vibe/tmp`、`.vibe/out` 里已归档变更的目录（那件事做完了）、`.vibe/tmp` 里七天没动过的目录（天数在配置页改，0 = 不自动清），删掉，并在会话开头说一句清了哪些。没归档的变更的目录放多久都不清。`pending/` 不清。
- 以前堆在 `.vibe` 里的零散旧文件：会话开头发现有三个以上，会提醒它做完手头的事顺手整理（七天提醒一次）。整理用 `node "%USERPROFILE%\.claude\vibe-kit\tools\vibe-tidy.js" [项目目录]` 先列出来，确认是用完的再加 `--apply` 挪进 `.vibe/tmp/<日期>-整理/`，**不直接删**，七天后没人要才清掉；想留的从那里挪回来，或者先写进项目说明（写了的就不算零散）。

## 归档之后才发现问题：怎么找回原来的任务

不用另外挂钩，本来就能溯源，只是线索分在三处：归档的变更目录还在（`openspec/changes/archive/<日期>-<名字>/`，proposal、design、tasks、revisions 都在，tasks.md 每项任务写着改了哪个文件）；规格已经并进 `openspec/specs/`，那是现在的"应该是什么样"；代码的提交在 git 里。缺的是把它们对上，所以加了一个工具和一条规范：

- `node "%USERPROFILE%\.claude\vibe-kit\tools\trace.js" <出问题的文件>[:行号]`：列出哪些变更（进行中的、已归档的）提到过这个文件、对应哪几项任务，这个文件最近的提交、这一行最后是哪个提交改的，并按"提案 ~ 归档"的时间段把提交对到变更上。只读。
- 规范里"归档之后发现的问题"只留一句"先溯源"，怎么分类由 trace.js 的最后一行和开口提醒给：代码没做到规格 → 当 bug 直接修，提交写 `fix: <问题>（源自 <变更名> <任务号>）`，以后 `git log` 一搜变更名就能看到它后来修过什么；规格本身漏了、写错了 → 新开一个变更改规格，proposal 里写明源自哪个变更；拿不准的给你看溯源结果，你来定。归档目录不改，那是历史。
- 你说"测试发现……有问题""报错了"这类话、项目里又有归档过的变更时，这句话会带上"先溯源再修"。

## 经验规则：审查里反复出现的问题，沉淀成规则（开关，默认开）

以前审查发现的问题改掉就完了，只留在那次会话、那个变更的 revisions.md 里，没有人再读。下一个变更里模型照样犯，审查照样再抓一次，每次都花一个子代理的钱。现在多了一条路：

```
审查报的问题，审查之后那个文件确实改了
  └ 收工时脚本自动收下来（Claude 也可以自己记一句：tools/lesson.js）
      └ 先进候选：不进上下文
          └ 同一条在另一个变更里又出现：升成这个项目的规则，跟着仓库提交
              └ 以后读到这类文件时，Claude Code 自动带上
```

- **用的是 Claude Code 自带的规则目录**（`.claude/rules/`，官方叫 Rules）。规则文件开头写着"读到哪类文件时带上"，没读到就不加载，一个会话只带一次。2.1.120、2.1.259、2.1.283 三个版本都实测过。
- **谁来记**：脚本（开关"审查报的问题自动收"，默认开）。收工时从审查代理的回复里把每一条问题取出来，**审查之后那个文件确实改过才算数**，没改的不收。以前只靠主模型自己记，它常常说"没有需要沉淀的经验"。开着的时候不催它记；它自己踩到的坑照样可以用 `lesson.js` 记，和脚本收的走同一套合并、上限。关掉这个开关就回到只靠它记：它没记也没说"没有需要沉淀的经验"，收工检查会催一次。
- **规则的文字从哪来**：审查代理每条问题多写一行"以后怎么避免"，写成"什么情况下：要怎么做"。规则用这一句。它写"无"的是一次性的疏忽，不收。这一句写得没法照着做（带"尽量""视情况"、太长）或者没写，就用"问题"那一句。
- **同一类问题反复出现**：同一种文件、同一个类别的问题在 3 个以上的变更里都出现过（各是各的问题，但都是"边界没处理"这一类），多出一条"这一类要对照检查"的规则，带最近的几个例子。
- **你说了算**：自动收的规则在配置页上带"自动"标记。你删掉的，脚本不再加回来；你改过字的，脚本不再动它。
- **什么样的会被收**：一句话，说清"什么情况下、要怎么做"。太长的、带"尽量、视情况"的、约定里已经写着的，工具不收。能用脚本查出来的不写规则，转成一条问题反馈交给改套件的人。
- **怎么算同一条**：工具按文字找出相近的列给它，它认了是同一件事才合并。同一个变更里出现几次只算一次。

**项目级还是用户级**，不让模型定，按证据来：

| 情况 | 去哪 |
|---|---|
| 刚记下、只出现过一次 | 候选，只在这台电脑上，不进上下文 |
| 在两个不同的变更里出现过 | 项目规则：出问题的文件所在仓库的 `.claude/rules/ttls-lessons-<类型>.md`，要提交 |
| 在两个不同的项目里都成了规则，而且不带项目特有的名字（表名、类名） | 列在配置页等你点头，点了才写进 `~/.claude/rules/`，所有项目生效 |
| 和文件类型无关的做事方式 | 不自动处理。要不要写进全局约定，你自己定 |

壳子结构下，规则写进子项目自己的仓库；在壳子里启动时，读到那个子项目里的文件才带上它的规则。

**不让规则越攒越多**：

- 平时不占上下文：规则都按文件类型分组（Java、SQL 和 Mapper、前端、提案文档、其他），读到那类文件才加载。每个请求都带的全局约定一个字没加。
- 每条最多 120 字；每组最多 10 条。满了挤掉次数最少、最久没再出现的，退回候选。
- 规则里提到的类、文件、表在项目里找不到了，下次写这个规则文件时顺手退掉；也可以跑 `lesson.js tidy`。
- 规则生效之后同样的问题又被审出来两次，配置页上标"没管住"：光靠写规则管不住，该改成脚本检查，或者把规则写得更具体。
- 门槛、每组条数、每条字数都在配置页"经验规则"里改。

**规则文件**长这样。每条规则上面那行注释记着编号、次数、出处，Claude Code 不会把它送进上下文，模型只看到正文：

```markdown
---
paths:
  - "**/*.java"
---
# 写Java时注意（这个项目的审查里反复出现过）

<!-- L916d46 次数=3 最近=2026-09-28 类别=边界 名字=OrderMapper 出处=add-export 2.3；fix-order 1.2 -->
- 调 OrderMapper.selectByIds 之前：先判空列表，传空列表会拼出 in () 报错
- 这一行没有编号注释，是你手写的，工具不动它
```

- 你可以直接改字、删行、加自己的规则。Claude 不能直接改（用 Edit、命令行改都会被拦），只能通过 `lesson.js`；看内容和 `git add`、`git commit` 不拦。
- 规则文件改了没提交，收工检查会催它提交一次（`docs: 更新经验规则`，和代码的修复分开）。你选了"我说了才提交"就不催。
- 这个仓库的 `.gitignore` 忽略了 `.claude` 的，规则只在本机生效，工具会说明。
- 编号是文字的指纹，不是流水号：几个人各自加规则再合并，不会撞号。两个人同时改同一个规则文件会有合并冲突，一行一条，好解。

**配置页"经验规则"**：看各个项目和用户级现在生效的规则、候选、已退役的；改字、删；确认升成用户级。升用户级、删用户级规则只有这里能做。有等你确认的，状态栏会挂一句"经验待确认 N 条"。

**三档**：开（默认）；只收集（记候选、不生成规则，想先看看模型记得像不像话时用）；关（不记也不催）。

**边界**：

- 只有读文件才触发规则。模型没读过任何同类文件就直接新建一个，规则不会带上；改已有的文件不受影响，改之前必须先读。
- 会话被压缩之后，按需加载的规则要等再读到同类文件才重新带上。
- 规则送到了不等于模型照做，弱一些的模型尤其如此。同一条反复"没管住"就是信号。

### Claude Code 自带的"自动记忆"默认关掉

Claude Code 自己有一个"自动记忆"（Auto memory）：模型想记什么就往 `~/.claude/projects/<项目>/memory/` 里记，索引每个请求都带着。它和经验规则重复，而且条数不受控制；它的说明文字也每个请求都占系统提示：

| Claude Code 版本 | 自动记忆的说明占多少字符 |
|---|---|
| 2.1.120 | 12,762（差不多是系统提示的一半） |
| 2.1.259、2.1.283 | 2,317 |

所以套件默认把它关掉：在 `settings.json` 的 `env` 里写 `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`（三个版本都实测管用）。已经记下的记忆文件不删，只是不再加载。想用回它，在配置页"经验规则"里改成"不管它"。你自己在 `settings.json` 里设过这一项的，套件不动。改了要重新打开 Claude Code 才生效。

## 套件出了问题：问题反馈和兜底放行

**问题反馈**。套件是给很多人用的，每个人的 AI 碰到的问题都应该回到改套件的人手里，而不是停在某次聊天里。

- 记在哪：`~/.claude/vibe-kit/feedback/`，一台电脑一处，所有项目的都在这里；装新版、卸载都不删。一条问题一个 `.md`：开头是字段（套件版本、Claude Code 版本、模型、涉及哪道检查、项目、会话、来源、次数、放行情况），后面是现象、当时在做什么、为什么认为是套件的问题、怎么处理的、建议，再附上拦下时的原话、出错的位置、钩子流水账的最后 20 行。密码、token 之类会遮掉。同样的问题不另起一条，只把次数加一、记一行"又出现了"。
- 谁来记：
  - **Claude 自己记**：它觉得套件有问题（拦错了、漏拦了、报错、提示看不懂、卡住）时，按约定用 `tools/feedback.js add` 记。它嘴上说了"是钩子的问题"却一条都没记，收工检查会让它补。
  - **钩子自动记**：钩子抛了异常（以前出错一律当放行，谁也看不到）、HTTP 方式下 25 秒没结果。
- 不记成问题的：

  | 事情 | 记在哪 |
  |---|---|
  | 同一条理由反复拦 | 记数，配置页"更新和上报"那一页的"拦得最多的规矩"；每天各道检查拦了几次跟着使用情况上报 |
  | 在配置页改了开关 | 配置页"套件开关"那一页"保护"一节的改动记录 |
  | 全自动模式下条件满足不了、申请放行 | "放行记录"。申请时加 `--bug` 才记成问题 |

- 同一个问题只记一条。AI 发现是已经记过的问题，用 `tools/feedback.js add --same <问题编号> --what "这次的情况"` 并上去。每次 `add` 之后会列出这个会话已经记过的。
  - **申请放行时记**：见下面。
- 做完之后：这个会话记过套件问题的，它说"做完了"时会被要求在交代里单独列一节"套件问题"，逐条写现象、影响、怎么处理的、编号。
- 怎么收：不用收。记下的问题自动上报成仓库里的 issue（见"问题上报"），维护的那台电脑导出 issue 交给改套件的人。配置页"更新和上报"那一页列着这台电脑记下的每一条、上报成了哪一条 issue（点编号打开），下面是放行记录和拦得最多的规矩。2026-10-01 起没有本机的"导出汇总""清空"了，`tools/feedback.js export` 也去掉了。记录留在本机，最多 1000 条，满了挤掉最老的。

**兜底放行**。检查写错了会把活卡住，但也不能让它随便绕过去。所以只放行"被拦的那一步"，而且要留下记录：

- 只有流程类的检查能申请：OpenSpec 产物的门槛（打勾、含糊词、任务写法、先探索再提案等）、归档门槛、产出位置、.vibe 整理和过程文件、起服务要经过 devserver、提交信息格式、新文件没 add。这些拦下时提示末尾带一个〔拦截编号〕。
- 永远不能放行（没有编号）：改套件、关掉钩子、结束路由进程、改非 UTF-8 文件、整仓 add / commit -a / gitlink、push 确认。
- 申请的步骤：`tools/feedback.js bypass <拦截编号> --why "查证过什么、为什么过不去"`（少于 20 个字不收）→ 记一条问题反馈（带上拦下的原话和它的理由）→ 给"再做一次那一步"开一张通行证：30 分钟内有效，只用一次，只在申请的那个会话里有效；而且会话记录里得真有那次成功的申请（照着格式手写一张通行证不算）。放行时按现在的开关判断，不按申请时的。
- 通行证按"同一个文件、同一件事"认：改同一个文件的同一道检查、归档同一个变更。中间内容变了（比如 tasks.md 又改了一行）照样有效。
- 编号别拿错：拦截编号是四位的字母数字，在拦下的提示末尾。拿问题反馈的编号（F 开头）去申请，会明说拿错了。
- 再做那一步时（配置页"被检查拦住、它又确信是套件拦错了"）：**默认弹 Claude Code 的确认框，你点同意才放行**，框里写着它的理由和问题编号；选"让它自己放行"就不问你；选"不许放行"它只能停下来告诉你。
- **全自动模式下不用你点**：能申请的检查都当场放行，通行证 30 分钟内可以用多次，每次记进全自动报告。不加 `--bug` 不记问题反馈。选了"不许放行"的照样不放行。
- 上限：每个会话最多申请 5 次，同一类检查最多 3 次。到了上限它只能停下来。全自动模式下一个会话最多 60 次。
- 为什么不干脆让它改套件：改了的代码下次装新版就被覆盖，别的同事那边照样是坏的；它改钩子可能把检查整个弄没（以前就发生过嫌钩子碍事去改）。真正的修复走问题反馈，回到改套件的人那里，发新包。

## 自动更新和问题上报（GitLab）

团队的 GitLab 仓库有两个用途：仓库里放着解开的安装包，同事的电脑从这里拿新版；仓库的 issue 收问题反馈。都在配置页的"更新和上报"那一页里看和改。

### 同事要做什么

1. 装一次带这个功能的安装包（从仓库页面下载 zip，或者 `git clone`，或者别人发的压缩包，见"安装"）。以后不用再拷压缩包。
2. 电脑上要有 git。
3. 和 GitLab 换过 SSH 密钥的，什么都不用填。没换过的，在配置页"更新和上报"里填一个令牌。

仓库地址默认是团队的那个，不用改。

### 连仓库走哪条路

挨个试，走通的那条记下来，下次先试它。

| 顺序 | 走哪条 | 要什么 |
|---|---|---|
| 1 | 配置页里手填的令牌 | 个人访问令牌，勾 `read_repository`；要建 issue 再勾 `api` |
| 2 | SSH 密钥 | 这台电脑的公钥登记在 GitLab 上，并且手动连过一次（确认过指纹） |
| 3 | 这台电脑上 git 已经登录的账号 | 凭据管理器里记着 |

- SSH 地址默认照仓库地址推：`http://主机/组/项目.git` 推成 `git@主机:组/项目.git`。GitLab 的 SSH 端口不是 22 的，在配置页里填 `ssh://git@主机:端口/组/项目.git`。
- git 和 ssh 一律不许交互。要输口令、要确认指纹的，直接失败并说明原因，不弹登录框，不卡住。密钥带口令的在后台用不了，要填令牌。
- 令牌不写进仓库地址，也不写进 `.git/config`。

### 自动更新是怎么跑的

1. 会话开始、你发消息、Claude 收工的时候，钩子看一眼"该不该检查了"。该了就甩出一个后台进程，钩子自己马上返回。
2. 后台进程问仓库现在是哪个提交。和上次一样就结束，不到一秒。
3. 不一样就下载到暂存处 `~/.claude/vibe-kit/update/repo`。只拿最新的那一个提交，之后每次只下载变了的文件。
4. 等路由手上没有请求在跑（最近 20 秒也没来过请求），再运行暂存处里的 `install.js`。这和手动双击安装是同一个程序。
5. 装完自检：每个钩子、每个库都载得进来，状态栏跑得出来。
6. 自检不过：从仓库拿上一版的标签装回去，记一条问题反馈。同一版装坏两次就不再装，等仓库里出了新的。

| 开关 | 默认 | 说明 |
|---|---|---|
| 发现新版之后 | 自动装上 | 还可以选"只提醒"和"不检查" |
| 几小时检查一次 | 2 | 1 到 24 |

- **装着的版本跟着仓库走**。仓库里退回了旧版，开着自动更新的电脑也跟着退。所以手动装了一个比仓库新的包，下一次检查会被换回仓库里的那一版。
- 你的开关、本机环境、模型和 key、问题反馈、仓库地址和令牌，更新时都原样保留。
- 没装过路由的电脑，自动更新不会给它装上路由。
- 状态栏：刚更新过的一小时里显示"已更新到 xxx"；选了"只提醒"时显示"有新版 xxx，去配置页更新"；新版装不上时显示"新版 xxx 没装上，看配置页"。
- 日志在 `~/.claude/vibe-kit/update/update.log`，安装器的输出在 `update/last-install.log`。
- 临时不想让它在后台跑：环境变量 `VIBE_KIT_NO_UPDATE=1`。

### 维护的人怎么发布

1. 打包，把压缩包整个解压出来。
2. 双击 `发布到 GitLab（双击我）.bat`。

它按这个顺序做：

1. 把这台电脑的自动更新关掉。发布的电脑每次都是先装再发，用不着自动更新；开着的话会被换回仓库里的旧版。
2. 在这台电脑上装一遍，再自检。装不上、自检不过就停，不发布。
3. 连仓库，看里面现在是什么，再决定发不发。
4. 推一个提交加一个标签 `v<版本号>`。同事的电脑装坏了退回上一版靠这个标签。
5. 《更新说明.md》这一版里写了"修了 #编号"的 issue，在下面留一句是哪一版修的。

| 仓库里现在是 | 怎么处理 |
|---|---|
| 空的，或者只有建项目时带的 README | 照常发布 |
| 不是套件的安装包 | 不发。确实要用这个仓库，命令行加 `--force` |
| 同一个版本号、内容一样 | 已经发过了，什么都不做 |
| 同一个版本号、内容不一样 | 不发。重新打包，换一个版本号 |
| 比这个包新 | 要输入 yes 确认，因为发布之后所有人都会退回这一版 |

- 要推送权限：令牌要勾 `write_repository`；走 SSH 的话账号在项目里至少是 Developer，分支受保护的要 Maintainer。
- 命令行参数：`--no-install` 不装只发，`--dry-run` 只看不推，`--rollback` 退回旧版不再问。
- Claude 要跑发布脚本时，和 `git push` 一样会弹确认框，要你点头。

### 问题上报

- 本机记下的问题反馈，由后台进程建成仓库里的 issue。传上去的就是本机那份记录，密码、令牌、内网地址在记的时候已经遮掉了。
- 不重复建：每条记录带一个签名。别的电脑已经报过同样的问题、issue 还开着，就在那条下面加一句"这台电脑上也出现了"。
- 又出现了：在对应的 issue 下面补一句，同一条 12 小时里最多补一次。
- issue 已经关了又出现：新建一条，写明之前是哪条。
- 不传的：套件代码被改过的记录，以及老版本留下的"改了开关""同一条理由拦了 3 次"这两类记录。
- 一次最多传 8 条，剩下的下次传。
- 传不上去不影响使用，问题照旧存在本机。令牌不对、没权限时停 6 小时再试。

**令牌从哪来**。GitLab 的接口只认令牌，不认 SSH 密钥。

| 情况 | 怎么办 |
|---|---|
| 配置页里填了令牌 | 用它 |
| 没填，SSH 是通的 | 用 SSH 密钥向 GitLab 申请一个，权限 `api`，30 天，到期前自动换。在 GitLab 你的账号的"访问令牌"里能看到，名字是 `vibe-kit-<电脑名>` |
| 没填，GitLab 不支持用 SSH 申请 | issue 建不了，问题只存在本机。要上报就手填一个令牌 |

不想让它自动申请：配置页"没填令牌的时候"选"不申请"。

**从什么时候开始传**。装好的那一刻记一个时间，之后新记的、又出现过的才传。装之前攒下的不传（20260928.2054 / 2055 那两版会把它们一次推上去，这一版去掉了）。

### 使用情况上报（开关，默认开）

套件哪里不顺，光看问题反馈不够：拦对了但提示写得不清楚、上下文涨过了线、审了五轮才过，这些不会有人记成问题。所以每天数一数次数，传给改套件的人。

- 数什么：会话怎么来的（新开、恢复、/clear、压缩后）、开口几次、进 OpenSpec 流程几次、接着交接记录做几次、写交接记录几次（你自己敲的、它自己调技能写的都算）、全自动收工报告几次；各道检查拦了几次（能不能申请放行的都数：串着 cd 的命令、改套件、读令牌、编码保护、收工检查都在里面）、放行几次（没问人的、问了人的）；上下文到 70%、90%、超过上限的会话各几个；提案、代码各审了几轮，报"问题 0 条"的几轮，轮数用完几次；开工前拉代码拉到新代码、本来就是最新、没拉成各几次；钩子出错几次；Claude Code 和套件的版本、系统、开关里和默认不一样的几项；路由里各个模型当天的请求、失败、切换、token；钩子在路由里的平均耗时；查库、查 redis 的工具用量和从用量里看出来能优化的地方。
- 不传：路径、项目名、文件名、分支名、提交信息、提示词、代码、模型的回答、令牌、key。模型的名字里带着内网地址的遮掉。
- 怎么传：每台电脑一条 issue，标题"[使用情况] 电脑名"，一天一条补充。只传过完了的日子（今天的明天传），由后台进程顺带传，一次最多补 7 天。本机的数留 14 天。
- 配置页"更新和上报"那一页的"使用情况上报"：看传到了哪一天，点"看看要传的内容"看今天到现在攒下的样子（就是明天要传的那一段），点"立即上报"马上传过完了的日子。关掉之后本机照样数，不传。
- 维护的人导出 issue 时，各台电脑的数汇总在导出文件最后：合计、每台电脑一行、各个模型、几台电脑报了同一个能优化的地方。

给改套件的人怎么看：拦得多、放行多的检查，提示可能写得不清楚或者判断错了；超过上限的会话多，自动压缩没起作用；审查轮数多、轮数用完的多，审查提示或者改法有问题；拉代码没拉成的多，看是分叉还是连不上；某个模型失败、切换多，看路由配置；钩子平均耗时长的，看那道检查。

### 导出 issue（只在维护套件的电脑上）

配置页"更新和上报"那一页"问题上报"的最下面，只在维护套件的那台电脑上出现。哪台电脑算"维护套件的"写死在套件的代码里，配置页上没有这一项，别的电脑看不到。

- 只导出**开放中**的问题 issue，连同下面的补充，合成一份 `.md`，由浏览器下载（在浏览器的下载目录里）。页面上留一个"再下载一次"，没下载成可以再点。本机不存：以前存在 `~/.claude/vibe-kit/issue-exports/` 的旧文件还在，不再用了，可以删。
- 最后附上各台电脑的使用情况汇总：上次导出之后的，没导出过就是最近 7 天。
- 文件交给浏览器之后，页面问一句存下来没有。点"确定"，这一批才在 GitLab 上关闭，下面留一句"已导出"；点"取消"不关，下次导出再带上。浏览器把下载拦了、另存为里点了取消，都不会把这一批关掉。
- 导出之后、关掉之前又有人补充过的不关：新补充的不在刚导出的文件里，下次导出整条带上。
- 所以每次导出的都是上次之后新冒出来的。各台电脑的"[使用情况]" issue 不关。
- 关掉的 issue 按编号还能查到。
- 只想看不想关：把"下载之后把这一批关掉"的勾去掉。

### 令牌怎么保护

- 令牌单独存在 `~/.claude/vibe-kit/secrets.json`。配置页只显示遮过的样子，接口从不把它原样回给页面。
- 模型读不到，三道一起挡。`router-data/`（模型的 key）同样保护。

| 模型怎么读 | 谁来挡 |
|---|---|
| Read 工具；Grep 直接对着这两处搜 | 安装器在 `settings.json` 里加的两条"不许读"的权限规则 |
| Grep 对着上级目录搜内容（套件目录、`~/.claude`、用户目录） | 钩子 `guard-read`。权限规则管不到这种搜法，2.1.120 上实测内容会被原样带出来 |
| 用命令读（`cat`、`Get-Content`、`grep -r`、`node -e`） | 钩子 `guard-commit` |

- Grep 只看文件名（`files_with_matches`）、只数个数的不拦。搜套件的 `hooks`、`lib`、`config.json` 照常。
- 用命令列目录、按名字找文件不拦：`ls <套件目录> | head -30`、`find ~/.claude -maxdepth 1 -iname "*.md"` 这种整条命令只是列名字、过滤名单的，读不到文件的内容。列完接着用 `xargs`、循环、`-exec`、命令替换去读的照样拦。
- 套件目录里还有一个 `.ignore` 文件，让搜索工具跳过这两处，算多一道保险。
- 关掉"禁止 Claude 自己改套件"之后，这两处照样不给读。
- 这是防误读，不是防攻击：存在本机的令牌是明文，能登录这台电脑的人都能看到。

### 出了问题先看哪

1. 配置页"更新和上报"点"测试连接"。它分三行说：拿新版通不通、SSH 通不通、建 issue 通不通，不通的写明原因。
2. 看 `update/update.log`。
3. 这一页上的"上次检查""上次上报"两行，失败的原因直接写在那里。

## 后台自动探索（开关，默认开）

以前进到一个新项目要先说一句 `/onboard`，模型花几十次工具调用去查怎么编译、怎么启动。这些事多数从文件里就看得出来，不需要模型。

现在由脚本在后台查，几秒钟就好：

| 查什么 | 怎么查的 | 写到哪 |
|---|---|---|
| 是什么工程、几个模块 | 构建文件：`pom.xml`、`build.gradle`、`package.json`、`.classpath` | `<项目>/.vibe/project.md` |
| 快检、全量、启动的命令，端口，上下文路径 | 构建文件加 `application*.yml`、`vite.config.*` | 同上 |
| JDK 用哪个 | `pom.xml` 里的 Java 版本，对上配置页"本机环境"里的 JDK | 同上 |
| 编码 | 抽查源文件，不是 UTF-8 的点出来 | 同上 |
| **开发环境**的数据库连接 | `application*.yml` / `.properties`、`jdbc.properties`、XML 里的数据源 | `<项目>/.vibe/db-crud.ini` |
| **开发环境**的 redis 连接 | 同上 | `<项目>/.vibe/redis.json` |

**什么时候跑**：会话开始、你每次开口时，钩子看一眼（读一个小文件、取十几个文件的修改时间，几毫秒）。该跑了就甩一个后台进程，钩子自己马上返回。

| 情况 | 做什么 |
|---|---|
| 没探索过 | 探索 |
| 依据的文件改了（`pom.xml`、`application-dev.yml`…） | 重新探索，只改变了的那几行 |
| 离上次整个扫一遍超过 6 小时 | 再扫一遍，看有没有新加的配置文件、新模块 |

**怎么告诉 Claude**：探索好了、更新了，夹在你的下一条消息里，只说一次。刚甩出去还没好的，你开口时最多等它一秒半。会话开始之前就探索好的，会话开始时带项目说明（壳子下面的子项目只列路径，用到哪个读哪个）。

**几条规矩**：

- **只配开发环境的连接**。看文件名（`application-prod.yml`）、目录、YAML 里的分段、数据源的名字。测试、生产环境的不写进去：宁可少找一个，不能把生产库配给 AI。公共配置（`application.yml`）里的连接，被 `application-dev.yml`（或者同一个文件里 `on-profile: dev` 那一段、`config/` 子目录里的）用同一个键换掉了的，也不算：跑开发环境时那一条被盖掉了，留在公共配置里的多半是测试、生产库。
- **注释掉的地址不算**。
- **命令没实际跑过**。照工程结构推出来的，项目说明里标着"（没跑过）"。Claude 第一次用的时候跑一遍，通了把标记去掉。
- **你和 Claude 改过的行不动**。项目说明一行一条，重新探索时只换"脚本生成的、而且这次和上次不一样"的行。
- **项目说明不是脚本生成的**（你写的、以前 `/onboard` 写的）：不动它，只在最后补数据库和 redis 两行。
- **你手写的连接、记过的坑不动**。来源文件里找不到了的连接不删，加一行说明。
- **壳子里套着子项目**：每个子项目各探索各的，壳子自己不建 `.vibe`。
- **查不了的不猜**：登录账号、代码之外的产出放哪、配置中心（Nacos、Apollo）里的连接、加密过的口令。
- **口令**：从项目的配置文件里原样抄进 `.vibe/`，不进项目说明、不进日志、不发给模型。探索完把 `.vibe/` 加进那个项目的 `.gitignore`。

用户目录、盘符根目录、套件自己的目录不探索。

命令行：

```
node "%USERPROFILE%\.claude\vibe-kit\tools\onboard.js" status
node "%USERPROFILE%\.claude\vibe-kit\tools\onboard.js" run --force
```

流水账在 `~/.claude/vibe-kit/state/onboard.log`。不想要，在配置页把"后台自动探索"关掉。

## 查库和查 redis

两个技能原来是单独装的（`urai-db-crud`、`redis`），现在跟着套件一起装、一起更新。

| 技能 | 要什么 | 连接配置 |
|---|---|---|
| `/ttls-db-crud` | Python 3、java 8 以上、数据库的驱动 | `<项目>/.vibe/db-crud.ini` |
| `/ttls-redis` | 什么都不用装 | `<项目>/.vibe/redis.json` |

连接配置一般不用手写，后台自动探索会配好。对话里直接说"哪张表存了订单""看一下缓存里 user:1 是什么"就行。

**查库快在哪**：

| 做法 | 效果 |
|---|---|
| 一条命令只起一次 java | 以前看一张表的结构起 2 到 4 次 |
| `find`、`columns` 一次几张表、`peek --eq 字段=值`、`query` 一次几条 | 少写 SQL，少来回 |
| 表结构存在本地，12 小时 | 再看同一张表不连库 |
| 后台执行器（开关，默认关） | java 不退、连接留着，后面的命令零点几秒 |

**改数据要你确认**：

- 查库的写操作分两步。第一步只算影响面、风险，什么都不改；你同意了才执行第二步。执行的那一刻在同一个事务里再数一遍行数，对不上就不执行。改之前的样子和反向 SQL 留在 `~/.db-crud/journal/`。
- `query` 只许跑查询，里面夹着写语句会被拦下。
- redis 的 `del` 给了几个 key、按匹配结果批量删，Claude 先用提问框问你。
- redis 的数据全自动模式下不改：redis 没有改前快照，做了回不去。任务标成"（留给用户）"，写进全自动报告。

**全自动模式下改库不等你确认**（只在走 OpenSpec 流程的会话里；别的会话照上面的来）。还是两步，第二步不用等你。条件是留得下备份，留不下的工具不执行（退出码 3），任务标成"（留给用户）"：

| 语句 | 要满足什么 | 留下什么 |
|---|---|---|
| UPDATE、DELETE | 影响几行数得出来、不超过快照上限；UPDATE 的表有主键；表里没有二进制列 | 改前快照 `before.json`、还原脚本 `undo.sql` |
| INSERT | 表有主键；主键值是语句里写明的，或者驱动能把自增、序列生成的值带回来 | 表名、每一行的主键；还原脚本是按主键一行一行删 |
| 建表、建索引、建视图、建序列、加字段、加起了名字的约束 | 不是 `CREATE OR REPLACE` | 对应的 DROP 脚本。不自动执行，要你看过再跑 |
| 别的：没有 WHERE、连表改、`INSERT … SELECT`、撞键就改的插入、改列删列、清空、删表、授权 | | 不执行 |

- 每一次都列在全自动报告"库里改过的"一节：哪张表、几行、新增的主键、留痕目录、还原的命令。
- 还原：`db.py --conn <连接> exec --undo <留痕目录>`。新增的按主键删，改、删的按快照写回去。
- 查库的工具怎么知道这个会话算不算全自动：它跑之前钩子留一张条子（按当前目录记，两分钟内有效）。没有条子的（在终端里手敲、套在脚本里跑）按你不在算。

### 数据库驱动

驱动不随包带：达梦、神通、金仓、Oracle 的驱动是厂商的，只限内部使用。

配置页"数据库驱动"那一页：

| 卡片 | 干什么 |
|---|---|
| 现在用的驱动 | 每种数据库一行：登记的是哪个 jar、什么版本、从哪来的。每行后面有"换驱动"（还没有驱动的是"选驱动"）：在弹窗里点选一个 jar，也可以把路径粘进去直接跳过去。认驱动看 jar 里面的驱动类，不看文件名；选的 jar 和那一行不是同一种数据库会被拒绝 |
| 自动搜索（"刷新"旁边） | 按"本机环境"里配的 Maven、`~/.m2` 的顺序到 Maven 仓库里找，每种数据库用最新的那个 |
| 查库快一点 | 后台执行器的开关、多久没人用就退出 |
| 用得怎么样 | 哪条命令跑了多少次、多慢、哪种错多 |

多数时候不用点：后台自动探索发现项目用到的数据库还没有驱动，会自己到 Maven 仓库里找一遍。

驱动放在 `~/.claude/vibe-kit/drivers/`，登记在 `~/.claude/vibe-kit/drivers.json`。卸载套件不删。命令行是 `node "%USERPROFILE%\.claude\vibe-kit\tools\drivers.js" list`。

### 用量和毛病自动记

每跑一条命令记一行：哪条命令、多少毫秒、起了几次 java、出错的类别。**不记 SQL、数据、表名、key、地址、口令**。导出的问题反馈里有"工具用量""能优化的地方"两节。工具自己出的毛病（脚本崩了、执行器没有输出、找不到驱动、找不到 java）自动记成问题反馈，和别的问题一起上报。

调用记录里的错每天汇总一次：同一种工具、同一种数据库、同一种错（比如"达梦 SQL_ERROR:42S02:-2106"）记成一条"工具报错"的问题反馈，写着这一天出了几次、是哪几条命令出的、这种错一般是怎么回事，跟着问题上报传到 GitLab。下一天又出现，还是那一条，次数加一。被工具自己拦下的（写操作没确认）不算错。

### 还没验过的

查库的执行器这一版改得多。这台电脑上只有 H2，**达梦、神通、Oracle、金仓、MySQL 的真库还没有验过**。第一次在真库上用，先跑一次试连和一次完整的读写。维护文档在工程的 `dev/docs/ttls-db-crud/`。

## 不是写代码的工程

不是所有仓库都有"编译""启动"这回事：开发技能的仓库、纯文档和规范的仓库、一堆散装脚本的仓库都不是。后台自动探索和 /ttls-onboard 先判断是什么工程，只查该查的：

- 代码工程：还是那五件事（类型、快检、全量、启动、编码）。
- 技能工程（skills/、commands/、agents/、插件清单）：技能怎么组织、怎么验证一个技能、脚本怎么跑和做语法检查、怎么装到本机试一次、编码。快检就是 `node "$HOME/.claude/vibe-kit/tools/skills-check.js" <仓库> --repo`，只清点仓库里的技能，不掺本机装的，有问题退出码 1。不查启动。
- 文档工程：文档怎么组织、有没有检查手段、编码。快检、全量、启动都记"不适用"。
- 脚本工程：每个脚本怎么跑、语法检查命令、依赖、编码。
- 说不清的问你一句。

项目说明里标了"不适用"的项，收工检查的钩子不再催：写了"快检：不适用"就不催跑验证，写了"看页面：不适用"就不催看页面。

## 装了技能，Claude 却不用

先搞清它为什么不用。Claude 并不"知道"自己装了什么，它只在每个会话开头收到一份技能列表，每个技能一行 description。三个常见原因，前两个清点一下就能看出来：

```
node "%USERPROFILE%\.claude\vibe-kit\tools\skills-check.js" D:\你的\项目目录
```

1. **列表超字数了**。整份列表默认最多占上下文窗口的 1%（20 万窗口约 8000 个字符），超了所有 description 都被压短，"什么时候用"这半句最先没。办法：删掉不用的技能，或者设环境变量 `SLASH_COMMAND_TOOL_CHAR_BUDGET` 调大。
2. **description 只写了"它是什么"**。"读取数据库的工具"不行，要写成"要知道表结构、字段，或者写 SQL、Mapper 之前使用"。模型是拿手头的任务去对这句话的。
3. **它不知道手头的资料过时了**。项目里有 DDL 文件，它读到了、觉得够用了，就不会再去想查库这回事。这种情况改 description 没用，在项目的 `CLAUDE.md` 里写一句："表结构用 /ttls-db-crud 查真实的库，db/ 下的 DDL 是旧的"。

## 加规范

在 `~/.claude/vibe-kit/rules/` 里放一个 `.md` 文件，文件名不要以下划线开头，然后：

```
node "%USERPROFILE%\.claude\vibe-kit\install.js" --sync
```

文件名前面的数字决定先后顺序。想停用某条规范，给文件名加个下划线前缀再 sync；以后更新套件不会把它重新启用。

## 平时怎么用

- 新功能：`/opsx:propose`（一个模块一个）→ `/opsx:apply`（每项任务：做完 → 验证 → 打勾 → 提交）→ 最后一项打勾时自动交叉审查一次，审出来的问题修掉再提交一次 → `/opsx:archive` → 你决定什么时候 push
- 开工前它会先拉一次代码（见"开工前拉代码"）；拉不下来的，它会说是分叉了、有没提交的改动碰到了，还是连不上
- 小改动、修 bug：直接说。改完没验证就想收工的，会被收工检查拦下来补
- 状态栏变红：这一轮说完后它会问你要不要交接。选"现在交接"→ 它写交接记录 → 你敲 `/clear`，再说一句"继续"（或"接着做"）→ 新会话先读交接记录再接着干。`/clear` 这一下只能你自己敲；一小时内的交接记录有效，只接一次，说别的事它不打扰。配置页"上下文上限和交接线"里的"交接后 /clear，新会话自动接着干"开了（要较新的 Claude Code 才认，默认关），/clear 之后不用说话它就接着干
- 普通的单个项目（不是壳子结构）：当前目录有 openspec 就用它，没有就用所在 git 仓库根目录的；钩子和规范都这么认，不会去仓库外面的上级目录找
- 提交：不用你说。每完成一项任务（验证过、自己过了一遍 diff）它就提交一次，信息按 `类型: 内容` 写；漏了的话收工时会被拦下来补。push 永远要你确认。不想自动提交，在配置页"套件开关"里改成"我说了才提交"

## 花多少 token

脚本做的判断都在本机，不花 token。花 token 的只有进到模型上下文里的文字：

| 项目 | 什么时候 | 大约 |
|---|---|---|
| 全局约定 + 规范 + 本机环境 | 每个请求都带（在系统提示里，走缓存） | 默认开关实测约 6,700 字（中文约 3,700），开全自动 + 多轮审查约 8,400 字；折合 3,000～5,500 token（不同模型的分词不一样）。钩子拦下时会给细节的（放行命令、修订记录模板、溯源的分类做法），约定里只留一句 |
| 项目说明、壳子结构 | 每个会话一次 | 300 token。后台自动探索生成的项目说明多数据库、redis 两行，一份 400～600 token；壳子下面的子项目在会话开始时只列路径 |
| 后台自动探索 | 探索本身是脚本，不用模型 | 0。探索好了、更新了，随你的下一条消息带一次 |
| 技能列表 | 每个会话一次 | 六个技能的 description 一共约 1,000 字，其中查库、查 redis 两条约 330 字 |
| 查库、查 redis | 用到的时候 | 一条命令一次工具调用。`find`、`columns` 一次几张表、`peek` 就是为了少调几次 |
| 打断提醒、进度行、交接提醒 | 只在对应情况出现时 | 每次 50～150 token |
| 到线后问你要不要交接 | 每个会话最多三四次（过线一次，之后每涨 10% 一次） | 要多发一到两次请求，每次都带着全部上下文。上下文 70 万 token 时这一问就是 70 万 token 的输入；嫌贵就在配置页里改成"不问，只提醒" |
| 收工检查 | 只在漏了验证时 | 100 token，外加它去补做验证的那几次调用 |
| 开工前拉代码 | 进流程的那一句话，同一个仓库 2 小时一次 | 拉到了新代码、没拉成时一两行，50～150 token；本来就是最新的不说，0；这一句话要多等一两秒（git fetch） |
| Claude Code 自带的自动模式（2.1.284 起默认进，套件默认关掉） | 关着：0。不管它：每条有风险的命令一次 | 一个分类请求约 14 万字符的系统提示（走缓存），外加当前这一段对话；分类模型答得不合格式时一条命令十个请求 |
| 使用情况上报 | 后台进程，每天一次 | 0 |
| 交叉审查 | 每个变更两次（提案、代码各一次），各开一个子代理 | 最贵的一项，几万 token；代码那次可以在配置页关掉自动触发、改成手动 |
| 记经验 | 审查报了问题、改完之后 | 脚本在收工时自动收，不花 token。Claude 自己记的时候多一到三次工具调用，每次输出约 100 token |
| 经验规则 | 一个会话里第一次读到那类文件时 | 每组最多 1,200 字，一个会话一次；没读到那类文件就是 0 |

钩子本身不花 token。命令方式每个钩子要起一个进程（实测 0.3～0.9 秒）；装了路由时高频的几个在路由里跑，一次几毫秒（见"检查在哪里跑"）。
