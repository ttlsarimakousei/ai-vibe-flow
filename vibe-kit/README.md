# vibe-kit

给内网 Claude Code（后面接公司网关上的私有模型）用的工作流套件。挂在 OpenSpec 上：需求、设计、任务归 OpenSpec 管；编号、git、编译、起停服务、提交节点这些能确定判断的事，由本机脚本在钩子里做，不花 token。

这份是短手册：怎么装、自动模式怎么选、平时怎么用、状态栏和配置页怎么看、出了问题看哪。细节在 `手册/` 下，一件事一份，见文末"附录"。每一版改了什么见[更新说明](更新说明.md)；配置页（敲 `/vk-config`）"套件说明"页有流程图。

## 里面有什么

| 东西 | 干什么 |
|---|---|
| 钩子 | 改文件、跑命令、提交、收工时在本机检查。拦下时提示里写着原因和怎么改 |
| 配置页 | 敲 `/vk-config` 用时才起，只在本机：开关、本机环境、查库、经验规则、更新和上报 |
| 状态栏 | Claude Code 底下：上下文、自动开没开；进了流程多一条步骤条和下一项 |
| `/ttls-onboard` | 后台自动探索不够用时手动接手项目（认不出的工程、要实际跑一遍命令、补登录账号） |
| `/ttls-db-crud`、`/ttls-redis` | 查库、改库（达梦、神通、MySQL、Oracle、人大金仓）；查 redis |
| `/ttls-see-page` | 起服务、照步骤操作页面或调接口、读页面上的值；还原原型按数字比，不靠读截图 |
| `/ttls-cross-review` | 审查需求文档和代码：脚本备材料，子代理 `ttls-reviewer` 审，和主会话同一个模型 |
| `/ttls-handover` | 你要求时写交接记录 |

## 装和升级

需要 Node 18 以上；看页面要 20 以上，自带的 OpenSpec 要 20.19 以上，Node 不够时安装器会说哪个用不了（套件照样装）。

1. 拿安装包：浏览器打开团队 GitLab 仓库 `http://scm.skytech.io/nb-2026/p1/ai-engineering/90-personal/3139/vibe-kit`，点"代码"下载 zip；有 git 的也可以 `git clone --depth 1` 这个仓库；连不上仓库时用别人发的压缩包。
2. **整个解压**，双击里面的 `安装（双击我）.bat`，或者在那个目录里 `node install.js`。套件装进 `~/.claude`，装完这个目录可以删。
3. 连模型的地址和 key 不归套件管，照你们平时的办法配（比如 cc-switch）。
4. 新开一个 claude 会话就能用。要改开关敲 `/vk-config`。在壳子目录里启动的，告诉它这次动哪个子项目。

**以前装过模型路由的**：升级之前先用 cch 把 Claude Code 切到网关，模型的 key 自己记好。新版第一次跑起来时，路由进程、开机自启、`router/`、`router-data/`（模型、key、用量、配置备份）一起删，删了找不回来。详细见[配置页和规范](手册/配置页.md)"模型路由删了之后"。

安装时会做的、你可能要知道的：

- 先检查后动手：`settings.json` 读不懂、全局 `CLAUDE.md` 不是 UTF-8，就什么都不动，说清是哪几行。覆盖你改过的技能、约定、规范、审查代理之前，先备份到 `~/.claude/vibe-kit/backup/`，配置页提示一次。
- 你自己的约定和规范放 `~/.claude/vibe-kit/user/`，更新从不碰；以前直接改过套件约定、规范的，升级时挪进去，照样生效。见[配置页和规范](手册/配置页.md)"加规范、改约定"。
- 在 `settings.json` 里放行 Bash、PowerShell、Read、Edit、Write、Glob、Grep，平时不弹确认。你删掉的放行、环境变量，再装不补回来。
- 在 `settings.json` 的 env 里设 `JAVA_TOOL_OPTIONS`，让 Java 程序的输出按 UTF-8；系统环境变量里已经设了的，写进去的是系统的值加上套件要的几项，不盖掉你的。
- 默认关掉 Claude Code 自带的 auto mode 和自动记忆，原因和改回去的办法见[保护和放行](手册/保护和放行.md)、[上下文和 token](手册/上下文和token.md)。
- 套件不接任何 MCP。你自己接的 MCP 工具只查读令牌和改套件，见[保护和放行](手册/保护和放行.md)"MCP 工具"一节。
- 以前单独装过 `urai-db-crud`、`redis` 技能的：装在用户目录里的删掉（先备份），装在项目里的不动。

升级：

- 装好之后不用再管。后台每 2 小时问一次 GitLab 仓库，有新版就下载：配置页勾了"先装新版"的（尝鲜组）马上装，没勾的等这一版发布满 24 小时、尝鲜组没报问题再装；装完自检，不过就装回上一版。可以在配置页"更新和上报"改成只提醒或不检查，也可以固定在这一版、跳过某一版，见[自动更新和上报](手册/自动更新和上报.md)。
- 手动升级：新包装在原来的上面，不用先卸载。开关、本机环境、你的约定和规范（`user/`）、问题反馈、GitLab 地址和令牌都留着。
- 升级后重开一次 Claude Code（新登记的钩子要重开才生效），不需要 `/clear`。
- 2026-10-31 起自动模式按会话开（`/vk-auto`），配置页上没有自动开关了；升级时配置里旧的两个开关清掉，升级那一刻正在自动干活的会话照旧开着。

卸载：`node "%USERPROFILE%\.claude\vibe-kit\install.js" --uninstall`，收回加的权限、环境变量、钩子和状态栏；本机环境、你自己的规范、问题反馈留着。

## 流程

```
探索 → [需求 → apply（每组只审查）] × N → 全面自测 → 人工核验 → 按顺序归档
```

中途打断不影响：问一句、说"停"都不退出流程，进度从文件算，换会话、死机后敲 `/vk-resume` 接回，死机前开着自动就接着开。单个 change 就是 N=1，走同一条路。配置页"套件说明"页有图。

进流程只有三种门：

1. 你敲 `/opsx:explore`。
2. 你的话里明确有 openspec。
3. 改动较大时模型用提问框问你，选"探索"才进；选"直接改"这件事不再问。

直接敲 `/opsx:propose`、`/opsx:new` 也算进流程，但要先有探索记录，短的也行。没进流程的改动按"小改动、修 bug"走。

- 探索结果边谈边写进 `openspec/explore/<大任务>.md`，`openspec/plan.md` 只当索引：列这个大任务有哪些 change、什么顺序。
- 流程里没开工就改源码要拦（带拦截编号，能放行）；不在流程里不拦。
- 探索完之后，需求、apply、自测都对着探索记录核对，不自己加。模型和审查想到的范围外建议不丢也不做，人工核验时列给你。
- 做到一半、全面自测、人工核验发现要改：照改，记进对应 change 的 `revisions.md` 再复验。前面的 change 还没归档，就直接改它的文档，不在后面的 change 里写 MODIFIED。

## 自动模式（每个会话自己开）

自动模式不在配置页开（2026-10-31 起，以前的"需求自动""Apply 自动"两个开关去掉了，升级时清掉）：在要自动的会话里敲 `/vk-auto`，或者说"这个需求自动做""开自动"，只对那个会话有效；`/vk-auto off` 或者说"别自动了"关。状态栏第一行写着"自动 开"或"自动 关"。`/vk-auto` 只是开关，开了不问什么，等你说要做什么。

开了以后：

1. 先探索：读相关代码和现状，跟你确认目标、范围、验收标准和疑问，写进探索记录。"还没定的"清空、"范围"写好，才开始自动。
2. 自动逐份写 proposal、specs、design、tasks，每份审修；定稿后提交方式是"自动"才提交，"关""询问"都不提交也不问，接着开工。你只让它写需求的不开工。
3. 每整组任务做完只审修，不自测，过了才进下一组；一个 change 做完，记下落地偏差，按 `plan.md` 的顺序接下一个。提交方式是"自动"才提交。
4. 全部 change 做完自动全面自测：所有验收用例和整体用例，改过代码退回重跑。过了停下等你核验，自动也停。
5. 你测出问题、改了需求：照改，记进 `revisions.md`，接着自动审、复验、提交，不退回人工一处一处问你。
6. 只做探索记录和需求里有的，不自己加（"这里加个按钮更好"这种不加）；做法上的取舍（怎么写、用哪种实现）自己定，记进 `revisions.md`。只有你的描述或材料让它完全走不下去时，先自己探索，还不行才问你。

手册里说的"自动模式生效时"，指这个会话开着自动（状态栏写着"自动 开"）、正在走流程。不走 OpenSpec 的修改一直按人工来。

开不开自动都一样的：

- 需求本身矛盾或缺关键信息，照样用提问框问你。审修不设次数上限，没有 P1、P2 才算过；子代理连续 3 次没交结论就不再催这一点，写进报告，不算通过。自动生效时，做法上的取舍（怎么写、用哪种实现）它自己定，记进 `revisions.md`，收工报告里列出来。
- 用户验收、归档、push 由你决定。它不会自己归档，不会自己推。
- 改套件、读令牌和 key、整仓 add、改非 UTF-8 文件，照样拦，不能放行。

自动模式生效时多出来的：流程类检查拦下时它可以自己申请放行，不等你点（选了"不许放行"的除外）；代码之外的产出没定位置的先放 `.vibe/pending/`；改库只做留得下改前快照和还原脚本的；收工时在项目的 `.vibe/reports/` 交一份报告（文件名 `全自动报告-日期-时间.md`），写做到哪、留给你做的、库里改过的、没验证的、放行的检查、它自己定的事。

## 平时怎么用

### 新功能

1. 敲 `/opsx:explore` 说需求（或者改动较大时它问你，选"探索"）。它读相关代码和现状，把目标、范围、业务规则、验收场景跟你问清，边谈边写探索记录。开了自动也不会猜你没说的规则。
2. 逐个写 proposal、specs、design、tasks，每写完一份审一次（人工模式先问你要不要审）。文档不限行数，复杂的关系配图。验收用例写在 design.md 的"验收用例"一节：每条写对应场景、前置数据和环境、步骤、预期、谁来测、对应第几组任务，写需求时就写完给你看。
3. 整套定稿后按提交方式提交（询问就问你）。然后问你"开工 / 还要改 / 先不做"（写完 tasks 时选了"定稿并开工""只定稿"的不再问）；开着自动时直接开工。
4. 开工后做完一项勾一项，每整组任务（1.x、2.x）做完审一次。一个 change 做完，用提问框问你接不接下一个；开着自动的按 `plan.md` 直接接。提交按"提交方式"。
5. 全部 change 做完做全面自测（人工模式先问你），交用例的实际结果。你核验，满意了说"归档"：先在临时副本里按 `plan.md` 的顺序预演一遍，过了才动真目录，再按顺序归档。验收不靠在任务清单里打勾。

需求文档的几条规矩：

- tasks 只写要做的实现任务，形如 `- [ ] 1.1 订单查询为空时返回空列表：src/order.js`。不写"验："，不写测试、审查、用户验收任务（新写的会被拦下，提示写进验收用例）；套件的审查进度、起服务、自测记录在本机，没装套件的同事也看得懂。
- 实施要用的非敏感材料放变更目录的 `assets/` 或 `references/`，用相对链接随提案提交；不依赖本机的临时文件、口令和连接配置。
- 任一阶段改了需求，同步改受影响的需求、设计、任务、代码、用例和流程图，改处加批注，`revisions.md` 写起因、变化和影响范围。开工后改了需求的，旧的开工许可失效：文档照常改，改代码和打勾要你重新说开工。
- OpenSpec 随套件装：安装包带一份（打包时的最新版），`/opsx:*` 命令装成用户级，项目没初始化的第一次用时自动建 `openspec/`；写出来的变更同事用自己的 OpenSpec 1.2 也能看、归档。电脑上的 Node 低于它要求的版本（1.14.3 要 20.19）时，照旧用你自己装的。详见配置页"套件说明"页。

审查怎么分轮、人工和自动的区别、跳过审查怎么记，见[审查和自测](手册/审查和自测.md)。大需求拆成几个变更的，`node "%USERPROFILE%\.claude\vibe-kit\tools\plan.js" new --task <大任务> --changes c1,c2` 建探索记录和 `plan.md` 里的一节，会话开头会带上"共几个、归档几个、进行中哪些、下一个是谁"。Claude 不会自己往表里加行：变更不在表里时，收工提醒你一句，你说要加才加。

### 小改动、修 bug（不走 OpenSpec）

直接说。改完它用一个提问框问一次，一件事一个问题：要不要跑快检（编译级，它已经跑过的不问）、审查、自测。你答了不用的那一样，这个会话后面再改代码不再问。

- 编译、类型检查、静态检查不算自测，它直接跑；跑测试、起服务、看页面算自测，先问你。你已经说过"跑一下测试""把服务起起来""启动 OA"的，直接做；这一轮说过的，改完再测、再审也不再问。
- 你说不用，它就接着做，不记待办；同一个要求里后面的小改动不再问。你提新要求、又改了代码，才再问。
- 提交按配置页"提交"卡片里的"提交方式"：关（默认，你说了"提交"才提交，一句"提交"这一轮里分几笔都算）、询问（交代后问你）、自动（做完就提交）。

### 修已归档功能的问题

你说"自测发现……""测试反馈……""报错了"时，它先溯源：`node "%USERPROFILE%\.claude\vibe-kit\tools\trace.js" <文件>[:行号]` 列出当初是哪个变更、哪项任务、哪个提交改的这里。

- 改动小（三个文件以内、不改接口和表结构、不改需求）：直接改、验证，提交写 `fix: 问题（源自 变更名 任务号）`，不新开变更。它要去新建提案会被拦一次。
- 要改需求、接口、表结构：它先告诉你，你说走提案再提案，proposal 里写明源自哪个变更。
- 归档目录不改，那是历史。

### 提交和推送

- 提交信息写成 `类型: 内容`（例：`feat: 新增修改页面`）。`git add -A`、`git add .`、`git commit -a` 一律拦，只 add 这次改的文件；它新建的文件漏了 add 会点名拦一次。
- 什么时候提交：做完一件完整的事（勾完一项任务、审查修复收尾、需求文档四份定稿、普通修改做完并快检过）才算。到了时机按"提交方式"：关（默认）就等你说"提交"，询问就问你，自动就直接提交。人工和自动模式都用这一个设置。
- 只提交这个会话改过的文件：`tools/commit.js`，暂存区里别的不动，照样过提交检查。
- 改坏了一条命令回去：`tools/checkpoint.js`（检查点，只还原这个会话改过的文件），自动模式开工前它会提醒 Claude 先存一个。
- push 要你当场明确说：说"推送""push"直接推，几笔提交都一样，不出推送计划，也不再弹 Claude Code 的确认框（只留套件这一道确认）。套件的合并推送工具 2026-10-28 起去掉了；你说"合并推送"的，Claude 照你说的自己用 git 合并没推的提交再推，不拦。强推、推到别的分支照旧问你。自动模式也一样。

细节见[提交和推送](手册/提交和推送.md)。开工前不再自动拉代码，要拉最新的你自己拉。

### 斜杠命令

说中文和敲命令都行，敲了就算你当场点头，不再问一遍：

| 命令 | 等于说 |
|---|---|
| `/opsx:explore` | 进流程，开始探索（见上面"流程"一节） |
| `/vk-resume [大任务名]` | 接回没做完的大任务：显示进度，从文件算到哪一步 |
| `/vk-config` | 打开配置页，不发模型请求 |
| `/vk-auto`、`/vk-auto off` | 这个会话开、关自动模式（见上面"自动模式"一节） |
| `/vk-go [变更名]` | 开工（照 `/opsx:apply` 做任务） |
| `/vk-commit` | 提交 |
| `/vk-push` | 推送 |
| `/vk-archive [变更名]` | 自测验收过了，归档 |
| `/vk-review` | 审查一下 |
| `/vk-test` | 自测一下 |
| `/vk-fix 要改的事` | 小改动快车道：直接改、快检，不问审查和自测，最后只问一次提交 |

状态栏第三行在等你时会写下一步说什么，例：`等你核验：看完说归档或 /vk-archive`。

### 查库、起服务、看页面

- 查库、查 redis：直接说"哪张表存了订单""看一下缓存里 user:1 是什么"。开发环境的连接后台已经配好。改数据先算影响面、留改前快照、等你确认。见[查库和 redis](手册/查库和redis.md)。
- 起服务一律经过 `tools/devserver.js`：已经在跑就复用，改过代码在同一个端口重启，端口在 30000—39999 里自动挑、避开项目配置的端口；换了目录、换了名字也认得自己起过的，要重启就在原来的端口先停再起；vite 这类热更新的改了代码不重启；你在 IDEA、终端里起着的服务不动。直接敲 `mvn spring-boot:run`、`npm run dev` 会被拦下。
- 看页面、调接口验后端：`/ttls-see-page`，写成场景文件让脚本执行。见[审查和自测](手册/审查和自测.md)。

### 进到新项目

不用你说。后台脚本查清工程类型、编译和启动命令、端口、编码、开发环境的数据库和 redis 连接，写进项目的 `.vibe/`（不进仓库，钩子会把它加进 `.gitignore`）。查不清的用 `/ttls-onboard`。见[项目说明和自动探索](手册/项目说明和自动探索.md)。

### 上下文快满了

默认 Claude Code 到线自己压缩（上限 100 万、压缩线 70% 时约用到 70 万），压缩后核对当前分支、任务、服务，不读旧交接。要换人接手时说 `/ttls-handover`；新会话说"继续"不会自动接上旧交接。见[上下文和 token](手册/上下文和token.md)。

| 第一行 | 红字警告（套件代码被改过、开关文件被直接改过、上下文过了上限没压缩）；目录和分支；上下文进度条和"已用/上限"，到"快满时怎么办"设的百分比前 15% 变黄、到线变红；`自动 开` 或 `自动 关` |
| 第二行（进了流程才有） | 步骤条，例：`探索✓ │ c2-api(2/3) 提案✓◆ 规格✓◆ 设计✓◆ 任务✓◆ 1组✓◆ 2组●◇ 3组○ │ 自测○ 核验○ 归档○`。✓ 做完，● 正在做，○ 没开始；◆ 审过，◇ 在审，✗N 有 N 条 P1、P2 待修。组太多折叠成 `组 3/8●` |
| 第三行（进了流程才有） | 下一项，或者在等你什么 |
| 有才出现的一行 | 放松了的保护（"允许改套件""被拦可自行放行"）；"经验待确认 N 条"；更新（"已更新到""有新版""新版没装上"） |

没进流程不显示 change：目录里有没勾完的 change 也不显示。没有新消息时每 10 秒刷新一次。

配置页敲 `/vk-config` 打开，用时才起，不常驻，六页：

| 页 | 干什么 |
|---|---|
| 套件说明 | 套件的组成、流程图、探索记录、接回和插话、发现要改时、不自己加、审查、人工和自动有什么不同、固定的规矩、自带的 OpenSpec |
| 本机环境 | JDK、Maven（可配多套）、Tomcat，先点"自动探测"；项目就绪 |
| 查库 | 查库的后台执行器、查库和查 redis 用得怎么样（驱动不用配，项目里声明的直接用） |
| 套件开关 | 上下文和交接、状态栏、全局（过程文件、审查与产物）、自动模式（说明，开关在会话里 /vk-auto）、提交、保护 |
| 经验规则 | 各项目和用户级的规则、候选；升成用户级只能在这里点 |
| 更新和上报 | GitLab 仓库和令牌、自动更新（先装新版、固定、跳过）、问题上报、使用情况上报、耗时异常上报、测试连接 |

改了开关，点页面底部的保存条，立即生效。每个开关的含义点开"细节"看，默认值见[开关一览](手册/开关一览.md)。配置放在哪、怎么加规范，见[配置页和规范](手册/配置页.md)。

## 出了问题看哪

| 现象 | 先看 |
|---|---|
| 不确定装得对不对、哪里不对 | `node "%USERPROFILE%\.claude\vibe-kit\tools\doctor.js"`：环境、套件文件、钩子登记、令牌规则、更新、开关、当前项目一项一行，[坏] 的后面写着怎么改。只读，不连外网 |
| 配置页打不开 | 再敲一次 `/vk-config`，地址以屏幕上写的为准；用 `127.0.0.1`，浏览器或系统代理要对本机地址直连 |
| 被拦下了 | 提示里写着原因和怎么改。流程类检查的提示末尾带〔拦截编号〕，它确信是套件拦错了可以申请放行，默认要你点同意。见[保护和放行](手册/保护和放行.md) |
| 套件拦错、报错、卡住 | 让它记一条问题反馈（多数时候它自己会记），自动上报成 GitLab 的 issue。配置页"更新和上报"能看到每条报成了哪一条 |
| 状态栏红字"套件代码被改过" | 重新运行安装包 |
| 新版没装上 | 配置页"更新和上报"点"测试连接"；日志 `~/.claude/vibe-kit/update/update.log` |
| 上下文过了上限还不压缩、网关报请求太大 | 敲 `/compact`；原因见[上下文和 token](手册/上下文和token.md) |
| 装了技能它却不用 | 见[项目说明和自动探索](手册/项目说明和自动探索.md)最后一节 |
| 想看套件认为流程走到哪了 | `node "%USERPROFILE%\.claude\vibe-kit\tools\diagnose.js" flow --session <会话编号>`；`push` 看推送，`hooks` 看钩子 |
