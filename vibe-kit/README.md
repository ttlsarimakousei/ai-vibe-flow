# vibe-kit

给内网 Claude Code（后面接公司网关上的私有模型）用的工作流套件。挂在 OpenSpec 上：需求、设计、任务归 OpenSpec 管；编号、git、编译、起停服务、提交节点这些能确定判断的事，由本机脚本在钩子里做，不花 token。

这份是短手册：怎么装、自动模式怎么选、平时怎么用、状态栏和配置页怎么看、出了问题看哪。细节在 `手册/` 下，一件事一份，见文末"附录"。每一版改了什么见[更新说明](更新说明.md)；本版的流程图和人工验收步骤见[开发流程](开发流程.md)和[验收清单](验收清单.md)。

## 里面有什么

| 东西 | 干什么 |
|---|---|
| 钩子 | 改文件、跑命令、提交、收工时在本机检查。拦下时提示里写着原因和怎么改 |
| 模型路由 | 在本机 15730 端口后台运行，没有窗口，登录后自动启动。按角色把请求转给你配的模型，出错自动换；带一个配置页 |
| 状态栏 | Claude Code 底下三行：上下文、自动模式生不生效、今天的用量 |
| `/ttls-onboard` | 后台自动探索不够用时手动接手项目（认不出的工程、要实际跑一遍命令、补登录账号） |
| `/ttls-db-crud`、`/ttls-redis` | 查库、改库（达梦、神通、MySQL、Oracle、人大金仓）；查 redis |
| `/ttls-see-page` | 起服务、照步骤操作页面或调接口、读页面上的值；还原原型按数字比，不靠读截图 |
| `/ttls-cross-review` | 独立审查需求文档和代码 |
| `/ttls-handover` | 你要求时写交接记录 |

## 装和升级

需要 Node 18 以上。

1. 拿安装包：浏览器打开团队 GitLab 仓库 `http://scm.skytech.io/nb-2026/p1/ai-engineering/90-personal/3139/vibe-kit`，点"代码"下载 zip；有 git 的也可以 `git clone --depth 1` 这个仓库；连不上仓库时用别人发的压缩包。
2. **整个解压**，双击里面的 `安装（双击我）.bat`，或者在那个目录里 `node install.js`。装两样：套件装进 `~/.claude`；模型路由在后台启动。装完这个目录可以删。
3. 全新的机器，安装器会打开配置页 http://127.0.0.1:15730/ui ：
   - "模型"页点"添加模型"，填网关地址和 key，一个模型一条；点"按常用的分三个角色"，需要的话把审查（sonnet）换到另一个模型；保存。
   - 点页面最上面的"接上"：把 `~/.claude/settings.json` 的 `ANTHROPIC_BASE_URL` 指到路由（先备份，点"断开"原样恢复）。这一步不自动做，免得这台机器的 Claude Code 本来连着别处、被改得用不了。
4. 新开一个 claude 会话就能用。在壳子目录里启动的，告诉它这次动哪个子项目。

安装时会做的、你可能要知道的：

- 先检查后动手：`settings.json` 读不懂、全局 `CLAUDE.md` 不是 UTF-8，就什么都不动，说清是哪几行。覆盖你改过的技能、约定、审查代理之前，先备份到 `~/.claude/vibe-kit/backup/`。
- 在 `settings.json` 里放行 Bash、PowerShell、Read、Edit、Write、Glob、Grep，平时不弹确认。你删掉的放行、环境变量，再装不补回来。
- 默认关掉 Claude Code 自带的 auto mode 和自动记忆，原因和改回去的办法见[保护和放行](手册/保护和放行.md)、[上下文和 token](手册/上下文和token.md)。
- 本机 IDEA 2025.2 以上开着 MCP 时自动登记给 Claude Code，见[IDEA 接入](手册/IDEA接入.md)。
- 以前单独装过 `urai-db-crud`、`redis` 技能的：装在用户目录里的删掉（先备份），装在项目里的不动。

升级：

- 装好之后不用再管。后台每 2 小时问一次 GitLab 仓库，有新版就在路由空闲时装上，装完自检，不过就装回上一版。可以在配置页"更新和上报"改成只提醒或不检查，见[自动更新和上报](手册/自动更新和上报.md)。
- 手动升级：新包装在原来的上面，不用先卸载。开关、本机环境、模型和 key、问题反馈、GitLab 地址和令牌都留着。
- 升级后重开一次 Claude Code（新登记的钩子、MCP 要重开才生效），不需要 `/clear`。路由自动重启。
- 本版的安装和升级会把"需求自动""Apply 自动"都关掉一次；之后你在配置页重新打开，不会再被重置。

不装路由：`node install.js --no-router`。卸载：`node "%USERPROFILE%\.claude\vibe-kit\install.js" --uninstall`，停掉路由，收回加的权限、环境变量、钩子和状态栏；模型和 key、本机环境、你自己的规范、问题反馈留着。在配置页点过"接上"的，卸载时替你"断开"。

## 两种自动模式怎么选

配置页"套件开关"里有两个独立的开关："需求自动模式"的"自动完善需求"和"Apply 自动模式"的"自动完成 Apply"，默认都关。

| 需求自动 | Apply 自动 | 适合 | 会怎样 |
|---|---|---|---|
| 关 | 关 | 你一直在旁边 | 需求和实施都跟你一步步来；审查、自测、复验先问你 |
| 开 | 关 | 需求想快点出稿，代码你要盯着 | 探索、问清疑问后，逐个写 proposal、specs、design、tasks，每份自动审修；定稿后提交（自动提交选了"我说了才提交"就先问你），再问你要不要 apply；实施按人工来 |
| 关 | 开 | 需求要和你逐条敲定，实施可以放手（开会、下班） | 需求和你一起定；你选了 apply 之后，自动做完这次确认的范围 |
| 开 | 开 | 需求清楚，整件事可以放手 | 先探索澄清；逐份审修，定稿提交后自动 apply（自动提交选了"我说了才提交"就先问你提交）。你只让它写需求时不会自己开工 |

手册里说的"自动模式生效时"，指当前阶段对应的开关开着、这个会话正在走 OpenSpec 流程、状态栏第二行写着"……，当前生效"。只是开关开着不算；需求阶段还要先探索、问清疑问之后才生效。不走 OpenSpec 的修改一直按人工来。

开不开自动都一样的：

- 有业务疑问、需求变了、审查到了轮数上限，照样用提问框问你。
- 用户验收、归档、push 由你决定。它不会自己归档，不会自己推。
- 改套件、读令牌和 key、结束路由进程、整仓 add、改非 UTF-8 文件，照样拦，不能放行。

自动模式生效时多出来的：流程类检查拦下时它可以自己申请放行，不等你点（选了"不许放行"的除外）；代码之外的产出没定位置的先放 `.vibe/pending/`；改库只做留得下改前快照和还原脚本的；收工时在项目的 `.vibe/reports/` 交一份报告（文件名 `全自动报告-日期-时间.md`），写做到哪、留给你做的、库里改过的、没验证的、放行的检查、它自己定的事。

## 平时怎么用

### 新功能

1. 说需求。它先读相关代码和现状（这一句话会先把仓库拉到最新，只快进），把目标、范围、业务规则、验收场景跟你问清。开了需求自动也不会猜你没说的规则。
2. 逐个写 proposal、specs、design、tasks，每写完一份审一次（人工模式先问你要不要审）。文档不限行数，复杂的关系配图。验收用例写在 design.md 的"验收用例"一节：每条写对应场景、前置数据和环境、步骤、预期、谁来测、对应第几组任务，写需求时就写完给你看。
3. 整套定稿后提交一次（人工模式先问你）。然后问你 apply、继续改、还是先不做；两个自动都开着时直接开工。
4. 开工后做完一项勾一项，每整组任务（1.x、2.x）做完审一次；Apply 自动开着"自动自测"时，审之前先跑这一组的验收用例，全部做完再全跑一遍。Apply 自动时按档位自动提交，人工模式提醒你提交。
5. 做完交用例的实际结果。你照验收用例自测，满意了说"归档"它才归档；验收不靠在任务清单里打勾。

需求文档的几条规矩：

- tasks 只写要做的实现任务，形如 `- [ ] 1.1 订单查询为空时返回空列表：src/order.js`。不写"验："，不写测试、审查、用户验收任务（新写的会被拦下，提示写进验收用例）；套件的审查进度、起服务、自测记录在本机，没装套件的同事也看得懂。
- 实施要用的非敏感材料放变更目录的 `assets/` 或 `references/`，用相对链接随提案提交；不依赖本机的临时文件、口令和连接配置。
- 任一阶段改了需求，同步改受影响的需求、设计、任务、代码、用例和流程图，改处加批注，`revisions.md` 写起因、变化和影响范围。开工后改了需求的，旧的开工许可失效：文档照常改，改代码和打勾要你重新说开工。
- OpenSpec 随套件装：安装包带一份（打包时的最新版），`/opsx:*` 命令装成用户级，项目没初始化的第一次用时自动建 `openspec/`；写出来的变更同事用自己的 OpenSpec 1.2 也能看、归档。电脑上的 Node 低于它要求的版本（1.14.3 要 20.19）时，照旧用你自己装的。详见配置页"套件说明"页。

审查的轮数、人工和自动的区别、跳过审查怎么记，见[审查和自测](手册/审查和自测.md)。大需求拆成几个变更的，让它在 `openspec/plan.md` 里列一张表（`node "%USERPROFILE%\.claude\vibe-kit\tools\plan.js" <项目目录>` 生成），会话开头会带上"共几个、归档几个、进行中哪些、下一个是谁"。

### 小改动、修 bug（不走 OpenSpec）

直接说。改完它用一个提问框问一次：要不要跑快检（编译级）、审查、按用例自测。

- 编译、类型检查、静态检查不算自测，它直接跑；跑测试、起服务、看页面算自测，先问你。你已经说过"跑一下测试""把服务起起来"的，直接做。
- 你说不用，它就接着做，不记待办；同一个要求里后面的小改动不再问。你提新要求、又改了代码，才再问。
- 提交按配置页"提交"卡片里的"提交方式"：询问（默认，交代后问你）、自动（做完就提交）、关（你说了才提交）。

### 修已归档功能的问题

你说"自测发现……""测试反馈……""报错了"时，它先溯源：`node "%USERPROFILE%\.claude\vibe-kit\tools\trace.js" <文件>[:行号]` 列出当初是哪个变更、哪项任务、哪个提交改的这里。

- 改动小（三个文件以内、不改接口和表结构、不改需求）：直接改、验证，提交写 `fix: 问题（源自 变更名 任务号）`，不新开变更。它要去新建提案会被拦一次。
- 要改需求、接口、表结构：它先告诉你，你说走提案再提案，proposal 里写明源自哪个变更。
- 归档目录不改，那是历史。

### 提交和推送

- 提交信息写成 `类型: 内容`（例：`feat: 新增修改页面`）。`git add -A`、`git add .`、`git commit -a` 一律拦，只 add 这次改的文件；它新建的文件漏了 add 会点名拦一次。
- 什么时候提交：做完一件完整的事（勾完一项任务、审查修复收尾、需求文档四份定稿、普通修改做完并快检过）才算。到了时机按"提交方式"：询问（默认）就问你，自动就直接提交，关就等你说。人工和自动模式都用这一个设置。
- push 要你当场明确说。只有一笔、目标明确、工作区干净时直接推；多笔先给你看合并预览（按任务或独立修复归组），你另说一次"确认推送"才执行。自动模式也一样。

细节见[提交、推送和合并推送](手册/提交推送和合并推送.md)。开工前不再自动拉代码，要拉最新的你自己拉。

### 查库、起服务、看页面

- 查库、查 redis：直接说"哪张表存了订单""看一下缓存里 user:1 是什么"。开发环境的连接后台已经配好。改数据先算影响面、留改前快照、等你确认。见[查库和 redis](手册/查库和redis.md)。
- 起服务一律经过 `tools/devserver.js`：已经在跑就复用，改过代码在同一个端口重启，端口在 30000—39999 里自动挑、避开项目配置的端口。直接敲 `mvn spring-boot:run`、`npm run dev` 会被拦下。
- 看页面、调接口验后端：`/ttls-see-page`，写成场景文件让脚本执行。见[审查和自测](手册/审查和自测.md)。

### 进到新项目

不用你说。后台脚本查清工程类型、编译和启动命令、端口、编码、开发环境的数据库和 redis 连接，写进项目的 `.vibe/`（不进仓库，钩子会把它加进 `.gitignore`）。查不清的用 `/ttls-onboard`。见[项目说明和自动探索](手册/项目说明和自动探索.md)。

### 上下文快满了

默认 Claude Code 到线自己压缩（上限 100 万时约用到 90 万），压缩后核对当前分支、任务、服务，不读旧交接。要换人接手时说 `/ttls-handover`；新会话说"继续"不会自动接上旧交接。见[上下文和 token](手册/上下文和token.md)。

## 状态栏和配置页

状态栏最多三行：

| 行 | 显示什么 |
|---|---|
| 第一行 | 红字警告（套件代码被改过、开关文件被直接改过、上下文过了上限没压缩、快到网关能接受的请求大小）；模型；目录和分支；上下文进度条和"已用/上限"，到交接线前 15% 变黄、到线变红；进行中的变更 `opsx 变更名 完成数/总数` |
| 第二行 | `需求自动 开/关 · Apply 自动 开/关`；当前阶段（"实施，当前生效""需求与提案，当前生效""等用户自测验收""范围变化，等用户确认""普通任务，照常，变更已归档"）；"到 900k 自动压缩"；放松了的保护（"允许改套件""被拦可自行放行"）；"经验待确认 N 条"；更新（"已更新到""有新版""新版没装上"） |
| 第三行 | 今天经过路由的请求次数和 token，用得最多的三个模型；次数到公司提醒线的 75% 变黄，到了变红 |

配置页 http://127.0.0.1:15730/ui ，七页：

| 页 | 干什么 |
|---|---|
| 套件说明 | 套件的核心思路和组成、人工和自动两条流程的图、固定的规矩（不做开关的）、大需求怎么写、自带的 OpenSpec |
| 模型 | 接上 / 断开 Claude Code；加模型、换 key、测试、分角色；每个模型现在正常还是在冷却、额度用完几点恢复；配置备份 |
| 用量 | 今天和最近 14 天的请求、token、缓存命中率，最近的请求和失败原因（长的点开看全文） |
| 本机环境 | JDK、Maven（可配多套）、Tomcat，先点"自动探测"；IDEA MCP；项目就绪与本机耗时 |
| 数据库驱动 | 每种数据库用哪个 jar、自动搜索、查库的后台执行器 |
| 套件开关 | 上下文和交接、状态栏、自动探索、全局（过程文件、审查与产物）、需求自动模式、Apply 自动模式、提交、保护 |
| 经验规则 | 各项目和用户级的规则、候选；升成用户级只能在这里点 |
| 更新和上报 | GitLab 仓库和令牌、自动更新、问题上报、使用情况上报、测试连接 |

改了开关，点页面底部的保存条，立即生效。每个开关的含义点开"细节"看，默认值见更新说明的"开关一览"。路由怎么转发、配置文件放在哪，见[模型路由和配置](手册/模型路由和配置.md)。

## 出了问题看哪

| 现象 | 先看 |
|---|---|
| 配置页打不开 | `node "%USERPROFILE%\.claude\vibe-kit\router\service.js" status`。没在运行就把 `status` 换成 `start`；端口被占见[模型路由和配置](手册/模型路由和配置.md) |
| 被拦下了 | 提示里写着原因和怎么改。流程类检查的提示末尾带〔拦截编号〕，它确信是套件拦错了可以申请放行，默认要你点同意。见[保护和放行](手册/保护和放行.md) |
| 套件拦错、报错、卡住 | 让它记一条问题反馈（多数时候它自己会记），自动上报成 GitLab 的 issue。配置页"更新和上报"能看到每条报成了哪一条 |
| 状态栏红字"套件代码被改过" | 重新运行安装包 |
| 新版没装上 | 配置页"更新和上报"点"测试连接"；日志 `~/.claude/vibe-kit/update/update.log` |
| 上下文过了上限还不压缩、网关报请求太大 | 敲 `/compact`；原因见[上下文和 token](手册/上下文和token.md) |
| 装了技能它却不用 | 见[项目说明和自动探索](手册/项目说明和自动探索.md)最后一节 |
| 想看套件认为流程走到哪了 | `node "%USERPROFILE%\.claude\vibe-kit\tools\diagnose.js" flow --session <会话编号>`；`push` 看推送，`hooks` 看钩子 |
