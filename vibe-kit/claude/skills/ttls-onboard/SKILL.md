# 接手项目

目的只有一个：以后在这个项目里改完东西，能在几秒内自己验证。所以这里查到的每条命令都要**真的跑一遍**，跑通了再记。不是每种工程都有"编译""启动"这回事：先判断是什么工程，只查该查的，不适用的就写"不适用"，别硬凑命令。

## 先看有没有自动探索的结果

项目的 `.vibe/project.md` 第二行是 `<!-- vibe-kit 后台自动探索 -->` 的，是套件的脚本照工程结构查出来的：工程类型、命令、端口、编码、开发环境的数据库和 redis 连接。脚本没有实际跑过命令。这时不用从头查：

1. 标着"（没跑过）"的命令各跑一次。通了，把"（没跑过）"去掉，补上耗时；不通，查清原因，把那一行改成对的。
2. 快检写着"还没备好"的、或者全量当快检太慢的，照 `recipes.md` 备好，把那一行换掉。
3. 脚本查不了的补上：登录账号（问我，记到 `.vibe/login.json`）、产出位置（问我）。
4. 数据库、redis 那两行是脚本从开发环境的配置里找的，不用动。连不上的，用 /ttls-db-crud、/ttls-redis 查原因。

你改过的行脚本以后不会覆盖。没有这个标记的项目说明（以前查的、人写的），照下面的做法核对。

## 先弄清在哪一层

公司的项目外面有一层给 AI 用的壳子（放 openspec、文档、.claude），里面是项目的各个子项目（放代码，各是独立的 git 仓库）。会话开头如果提示过"这个目录是一层壳子"，那就是在壳子里；没提示的话自己看一眼：当前目录自己没有 pom.xml、package.json 这类构建文件，代码都在下面的几个子目录里，也是壳子。

- 在壳子里：**不要对整个壳子跑 onboard**。问用户这次要动哪个子项目，只对那一个做；其余的用到再说。
- 在某个子项目里，或者就是一个普通项目：对当前目录做。

下面说的"项目根目录"都是指**要动的那个项目**的根目录。

## 再判断是什么工程

看目录结构和标志文件，对号入座。一个仓库里套着几种的（后端一个目录、前端一个目录、旁边还有一堆脚本），分别记。

| 工程 | 怎么认 | 要查清的 |
|---|---|---|
| 写代码的 | pom.xml、build.gradle、package.json、WEB-INF、.classpath、*.iml、go.mod、pyproject.toml 这些 | 下面"代码工程的五件事" |
| 开发技能的 | skills/*/SKILL.md、commands/*.md、agents/*.md、.claude-plugin/、插件清单；正文以 Markdown 提示词加几个脚本为主 | 技能怎么组织；怎么验证一个技能（清点工具）；脚本怎么跑、怎么做语法检查；怎么装到本机试一次；编码 |
| 纯文档、规范 | 几乎全是 .md / .docx，或者只有 openspec/，没有构建文件 | 文档怎么组织（目录、命名、模板）；有没有检查手段；编码 |
| 散装脚本、工具 | 一堆 .bat / .ps1 / .py / .js，没有构建文件，各跑各的 | 每个脚本怎么跑（参数、依赖、要不要管理员）；语法检查命令；编码 |
| 说不清 | 上面都对不上，或者对上好几个 | 问用户一句：这个仓库是干什么的？改完怎么算改对了？按回答记 |

每种工程要查什么、命令怎么拼、有哪些坑，见同目录的 `recipes.md`，先读对应的那一节。**不是代码工程的，不查怎么编译、怎么启动**，那两项直接记"不适用"。

## 代码工程的五件事

1. **这是什么项目**：Maven（单模块／多模块／Spring Boot 几）、Gradle、前端（Vue／React，Vite／webpack）、还是没有 pom、在 IDE 里配 Tomcat 启动的老式 Java Web。一个仓库里常常套着好几个（后端一个目录，前端一个目录），分别记。
2. **快检**：改完一处（可能涉及几个文件），只检查改过的这几个文件，几秒内出结果的命令。
3. **全量**：收尾时整体编译或构建一次的命令，记下大概要多久。
4. **启动**：怎么跑起来，端口是多少，怎么判断它起来了。试跑用 `node "$HOME/.claude/vibe-kit/tools/devserver.js" start --name <名字> --port auto --avoid <配置里的端口> -- <启动命令>`（端口它自己挑，离配置里的远；它会记下来，查完 `stop --all`），项目说明里记原始的启动命令和配置里的端口；IDEA 里有运行配置的，再记运行配置名和它监听的端口（devserver 加 --idea 用）。登录账号问用户，记到 `.vibe/login.json`，不要猜。
5. **编码**：源码是 UTF-8、GBK 还是混着的。

前后端联调另外记清：代理配置在哪、是否读取环境变量、后端的上下文路径，以及统一认证回调和服务端 CORS 是否限定前端端口。后端先用 devserver 起，前端带 `--backend <后端服务名>`；代理读取 `VIBE_BACKEND_URL` 并保留上下文路径（例如 `(process.env.VIBE_BACKEND_URL || 'http://127.0.0.1:8096') + '/oa'`）。需改项目配置时保留原默认行为。固定端口已有用户服务时不接管，说明冲突和需要用户处理的依赖；端口能监听不代表登录和代理已通。

## 不是代码工程时，"验证"指什么

- **技能工程**："快检"= 改过的 SKILL.md 用清点工具过一遍（frontmatter 读不读得出、description 有没有说清什么时候用、长度有没有超、有没有同名）：`node "$HOME/.claude/vibe-kit/tools/skills-check.js" <仓库目录> --repo`，有问题退出码 1；改过的脚本做语法检查（node --check、python -m py_compile、PowerShell 的语法检查，命令见 recipes）。"全量"= 对整个仓库跑一遍清点工具，加仓库自带的测试。"启动"不适用；要试一个技能，按仓库自己的安装方式装到本机试一次（没写的就复制到 `~/.claude/skills/<名字>`，或者 `claude --plugin-dir <仓库>`），试完把复制过去的删掉，把做法记下来。别碰 vibe-kit 自己的技能。
- **文档工程**："快检"= 仓库有 lint、链接检查就记命令；没有就记"不适用：改完通读改动的那一节，文中的路径和链接用 grep 核对存在"。"全量""启动"不适用。
- **脚本工程**："快检"= 语法检查；"全量"= 不适用，或者仓库自带的自测脚本；"启动"= 记成"每个脚本怎么跑"。

## 做法

0. 先看项目根目录的 `CLAUDE.md` 里有没有"项目说明（团队共享）"一节：有就是同事查过的，照它在本机把命令各跑一次，只补本机的部分（见下面"记到哪"），不用从头查。
1. 看目录结构和标志文件，按上面的表判断类型；说不清就问用户一句。
2. 代码工程：JDK、Maven、Tomcat 在哪，先看全局约定里的"本机环境"一节，那是用户配好的，直接用，不要满硬盘找。这个项目要用的版本和默认的不一样（比如默认 JDK 8，这个项目要 17），从"本机环境"里挑对的那个，记进项目说明。"本机环境"里没有要用的东西，问用户，并提醒他可以在路由配置页的"本机环境"里补上。
3. 照 `recipes.md` 里对应的一节，把该查的命令拼出来，**各跑一次**，记下耗时。跑不通就查原因，修到通为止；确实通不了（比如缺依赖、连不上私服），如实记下卡在哪。
4. 快检需要长期用的中间文件（classpath 清单 `cp.txt`、javac 参数文件 `javac.args`、基线 `*-baseline.txt`）放到项目根目录的 `.vibe/` 下，别的名字要在项目说明里写明路径和用途。查的过程中临时写的脚本放 `.vibe/tmp/onboard/`，查完删掉。`.vibe/` 不用你管忽略的事：往里写文件时，钩子会自动把它加进那个仓库的 `.gitignore`。
5. 查编码：挑十来个带中文的文件看一下。发现不是 UTF-8 的，列出来告诉用户，不要自己动手批量转。
6. 代码工程的启动命令如果会连数据库、占端口，先问用户现在方不方便跑；不方便就只记命令，标明"没实际跑过"。
7. **产出位置**：以后在这个项目里写 DDL 脚本、功能说明、分析报告这类代码之外的文件，放哪要是用户定的。看一眼项目里有没有现成的地方（sql/、db/、docs/、文档/ 这类目录），列成几个选项用提问框问用户（选项写实际目录），按用户选的记进"产出位置"（写法见下面的例子）。用户说还没想好的就不记，以后用到时再问。只能记用户说过的，不要自己替他定。

## 记到哪

分两处记：

- **本机的**写进项目根目录的 **`.vibe/project.md`**：只在本机，不提交。JDK、Maven 用的哪一套、耗时、本机的路径这些每个人不一样，提交了反而互相覆盖。以后每个会话开始时，钩子会自动把它带给模型，不用谁记得去读。收工检查的钩子也认它：标了"不适用"的项不会再催你验。
- **团队都一样的**（是什么工程、快检和全量的命令、启动命令和端口、编码情况、哪些项不适用、产出位置、坑）可以写进项目根目录 `CLAUDE.md` 的 **"## 项目说明（团队共享）"** 一节：它跟着仓库提交，同事的 Claude Code 打开这个项目就读得到，不用每个人各查一遍、各踩一遍坑。**写之前用提问框问我**（选项：写进 CLAUDE.md 一起提交 / 只记在本机），因为它会进仓库；我同意了才写，只写这一节，CLAUDE.md 里别的内容不动。命令里不带本机路径（写 `mvn -q compile`，不写 `D:\apache-maven\bin\mvn`），账号密码两处都不写。

已经有"项目说明（团队共享）"这一节的（同事查过了）：不用从头查，照它把命令在本机各跑一次，跑通了只把本机的部分记进 `.vibe/project.md`；和它对不上的（命令变了、坑已经没了），告诉我，我同意了再改那一节。

`openspec/config.yaml` 这类文件不要写。

Maven、JDK 用哪一套：全局约定的"本机环境"里可能配了好几套（不同的 settings.xml、不同的本地仓库、不同版本的 JDK）。先用标了"没有特别说明时用这个"的那一套试；编不过、依赖拉不下来，再换别的试，试通了把用的是哪一套记进项目说明。

代码工程（没有团队共享那一节时，全记在本机这份里；有的话，这里只记"环境"和耗时这些本机的）：

```markdown
# 项目说明（/ttls-onboard 于 2026-09-19 查得）

- 类型：代码工程。Maven 单模块，Spring Boot 2.7，Java 8；前端在 ../xxx-front（Vue 3 + Vite）
- 环境：JDK 用"本机环境"里的 8；Maven 用默认的
- 快检：<命令>（约 2 秒）
- 全量：<命令>（约 40 秒）
- 启动：<命令>，端口 8080，起来的标志是 <…>；账号见 .vibe/login.json
- 自测联调：代理配置 <路径>，后端地址读取 <变量>，上下文路径 <路径>；认证回调/CORS 的固定端口 <已查得约束或不适用>；进入目标页的菜单 <路径>
- 编码：UTF-8；以下 3 个文件是 GBK，别直接改：<…>
- 产出位置（用户定的，代码之外的产出放这里）：
  - DDL 脚本：sql/ddl/
  - 功能说明、分析报告：docs/
- 坑：<只写会让人栽跟头的，比如"离线编不了，要连私服""vue-tsc 现在就有 12 个错，只看新增的">
```

技能工程：

```markdown
# 项目说明（/ttls-onboard 于 2026-09-23 查得）

- 类型：技能工程。12 个技能在 skills/ 下，各带 scripts/；发布方式见 README（复制到 ~/.claude/skills）
- 快检：node "$HOME/.claude/vibe-kit/tools/skills-check.js" . --repo（约 1 秒）；改了脚本再加 node --check <文件>
- 全量：同上；tests/ 下有 npm test（约 8 秒）
- 试用：复制到 ~/.claude/skills/<名字>，新开会话说一句触发词看用不用，试完删掉
- 启动：不适用
- 看页面：不适用
- 编码：UTF-8
- 坑：description 第一句要写"什么情况下用"，模型只看这一句
```

团队共享的那一节（写进项目根目录的 CLAUDE.md，问过我才写）：

```markdown
## 项目说明（团队共享）

- 类型：代码工程。Maven 单模块，Spring Boot 2.7，Java 8；前端在 ../xxx-front（Vue 3 + Vite）
- 快检：mvn -q compile -o（只编改过的模块）
- 全量：mvn -q package -DskipTests
- 启动：mvn spring-boot:run，端口 8080，起来的标志是日志里出现 Started XxxApplication
- 编码：UTF-8；src/main/java/com/x/legacy/ 下是 GBK，别直接改
- 产出位置（团队定的）：
  - DDL 脚本：sql/ddl/
  - 功能说明、分析报告：docs/
- 坑：离线编不了，要连私服
```

保持简短，二十行以内，别写成文档。账号密码不写在这里，写在 `.vibe/login.json`。

以后发现这里记的和实际对不上（命令变了、端口改了），直接更新这个文件。

## 最后

用三五行告诉用户：这是什么工程、查到了什么、哪条命令实际跑通了、哪条没跑通及原因、哪些项不适用；团队共享的那一节写了没有（写了的，提醒用户跟着下一次提交带上）。
