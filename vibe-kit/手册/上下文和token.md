# 上下文和 token

上下文上限、自动压缩、交接、网关请求大小，以及套件的每一部分花多少 token。回到[用户手册](../README.md)。

## 上限和进度条

- 状态栏的进度条 = 已经用的 token ÷ 上下文上限。上限默认 100 万（内网模型的标称值），在配置页"上下文和交接"改，改完下一条消息就按新值算；填 0 表示跟着 Claude Code 自己报的窗口走。
- 进度条到交接线（默认 70%）前 15% 变黄、到线变红。

## 自动压缩（默认）

配置页"连续工作的方式"默认"自动压缩优先"：Claude Code 用到一定量时自己把对话总结成一段再接着做。压缩后套件核对当前分支、任务、服务和验证事实，不自动读旧的交接记录。

**压缩线由套件替你设好**（"自动压缩线"，默认 70%）。新版 Claude Code（2.1.259 这类）不设压缩窗口时不按用量压缩，要等模型接口报"请求太长"才补救，内网模型报的错它认不出，用到 1001% 都不压缩（2026-10-01 遇到过）。

- 套件把窗口写进 `settings.json` 的 `autoCompactWindow`：窗口 = 上限 × 压缩线 + 3.3 万，最小 10 万、最大 96 万；Claude Code 在"窗口 − 3.3 万"处压缩。上限 100 万、压缩线 70% 时约用到 70 万压缩。2.1.120、2.1.259、2.1.289 都认这一项。
- 为什么最大 96 万：窗口设到 97.7 万以上，Claude Code 还没压缩就先报 `Prompt is too long`。所以最晚用到 92.7 万压缩。
- 改了之后新开的会话生效。开着的会话敲配置页上算好的那条 `/autocompact <窗口>` 马上生效。
- 压缩线填 0：套件不设，照 Claude Code 自己的。你装套件之前自己设过 `autoCompactWindow` 的，填 0、卸载时还给你；在 Claude Code 里用 `/autocompact` 改过的，下次保存开关、升级时换回配置页算的值。`env` 里设了 `CLAUDE_CODE_AUTO_COMPACT_WINDOW` 的以它为准，安装时提醒。
- 用量还是过了上限：状态栏第一行红字说"Claude Code 没自动压缩"，敲 `/compact`，或者 `/ttls-handover` 交接。

## 交接

- 只在你明确要求时写（`/ttls-handover`）。默认的自动压缩方式下不提醒交接、不自动写记录、不自动 `/clear`。
- 新会话说"继续"不会接上旧交接。要读旧记录得点名；记录里的分支、任务、服务和许可都要按现在的情况重新核对，过期的只当资料，不照着往下做，也不能从旧记录拿回动作许可。
- 想按交接线提醒：把"连续工作的方式"改成"按交接线提醒"。这时"到了交接线之后"可选只提醒一句（默认，你说交接才交接）、或者用提问框问你；压缩线要设得比交接线高，才会先提醒交接、再压缩；Apply 自动生效时，"到交接线先写交接记录"开着就先写一份再接着做。

## 网关的请求大小

**模型的上下文长度和网关能接受的请求大小是两回事。** 内网网关对单次请求可能有大小上限（之前实测约 1 MB，合二十三四万 token），超了直接回 413，到不了模型，换模型、`/compact` 都没用。

- 套件不写死这个上限：路由真被拒过一次，才记下当时的请求大小；之后快到它的 85% 时，状态栏提前红字警告。之后有更大的请求成功了（管理员调大了），这条记录自动作废。配置页上能看到这条记录，也能手动忘掉。
- 想真正用满 100 万，要请网关管理员把请求体上限调大（nginx 的 `client_max_body_size`）。

## 缓存

路由不改请求：Claude Code 发出的请求原样转给网关（只换 key；配了模型名改写的只改 model 字段），同一个会话始终落在同一个模型上，缓存该命中就命中。

真正让缓存失效的是：换模型（另一个模型要把整个上下文从头算一遍）、请求被放弃后重发、上下文本身太长（内网实测：5 万 token 时同前缀第二次只要 0.25 秒；30 万 token 时热请求比冷请求还慢）。前两件路由尽量避免，第三件靠及时压缩。

配置页"用量"页最上面有按模型算的缓存命中率、换模型次数、限流等待次数。命中率一直是 0、而同一个会话的第二条请求明显比第一条快，说明网关没把这个数传回来，不是没命中。

## 两件 Claude Code 自己的事

- **模型名**：不指定模型时 2.1.259 发出去的模型名是 `claude-opus-5`，按 100 万窗口算。把 Claude Code 的模型名改成它不认识的（比如内网模型的真名），它按 20 万窗口算，而且用到 19 万左右直接报 `Prompt is too long`。这时在 `settings.json` 的 `env` 里加 `CLAUDE_CODE_MAX_CONTEXT_TOKENS=1000000`。路由里配的"模型名改写"不影响这一条。
- **自动记忆默认关掉**：Claude Code 自带的自动记忆（`~/.claude/projects/<项目>/memory/`）和经验规则重复、条数不受控，说明文字每个请求都占系统提示（2.1.120 上 12,762 字符，差不多系统提示的一半；2.1.259 上 2,317）。安装器在 `settings.json` 的 `env` 里写 `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`。已有的记忆文件不删，只是不再加载。想用回它，在配置页"经验规则"里改成"不管它"，重开 Claude Code 生效。你自己设过这一项的，套件不动。

## 花多少 token

脚本做的判断都在本机，不花 token。花 token 的只有进到模型上下文里的文字：

| 项目 | 什么时候 | 大约 |
|---|---|---|
| 全局约定 + 规范 + 本机环境 | 每个请求都带（走缓存） | 2026-10-16 实测：默认开关约 5,500 字，两个自动都开约 5,700 字，合约 2,500～3,500 token；本机环境另算。钩子拦下时才给细节，约定里只留一句 |
| 项目说明、壳子结构 | 每个会话一次 | 300 token；带数据库、redis 两行的一份 400～600 token；壳子下的子项目只列路径 |
| 后台自动探索 | 脚本做，不用模型 | 0。探索好了随你下一条消息带一次 |
| 技能列表 | 每个会话一次 | 六个技能的说明一共约 1,000 字 |
| 查库、查 redis | 用到时 | 一条命令一次工具调用 |
| 打断提醒、进度行 | 只在对应情况出现时 | 每次 50～150 token |
| 收工检查 | 只在漏了验证时 | 100 token，外加补做验证的那几次调用 |
| 开工前拉代码（2026-10-17 起不再拉） | 不再有 | 拉到新代码、没拉成时 50～150 token；本来就是最新的 0 |
| 审查 | 每个文档产物、每整组任务一个审查点；自动模式每点不超过所设轮数 | 文件数、总时间有限；实际 token 随材料和模型变，没有量化过 |
| 经验规则 | 一个会话里第一次读到那类文件时 | 每组最多 1,200 字；没读到那类文件就是 0 |
| 使用情况上报 | 后台每天一次 | 0 |
| Claude Code 自带的 auto mode | 套件默认关掉：0；"不管它"时每条有风险的命令一次 | 一个分类请求约 14 万字符系统提示，格式不对时一条命令十个请求 |

钩子本身不花 token。命令方式每个钩子起一个进程（0.3～0.9 秒）；装了路由时高频的几个在路由里跑，一次几毫秒到几十毫秒，见[模型路由和配置](模型路由和配置.md)。
