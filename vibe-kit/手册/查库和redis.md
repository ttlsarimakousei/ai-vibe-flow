# 查库和 redis

`/ttls-db-crud` 和 `/ttls-redis` 跟着套件一起装、一起更新。回到[用户手册](../README.md)。

| 技能 | 要什么 | 连接配置 |
|---|---|---|
| `/ttls-db-crud`（达梦、神通、MySQL、Oracle、人大金仓） | Python 3、java 8 以上、数据库的驱动 | 项目的 `.vibe/db-crud.ini` |
| `/ttls-redis` | 什么都不用装，只用 Node 自带的模块 | 项目的 `.vibe/redis.json` |

连接配置一般不用手写：后台自动探索从项目的配置文件里找**开发环境**的连接写进去（测试、生产的不配，见[项目说明和自动探索](项目说明和自动探索.md)）。口令不经过模型、不上命令行。对话里直接说"哪张表存了订单""看一下缓存里 user:1 是什么"就行。

## 查得快

| 做法 | 效果 |
|---|---|
| 一条命令只起一次 java | 以前看一张表的结构要起 2 到 4 次 |
| `find`、`columns` 一次几张表；`peek --eq 字段=值`；`query` 一次几条 | 少写 SQL、少来回 |
| 表结构在本地缓存 12 小时 | 再看同一张表不连库 |
| 后台执行器（配置页"数据库驱动"里的"查库快一点"，默认关） | java 不退、连接留着，后面的命令零点几秒 |

中文 SQL 用 UTF-8 文件加 `--sql-file` 传；`--sql` 里带非 ASCII 或者空的 LIKE 模式会先拒绝。查表关键字、按值条件里的中文也传不了时，用 `find --keyword-file`、`peek --eq-file`；条件文件是空的直接停下，不会变成不带条件的查询。要给脚本处理结果用 `query --json`，看 `truncated_cell`、`truncated_rows` 有没有截断。

## 改数据要你确认

- 写操作分两步：第一步只算影响面和风险，什么都不改；你同意了才执行第二步。执行时在同一个事务里再数一遍行数，对不上就不执行。改之前的样子和反向 SQL 留在 `~/.db-crud/journal/`。
- 确认串只含 ASCII；旧的中文确认串可以用 `exec --ack-file` 从文件读入，照样要先确认影响面。一个确认串只能执行一次，两个进程同时拿同一个串，只有一个能执行。
- 提交那一步出了错（连接断了、超时）：库那边可能已经提交了，它会说"结果不明"，不会说"已经回滚"。这时先查一下数据现在的样子再决定，不要直接重跑。
- 改前快照记的是取快照那一刻的旧值。取完快照到真正执行之间，别的人或程序改了同一行，还原脚本可能对不上。重要的数据改之前，先确认那几行没人在改。
- redis 改值（`set`）时，原来有过期时间的照样留着（一条 `SET … KEEPTTL`；redis 6 以前的退回 `PX`），马上过期的 key 不会变成永久的。
- `query` 只许跑查询，夹着写语句会被拦下。
- redis 的 `del` 给了几个 key、按匹配结果批量删，先用提问框问你。

## 自动模式生效时改库

只在走 OpenSpec 流程、自动模式生效的会话里；别的会话照上面的来。还是两步，第二步不等你，但必须留得下备份；留不下的不执行，任务标成"（留给用户）"：

| 语句 | 要满足什么 | 留下什么 |
|---|---|---|
| UPDATE、DELETE | 影响几行数得出来、不超过快照上限；UPDATE 的表有主键；表里没有二进制列 | 改前快照 `before.json`、还原脚本 `undo.sql` |
| INSERT | 表有主键；主键值是语句里写明的，或者驱动能把自增、序列的值带回来 | 表名和每一行的主键；还原按主键逐行删 |
| 建表、建索引、建视图、建序列、加字段、加起了名字的约束 | 不是 `CREATE OR REPLACE` | 对应的 DROP 脚本，不自动执行，要你看过再跑 |
| 别的：没有 WHERE、连表改、`INSERT … SELECT`、撞键就改的插入、改列删列、清空、删表、授权 | | 不执行 |

- redis 的写操作不做：redis 没有改前快照，做了回不去。
- 每一次都列在收工报告"库里改过的"一节：哪张表、几行、新增的主键、留痕目录、还原命令。
- 还原：`db.py --conn <连接> exec --undo <留痕目录>`。
- 在终端里手敲、套在脚本里跑的查库命令，按你不在场算（要等你确认）。

## 数据库驱动

达梦、神通、金仓、Oracle 的驱动是厂商的，只限内部使用，不随安装包带。在配置页"数据库驱动"管：

| 卡片 | 干什么 |
|---|---|
| 现在用的驱动 | 每种数据库可以登记多个版本：选第二个 jar 保留旧版本，可以设默认、去掉单个版本；"不用了"去掉整个数据库的登记。认驱动看 jar 里的类，不看文件名 |
| 自动搜索（"刷新"旁边） | 按"本机环境"里配的 Maven、`~/.m2` 的顺序在 Maven 仓库里找，每种数据库用最新的 |
| 查库快一点 | 后台执行器的开关、多久没人用就退出（默认 5 分钟） |
| 用得怎么样 | 哪条命令跑了多少次、多慢、哪种错多 |

- 多数时候不用点：后台自动探索发现项目要的数据库或声明的版本还没登记，会去 Maven 仓库找一遍，不改原来的默认。
- 查询时优先用明确指定的 jar、项目自己带的 jar，再按所属子项目的 pom（和本地父 pom）声明的版本选；版本不明确就提示你指定 `driver_jar`，缺了项目要的版本不拿别的版本顶替。外部 BOM、复杂 profile、没解析出来的属性不猜。没声明版本才用默认。
- 驱动放在 `~/.claude/vibe-kit/drivers/`，登记在 `drivers.json`，卸载套件不删。命令行：`node "%USERPROFILE%\.claude\vibe-kit\tools\drivers.js" list`。

## 用量和报错

每跑一条命令在本机记一行：命令类别、多少毫秒、起了几次 java、出错的类别。不记 SQL、数据、表名、key、地址、口令。工具自己出的毛病（脚本崩了、执行器没输出、找不到驱动或 java）脱敏后记成问题反馈。同一种工具、同一种数据库、同一种错每天汇总成一条"工具报错"上报，第二天又出现就次数加一。被工具自己拦下的（写操作没确认）不算错。
