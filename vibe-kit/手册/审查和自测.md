# 审查和自测

什么时候审、审几轮、人工和自动有什么不同、什么算自测、起服务和看页面怎么做。回到[用户手册](../README.md)。

## 审查点

| 阶段 | 审查点 | 什么时候审 |
|---|---|---|
| 需求 | proposal、specs、design、tasks 各一个点 | 每写完一份审一次，审修完再写下一份；不要先写完四份再一起审 |
| 实施 | 每整组任务（1.x、2.x）一个点 | 一整组都勾上后审，不必等全部做完 |

每个点的轮数各自计，上限在配置页"需求自动模式""Apply 自动模式"里分别设，默认 3 轮，可设 1—20。一次审查材料分成几批送也只算一轮；启动后取消或中断的也占这一轮。内容改过之后，只有受影响的点的旧结论失效。

## 人工和自动

**自动模式生效时**：自动审查、核验意见、修改、复验，这一点没有问题就结束。到了上限还有问题，停止这一点的自动循环，把问题交代给你，不算通过。你主动要求再审，不受上限限制。

**人工模式**（对应阶段的自动开关关着，或者不走 OpenSpec）：

- 审查、自测、复验之前都先用提问框问你；你已经明确要求的（"审一下""跑一下测试""把服务起起来"）直接做。
- 每个要求最多问一次。你说不用之后，同一个要求里后面的小改动不再问；你提了新要求、又改了东西，才再问。
- 改了代码还没跑过快检的，同一个提问里也问你要不要跑快检，不强制，说不用就接着做。
- 审完先把问题全部列出来，再逐条问你"改（按推荐）／不改／自行输入"。改完的复验也先问。
- 你选择不审、不测，它就接着做：不记"未审查""未测试"、不记待办、不反复催，也不记成通过。
- 打勾不检查验法；归档不要求先审查，归档前的提示如实说审过没有。

## 快检和自测

人工模式下，快检直接跑，自测先问你。

| 类别 | 例子 |
|---|---|
| 快检 | `mvn compile`、`test-compile`、`validate`；带 `-DskipTests` 或 `-Dmaven.test.skip=true` 的 `mvn package`、`install`；`gradle compileJava`、`classes`、`assemble`、`build -x test`；`javac`；`tsc`、`vue-tsc`；`eslint`；`npm run build`、`lint`、`typecheck`；`node --check`；`python -m py_compile`；IDEA 的 `build_project`、`get_file_problems`、`lint_files` |
| 自测 | `pytest`、`jest`、`vitest`、`playwright test`；`npm test`、`npm run test:*`；`mvn test`、`verify`，不带跳过测试参数的 `package`、`install`；`gradle test`、`check`，不带 `-x test` 的 `build`；名字带 test、spec、scenario、probe 的脚本；`devserver.js start` 起服务；`/ttls-see-page` 看页面；IDEA 的 `execute_run_configuration` |

Apply 自动生效时，按配置页的两个开关：

- **自动自测**（默认开）：按需求阶段准备的验收用例自测。验不了的说明"没验证"和原因。项目说明里写了"快检：不适用"的不查。
- **自动验证页面**（默认开）：改了 `.vue`、`.html`、`.css` 这类文件却没跑过页面场景，让它用 `/ttls-see-page` 看一遍；改动不影响显示的说明原因。关掉之后约定改成"我让你看时再看"，任务的验法写"人工看页面"。
- 打勾要在改完代码后跑过这一项的验法；验法里写了"本次不做（原因）"的那部分不查。

## 审查怎么跑

配置页"全局：审查与产物"：

| 设置 | 默认 | 说明 |
|---|---|---|
| 审查方式 | 限时独立模型审查 | 脚本挑有限的材料，经路由的审查角色（sonnet）单独请求，不给工具。自动逐点审查固定用这个；"原审查代理"只在人工整套审查时可选，提案、代码各审一次 |
| 每次审查的时间预算 | 300 秒 | 一个点的一轮最多用这么多时间，材料分批共用 |
| 每轮最多审文件数 | 20 | 超出的列为未覆盖 |

- 首批失败的继续送后面能送的批次；总预算用完就停。进度分别写尝试了几批、收到几批回复、完成几批、覆盖了哪些文件。失败、超时、取消、只覆盖一部分的，都不算完整审查。
- 送审的材料：这个点的产物、design 的背景和现状全文、当前引用的文件和变更目录里的 `assets/`、`references/`。确实要一起审的源码文件，在文档里写"审查材料：src/文件名"。单个文件超过 4MB 的列为未覆盖。
- 审查报告、意见处理、预算和故障记录只留在项目的 `.vibe/reviews/`，不写进团队的需求文档和修订记录。
- 你明确决定跳过某个点的审查：它运行 `review.js waive --change <变更> --mode proposal|code --project <项目> --reason <原因>`。代码这一侧会在审查任务上标"用户决定跳过审查"，不记成审查通过；之后代码或需求改了，这条记录失效。你明确接受某条问题不改的，意见处理里记成"接受"，保留问题和理由。
- 用兼容代理审完却没记上：`review.js diagnose` 看原因，`review.js sync --project <项目> --transcript <当前会话记录>` 只补登记能核对的完整结果。默认的独立审查用 `review.js status` 看。

## 起服务：不重复起、不换端口（默认开）

以前的毛病：它忘了之前起过，端口被占就换一个端口又起一个，测的不是它改的那一份，机器上还挂着一堆旧进程。现在起服务一律经过 `devserver.js`：

```
node "%USERPROFILE%\.claude\vibe-kit\tools\devserver.js" start --name backend --port auto --avoid 8080 -- mvn spring-boot:run
node "%USERPROFILE%\.claude\vibe-kit\tools\devserver.js" status
node "%USERPROFILE%\.claude\vibe-kit\tools\devserver.js" stop --all
```

- **端口自己挑**（`--port auto`）：在 30000—39999 里挑空着的，离 `--avoid` 给的端口至少 1000，你自己在 IDE 里按配置的端口起同一个服务不会撞上。同一个服务每次挑到同一个端口。挑到的端口填进命令里的 `{port}`，也设进环境变量 `PORT`、`SERVER_PORT`（Spring Boot、Vue CLI、Next、CRA 认得；Vite、webpack-dev-server 要写 `npm run dev -- --port {port}`）。前端代理写死了后端端口的，用 `--port <端口>` 指定。
- **start 的意思是"确保在跑，而且跑的是现在的代码"**：在跑、代码没改过（或者加了 `--hot` 会热更新）就直接用；改过代码就在同一个端口重启；端口通了才返回，起不来把日志最后几十行打出来。最后一行就是结果："起来了：名字，端口，用了几秒"或者"没起来：……"。
- 起得慢的（大型 Spring Boot）：进程在、端口还没通算"还在启动"，再 `start` 会接着等，不会结束重起。
- 端口被占着又没有记录：命令行里有这个项目目录的（以前起了忘关），停掉重起；别的程序，说清是谁、不动它、也不换端口。停的时候连子进程一起停，模型路由无论如何不停。
- 在子目录里起（壳子里的子项目、工程里的前端目录）：加 `--cwd <子目录>`，不要先 `cd` 进去。
- 服务在后台跑、不弹窗口，输出在项目的 `.vibe/run/<名字>.log`。Tomcat 用 `catalina.bat run`，`startup.bat` 会自己另开窗口。
- 直接敲 `mvn spring-boot:run`、`gradle bootRun`、`npm run dev`、`vite`、`catalina run`、`java -jar target/xxx.jar` 会被拦下，让它改用 `devserver.js`。不想要这道检查，关配置页"起服务走 devserver"。
- 会话开始时，以前起了没关的服务会告诉它。

## 看页面和接口场景

`/ttls-see-page` 由模型写场景文件、脚本执行，用无头浏览器，不开窗口。还原原型时，原型和页面各导出一份每个元素的位置、尺寸、颜色，按数字比。

后端改动用接口场景验，不再只看能不能编译：

```json
{ "name": "下单并查回", "steps": [
  { "request": "POST /api/orders", "json": { "customer": "张三" } },
  { "expectStatus": 201 },
  { "readJson": "data.id", "as": "orderId" },
  { "request": "GET /api/orders/{{orderId}}" },
  { "expectJson": "data.status", "equals": "待支付" }
] }
```

- `request` 调接口（`json`、`form`、`params`、`headers`），`expectStatus` 查状态码，`expectJson` 查返回的字段（`equals`、`contains`、`exists`、`gte`、`lte`），`readJson` 读出来给后面用（`{{名字}}`）。断言可以和动作写在同一步里。登录这类"失败也返回 200"的接口要查返回的内容。
- 和页面步骤混着用时，接口请求带着页面的登录状态；页面上点按钮发出的请求用 `waitResponse` 等返回再查。全是接口步骤时不开浏览器。
- 页面步骤还有 `upload`、`onFileChooser`；`click` 加 `"force": true` 能点被盖住的控件。一步里写了两个动作只做第一个，结果的 `warnings` 里提醒。
- 场景做不了的操作用 `page/probe-run.js` 跑探针，写法见技能说明。
- 跑过的接口场景、页面场景算"验证过"。失败、超时、没跑完的，以及改代码之前的旧结果不算。

## 经验规则（默认开）

审查发现的问题改掉就完了，下一个变更里模型照样犯。经验规则把反复出现的问题沉淀成读到那类文件时才带上的规则（用的是 Claude Code 自带的 `.claude/rules/`）：

```
审查报的问题，之后那个文件确实改了
  └ 收工时收下来，先进候选（只在本机，不进上下文）
      └ 同一条在另一个变更里又出现：升成项目规则，跟着仓库提交
          └ 以后读到这类文件时自动带上
```

- **谁来记**：用兼容的审查代理时，收工时脚本从它的回复里取出每条问题，之后那个文件确实改过才收（开关"审查报的问题自动收"）。默认的独立审查请求目前不走这条路，靠 Claude 自己用 `tools/lesson.js` 记，和脚本收的走同一套合并和上限。
- **去哪**：只出现一次的是候选；在两个不同变更里出现过，写进出问题的文件所在仓库的 `.claude/rules/ttls-lessons-<类型>.md`，要提交，同事的 Claude 也能用上；在两个项目里都成了规则、又不带项目特有名字的，列在配置页"经验规则"等你点头，才写进 `~/.claude/rules/`（只在这台电脑）。同一类问题在 3 个以上变更里出现，多出一条"这一类要对照检查"的规则。
- **不越攒越多**：按文件类型分组（Java、SQL 和 Mapper、前端、提案文档、其他），读到那类文件才加载，一个会话一次；每条最多 120 字，每组最多 10 条，满了挤掉次数最少、最久没再出现的；规则里提到的类、文件、表找不到了自动退掉。生效之后同样的问题又被审出来两次，配置页标"没管住"。这些数在配置页改。
- **你说了算**：规则文件你可以直接改字、删行、加自己的规则；你删掉的不再加回来，改过字的不再动。Claude 不能直接改，只能通过 `lesson.js`。规则文件改了没提交，收工时催它单独提交一次（`docs: 更新经验规则`）；你选了"我说了才提交"就不催。
- 三档：开（默认）、只收集（记候选、不生成规则）、关。
- 边界：只有读文件才触发规则；会话压缩之后，要再读到同类文件才重新带上；规则送到了不等于模型照做。
