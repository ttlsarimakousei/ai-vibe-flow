# 提交和推送

提交时查什么、什么时候提交、push 怎么确认。回到[用户手册](../README.md)。

开工前不再自动拉代码（2026-10-17 起）：要拉最新代码你自己拉。

## 提交时查什么（开关"提交检查"，默认开）

- 提交信息要写成 `类型: 内容`，例 `feat: 新增修改页面`。
- `git add -A`、`git add .`、`git add -u`、`git commit -a` 一律拦：会把你工作区里原来就有的改动一起带进去。壳子里 add 子项目目录也拦（会提交成 gitlink）。新建的仓库第一次入仓不拦。
- 它这个会话新建的文件还没 `git add` 就提交，点名拦一次：属于这次提交的一起 add，测试用的不提交。用临时 index（`GIT_INDEX_FILE=…`）提交的看那份 index。`for r in a b; do git -C "$r" …` 这类循环按每个取值各查一遍。
- 不查提交内容里像密码的东西（2026-10-17 起）。套件自己的令牌文件（GitLab 令牌、模型的 key）一直不许提交，不受这个开关管。

## 什么时候提交（配置页"提交"卡片里的"提交方式"）

人工和自动模式都用这一个设置，不走 OpenSpec 的改动也按它。到了提交时机：

| 提交方式 | 做什么 |
|---|---|
| 关（默认） | 什么都不做，不问也不提交；你说"提交"它才提交。同一句"提交"在这一轮里按规矩分几笔提交都算，不再问（2026-10-28 起）；中间你答了别的提问框（比如"要不要审查"），这句照旧有效，除非你在答案里说了"先别提交"（2026-10-30 起，推送、归档也一样） |
| 询问 | 交代改了什么、怎么验的，用提问框问你"提交 / 还要改"，你选了提交才提交。自动模式下你不在，先不提交，把要提交的列进全自动报告，等你回来说 |
| 自动 | 直接提交，一件事一笔 |

提交时机参照 Claude 桌面版，"做完一件完整的事"才算，做到一半不算：

| 场合 | 什么时候算做完一件事 |
|---|---|
| 需求文档 | proposal、specs、design、tasks 四份都写完、定稿（自动模式时四份都审过）。提交不等于开工许可 |
| OpenSpec 实施 | 上次提交之后又勾完了一项任务；审查修复全部收尾（审出了问题还没处理完的不提交，不逐轮提交；子代理连续 3 次没交结论、这一点没审成的不挡）；任务都勾完以后，改完你报的一处问题（2026-10-31 起） |
| 不走 OpenSpec 的改动（修 bug、改配置、改文案） | 改完、跑过快检 |
| 经验规则文件 | 单独一笔 `docs: 更新经验规则`，询问、自动都不再问；关：提醒你、问你提不提交 |

- 只 add 它这一轮改的和新建的文件，工作区里原来就有的改动先核对归属，不整文件混进去。
- 你选了"先不提交"，同一份改动可以照常收工；之后的新改动再按上面的规矩问。
- 修的是某个 OpenSpec 变更做出来的东西，提交信息末尾加"（源自 <变更名> <任务号>）"。

## 只提交这个会话改过的文件（commit.js）

`node "%USERPROFILE%\.claude\vibe-kit\tools\commit.js" -m "类型: 内容"`（2026-11-01 起）：只提交这个会话用 Edit、Write 改成功的文件，Claude 提交时可以用它代替 `git add` 加 `git commit`。

- 用一份临时 index 提交：你暂存区里别的文件、工作区里别人的改动都不动；git 自己的钩子（pre-commit 这些）照常跑。提交完，暂存区里这几个文件同步成刚提交的样子。
- 不提交的，列出来说为什么：别的仓库的（壳子里的子项目，`--dir <子项目>` 各提交一次）、套件自己的文件（含令牌文件）、`.vibe` 里的、过程文件（备份、日志）、被 `.gitignore` 忽略的、和上次提交一样的。用 Bash 改的（sed、脚本生成的）认不出来，那些照旧 `git add`。
- `--only a.java,b.vue` 只提交其中几个，这个会话新建的别的文件会点名提醒一次；`list` 只列出会提交哪些，不提交。
- 和 `git commit` 一样过上面的提交检查（提交信息格式、提交方式、新文件、过程文件）。没经过检查的不提交：钩子没跑（路由不在、钩子出错）时它不提交，让 Claude 改用 git。
- 一个文件里既有你原来没提交的改动、又有这个会话的改动，整个文件一起提交：开工前就改着的文件先核对。

## 检查点和一键回退（checkpoint.js）

改坏了一条命令回去（2026-11-01 起）。`node "%USERPROFILE%\.claude\vibe-kit\tools\checkpoint.js"` 后面跟：

| 命令 | 做什么 |
|---|---|
| `save --why "改订单导出"` | 把工作区存一份，挂在本机的 git 引用 `refs/vibe/ckpt/<会话>/<序号>` 上。不动暂存区、分支、工作区，不会推到远端 |
| `list` | 这个会话存过的 |
| `restore <序号>` | 只还原这个会话用 Edit、Write 改过的文件，别的文件不碰；检查点之后才建的删掉。回退前自动再存一个，回退也能撤销（restore 那个新序号） |
| `restore <序号> --only a.java` | 只还原其中几个 |

- 拿不准那时样子的不动、列出来：被 `.gitignore` 忽略、存检查点时这个会话还没改过的；超过 20 MB 没存的。用 Bash 改的文件（sed、脚本生成的）认不出来，回退不管。
- 壳子里改了几个子项目：每个仓库各存一份，序号相同。每个会话留最近 30 个，别的会话 14 天前的自动清掉。
- 自动模式开工、开新一组任务之前，钩子提醒 Claude 先存一个；人工模式不提醒，要存就跟它说。

## push

push 要你当场明确说。权限规则按前缀匹配挡不住 `git -C 子项目 push`，所以套件自己认：写在 if、try、循环、子 shell、函数、脚本文件里的 push 也认得出。否定、询问、后台通知、旧的确认都不算授权。自动模式也一样。

你说"推送""push"，它就直接 `git push`，几笔提交都一样，不给推送计划、不再问；壳子里几个子项目都有没推的，各推一次。

套件的合并推送工具 2026-10-28 起去掉了：没有合并预览、推送计划、`merge-push.js`。你自己说"合并推送""合并成1条推送"的，Claude 照你说的用 git 把还没推的提交合并了再推（`reset --soft`、`rebase` 这类），不出计划、不再问，合并时重新提交也不用你再说"提交"；只动没推上去的提交。以前看过合并计划、改主意直接推被拦住的（#233），不会再出现。

强推（`--force`）、删远端分支、推到不是当前分支跟踪的那个远端分支，照旧弹确认框问你。

- 内网发布安装包（`publish.js`）和 push 一样要你点头，push 的授权不能拿来发布。
