## 1. 诊断编码（一分钟，最要紧）

项目体检里每个 Java 项目的编译都报 `unmappable character for encoding UTF-8`，而且全在第 1 行，连编码普查判定为纯 UTF-8 的项目也报。我在本机复现过：只有 GBK 文件才会报这个错。可两次扫描都说这几个文件是合法的 UTF-8。两边不可能同时对。

双击 **诊断编码（双击我）.bat**，把这个文件拖进去：

```
D:\workspace\code\SJYT\AI-OA\sjytoa\src\com\skytech\api\JACTInterface\JACTUtil.java
```

它会让 Java 自己的解码器指出第一个出错的字节和所在行，再用 javac 单独编译这个文件，最后现写一个带中文的 UTF-8 文件做对照。桌面会多一份 `编码诊断-<时间>.md`。有空的话再对这个文件跑一次：

```
D:\workspace\code\SJYT\CZXT\SmartTreasuryPlatform\src\main\java\com\skytech\finance\settlement\model\dto\SettlementTaskBatchReturnDTO.java
```

## 2. 统一编码：可以真改了

清单里那 16 个 .java 确实是 GBK（两种方法都判得一致），改它们没有风险。在 coop-probe 目录开命令行：

```
powershell -ExecutionPolicy Bypass -File tools\encoding-fix.ps1 -Dir "D:\workspace\code\SJYT\AI-OA\sjytoa" -Apply
```

转前整份备份，转后逐字校验。另外 8 个非 .java 的先不动。转完在 IDEA 里把工程编码设成 UTF-8（Settings → Editor → File Encodings）。

## 3. 项目体检：换新版再跑一次

上一版有两个问题这版修了：

- **套在里面的项目认不出来**：`AI-OA` 底下有 5 个子工程，`CZXT` 底下是 `SmartTreasuryPlatform`，上一版把它们整个当成了一个大项目。这版往下找三层，报告里会按 `CZXT\SmartTreasuryPlatform` 这样的路径列出来
- **原始输出没留**：这版每一步的完整输出都存在结果目录的 `*.log` 里，报告里只放第一行错误

双击「项目体检」，拖 `D:\workspace\code\SJYT` 进去。

`CZXT\SmartTreasuryPlatform` 是 Spring Boot 项目，上一版把整个 `CZXT` 当成了散源码目录、只找到 33 个 jar，那组数不作数。新版会按 Maven + Boot 处理。想顺带量它从启动到能访问要多久，在 coop-probe 目录开命令行跑（会真的把服务起起来、连数据库）：

```
powershell -ExecutionPolicy Bypass -File tools\project-profile.ps1 -Dir "D:\workspace\code\SJYT\CZXT\SmartTreasuryPlatform" -Run
```

跑之前确认 `JAVA_HOME` 指的是这个项目要的 JDK（Boot 2 用 8，Boot 3 要 17）。其他 Spring Boot 项目如果不在 `D:\workspace\code\SJYT` 下，对那个目录再跑一次就行。
