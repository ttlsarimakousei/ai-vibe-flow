# vibe-kit 自我审查报告（2026-09-24）

范围：钩子、公共库、模型路由和配置页、安装器、约定规范技能、工具脚本、README。分四路并行审查，每条都读代码核对，大多数在临时目录里跑代码复现；最关键的几条在内网 Claude Code 2.1.259 上实测。这次没改任何代码。

标注：**实测** = 在 2.1.259 真实程序上跑过；**复现** = 用钩子或路由代码加构造的输入跑出来；**读代码** = 看代码确认，没跑。

---

## 一、最严重的：破坏套件的核心承诺（建议先修）

1. **`git -C <子项目> push` 不经确认直接推送**（实测）
   push 确认只靠权限规则 `Bash(git push:*)`，它按命令前缀匹配。实测：`git push`、`cd x && git push`、`git status && git push` 都要确认；`git -C sub push` 直接执行了。套件自己在会话开头和提交规范里教模型用 `git -C <子项目目录>` 操作子项目。
   改：guard-commit 识别到任何写法的 push（`-C`、`--git-dir`、`cd` 之后、`cmd /c` 里）都返回 `permissionDecision: "ask"`。

2. **模型写一行项目设置就能关掉全部钩子**（实测）
   往项目里写 `.claude/settings.local.json`，内容 `{"disableAllHooks": true}`，guard-kit 放行。实测下一句话起，所有钩子都不再触发，编码保护、提交检查、收工检查全部失效。
   改：写任何 `settings*.json` 时内容里有 `disableAllHooks` 就拦，命令里出现也拦。

3. **提案"审过"几乎记不上，apply 第一次打勾永远被拦**（复现，两路审查独立发现）
   只有"同一轮改过产物 + 调了审查 + 不是被拦后的续跑"三条同时满足才记成已审。按钩子的催法，审查恰好发生在被拦后的续跑里，所以记不上；之后再审，这一轮没改产物，照样记不上。每条消息还会一直提醒"提案还没审过"，全自动模式下流程停住。
   位置：verify-gate.js:71-87、429；guard-spec.js:55-58。
   改：只要这一轮出现审提案的调用就记成已审，续跑里也记，按提示里点名的变更记。

4. **"代码审过"记的其实是"催过"**（复现）
   钩子一催就写 reviewed.json，模型没审也能归档；审查调用失败、审提案的那次也算。反过来，关掉"自动交叉审查"后手动审完也记不上，归档永远被拦。
   位置：verify-gate.js:388-399；guard-commit.js:70-71。
   改：催的时候只记"催过"；看到一次有结果、不是报错、带"结论：问题 N 条"、不是审提案的代码审查，才记"审过"，不看开关。

5. **开了多轮审查，收工钩子在同一轮里无限拦**（复现，只在打开"多轮审查"时出现，默认关）
   每次收工都把这一轮里所有审查调用重新计一遍轮数，轮数用完后重置又从头来。实测连续收工 8 次拦 8 次，全自动模式会整夜空转；老老实实复审的，审完第 2 轮就被记成 3 轮。
   位置：verify-gate.js:266-279。
   改：记下已经计过的审查调用，只累加新出现的；没有新调用时不重置、不重复催。

6. **三天后审查记录被清掉**（复现）
   清理过期状态时只保留了 reviewed.json、gateway.json、hooks.log。reviewed-proposal.json、review-rounds.json、plan-unlisted.json 三天没写就删。周五审完提案、周二开工，第一次打勾被拦；多轮审查没审完也能归档。
   位置：session.js:206-208。
   改：只清按会话 id 命名的文件，全局记录不按时间删。

7. **配置页自动保存会把刚保存的开关改回去**（复现，浏览器实测）
   改交接线、上下文上限、"到线后问不问"时，其余字段取的是页面打开时的旧值。实测：勾上全自动 → 点保存 → 改交接线离开输入框 → 文件里全自动变回关，页面上还勾着。挂机前这么操作，全自动实际没开。
   位置：ui.html:539、573。
   改：保存成功后用返回的配置刷新页面缓存；或者接口只合并传进来的字段。

8. **提交信息用 heredoc 写时，同一条命令里的 `git add -A` 不检查**（复现）
   2.1.259 自带的提交说明要求用 heredoc / here-string 传提交信息，模型常把 add 和 commit 串成一条。在壳子里跑 `git add -A && git commit -m "$(cat <<'EOF' …)"` 或 `git add .; git commit -m @'…'@` 都放行，子项目被提交成 gitlink，踩公司红线。
   位置：guard-commit.js:186-195。
   改：判完多行提交信息不退出，接着检查 add。

## 二、其他缺陷

### 打勾和提案门槛：会误拦合法操作，或者漏拦

- 失败的打勾 Edit（比如"找不到要替换的文字"）被当成"上次打勾"，重试时被拦"没跑过验法"。guard-spec.js:63-67。（复现）
- 打勾时顺手在行尾加了"（已完成）"，打勾检查和提案审查门槛整个绕过。session.js:469-475。（复现）
- CRLF 的 tasks.md 上跨行编辑，guard-spec 的所有检查都跳过；Claude Code 自己会先把换行归一化再改，所以编辑是成功的。guard-spec.js:95-98。（复现）
- 含糊词按子串匹配：误拦"保存之后再次打开""状态变为'待确认'""待补充资料的客户"；"按钮"又会被当成"按…做"的决策项，把真正的含糊话放过。session.js:252-263。（复现）
- 只写文件名时找文件最多往下 7 层，多模块 Maven 项目的 Controller 常在 8 层以下，被判"不存在"；壳子里前面的子项目文件多时，后面的也找不到。session.js:300-318。（复现）
- 路径提取认不了中文文件名、`@/views/…`、`/src/…`，被判"没写改哪个文件"或"不存在"。session.js:283-298。（复现）
- 验法按子串匹配：`py` 能匹配到 Copy-Item，`ant` 能匹配到 Constant.java；失败的命令、没装的命令也算跑过。session.js:485-496。（复现）
- "设计依据"和"能力没有规格"两项检查在续跑里反复拦；"读过"不认带 path 的 Grep、不在行首的 Get-Content。verify-gate.js:57-59、424、428。（复现）
- 交接后的新会话写提案，被当成"探索和提案在同一轮"拦下，要你再确认一次。guard-spec.js:38-44。（复现）
- 审查模式靠提示里有没有"proposal"判断：代码审查的提示里写了"proposal 和规格"就被算成审提案；没点名变更的审查，会算到最近动过的变更头上。verify-gate.js:239、243。（复现）
- 全自动模式判断"卡住"的词太宽（账号、密码、等你、请你、GBK），最后一句是"等你回来定的事：暂无"就不再催下一项。verify-gate.js:294。（复现）
- 续跑里改的代码不再查验证：审出问题、改完没跑快检就收工，放行。这是"每轮只拦一次"的副作用。verify-gate.js:377-387。（复现）
- 同名变更归档后重建，会继承"已审"。（读代码）
- 状态文件读改写没锁、不是原子写，两个会话同时收工可能丢记录（压测 600 个键只剩 69 个，真实中同时写的概率低）；reviewed.json 的键没做大小写归一化，换个大小写打开同一个项目会被要求再审一次。（复现）

### 交接

- 模型用 Skill 工具调 handover、而不是你敲 /handover 时，会话记录里没有标记。你在老会话里先说一句话，交接记录就被老会话"用掉"了，/clear 后的新会话不再续接。task-anchor.js:93-95。（复现，并读 2.1.259 的过滤逻辑确认）
- 任何一个变更归档都会把交接记录判成过期，包括同事的变更被 git pull 下来。应该只看交接记录里提到的变更。session.js:502-517。（复现）
- 你在提问框选了"再做一会儿"，之后每条消息的提醒仍然说"做完这一小步就 /handover，不要开始新的大任务"。全自动模式下钩子说"写完交接记录继续做"，交接技能第 4 步却说"不要再做别的事"。（复现 + 读代码）
- 压缩之后不再问交接：要涨到上次问的百分比加 10 才问，92% 时选过"再做一会儿"，压缩后等于这个会话不再问。压缩摘要也会被当成一条用户消息，影响"这一轮"的边界。（复现 + 读源码）

### 提交、归档、禁止改套件：命令检查的漏洞

- `git commit -am`、`git add -u` 会把你原来就有的已跟踪改动一起提交，规范和钩子都没管。（复现）
- 壳子里 `git add <子项目目录>`、`git add -Av`、`git add :/`、`git add ./*` 放行；子项目恰好叫 docs 或 templates 时，壳子识别会漏掉它；PowerShell 里 `cd "D:\壳子\"; git add -A` 整条被当成一个 cd，add 没检查。（复现）
- 提交信息 `-m"wip"`、`-mwip`、续行写法、`cmd /c "git commit -m wip"` 不检查。（复现）
- `openspec archive -y <名字>` 把变更名取成了 `-y`，没做完也放行；`cd openspec/changes && mv …` 放行。（复现）
- 改套件：`>~/.claude/...` 紧贴写法、管道给 Remove-Item、`find -delete`、小写 `$home` 放行；反过来 `cat … 2>&1`、`Get-Content … 2>$null` 这种只读命令被误拦。（复现）
- `~/.claude` 是目录联接（C 盘不够挪到 D 盘时常见）时，禁止改套件的保护整体失效。（复现）

### 编码

- 项目里的 .md 是 GBK（记事本存的）时，套件自己的 `.vibe/project.md`、`handover.md` 被拦，/onboard、/handover 写不进中文。guard-encoding.js。（复现）
- 周围没有带中文的同类文件时，提示"可以先转成 UTF-8"。老项目按 GBK 编译时照做会编坏或静默乱码。guard-encoding.js:71、117-121。（复现）

### 上下文

- 百分比不看 Claude Code 报的更小窗口。Claude Code 对不认识的模型名按 20 万算、19 万就报"Prompt is too long"，状态栏这时却显示绿色的 19%，交接提醒也不出。session.js:166-170。（复现）

### 模型路由和配置页

- 你按 Esc 取消一个等了 2 分钟以上的回复，路由把这个模型冷却 5 分钟，会话换到别的模型、缓存全丢，正是网关投诉的情况。router.js:398。（复现）
- 停路由时按端口号取 netstat 第一条就杀，可能杀掉监听 0.0.0.0:15730 的别的程序。service.js:62、94-95。（复现）
- 网页能用 text/plain 的 POST 借路由发请求，带着你的 key；转发路径不看 Origin。浏览器会不会放行是推测。router.js:734-747。（复现路由一侧）
- 配置页把"行为参数"清空再保存，发的是 0，变成最不利于网关的取值：30 秒超时、429 立刻换模型。ui.html:272。（浏览器实测）
- "大请求超时不换模型"只对路由自己的计时器生效，网关先回 504/502 时照样换。router.js:303-305。（复现）
- 并发时会把请求转给刚进冷却的模型；流里报错、没有结尾都被记成成功；Esc 取消的请求不记用量；取消被写成"上游中途断开"。（复现）
- 换过端口后，"断开"恢复不回原来的地址，原来的网关地址丢失。kit-api.js:147-151。（复现）
- 技能下拉框永远是空的（接口没返回名字）；模型"测试"的结果 5 秒就被刷掉；router.out.log 一次运行期间没上限；停路由丢最近 20 秒用量，用量文件不是原子写。（复现）

### 安装器

- 升级时把你从 allow 里删掉的权限（比如 "Bash"）又加回来，等于悄悄放宽权限。install.js:122-129。（复现）
- 技能的附带文件（比如你在 recipes.md 里加的公司配方）升级时不备份就覆盖；卸载时改过的审查代理不备份就删。（复现）
- 你自己的全局 CLAUDE.md 是 GBK 时，块外的中文被写坏，卸载也恢复不了。install.js:227-235。（复现）
- 备份目录只增不减：配置页每保存一次开关就多一份。（复现）
- 双击安装的 .bat 用 `where node` 找 node，PATH 里没有 System32 的机器上直接报"没找到 node"。这台开发机的 PATH 就是这样。（复现）
- 用 `--no-router` 装的，卸载时照样去停端口上的路由。（读代码）

### 约定、规范、技能、文档互相打架

- 审几次：约定写"每个变更只审一次"，规范写"提案一次、代码一次"，多轮审查又是另一套。弱模型可能审过提案就跳过代码审查。
- "提交节奏"一节不跟自动提交开关走：选了"我说了才提交"，同一份约定里还写着"提案写好提交一次"。
- 关掉"看页面"只改了约定里的一句，规范里另一行还让用 /see-page；任务验法写了页面场景的，没跑照样不让打勾。
- openspec 在哪：规范说"当前目录没有就 openspec init"，钩子会往上认仓库根目录的，两边可能各建一套。
- 行数上限：规范写 200，钩子和 README 按 250。
- README 过时：写"约 3000 字符、每个会话一次"，实测全局约定块默认 6107 字符、全开 7401 字符，每次请求都带；还有几处功能描述过时。
- 看页面执行器：忽略 console 错误的配置按正则解释，`[Vue warn]` 没转义成了字符类，几乎所有错误都被忽略，"无 console 错误"检查假通过。scenario-run.js:39-42。（复现）
- 技能清点工具：只要含"用于"就算写了使用时机；YAML 多行写法只读第一行；审查代理被当成命令算进字数。（复现）

## 三、优化点

1. **钩子延迟：每次改文件、跑命令都多等 0.7～0.9 秒**（实测）
   开销主要是起 shell 和 node，本机起一个空 node 约 0.27 秒，钩子逻辑本身只占 15～125 毫秒。同一事件的几个钩子是并行跑的，所以只合并进程省不了多少时间。
   内网 2.1.259 支持 HTTP 钩子，实测：能正常拦截，一次工具调用只要 0.1～0.2 秒；服务没开时 Claude Code 照常执行、不拦。
   建议：高频钩子（改文件、跑命令、收工）改由已经常驻的路由进程通过 HTTP 提供；会话开始和用户开口两个低频钩子保留命令方式，顺便保证路由活着。不用路由的机器保留现在的方式。改动大，先做个小实验。

| 情况 | 一次 Read 从发出到结果回到模型 |
|---|---|
| 没有钩子 | 0.14 秒 |
| 3 个空的命令钩子 | 0.86 秒 |
| 1 个 HTTP 钩子 | 0.09～0.16 秒 |

2. **全局约定块瘦身**（实测）
   默认 6107 字符、全开 7401 字符，每次请求都带。钩子拦下时本来就会把具体要求原样给出，"提案的门槛""链路要对齐""plan.md""先探索再提案""提交节奏"几节压成一两句，每次请求约少 1800 字符，约三成。

3. **大项目里的钩子开销**（复现）
   收工时每个改过的仓库跑一次 git status，约 0.5 秒；task-anchor 每条消息给所有变更的产物算哈希，40 个子项目时 2.3 秒；状态栏每次刷新扫所有 tasks.md；guard-commit 碰到 heredoc 写大文件时 1.9 秒；编码普查对纯英文文件不设上限。改成按修改时间缓存、设上限；git status 加 `--no-optional-locks`，免得和 IDE 抢锁。

4. **技能说明把触发条件放第一句**
   四个技能都是先说"它是什么"，技能列表超字数时从后面截，最先被截掉的正是触发条件；审查代理的说明过不了套件自己的清点工具。

5. **审查模式用固定首行**
   审查提示第一行固定写"模式：提案 / 代码 / 复审提案 / 复审代码"，技能、代理、钩子都只认这一行，不靠关键词猜。

6. **拦截提示只说相关的**
   打勾因为"没跑验法""提案没审"被拦时，也附上了"任务的写法""不许写以后再说"，弱模型容易去改 tasks.md 的格式。

7. **约定里把收工检查说全**
   现在只说"漏了验证，不适用就说明原因"。收工检查还管提交、修订记录、提案审查、plan.md，弱模型对这些也回一句"不适用"就收工了。

8. **路由对网关更友好、更稳**
   429 超出等待预算、529 都立刻换模型并冷却 300 秒，应按 retry-after 冷却；整段返回的网关上长输出 300 秒会被判卡住；配置页选目录、自动探测是同步文件操作，碰到断开的网络盘会卡住所有转发；停路由改用 pid 文件并核对命令行；上游证书默认不校验，加开关；保存配置加版本校验，别覆盖手改的内容。

## 四、查过没问题的

- 钩子命令在带空格和中文的路径下，经 cmd、Git Bash、PowerShell 都能正常执行；重复安装不重复登记；卸载能收回全部钩子、权限、环境变量、状态栏。
- 路由请求体逐字节透传，请求头只换 key；每条路径最终都会回复客户端，没有挂死的；配置页接口只允许本机且要带自定义头；页面上显示的文字都做了转义；.vbs 自启的路径转义正确；各种列表和日志都有上限（out.log 除外）。
- 会话开始时拉起路由不拖慢启动；读会话记录不是瓶颈（8 MB 约 88 毫秒）；编码判断对 BOM、UTF-16、纯英文文件不误拦；Windows 路径的大小写、正反斜杠、Git Bash 写法都认对了（目录联接除外）。

## 五、建议的修复顺序

1. **安全和红线**：push 确认绕过、disableAllHooks、heredoc 下的 git add -A、commit -am / add -u、壳子里 add 子项目目录。
2. **流程卡死**：提案审过记不上、代码审过记错、多轮审查死循环、审查记录被清、配置页开关被改回。
