# 修改指导：发版提速

2026-10-17 由 Claude 写。第 1 项改的是主人 10-14 定的"发版全量测试"，**要主人确认后才做**；第 2—4 项不改规矩，可以直接做。

## 现在的耗时

10-16 这一版在这台电脑上跑完整回归约 2 小时，大头：

| 部分 | 用时 |
|---|---|
| 两份新旧钩子对比（diff-hooks） | 各 9—12 分钟，共约 22 分钟 |
| 15 套端到端（三个版本的 Claude Code，各 5 套） | 约 15—20 分钟 |
| 查库（H2） | 8—12 分钟 |
| 自动更新和发布 | 3—5 分钟 |
| 其余 50 多套 | 合计约 30 分钟 |

## 1. 没动过的独立模块不测（要主人确认）

主人 10-17 原话："完全没动过的独立模块就不要测试里比如数据库 redis之类的"。

**怎么算"没动过"**：由脚本判断，不靠模型判断。

1. 先量出每套测试实际依赖哪些文件，不手写清单：
   - 写一个追踪脚本 `dev/lib/trace-deps.js`，用 `NODE_OPTIONS=--require` 挂进测试进程和它起的子进程，记下加载过的套件文件：`require` 到的 .js，以及 `spawn` / `execFile` 跑到的 Python、Java、PowerShell 脚本。
   - 假用户目录里的路径（`.claude/vibe-kit/...`）按相对位置换回仓库路径。
   - 结果写成 `dev/deps.json`：每套测试对应一组仓库文件，外加测试文件自己和 `dev/lib/` 里它用到的文件。测试或套件结构变了就重新生成，发版规程里加一步"依赖表是否最新"。
2. `run-all.js` 加 `--since <标签>`：用 `git diff --name-only <标签>..HEAD` 算出改过的文件。只有标成"独立模块"的套件可以跳过：它的依赖文件、它自己的测试文件都没改过才跳。跳过的套件在结果里单独列出来，并写明依据。
3. 哪些算独立模块，第一版建议：

   | 模块 | 套件 |
   |---|---|
   | 查库 | 查库（H2）、1012 数据库诊断、配置页的数据库驱动 |
   | redis | 查 redis |
   | 看页面 | 看页面 0929、1012 页面探针 |
   | 起服务 | 起服务 0929、服务实际地址 |
   | IDEA 接入 | IDEA MCP 自动接入、IDEA MCP 保护入口 |
   | 自动更新和上报 | 自动更新和发布、问题上报和导出、配置页的更新和上报、使用情况匿名标识、三个版本的更新端到端 |

   钩子、共用库（session、flow-policy、guard-commit 等）、新旧钩子对比、工作流和许可这些核心套件，永远照跑。
4. 预计省下：没动这些模块的版本，能少 15—25 分钟。

**要先确认的事**：依赖量出来之后，如果某个模块几乎每版都会被共用文件带上（比如依赖了 session.js），这条规则就省不了时间。到时把量到的依赖表给主人看，再定要不要把这类依赖排除在外。

## 2. 两份新旧钩子对比同时跑（不改规矩）

两份对比各用自己的临时目录，不占端口，互不影响，可以同时跑，能省 10 分钟左右。实现：`run-all.js` 把 diff-hooks 放进一个最多同时跑 2 个的小队列，其余套件仍然一个一个跑。

注意 10-16 遇到过：机器忙时，审查请求复用空闲连接会报 ECONNRESET（已修，`f5d1078`）。同时跑的只有 diff-hooks 这两份；端到端和查库保持一个一个跑。改完连跑两次完整回归，结果要一致。

## 3. 失败时直接给完整原因（不改规矩）

现在 `run-all.js` 每套失败只打印以 6 个空格开头的行，最多 30 行，常常只看到原因的第一行（10-16 有一项就因此差点看漏）。改成：

- 每套的完整输出都存到 `.vibe/tmp/<这次回归>/<套件>.log`；
- 失败时打印每个 `[X]` 项和紧跟的说明，每项最多 20 行，后面附日志路径。

## 4. 等回归时少打扰（Claude 自己的做法，不改代码）

等回归时只关心两件事：有失败、全部跑完。不要每跑完一套就通知一次：每次通知都要重读整段对话，白花 token。

## 验收

- 第 2、3 项：连跑两次完整回归，结果一致，总时间少 10 分钟左右，失败输出能看到完整原因。
- 第 1 项（主人确认后）：用"只改了 README"的提交试跑，独立模块全部跳过、核心套件照跑；再用"改了 db.py"的提交试跑，查库照跑。两次的跳过清单都打印出来。
