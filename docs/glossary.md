# 术语

套件的代码、提示语、文档里反复出现的词。给用户看的文字也用这些说法。

| 词 | 意思 |
|---|---|
| 套件 | `vibe-kit` 装进 `~/.claude` 的那一套：约定、规范、技能、审查代理、钩子、状态栏、工具 |
| 路由 | 本机常驻的模型路由（默认 `127.0.0.1:15730`），Claude Code 连它，它按角色把请求分给内网的各个模型 |
| 配置页 | 路由提供的本机网页 `http://127.0.0.1:15730/ui`：模型、角色、开关、本机环境、驱动、经验规则、更新和上报 |
| 角色 | 路由按 Claude Code 发来的模型名分流：opus（主会话）、sonnet（审查代理）、haiku（后台小任务） |
| 壳子 | 用户的一种项目结构：外面一层放 openspec、文档、`.claude`，不放代码；代码在下面的各个子目录里，每个子目录是独立的 git 仓库 |
| 子项目 | 壳子下面那些各自独立的 git 仓库 |
| 全局约定 | 装进 `~/.claude/CLAUDE.md` 两行标记之间的那一段，每个请求都带着 |
| 规范 | `vibe-kit/claude/rules/` 里的文件，启用的并进全局约定 |
| 项目说明 | 子项目的 `.vibe/project.md`（后台自动探索写的，本机用、不提交）和项目 `CLAUDE.md` 里"项目说明（团队共享）"那一节（跟着仓库提交） |
| `.vibe/` | 子项目里套件用的目录：项目说明、交接记录、过程文件（`tmp/`、`out/`）、全自动报告（`reports/`）、等定位置的产出（`pending/`）。自动加进 `.gitignore` |
| 过程文件 | 备份、临时脚本、草稿、日志、测试数据。放 `.vibe/tmp/<事由>/`，事由是变更名的留到归档 |
| 产出 | 代码之外要交给人的文件：DDL 脚本、说明文档、分析报告、表格。放哪要用户定过（项目说明里的"产出位置"） |
| 变更 | OpenSpec 的一个 change，`openspec/changes/<名字>/` 下面的 proposal、design、specs、tasks |
| 提案的门槛 | 写提案、任务、打勾、归档时的检查（`guard-spec`、归档门槛）。开关 `specGate` |
| 验法 | tasks.md 里每项任务写的"验：…"，打勾之前要在会话里跑过 |
| 交叉审查 | 用审查代理（经路由落到另一个模型）审一遍：每个变更提案一次、代码一次 |
| 多轮审查 | 审查报了问题、改了之后再审改动点，直到报"问题 0 条"。开关 `reviewLoop` |
| 交接线 | 上下文用到上限的百分之多少要交接（默认 70%）。到线时用提问框问要不要写交接记录、开新会话 |
| 交接记录 | `.vibe/handover.md`，`/ttls-handover` 写的。新会话说"继续"就接上 |
| 自动压缩线 | 上下文用到上限的百分之多少时 Claude Code 自己压缩（默认 70%），套件写成 settings.json 的 `autoCompactWindow` |
| 全自动模式 | 用户不在时用：在 OpenSpec 流程里不问、不等，被流程类的检查拦下自己放行，收工时交报告。开关 `autoMode` |
| 在流程里 | 这个会话正在走 OpenSpec 流程（敲了 `/opsx:…`、提了需求、接着交接记录做……）。全自动模式只在流程里算数。记在 `state/<会话>-flow.json` |
| 全自动报告 | 全自动模式收工时合成的报告，`.vibe/reports/全自动报告-<时间>.md`：做了什么、留给你做的、库里改过的、自己定的事、没验证的、放行的检查、套件问题 |
| 拦截编号 | 流程类的检查拦下时提示末尾的〔四位字母数字〕，申请放行要用它 |
| 放行、通行证 | 模型确信是套件拦错了，用 `tools/feedback.js bypass <编号>` 申请；批下来是一张 30 分钟内有效的通行证，再做那一步时生效（默认弹确认框） |
| 问题反馈 | 套件本身的问题（拦错了、漏拦了、报错、提示看不懂、卡住），记在 `~/.claude/vibe-kit/feedback/`，自动上报成内网 GitLab 的议题 |
| 议题 | 内网 GitLab 仓库里的 issue。问题反馈建成的、每台电脑的"[使用情况]" |
| 使用情况 | 每天数的次数（开口、拦下、放行、上下文、审查、拉代码、模型用量），第二天传到这台电脑的"[使用情况]"议题 |
| 经验规则 | 审查里反复出现的问题沉淀成的一句话规则，写进项目的 `.claude/rules/ttls-lessons-<类型>.md`，读到那类文件时才加载 |
| 后台自动探索 | 进到没探索过的项目，脚本在后台查工程类型、命令、端口、编码、开发环境的连接，写进 `.vibe/project.md`，不用模型 |
| 快检 | 改完马上能跑的验证（编译改动的文件、语法检查），一般一两秒 |
| HTTP 钩子 | 登记成 `type: "http"` 的钩子，在路由里跑，一次几毫秒。路由没在跑时 Claude Code 当放行，所以用户开口时要自检 |
| 封条 | `state/config-seal.json`：放松保护的三个开关（关禁改、自己放行、全自动）只认配置页和安装器改的，绕开它直接改文件的不生效 |
| 基线 | `dev/baseline/<版本号>/`：打包时留下的那一版代码，下一版做新旧对比时当"上一版" |
| 维护的那台电脑 | 发布安装包、导出议题的那一台。地址写死在 `kit/lib/gitlab.js` |
