## 要定的（仓库主人 2026-11-12 在提问框里选的）

1. 自动实施中途被打断：**插话不关，说停才关**。插话、提问回应完接着自动；说"停""别自动了"关，之后说"继续""开工"先问一次"自动接着做 / 人工接着做"。
2. 全部通过、自己关了以后，核验时报的问题：**照旧自动修**。
3. 一个大任务几个 change：**每个 change 的需求审完都问**。
4. 删 /vk-auto 后对话里的说法：**只认关**（"开自动""这个需求自动做"不算，"别自动了"照样关）。

Claude 自己定的边界（写进 decisions.md）：做任务中途改了需求、退回后再说"开工"的不问自动还是人工（不是第一次开工）；表外的 change 也要有全面自测，加 `workflow.js selftest --change`；`/vk-resume` 接回照旧恢复死机前的自动。

## 自审

- 宽松认答案（套件等着问自动还是人工时）：只认问题里说到自动、又问的是实施、开工、接着做的，免得"导出用哪种格式"答"自动识别"被认成开自动。
- 核验期自动修的检查每次改文件都跑：先看哪儿记了 autoFix，没有直接走，不读计划表。
- 写需求那一段开着自动时提交方式"询问"被说成"全自动下不问"，和让模型问用户提交矛盾：`guard-git` 只在做任务那一段按自动算。
- 同类入口：开工的入口（说"开工"、`/vk-go`、`/opsx:apply`、`/vk-resume` 接回、表外 change 接回）都会先问；做任务中途改需求退回再开工的不问。
- 出错放行：`syncAutoAnswer`、`auto-run` 的调用都在 try 里，出错按人工算、不拦。
- 没做的：没跑全量回归、没打包（等仓库主人说发版）。
