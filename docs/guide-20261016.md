## 用户决定（2026-10-16，用户定的）

1. 编译、类型检查、静态检查不算自测，人工模式直接跑；跑测试、起服务、看页面才算自测，人工模式先 Ask。
2. 人工模式问"要不要审查、自测"：每个用户要求问一次；用户说不用之后，这个要求里后面的小改动不再问。
3. 人工模式打勾不检查验法（保持现状）。
4. 人工模式归档不要求代码审查；提示如实说审过没有，不把审查写成必经步骤。
5. 人工模式改了代码、还没跑过快检时，不强制、也不做开关，在第 2 条那个"每个要求问一次"的 Ask 里一起问用户要不要跑快检（编译级）；说跑就跑，说不用就接着做，不记待办。用户原话："可选吧，有的人任务比较急很简单看一眼能编译就行了"，"这个能不做开关吗，对话的时候直接 ask 询问使用者"。

## 项 1：编译不算自测

**现状**：`vibe-kit/kit/lib/flow-policy.js:124` 把 IDEA 的 `get_file_problems`、`build_project`、`lint_files` 当自测；`testCommand`（同文件 148 行起）把参数里的 build、compile、check、`--check` 和 `javac` 都当自测。结果人工模式下 `mvn -q -o compile` 被 `actionIssue` 拦下要求先 Ask（`dev/diff-hooks.js` 的 1014 段把它登记成了有意改动）。

**要的行为**：

| 类别 | 例子 | 人工模式 |
|---|---|---|
| 快检 | `mvn compile`、`test-compile`、`validate`；`mvn package`、`install` 带 `-DskipTests` 或 `-Dmaven.test.skip=true`；`gradle compileJava`、`classes`、`assemble`，`gradle build -x test`；`javac`；`tsc`、`vue-tsc`；`eslint`；`npm`/`pnpm`/`yarn run build`、`lint`、`typecheck`、`type-check`；`node --check`；`python -m py_compile`；IDEA `build_project`、`get_file_problems`、`lint_files` | 直接跑 |
| 自测 | `pytest`、`jest`、`vitest`、`playwright test`；`npm`/`pnpm`/`yarn test`、`run test`、`run test:*`；`mvn test`、`verify`、`integration-test`，以及不带跳过测试参数的 `package`、`install`、`deploy`；`gradle test`、`check`，不带 `-x test` 的 `build`；名字带 test、spec、scenario、probe 的脚本，或 test、tests、`__tests__`、spec 目录下的脚本；起服务 `tools/devserver.js start`；看页面 `/ttls-see-page`、`page/scenario-run.js`、`page/probe-run.js`；IDEA `execute_run_configuration` | 先 Ask |

**改哪里**：

- `flow-policy.js` 的 `testCommand`：按上表分成"快检"和"自测"，只有自测返回真。保留 10-16 的路径规则（带路径的参数只看文件名；`--prefix`、`--cwd`、`-C`、`-f`、`-p` 等开关的取值不当子命令）。
- `flow-policy.js:124`：IDEA 只把 `execute_run_configuration` 和 see-page 技能当自测。`execute_tool` 转发已在 `actionIssue` 开头按路由解析成实际工具，不用另改。
- 起服务：`tools/devserver.js` 是套件自己的工具，被 `session.js` 的 `NOT_VERIFY_SEG` 排除在 `VERIFY_CMD` 之外，现在走不到 `testCommand`。在 `actionIssue` 里单独认出 `node <套件>/tools/devserver.js start`（只有 start；stop、list、status 不算）。直接用 `mvn spring-boot:run`、`npm run dev` 起服务已被 `serverGuard` 要求改走 devserver（`guard-commit.js:1575`），不用另拦。
- 用户明确要求的词表：`intent.js:11` 的 `TOPIC.test` 和 `session.js:236` 的 `SAID.test.yes` 补上"起服务、启动服务、把服务起起来、跑起来、启动项目"这类说法。不补的话，用户说"把服务起起来"也会被拦下要求先 Ask。
- 约定：`vibe-kit/claude/CLAUDE.md:33` 和 `vibe-kit/claude/rules/10-openspec.md:9` 各补一句"编译、类型检查、静态检查不算自测，直接跑"。全局约定每个请求都带，只加这一句，不展开上表。

**测试**（每个新断言都要在改之前的代码上失败）：

- `dev/test-workflow1014.js`"自测命令不因目录名带 test 误判"那组：`node --check src/A.js`、`npm --prefix test-package run build` 改成期望假；补 `mvn -q compile` 假、`mvn package` 真、`mvn -q package -DskipTests` 假、`gradle build` 真、`gradle build -x test` 假、`npm test` 真、`npm run lint` 假、`node "<套件>/tools/devserver.js" start --name a -- node a.js` 真、`node "<套件>/kit/page/scenario-run.js" a.json` 真。

## 项 2：每个用户要求问一次

**现状**：`flow-policy.js:96` 的 `once(j, id, signature, text)` 用指纹当签名。代码改动的提示（同文件 113 行，`plain-test`）按整份代码的指纹，代码一变就再问；同一个要求里用户说了不用，模型再改一处，收工又问。审查点的人工提示（108 行）按该点的指纹。

**要的行为**：人工模式的这些提示，每个用户要求最多问一次；用户提新要求时，只有相关内容自上次问过之后又变了才再问。自动模式的提示（110 行）不变。

**改哪里**：`verify-gate.js:709` 已算出 `turnId`，在 801 行调用 `policy.stop` 时传进去。人工提示的状态改成记 `{ sig: 指纹, turn: turnId }`；问不问的条件是"`turn` 和本轮不同，而且 `sig` 和当前指纹不同"。`turnId` 为空（会话记录末尾找不到这一轮的开头）时只按指纹判断。状态文件仍是 `<会话>-workflow-prompts.json`，`docs/architecture.md` 两阶段那节的描述跟着改。

**测试**：扩展 test-workflow1014"人工只提示一次，放弃不被同输入反复催"：同一个要求里代码再变，不再问；新要求带新改动，再问一次；新要求没有改动，不问。

## 项 4：归档提示照实说

**现状**：`guard-commit.js:611` 人工模式归档已经不要求代码审查，这和决定一致。但提示文字没跟上：
- 633 行拦截时写"顺序是：任务全部打勾 → /ttls-cross-review 审代码 → 修掉成立的问题并验证 → 再归档"，把审查写成了必经步骤。
- 629 行任务都勾了、等用户说归档时写"任务都打了勾、代码也审过了"，没审过也这么说。

**要的行为**：
- 人工模式拦截时写"顺序是：任务全部打勾 → 审查、自测由你决定 → 你说归档再归档"。
- 等用户说归档时如实说：审过了（`codeReviewed` 或 `flow-policy` 的 `allPassed(dir, 'code')`）写"代码审过了"，没审过写"代码没有做过完整审查（人工模式审不审由你决定）"。
- 自动模式的两条提示不变。

**测试**：
- 人工模式、任务全勾、没有审查：等用户说归档的提示里不能有"代码也审过了"，也不能把审查写成必经步骤。
- 有一次完整的零问题审查：提示说审过了。
- 自动模式输出不变，由 diff-hooks 盯住。

## 项 5：快检在对话里问，不做开关

**现状**：`verify-gate.js:771` 的 `checking = cfg.autoMode || explicit(j, 'test')`，人工模式除非用户明确要求测试，改了代码收工从不提快检。用户既不要强制，也不要开关，要在对话里问。

**要的行为**：
- 人工模式，这个要求里改了代码，最后一次修改之后还没成功跑过快检：项 2 那个"每个要求问一次"的 Ask 里，加一问"要不要跑快检（编译级）"。
  - 用户说跑：直接跑，按项 1 不用再问。
  - 用户说不用：接着做，不记待办，不再催。
- 已经跑过快检：Ask 里不问快检，只问审查、自测。
- 收工不能因为没跑快检被拦下：不要恢复 778 行那种强制补跑的提示。
- 项目的快检命令按项 1 的表算自测时（比如 `.vibe/project.md` 里写的快检是 `npm test`），问的时候说明这个快检要跑测试。
- 不新增开关。`autoVerify` 的含义和配置页文字维持现状（Apply 自动时按验收用例自测）。Apply 自动模式不变。看页面（773 行）按项 1 算自测，人工模式维持现状。

**改哪里**：
- `verify-gate.js` 在 801 行调用 `policy.stop` 时，多传一个"还没跑快检"的标记。判断沿用 776—778 行的做法：最后一次代码修改之后没有成功的 `VERIFY_CMD`，`evidence.commands` 里也没有。
- `flow-policy.js` 的人工提示（113 行 `plain-test`，108 行里代码组的那条）据此加上快检这一问。提示要写清问法，例："用 Ask 一次问清（可多选）：跑快检（编译）、审查、按验收用例自测、都不用"。
- 不改配置页、`DEFAULT_CONFIG`、`kit-api.js`。

**测试**：
- 人工模式改了代码没跑快检：收工的 Ask 提示里有快检这一问。
- 跑过快检：提示里没有快检这一问。
- 同一个要求里不重复问（和项 2 一起测）。
- 人工模式收工不会因为没跑快检被拦。
- `dev/diff-hooks.js` 1014 段"收工：改了代码没验证"：期望改成 Ask 提示里带快检这一问。
