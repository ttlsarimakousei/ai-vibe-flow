## 修改计划

按"要定的"改，和开头的方向比有三处不一样：

- 阶段没有整个改成按 change 算：`stage` 还是会话一个值，改的是会让它出错的几处（改需求不退回、写别的 change 不退回、同一个大任务里已开工的放行）。整个改掉要动收工检查、审查、提交里所有读 `stage` 的地方，这一批不做。
- A7（中途新开 change 要先进 plan.md 的表）不改：拦截提示里给的 `plan.js new --task … --changes …` 随时能跑，照做就能写提案，不是死路。
- A12 只做了"另有 c3 做到 1/3"，表的顺序（先做完 c1 再回 c3）是 11-03 定的，没动。

## 自审

对着 diff 过了一遍，审出来当场改的：

- `startedInScope` 没看 `holdApply`：用户说了"只写需求"、开工范围还在的，会放过代码改动。加上了。
- `askedNow` 把"开工 c1"这种带名字的开工话也当成"让改一处"，开工后第一笔半成品能自动提交。加了 `applyIntent` 排除。
- "另有 … 做到 n/m"在老任务（没有探索记录的 plan.md）里会把早就不用的行带出来（`test-old-plan.js` 查出来的）：老任务不带。
- 开工时"先问要不要提交"的提示，20 秒内重新说开工会再说一遍：记 `dirtyTold`，只说一次。

逐项：

- 同类入口：打勾的"我还没说开工"（guard-spec）和改代码的拦截（pre-edit）用同一个 `startedInScope`；Bash 改文档的也会在 after-tool 里比指纹。
- 全自动：开着自动的会话走的还是原来那条分支（`sessionAuto`），`test-auto-session.js`、`test-multi-change.js` 的自动用例没变、全过。
- 出错放行：新加的调用都包在 try 里，after-tool 那一处出错记反馈（预算用完、模块不在不记）。
- 令牌保护：没碰。
