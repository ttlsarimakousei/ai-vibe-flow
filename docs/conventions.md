# 约定：代码、提示语、文档怎么写

## 代码

- **Node 18 起能跑**，只用 Node 自带的模块（`fs`、`path`、`child_process`、`http`、`crypto`、`worker_threads`……）。看页面的执行器是唯一的例外，它的依赖带在 `kit/page/node_modules` 里。
- `'use strict';`，CommonJS（`require`），两个空格缩进，单引号，分号。和周围的代码保持一样的写法。
- **每个文件开头一段中文注释**：这个文件管什么、在什么时机被谁调、关键的取舍和原因（"为什么"比"做什么"重要）。改了行为，这段注释跟着改。
- 函数上面的注释写它返回什么、什么情况下返回空。注释写人话，提到起因时写日期和事情（"2026-09-30 用户遇到……"），方便以后判断还要不要。
- **出错不拖垮调用方**：读不到文件、解析失败、子进程失败，返回空值或者当放行，`catch` 里写一句为什么可以忽略（`/* 记不了不影响对话 */`）。钩子出错记一条问题反馈（`recordHookError`）。
- **路径**：用户目录按代码自己的位置推（`path.join(__dirname, '..')`）；比较路径用 `normKey()`（统一斜杠、小写）。Windows 和 Git Bash 的 `/c/` 写法都要认。
- **写状态文件**：用 `session.js` 的 `writeState` / `updateState`（先写临时文件再改名），不要直接覆盖写：好几个钩子进程、路由的工作线程会同时读写。
- **起子进程**：`windowsHide: true`；要等结果的给 `timeout`；git 一律不交互（`GIT_TERMINAL_PROMPT=0`、`GCM_INTERACTIVE=Never`、ssh 加 `BatchMode=yes`）。会起孙进程的，超时用 `taskkill /T /F` 连子孙一起结束，不留进程。
- **HTTP 钩子的工作线程是常驻的**：钩子和库里不要写模块级的缓存（上一个会话的数据会带到下一个会话）。
- **默认值只有一处**：开关的默认值在 `session.js` 的 `DEFAULT_CONFIG`；`kit-api.js` 那份要和它一样。
- 能用脚本确定判断的就别交给模型；交给模型的，给出要看到什么才算过。

## 给模型看的文字（钩子的提示、约定、技能）

- 开头带来源：钩子的提示以 `[vibe-kit 提醒]`、`[vibe-kit 提案检查]` 这类开头，模型和用户都看得出是套件说的。
- **说清要看到什么才算过，带一个照着改的例子**。内网的模型只被告知"不对"，会原地打转（2026-09-28 的反馈里，同一条路径检查连着三次没改对）。
- 拦下时把"为什么拦""怎么改""改不了怎么办（流程类的检查可以申请放行）"一起说。
- 全自动只管有效 apply 范围内的实现、验证和审查。无依赖的助手任务继续做；用户验收、归档、推送确认和重开审查预算要保留用户决定。不能把这些确认改成模型自行批准，也不能借旧交接恢复许可。
- **字数就是钱**：全局约定每个请求都带；钩子注入的每条消息都带。能在对应时机由钩子送一次的，不进约定。加字之前估一下多少 token、多久送一次。
- 不用"应该是""一般来说"这类模糊词给结论；不写"待定、后续完善、视情况"（套件自己就拦这些）。

## 给用户看的文字（配置页、安装器输出、README、更新说明）

- 简体中文，直白。开关的名字说它管什么，一句话说明不超过 90 个字（配置页的测试会查），细节放进折叠的"细节"里。
- 说结果和用户要做的事：装完要不要重开会话、开着的会话要敲什么。
- 不出现内部地址、维护的电脑的地址、令牌。
- 用户的项目结构说"壳子"和"子项目"。

## 文件编码和换行

| 文件 | 编码 | 换行 |
|---|---|---|
| `.js`、`.md`、`.json`、`.html` 等文本 | UTF-8，无 BOM | LF |
| `.bat`（双击运行的） | GBK | CRLF（cmd 才认得中文） |
| 体检包里的 `.ps1` | 只写 ASCII，或者 UTF-8 带 BOM | 照原样 |

仓库根目录的 `.gitattributes` 是 `* -text`：git 不改换行，检出来的和提交的一模一样（打包脚本会逐字节核对）。改 `.bat` 用脚本按字节读写，不要用编辑工具（会被转成 UTF-8）。

## 测试

- 一个功能一套测试文件，放 `dev/`，名字带上是哪一批（`test-1001.js`）或者测什么（`test-issues.js`）。用 `dev/lib/harness.js` 的支架：`H.makeHome` / `H.freshHome` 建假用户目录，`H.hook` 跑钩子，`H.ok(名字, 条件, 出错时显示的东西)` 记一项，`H.done(标题)` 收尾（核对真实文件没变、没留进程、删临时目录）。
- 断言写成一句话说清在测什么（`H.ok('分叉了：不拉，告诉它，要合并先问我', …)`），失败时把实际输出带出来。
- 新测试加进 `dev/run-all.js` 的 `suites`，并在 `dev/README.md` 的表里写一行。

## 提交信息

`类型: 内容`，英文冒号加一个空格，一行。类型：`feat`（新功能）、`fix`（修毛病）、`docs`（只改文档）、`style`（格式）、`refactor`（重构，行为不变）、`chore`（杂项、工具、测试支架）、`release`（发版）。例：

```
fix: 导出议题时漏了使用情况的汇总
docs: 补上开工前拉代码的说明
```
