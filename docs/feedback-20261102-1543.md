原因：

1. 只有 0 条问题才算过（`flow-policy.js` 的 passed），P3 标了"修了"也要再审。
2. `review.js` 每轮全量重审，不带上一轮的结论。兼容的审查代理有复审模式，默认路径没有。
3. 提示不分阶段；提案里被要求写魔数表、算法步骤。
4. 下一份文档被拦着不能写（`guard-spec.js`），实现细节只好塞进提案，越改越长，问题越多。
5. `tasks` 这个点要把四份文档全审一遍（`flow-policy.js` 的 pointFiles）。
6. 没有收敛判断，唯一的出口是 20 轮上限。到上限了 `guard-spec.js` 还照样拦下一份文档。
7. 提案的修改也要求"当前输入的成功复验证据"：窗口里为了登记提案的修改先跑基线编译。
8. 过程没记全：`revisions.md` 只在收工时提醒，自动模式第 3 轮之后一直没收工；结果文件每轮被盖掉；处理记录散在 `.vibe/tmp`。
