### L 本仓库自己的规范

草案见文末，商量 11。

## 要商量的

1. **Apply 中途改需求文档要不要退回人工**（A3）。推荐：只有改需求本身（proposal.md、specs 里的要求）才退回；design 补说明、tasks 改措辞或拆子任务、修订记录不退，照旧自动，收工报告列出改了哪些。
2. **push 唯一的那道检查出错时怎么办**（B3）。去掉确认框以后，路由坏着、HTTP 钩子连不上，Claude Code 当放行，push 就直接出去了。推荐：push 的检查单独走命令方式（每条 Bash 多起一个很快退出的进程，约 0.1 秒），检查出错时问一下；别的检查照旧。

## 附：本仓库自己的规范（草案）

1. **问题从哪来，先记在哪**

   | 来源 | 先记在哪 | 编号 |
   |---|---|---|
   | 仓库主人在对话里提的 | `docs/owner-issues.md`，按原话记（10-22 定的，不变） | 第 N 条 |
   | 内网同事导出的议题 | 核对时写进当批的 `docs/feedback-<日期>.md` | GitLab 议题号 #N |
   | Claude 自审 | 当批 feedback 文档的"自审"一节 | 自审 N |
   | 第三方审查（Codex 等） | `reviews/<审查者>/`（10-29 定的，不变） | 照报告里的编号 |

2. **未结清单 `docs/backlog.md`（新加）**：所有来源里还没结的都列在这一张表里（编号、一句话、状态、在哪分析、下一步）；结了就删掉那一行，历史看 feedback 文档和 git。交接不再列旧议题，只指向它。
3. **一批修复一份文档**：`docs/feedback-<日期>.md`，固定几节：来源、核对（成立 / 不成立 / 重复 / 证据不足，带 `文件:行号`）、要定的、修改计划、修复结果（提交号、测试）、自审。没做的挪进未结清单。
4. **自审**：每批改完、提交前，Claude 对着 diff 自审一遍：同类入口、全自动场景、出错放行并记反馈、令牌保护、配置页说明和行为双向、文档跟着改、新测试拿上一版跑会不过。审出的直接改，结论写进"自审"一节。改了钩子、路由的批次，再请一个别的模型独立审一次，报告放 `reviews/claude/<日期>-<主题>-复审.md`。
5. **第三方审查**：别的 AI 只审查，报告写进 `reviews/<自己>/` 并提交推送，不改代码、不改别的文档。Claude 逐条核对（能复现的拿它的脚本重跑）、和自己的结论去重，写进当批 feedback 文档；修改都由 Claude 做（仓库主人 10-30 定的）。修完回填 feedback 文档和未结清单，不改人家的报告。
6. **交接**：`docs/handoff.md` 的规矩从 CLAUDE.md 挪进 AGENTS.md，所有 AI 都照着做。只写现在的状态：在做哪一批、做到哪、等仓库主人定的、要注意的。一批提交之后、上下文过七成、会话要停之前更新，覆盖重写，40 行以内。
7. **状态词统一**：待核 / 待修 / 待定（等仓库主人）/ 证据不足 / 后做 / 修了（提交号）/ 不修（理由）。问题表第 10 条的"待问清"改成"待定"。
