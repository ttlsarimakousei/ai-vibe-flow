## 回归发现与修复

第一轮完整回归核对三版 CLI、四份旧基线和 H2。新许可规则使旧假模型的自行提交及归档被正确挡住，旧测试改为先核对拦截，再发送真实用户确认，检查 Git 或目录确实改变。没有为通过测试放宽规则。

同时修复实际缺陷：续锁覆盖随机身份导致后台更新退出；脱敏误遮普通选项导致配置页出现错误；旧“留给用户”任务被当作助手工作；Markdown 与审查对象重复 JSON 编码；审查取消后预算丢失；新审查沿用旧处理状态；恢复包未拒绝额外文件；审查未先核对目录链接范围。

补充发现独立提案审查未绑定实质产物。需求、设计或任务验法改变后旧结论现已失效；实现代码、任务打勾和生成交付摘要不会要求重新审需求。新增专项在本轮修复前有三项失败，修复后 19 项通过。为保持被测代码不变，停止上一轮回归后修复，再重新启动完整回归。

## 适用边界

- 未拿到那次“一小时没有结果”的现场日志，不能声称已经定位真实网关、模型排队或子代理的具体耗时原因。默认改为无工具的有限独立请求，总预算 300 秒，可配置；兼容代理需主会话取消已知任务，套件不会杀 Claude 主进程。
- 目录、配置和驱动就绪仅代表已识别，业务构建、IDEA 索引和版本兼容需实际验证。前端写死的代理不会自动改成环境变量，服务存活不替代页面与接口验证。
- 实测同一次调用中的重复 Git 查询只启动一次，下一次重新核对；没有把这个结果换算成整轮耗时或 token 节省百分比。真实网关收益待现场观察，本轮不扩大遥测。
- 完成事件使用真实 CLI 加假网关验证；旧会话记录仍保留兼容判断，不能声称所有版本都只靠新事件。真实 IDEA 含秘密输出、厂商业务数据库未做破坏性测试。
- 更新保留原远端回退及安全政策，本地恢复只含受管程序。文件哈希与目录集合校验不能替代用户自己的业务数据备份。
