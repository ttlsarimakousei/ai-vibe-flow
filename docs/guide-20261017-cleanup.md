## 二、重写用户手册

`vibe-kit/README.md` 有 934 行，按版本一段段加出来，同一件事散在好几处（审查、提交、自动模式各出现三四次），10-16 那一遍校对只改了和代码对不上的句子。建议拆成：

1. **`README.md`（目标 200 行以内）**：装和升级；两种模式怎么选（一张表）；平时怎么用（新功能、小改动、修已归档功能的问题、提交和推送）；状态栏和配置页怎么看；出了问题看哪。只写用的人感觉得到的行为。
2. **附录**：保护和放行、审查和自测、提交推送和合并推送、查库和 redis、自动更新和上报、上下文和 token，各一份，放在 `vibe-kit/手册/` 下。

**注意**：`vibe-kit/` 下新加的文件要同时加进 `publish.js` 的 `PACKAGE` 清单和 `dev/pack.js` 的必备清单。10-16 的 `验收清单.md` 就是漏了发布清单，同事自动更新拿不到。

做法：

- 先把现在 README 每一节按"讲的是哪件事"归类，每件事只留一处说明。拿代码逐条核对，不照搬旧段落。
- 写给用的人看：写行为和要他做的事，不写钩子名和内部状态文件，除非他需要去看那个文件。
- 重写后 grep 旧说法（"全自动模式下""多轮审查""提案、代码各一次"等），确认只出现在历史章节。

验收：test-update（安装包和发布内容一致）、pack.js 的必备文件检查通过；另请一位没用过套件的同事照新手册装一遍，记下卡住的地方。
