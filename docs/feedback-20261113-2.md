### 第 90 条：询问发出后没人回，过 10 分钟自动替他做主

| 问的 | 证据 | 结论 |
|---|---|---|
| 套件现在有没有超时 | 没有。提问框一律放行：`hooks/guard-ask.js:71`（"自动阶段仍允许 Ask 澄清需求本身的疑问"）；安装器只在提问框弹出之前登记了一个钩子（`install.js:378` 的 PreToolUse），框弹出来以后没有套件的代码在跑 | 确认 |
| 能不能测到人不在电脑前 | 钩子只在 Claude Code 的事件上跑，拿不到键鼠、锁屏的信号。要测得另起进程调系统接口。换成"框弹出后多久没答"来判，不用测人 | 不做，用超时代替 |
| 官方文档怎么说 | [hooks 文档](https://code.claude.com/docs/en/hooks)（2026-11-13 读）：PreToolUse 钩子能带 `updatedInput.answers` 替提问框作答；PermissionRequest 在"要问用户之前"触发，能 allow / deny；Notification 的 `permission_prompt` 在框显示约 6 秒后来，只能收、不能作答。框已经显示以后钩子的决定还作不作数，文档没说；没有任何"多久没答就怎样"的设置 | 要实测 |
| 框显示以后钩子还能不能作答 | 实测（`dev/probes/cc-ask-timeout.js`：交互界面、假网关、假用户目录），见下表 | 能 |

实测结果（2.1.120、2.1.259、2.1.289 和内网在用的 2.1.316）：

| 做法 | 结果 | 测过的版本 |
|---|---|---|
| PermissionRequest 钩子等 10 秒，allow 并带 `updatedInput.answers` | 框先显示（0.2 秒后钩子被调），到点框自己收起，工具返回钩子给的答案，屏幕上写"Allowed by PermissionRequest hook"，会话接着走 | 四个都是 |
| 等 10 秒，deny 并带一句话 | 框收起，模型收到一条出错的工具结果，内容就是那句话，会话接着走 | 2.1.289、2.1.316 |
| 用户 5 秒时先答了，钩子 14 秒才给决定 | 用户的答案作数。钩子的进程不会被结束，一直跑到自己退出；后到的决定不起作用 | 2.1.289、2.1.316 |
| Bash 的权限确认框，钩子等 10 秒后 allow | 框收起，命令执行 | 2.1.289、2.1.316 |

结论：成立，能做。做法是登记一个 PermissionRequest 钩子：自动实施在生效时等够时间，没人答就替他收掉这个框。用户先答了钩子要自己早点退（不然每个提问框留一个等 10 分钟的进程）。

## 自审

对着 diff 看的：

- **同类入口**：查库的写操作只有 `exec` 一个入口；第一步、第二步、行数变了重给确认串三处都走 `write_policy`。还原（`exec --undo`）没动，照旧两步、要人确认、全自动下不做。redis 的 `set`、`del` 是全部写操作。提问框和权限确认框都走 PermissionRequest，一个钩子管。
- **全自动场景**：全自动下要人确认的删照旧退出码 3、不给确认串；提问框到点收掉后模型照 message 自己定；推送确认框到点不允许，和 `guard-commit` 全自动下 push 一律留给用户一致。
- **人工场景**：确认串登记里记了"要不要人点头"，第二步有人在时照它算、不连库重算；指纹里有 SQL、行数、风险，变了就对不上，不会拿"不用问"的串去执行别的语句。
- **出错放行**：`ask-timeout` 出错、算不出流程状态都什么都不说（框照常等人），记问题反馈；不走 `cli()` 的 12 秒预算，读开关单独给 12 秒。
- **令牌保护**：没碰。
- **配置页说明和行为双向**：配置页"自动模式"一节的说明（改库只有还原不了的删留给你、等多久替你做主和细节）和钩子、db.py 的行为对过；手册开关表用 `config-doc.js --write` 重写。
- **文档跟着改**：技能 SKILL.md、CHANGELOG、全局约定、README、手册"查库和 redis"、更新说明 `@@VER@@` 一节、architecture、decisions、claude-code-facts、dev/README、contracts。
- **审出来改了的**：钩子在会话记录里找这次调用时跳过了子代理的条目，子代理弹的框用户答了也认不出、会白等到点，去掉了这个过滤。测试里"默认等 10 分钟"一项原来是空断言，改成直接核对 `waitOf`。
- **没覆盖的**：没在真的 Claude Code 里装上套件、跑一次带 `ask-timeout` 的自动实施（探针测的是同样输出的通用钩子，套件钩子的输出另由单测核对）。`test-dbcrud.js` 不收旧版目录参数，没拿上一版跑；重写的那一节断言的都是和旧行为相反的（没主键的表新增照做、改列照做……），旧版必然不过。权限确认框到点"允许"也会放过 Claude Code 自己认为危险、要人确认的命令（推送、发布除外），这是仓库主人选的。
- **复审**：这批新加了钩子，按规矩要请别的模型独立复审，还没做。
