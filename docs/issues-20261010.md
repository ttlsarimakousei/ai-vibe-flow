## 个人反馈和类似问题

### 同库多个驱动版本

登记第二个 jar 时保留第一个，不覆盖整个数据库的登记。配置页可看各版本、设默认、去掉单一版本。旧登记格式和默认 jar 保持兼容。

查询时优先连接明确指定的 jar，其次项目自己的驱动，再按当前项目 pom 和本地父 pom 的版本从登记池选择。子项目覆盖父项目的依赖版本。壳子里选连接时，从连接配置来源找所属子项目，不拿兄弟项目的版本做决定。

项目明确要求的版本缺失或同一版本存在多个不同文件时，说明缺少或有歧义，让用户添加或明确指定，不拿全局默认的另一个版本顶替。没有明确版本时才使用默认。外部 BOM、复杂 profile 和未解析的属性不宣称已经实现 Maven 的完整依赖解析。厂商驱动不进包。

### 提交时机

| 场景 | 时机 | 许可 |
|---|---|---|
| 提案 | 写、审、修完后交代结果，立即问是否提交 | 提交许可单独确认，不拖到 apply |
| 开工 | 用户明确说开工或执行 apply | 不等于同意提交提案 |
| apply 实现 | 完成并验证一个任务或阶段，按所选档位 | 全自动服从档位，“我说了才提交”仍需用户许可 |
| 审查修复 | 成立问题修完、验证、所需审查轮次收尾 | 一起提交，不逐轮提交 |
| 非 OpenSpec 长任务 | 改完、验证、交代，用户仍可继续提修改意见 | 用户同意后才提交，历史上做过变更不能代替当前授权 |
| 归档 | 用户自测满意并明确同意 | 不被全自动或提交许可替代 |
| push | 用户明确授权推送 | 本地自动提交不能授权 push |

保留“每项任务提交”的默认值。细提交提供恢复点、方便定位回归、便于逐个审查；想减少频率可以选“按阶段”，一组三五项可独立验证的任务较合适。频率只影响提交，任务完成后仍立即打勾。

### 合并push

用户明确输入“合并push”才进入整理和推送流程。先列出本地未推送提交的分组计划；事件用 OpenSpec 来源或事件标记识别，不凭标题相似猜。提案、实现、归档保留独立边界；同一事件交错时，只有文件不相交才尝试重排，文件相交就保持原顺序。普通任务可在信息里写“事件: 名字”，归属不清的保留独立提交。

计划和执行都核对工作区、当前分支、远端状态。已有远端提交不改，含 merge、签名、版本标签或远端分叉就停止；不 stash、不 force。先用独立 index 重建，最终 tree 与原 HEAD 完全相同才替换分支。旧提交留下备份引用，合并后的说明保留原提交记录。推送失败返回备份和本地结果，不能为追求成功改成强推。

本轮只向临时裸仓库验证这项功能，没有整理或推送本项目的真实历史。

### 提案材料可交付和新增边界

提案、设计、规格、任务的实施输入不能依赖本机 `.vibe/tmp/` 或 `.vibe/out/`。模型写产物前先把所需非敏感脚本、样例、参考材料移到变更目录 `assets/`，更新相对路径并随提案提交。写入、收工、提交三个入口均检查；被忽略的文件、链接到目录外的材料、暂存区仍保留的旧引用也不能假装已交付。任务里声明的新建文件、每台机器自己的项目说明、明确的运行时输出仍允许。

同类检查修复了普通文档借提交标题跳过确认、续审没有内嵌 result 时漏记最新结论、中文事件不识别和归档后修复被挪到归档前的问题。本仓库按具体修复分开提交，不整理真实远端历史。

### IDEA 的启动、重启和日志

在 IDEA 的终端里打开 CLI，本身不会让 CLI 获得 Run 窗口控制能力。

IDEA 从 2025.2 起内置 MCP Server。可在 Settings / Tools / MCP Server 启用并配置 Claude Code 或 Codex。官方工具可列出运行配置、执行配置，运行工具返回的 fullOutputPath 可用于读取它启动的执行输出。参考 [JetBrains 官方说明](https://www.jetbrains.com/help/idea/mcp-server.html)。

不能据此承诺所有版本都能停止、重启用户原先在 Run 窗口启动的服务，或读取原有控制台全部内容。具体取决于当前版本暴露的工具。没有相应工具时，服务日志写到文件可以读取；完整接管生命周期需要 IntelliJ 插件，连接运行配置和进程、输出监听。参考 [官方 Run Configurations SDK](https://plugins.jetbrains.com/docs/intellij/run-configurations.html)。这是可行的开发方向，本轮未开发该插件，也没有连接或重启用户的 IDEA。
