## 自审

对着 diff 逐项看了：

1. 同类入口：
   - 锁：别处都走 `state-store.acquire`（经验规则、自动更新、探索、替你定的事），一起好了。Python 的 `dbconf.record_driver` 自己按 60 秒算过期，不受这个影响。
   - 令牌：Read、Grep（guard-read）、跑命令（guard-kit）、MCP（guard-mcp 调 guard-read 和 `realish`）四条路，换写法都先过 `localPath`。
   - 查库：`query`、`peek --where`、`exec` 三处都认函数名单，后台执行器走同一个 `sqlguard`。
2. 顺带查出的旧漏洞（不在报告里）：跑命令读令牌时，文件本身的短名是 `SECRET~1.JSO`，字面检查认不出；`\\?\` 里的 `?` 又让它跳过真实路径。上一版 `cat "\\?\…\SECRET~1.JSO"` 直接放行，这一版拦下（测试最后两项）。
3. 出错放行：
   - guard-read 载入出错时，Claude Code 照常读，等于放行；`cli()` 里的出错照旧记反馈。
   - guard-commit 载入崩时的兜底自己也包着 try，出错就放行。
4. 全自动场景：guard-commit 载入崩时回 `ask`。全自动下没人点，要等到点 ask-timeout 按"像推送"收掉（默认 10 分钟）；平时载入正常，全自动的 push 照旧当场拦下。这个情况只在自动更新覆盖到一半时出现，不另读开关（库可能正是坏的那个）。
5. 令牌保护只收紧，没放宽：Read 多了一道，原来的拒读规则不动。
6. 配置页说明和行为：到点放行那一条改成和 `DESTRUCTIVE` 一致，测试从 `ask-timeout.js` 里取出正则对照说明。
7. 性能：Read 多一个进程，本机约 0.2 秒（仓库主人选的时候知道这个代价）。
   - 顶上只载 `session-kitfiles`，不载整个 `session.js`。
   - 别的电脑上的共享路径不去算真实路径，免得网络不通时卡住（自审时补的）。
8. 我自己的过程文件：
   - 审核时坏锁探针直接载入了源码里的 `state-store`，等锁的诊断写进了源码目录的 `vibe-kit/kit/state/diag.json`，被 `.gitignore` 忽略，看不出来；`makeHome` 把它拷进假用户目录，`test-diag` 因此出错一次。已删，重跑过了。
   - SQL 探针留在技能目录里的 `__pycache__` 也删了。
9. 改了钩子（guard-ask、guard-commit、guard-read），照 AGENTS.md 请别的模型（Sonnet）独立复审，见下一节。

## 独立复审的处理

报告：[reviews/claude/20261121-全量审核修复-复审.md](../reviews/claude/20261121-全量审核修复-复审.md)。Sonnet 审的，看了 3f049bb..2cf852f，跑了新测试（本版全过、旧版 28 项不过）和 SQL 自测，R1、R2 用假用户目录复现了。逐条核对：

| 条 | 结论 | 怎么处理 |
|---|---|---|
| R1 Read 写成卷 GUID（`\\?\Volume{…}\…`）：`localPath` 去掉前缀后成了相对路径，guard-read 放行 | 成立（本机 `mountvol` 取到 GUID，Node 读得出、旧代码放行） | `localPath` 只在前缀后面是盘符或 `UNC\` 时去掉；卷 GUID、GLOBALROOT 这类原样留给 `realpathSync.native`，它会还原成盘符（实测）。guard-read 只对别的电脑的共享跳过 realpath；guard-kit 判断通配符时跳过设备前缀。测试加了 Read、跑命令、MCP 的卷 GUID 写法（fc804be） |
| R2 函数名加引号（`"setval"(…)`、`"pg_catalog"."setval"(…)`、`[OPENQUERY]`）绕过名单 | 成立（复现） | 查名单前先去掉标识符的引号（`_side_effect`），`query`、`peek --where`、`exec` 三处都用它；自测加 5 条，别的 schema 下加引号的同名函数照旧不算（3735501） |
| R3 guard-commit.js 自己被覆盖到半截时，B3 的兜底跑不到 | 成立（读代码）；本机边装边读没抓到半截（文件小、拷得快） | 仓库主人选"安装器改成原子替换"：`copyFile` 先拷成同目录的临时文件再改名，改名失败重试，几次不行退回原地覆盖。测试查了没留临时文件、边装边读不缺不截、拷法本身（91a7281） |
| R4 名单是黑名单，`pg_advisory_lock`、`GET_LOCK`、`pg_sleep` 不在 | 成立但不改 | 仓库主人选"不加"：它们不改数据，连接一关就释放。写进了技能的 CHANGELOG |
| 附带：guard-mcp 的路径字段可能没过 `localPath` | 不成立 | guard-mcp 交给 guard-read 和 `realish`，两处都先过 `localPath`；测试加了 MCP 的 `\\?\`、管理共享、卷 GUID 三种写法，复审前的代码上前两种本来就拦得住 |
