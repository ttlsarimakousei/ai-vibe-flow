## 1. 删 IDEA MCP 接入和 IDEA 起服务

仓库主人反馈："不是被拦截就是起不来也不自觉的去启动"，devserver 以前好用。代码里对得上的原因：

- 两个入口：`devserver.js start --idea` 和模型直接调 `execute_run_configuration`。直接调的，人工模式算自测要先问（`flow-policy.js:264`），同一个运行配置这个会话起过又被拦（`idea-tools.js:58-98`）。
- IDEA 连着、项目里有运行配置时，devserver 不写 `--idea` 就不起，只列运行配置名（`devserver.js:586-587`）；写了还要模型自己填对端口。
- 前提多：IDEA 开着、项目在 IDEA 里打开、开了 brave mode、运行配置没错；运行配置有错时 IDEA 弹模态框，之后所有 MCP 调用都挂住（`docs/claude-code-facts.md` 的实测）。

改法：

- devserver 去掉 `--idea`、"IDEA 连着就不起"、IDEA 会话的起停；以前用 IDEA 起、记成 `mode: idea` 的记录，stop、status 时说清"以前用 IDEA 起的，到 IDEA 里停"，记录删掉，不动进程。第 13 条前半句"用户在 IDEA 里起的不动"现在就是这样（`devserver.js:16-17`，端口被用户的 IDE 占着说清是谁、不动）。
- 安装、更新不再登记 IDEA 的 MCP，已登记的、套件加的、没被改过的撤掉（沿用 `idea-mcp.js` 原来卸载时的撤回逻辑）；配置页去掉"IDEA MCP"一节和 `ideaMcp` 开关；后台不再探测。
- `lib/idea-run.js` 删掉；装新版时删掉旧版留下的这个文件。
- `lib/idea-tools.js` 留着：用户自己登记的 `jetbrains` MCP 照旧只走和普通工具一样的检查（终端按 Bash、改文件按 Edit、读套件令牌照拦，硬规矩第 6 条只能收紧）；去掉"同一个运行配置已经在跑"的拦截和给环境就绪用的能力说明。
- 第 15 条（MCP 起服务先 STOP 再 START）随这条删除不再适用：套件不再用 IDEA 起服务。

## 2. 取消合并推送（第 9 条、#233）

#233：用户说"合并推送"，模型给了计划；用户改选"不合并了，直接推送"。`guard-commit.js:1801` 只要这个仓库有 30 分钟内没用掉的预览（`merge-push.js:216-218`）就按合并推送走，`simpleAllowed`（`:293-302`）要 1 条提交或"预览之后的确认"，19 条提交的仓库直推永远被拦，没有取消预览的命令。

改法：去掉合并预览、合并计划、合成一条推送（`merge-push.js plan/apply/squash`）。说"推送""push"照旧直接推；"合并推送""合并成1条推送"不再是套件的说法，按普通推送的规矩走（用户说了推送就推，不改写历史）。普通推送的保留检查不变：强推、删远端分支、推到别的分支要确认（原 `plainAllowed` 挪进 guard-commit）。

## 3. 模型请求不带模型名（第 10 条）

路由转发时原样带着 Claude Code 发来的 `model`（`router.js:776`，只有配置页填了"换成这个模型名"才换）；测试连接写死 `claude-sonnet-4-5`（`:861`）；审查请求写 `claude-sonnet-vibe-review`（`review-runner.js:218`，路由按它分角色）。

改法：路由照旧用请求里的模型名分角色、记用量，转发给上游前把 `model` 去掉；测试连接不带模型名；配置页"换成这个模型名再发出去"一栏去掉（填了也是指定名称）。

## 4. 不用 openai 的方式请求（第 11 条）

`router.js:774`、`:863` 除了 Anthropic 的 `x-api-key` 还加了 `authorization: Bearer <key>`（OpenAI 的认证写法）。Claude Code 自己发来的 `authorization` 也会原样带上。

改法：转发和测试连接只带 `x-api-key`、`anthropic-version`，去掉 `authorization`。请求路径照旧是 Anthropic 的 `/v1/messages`。

## 5. 审查：去掉预算上限，超了分析上报；思考吃满输出上限（第 6、7 条，#226）

- 第 7 条问的 `review-runner.js:191-192` 是 16000、32000（不是 160000）：一次审查请求最多让模型输出多少 token。先给 16000；模型只输出了思考、停在上限，同一批用 32000 再试一次。它不拦命令，碰到了这一批就算失败，整轮记成部分覆盖或失败。
- 预算：`:281` 总预算按配置页的秒数（10—1800），到点截断剩下的批次判 timed_out（`:300-302`、`:322`）；累计用完还要 `--new-budget` 和用户点头（`:238-247`）。
- #226：deepseek-flash 两次都把 32000 全用在思考上，到 600 秒判失败。

改法：

- 不再有总预算截断：每批都发完；配置页的秒数改成"预期用时"，审完超出就自动记一条问题反馈，写清总用时、各批用时、重试、输出 token、停止原因、材料大小、模型，供优化审查。`--new-budget` 不再需要。
- 只回思考：第一次重试用 32000，提示里要求少想、直接给 JSON；还是只有思考，把这一批拆成两半各审一次。都不行的这一批记失败，接着审下一批，审完一起上报。
- 配置页审查那一节写清这几个数。

## 6. 不走 OpenSpec 的审查登记决定（#234）

`review.js run --mode code --base <提交>` 支持不带变更名，结果在 `.vibe/reviews/plain/code.json`；但 `resolve` 一定要变更（`:356`），模型执行带"接受"的 resolve 时钩子也要变更（`:258`）。

改法：`resolve` 不带 `--change` 时按 `--project` 找这次不带变更名的审查报告，把决定写进报告；钩子按项目目录核对用户的"接受"许可。

## 7. 中途打开 Apply 自动（第 8 条、#227）

假用户目录复现：需求写完时 Apply 自动关着，打开后回窗口说"执行apply""开工""apply""/opsx:apply feat-019"都按自动走；说"开始实施 feat-019"认不出开工（`intent.js:17` 没有"实施"），还在需求阶段，照人工走。#227 的会话 14:06 记的是"提了需求，在写提案那一段"，钩子提示只写"人工模式"（`flow-policy.js:290`），模型和用户都以为是没读到新开关。

改法：开工的说法加"实施""开始实施""执行任务"；开关开着、这一轮又不算自动时，提示写清为什么（还在需求阶段要说开工、这一轮不在流程里、范围变了等用户确认），不再只写"人工模式"。

## 8. 产出位置（#225）

- 提问框答"项目根目录"：文件在根目录时，`outputs.js:280` 只认"根目录 + 文件名"的写法（#58 定的，防误认），光说"项目根目录"不认。
- 放行不生效：第一次拦（L2SU）的话是"这类产出放哪还没跟用户定过"，模型把位置记进项目说明后第二次拦的话变成"项目说明里现在有这个位置，但它是这个会话里自己加的"。通行证按拦截话的第一行认同一条规矩（`feedback.js:64`、`:343-347`），两种话第一行不一样，L2SU 的放行对第二次不算，又换发了 YWHW。

改法：提问框问的是放哪（问题里有放哪、位置、目录），答"项目根目录""仓库根目录""根目录"的，根目录下的文件算定过；这个会话里问过位置、用户答过，模型照答案记进项目说明的条目也算定过。两种拦截话第一行统一成同一句，放行对两种都算。

## 9. 起服务看日志（第 14 条）

devserver 等服务起来时每秒连一次端口，端口通了就每秒发一次 HTTP 请求（`devserver.js:392-413`），不看日志；起不来要等到超时（默认 180 秒）才把日志贴出来。

改法：每 2 秒看一次日志新增的内容：看到起好了的标志（Spring Boot 的 `Started … in … seconds`、Tomcat 的 `Server startup in`、Vite 的 `ready in`、`Local: http` 这类）再发一次 HTTP 确认；看到起不来的标志（`APPLICATION FAILED TO START`、`BUILD FAILURE`、端口被占、`npm ERR!` 这类）马上停掉自己起的进程、贴日志返回，不干等。端口照旧连（不发请求）；日志里认不出标志的，端口通了之后每 10 秒发一次 HTTP，60 秒不答照旧算起来。
