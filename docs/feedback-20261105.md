# 2026-11-05 审查时机：四份文档写完审一次，一个 change 做完审一次

问题表第 57、58 条（原话在 [owner-issues.md](owner-issues.md)）。仓库主人："改成自动模式下写完所有task再开始自动审核，手动模式下提醒用户看一看，然后引导继续执行下一步 写完task询问是否审核"；"再帮我看看apply的审核时机是什么，如果也是一个个来的话也太消耗时间了，看看怎么改"。

## 要定的

问过仓库主人 apply 改成哪种（每个 change 审一次 / 所有 change 做完审一次 / 保持按组审），选"每个 change 审一次"。

## 修改

- **审查点**：`points` 改成必审的点：文档 `tasks`（tasks.md 写了才有，审整套），代码 `change`（任务全勾完才有，审开工基线以来的全部改动）和跨 change 的 `cross-*`。新加 `written`（写好了哪几份，原来 `.length === 4` 的地方用它）、`reviewable`（必审的加上用户点名才审的单份文档、做完的组）。`group-rest` 取消。
- **`tasks` 这个名字接着用**：它的输入本来就是四份文档，旧版审过的记录接着认。
- **`change` 的指纹分两段**（文档和任务 : 代码），`sameInput` 比。后面的变更开工了（`work-baselines` 里同一项目有更晚的记录）只比前一段：不然 c2 改代码会把审过的 c1 重新打开，c1 的范围里又混着 c2 的改动。
- **升级**：没有 `change` 记录、每组都过了的 change 算审过，不重审。
- **钩子**：`guard-spec` 自动模式写下一份不看审查，人工只提醒看一看、引导下一步；打勾只要求上一组做完。`stop()` 自动模式 tasks 没写时催接着写（同一份内容只催一次）；人工 tasks 没写时提醒看一看，写了才问审不审。`actionIssue` 自动模式下没人要求就单独审单份、某一组的拦下。
- **审整套**：`review-runner` 四份都审、不标上游；`STAGE.tasks` 改成整套的要求；单独审过留下的 deferred 带进第一轮；审整套不能标 deferred（没有后面的文档，标了这条就没人看了）。
- **相邻两处**：`nextStepTodo` 人工模式不审的接着引导下一步，在问、审过没收尾的才停；`bar` 最后一个 change 做完、有 change 在审时步骤条显示它，多一个"审查"。
- **文字**：规范、审查技能、`/vk-auto`、`/opsx:propose` 的套件规矩、开口和开工的提醒、README、`手册/审查和自测.md`、`手册/上下文和token.md`、配置页（流程图和"套件说明"页）、更新说明、决定记录。

## 复审

别的模型（Sonnet）独立复审，报告 [reviews/claude/20261105-审查时机-复审.md](../reviews/claude/20261105-审查时机-复审.md)。6 条都核实成立，都修了：

- 大任务只记现在要做的 change 的开工基线；后面开工的 change 目录不在了不算；同名重建重记基线。
- `change` 审查不送"开工前就有改动、开工后没动过"的文件，前面 change 没提交的代码不再重审。
- 升级时每组都过了，没点名的文件有改动的还要 `group-rest` 审过。
- 人工模式这一轮要了审查、还没审，不往下走。
- `change` 的指纹排除构建目录，大文件不读内容，一次钩子调用只算一次。

## 自审

- **同类入口**：`points(dir, 'proposal')` 当"写好的文档"用的地方都换成了 `written`；`group-rest`、`restFiles` 清干净了；提示语、规范、技能、手册、配置页按"每份""每组""逐产物"全文搜过。
- **全自动**：模型写完一份就停没人催（核对第 5 条）是这批才有的新问题，加了"接着写下一份"，同一份内容只催一次，不会循环。
- **出错放行**：新加的都在原有的 try/catch 里，或者只读状态。
- **令牌保护**：`NOT_INPUT` 排除 `secrets.json`、`.env`、`router-data`，指纹不读这些文件。
- **配置页说明和行为双向**：流程图、"套件说明"页的审查和自测几条改了，步骤条说明带上"审查"。
- **新测试拿上一版跑**：112 项里 73 项不过。
