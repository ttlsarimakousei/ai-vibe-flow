# 2026-10-07 导出议题的核对

2026-10-10 处理。原始导出文件包含内部项目路径、电脑名和流水账，不放进仓库；这里仅记录可复现行为和处理结果。

| 议题 | 核对结果 | 处理 |
|---|---|---|
| #11 | 命令行可损坏中文 SQL；文本结果本来按显示宽度排版，不能当固定字符列处理 | 非 ASCII 和空 LIKE 的命令行 SQL 先拒绝；中文走文件；JSON 原值输出含截断标记；补显示宽度说明 |
| #12 | `env -C` 的目录参数被当成命令名，误拦套件脚本 | 解析临时工作目录，内层命令重新检查；后续命令恢复原目录；套件写保护和令牌保护保留 |
| #13 | 否定归因漏认 vibe-kit 和分隔空格；整段否定还会吞掉另一句肯定 | 按句子检查肯定归因，标题和否定不算；转折后的明确问题照常提醒 |
| #14 | 外部技能模板含 scope、多行，公司规范是单行 | 外部技能没有包含在本仓库；不放宽提交规范，其源仓三处模板应改为 `chore: 初始化 <名字> 过程资产仓` |
| #15 | 当前版能识别裸名、相对目录、完整路径；没有复现报告中的漏记 | 技能示例统一裸名，保留路径兼容；独立重置记录验证前台结果、后台通知、错误变更名不借用其他名字 |
| #16 | 旧确认串固定有中文，容易受 Windows shell 影响 | 新串全部 ASCII；文件确认兼容旧串，仍核对 SQL 指纹、影响面和一次性；查找关键字和按值条件也能从文件读取 |
| #17 | apply 全自动标记无条件拦 push，没有识别用户当场要求 | 最后真实用户指令明确授权时放行；否定、问句、旧授权取消、后台通知不授权；没授权的全自动 push 仍拦 |

新增专项回归 `dev/test-feedback1007.js` 在修复前 20261007.1653 上有失败；修复后通过。数据库 JSON、文件确认和中文参数文件由真实 H2 读写验证覆盖。

同类排查还收紧了确认来源：只认对应 AskUserQuestion 的结果，工具输出里的同款文字不能冒充人工确认；新用户消息之后迟到的旧答案也不能覆盖新指令。SQL 文件不能解码时停止，避免替换坏字节后跑出另一条 SQL。

代码推送的授权不能用于发布内网安装包；发布仍单独确认，包括临时工作目录里的相对发布脚本。条件文件为空时在连接数据库前报错，不能退化成无筛选查询。

外部技能 #14 的修正方式：Phase 3.3、M2.3、M3.3 的提交模板均改为单行，把原来正文里的资产列表写进该壳子的 README 或 workspace.yaml。需要在其源仓改，不由套件安装器覆盖用户的外部技能。
