用户要用小改动快车道修：$ARGUMENTS

1. 先查清原因：归档过的功能出的问题，用套件的 tools/trace.js 溯源，找到当时的需求和改动。
2. 直接改，不建提案、不写需求文档。
3. 跑快检（项目说明里的快检命令，编译级）。
4. 不问要不要审查、自测。做完交代改了什么、为什么、快检的结果，最后用一个提问框问一次要不要提交。

超出小改动就停下，说明原因，建议走提案：要改三个以上的文件、改接口或表结构、改需求，都算超出。
