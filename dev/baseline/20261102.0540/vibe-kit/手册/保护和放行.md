# 保护和放行

套件拦下的事分两类：做错了收不回来的（改套件、读令牌、push 这些），什么时候都拦，不能放行；流程类的检查（提案门槛、产出位置、过程文件这些），它确信是套件拦错了，可以申请放行那一步。回到[用户手册](../README.md)。

## 禁止 Claude 改套件（默认开）

发生过：Claude 嫌钩子碍事，自己去改 `~/.claude/vibe-kit` 里的钩子。开着时：

- 用 Edit、Write 改这些一律拦：`~/.claude/vibe-kit` 整个目录、`settings.json`、全局 `CLAUDE.md`、套件装进去的技能和审查代理。
- 命令行改也拦：rm、del、Remove-Item、cp、mv、`sed -i`、`find -delete`、`>` 重定向、管道后面的写入、跑 `install.js` / `service.js`，只要命令里出现套件的路径（`~`、`$HOME`、`%USERPROFILE%`、`$env:CLAUDE_CONFIG_DIR`、cd 过去再改、目录联接都认得出）。直接调路由的 `/api` 和钩子入口也拦。
- 往任何 `settings*.json` 里写 `disableAllHooks`（会把所有钩子一起关掉）都拦。
- 不拦：只读命令（cat、type、Get-Content、ls、grep……）；跑套件自带的工具（`tools/`、`page/` 里的脚本）；项目里的东西（`.vibe/`、代码、openspec）。
- 拦下时让它把原因和想改成什么告诉你，由你来改。确实要让它帮你调钩子、改规范，先在配置页"保护"里关掉这个开关，改完再打开。

两道兜底：

- **套件代码被改过能发现**：安装时记下 hooks、lib、tools、page 下每个脚本的指纹，每个会话开始时比一遍。对不上的告诉 Claude 先跟你说、别去"修"，状态栏挂红字"套件代码被改过"，并记一条问题反馈。重新运行安装包就恢复。
- **开关防篡改**：关掉禁改、打开"它自己放行"，只认配置页（和安装器）改的。绕开配置页直接改 `config.json` 的，钩子按安全的值算，状态栏挂红字"套件开关文件被直接改过"，并记一条问题反馈。在配置页改这几项也各记一条，"保护"一节下面看得到最近的改动。

## 令牌和模型的 key

GitLab 的令牌存在 `~/.claude/vibe-kit/secrets.json`，模型的 key 在 `~/.claude/vibe-kit/router-data/`。配置页只显示遮过的样子。模型读不到，三道一起挡：

| 模型怎么读 | 谁来挡 |
|---|---|
| Read 工具；Grep 直接搜这两处 | 安装器在 `settings.json` 里加的两条"不许读"的权限规则 |
| Grep 对着上级目录（套件目录、`~/.claude`、用户目录）搜内容 | 读文件的钩子（权限规则管不到这种搜法） |
| 用命令读（`cat`、`Get-Content`、`grep -r`、`node -e`） | 跑命令的钩子 |

- Grep 只看文件名、只数个数的不拦。整条命令只是列目录、按名字找、过滤名单的不拦（`ls <套件目录> | head -30`）；列完接着用 `xargs`、循环、`-exec`、命令替换去读的照样拦。
- 关掉"禁止改套件"之后这两处照样不给读。
- 这是防误读，不是防攻击：令牌在本机是明文，能登录这台电脑的人都看得到。

## 不让它停在确认框上、不误杀路由

- **串着 cd 的命令**：`cd 子项目 && mvn …` 这种，Claude Code 会停下来等人点确认，开着跳过权限模式也照样问，自动模式时就一直挂着。套件当场拦下，按后面的命令给出不用 cd 的写法：`git -C`、`mvn -f`、`npm --prefix`、`devserver.js --cwd`，脚本和文件写完整路径，搜代码读文件用 Grep、Read。单独一条 cd 不拦。
- **一把结束所有 node**：`taskkill /IM node.exe`、`Stop-Process -Name node`、`pkill node` 会把模型路由一起杀掉（Claude Code 连模型、套件的检查都靠它）。装了路由时这类命令一律拦，让它按端口找到 PID 再停。结束路由自己的进程也拦。

## 中文不被写坏

Claude Code 读写文件只认 UTF-8：用 Edit 改 GBK 文件里的一个数字，整个文件的中文都会变成乱码，工具还照常报成功。所以拦三种：

1. 目标文件是 GBK。
2. 目标文件里 GBK 和 UTF-8 的行混着。
3. 新文件或纯英文文件要写进中文，而同目录的同类文件以 GBK 为主。

工程以 UTF-8 为主的，提示会给出把这一个文件转成 UTF-8 的命令；以 GBK 为主的不能单转（按 GBK 编译会编不过或者变乱码），停下来让你定；两种编码混着的，停下来让你在 IDE 里统一成一种。判断不了（二进制、读到的不是明文）就放行。

## 代码之外的产出放哪（默认开）

DDL 脚本、功能说明、分析报告、导出的清单这类文件放哪由你定，不由模型自己挑。

- 新建 `.sql`、`.md`、`.txt`、`.docx`、`.xlsx`、`.csv`、`.pdf` 这类文件时，位置没确认过：不停下来问你，先写到 `.vibe/pending/`，接着干；这件事做完收尾时用一个提问框问你放哪（一个文件一个问题，选项写实际目录），定了挪过去、记进项目说明的"产出位置"（2026-10-30 起，以前是新建时先问）。确认过只认两种：项目说明"产出位置"里记着的；你这次会话里亲口说过、在提问框里选过的路径。提问框问"放哪"、你选"项目根目录"的，根目录下的文件也算（#225）。你定了它记进项目说明，以后同类的不再问；这个会话里用提问框问过你放哪、它照你的答案记进项目说明的，当场就算定过（会话里没问过你、它自己加的不算）。两种拦截说的是同一条规矩，为前一种申请的放行，后一种也认。
- 不管的：改已有的文件；openspec、`.vibe`、`.claude`、临时目录；README、CHANGELOG 这类；源码目录里的 `.sql`；代码目录（resources、test、public、static、assets、i18n、mapper……）里的文件；技能工程、文档工程里的文档。
- 自动模式生效时收尾也不问：收工报告里列在"等你回来定的事"。项目里现成的同类目录（同一目录已经有两个以上同类文件）直接用，人工、自动都一样。`requirements.txt`、`CMakeLists.txt` 这类构建、依赖清单不算产出。
- 按会话启动的那个目录找定过的位置。壳子的 `CLAUDE.md`、各个子项目的项目说明都看。写法里的 `<需求编号>`、`{日期}` 当通配符，"不要放在 src/ 下"这种否定的不算。

项目说明（本机）或团队的 `CLAUDE.md`（一起提交）里这样写：

```markdown
- 产出位置：
  - DDL 脚本：sql/ddl/
  - 功能说明、分析报告：docs/
```

## 过程文件都放 .vibe/tmp（默认开）

`.vibe/` 不进仓库，只放套件长期要用的：项目说明 `project.md`、交接记录、账号 `login.json`、快检的中间文件、看页面的 `scenarios/`、`out/`、`design/`，起服务的记录 `run/`，位置待定的产出 `pending/`，收工报告 `reports/`。

- 备份、临时脚本、草稿、测试数据、日志、导出的中间结果放 `.vibe/tmp/<事由>/`，一件事一个目录（做 OpenSpec 变更时事由就是变更名）。往 `.vibe` 别处新建文件会被拦下，告诉它放哪。
- 往项目里留过程文件也拦（用 Write 写，或者 `cp`、`mv`、`> 文件`、`| tee` 生成）：`A.java.bak`、`x.orig`、`build.log`、`A - 副本.java`；旁边有原文件才算的 `A_old.java`、`A备份.sql`；项目里原来没有的 `bak/`、`backup/`、`tmp/` 目录。`git add` 过程文件也拦。拦错了（比如测试要读的 `sample.log`），它原样再做一次就放行，同一个文件只拦一次。
- 临时看 JAR、ZIP、WAR、TAR、7z：先只列目录或读条目（`jar tf`、`unzip -l`、`unzip -p`）。解包到项目根、源码目录或 `.vibe/tmp` 根会被拦，要放 `.vibe/tmp/<事由>/`。
- 什么时候删：事由是变更名的留到变更归档，之前删会被拦，归档后套件自己清；别的事由做完就删；`.vibe/tmp` 里 7 天没动的会话开始时自动清（天数在配置页"全局：过程文件"改，0 是不清）。`pending/` 不清。
- 收工时点名它这个会话新建了、还没进 git 的文件，和冒出来的备份、日志：要交的提交，测试用的删掉。
- 以前堆在 `.vibe` 里的零散旧文件：`node "%USERPROFILE%\.claude\vibe-kit\tools\vibe-tidy.js" [项目目录]` 先列出来，确认后加 `--apply` 挪进 `.vibe/tmp/<日期>-整理/`，不直接删。

## 兜底放行

检查写错了会把活卡住，但也不能让它随便绕过去。所以只放行"被拦的那一步"，并留下记录。

- 能申请的只有带〔拦截编号〕的流程类检查：OpenSpec 产物的门槛（打勾、含糊词、任务写法、先探索再提案等）、归档门槛、产出位置、过程文件、起服务要经过 devserver、提交信息格式、新文件没 add。
- 不能放行（没有编号）：改套件、关掉钩子、结束路由进程、读令牌和 key、改非 UTF-8 文件、整仓 add、`commit -a`、gitlink、push 确认。
- 怎么申请：`node "%USERPROFILE%\.claude\vibe-kit\tools\feedback.js" bypass <拦截编号> --why "查证过什么、为什么过不去"`（少于 20 个字不收）。它会记一条问题反馈，再开一张通行证：30 分钟内、只在这个会话里、对同一个文件或同一件事的这道检查有效。中间内容变了照样有效。拦截编号是四位字母数字；拿问题编号（F 开头）去申请会明说拿错了。
- 再做那一步时按配置页"保护"里"被检查拦住时能不能放行"：

| 选项 | 会怎样 | 上限 |
|---|---|---|
| 要我点同意（默认） | 弹确认框，框里写着它的理由和问题编号，你点同意才放行；通行证只用一次 | 每个会话 5 个不同问题，同一类检查 3 个 |
| 它自己放行 | 不弹框 | 每个会话 60 个不同问题 |
| 不许放行 | 被拦就停下来告诉你 | — |

- 自动模式生效时不用你点：能申请的当场放行，通行证 30 分钟内可以用多次，每次记进收工报告；不加 `--bug` 不记问题反馈。选了"不许放行"的照样不放行，上限按 60 个算。
- 同一检查、目标和理由的重试不重复扣额度，申请结果里写着还剩几个。放行记录在配置页"更新和上报"。
- 为什么不干脆让它改套件：改了的代码下次装新版就被覆盖，别的同事那边照样是坏的；真正的修复走问题反馈，回到改套件的人那里发新包。

## Claude Code 自带的 auto mode 默认关掉

这不是套件的自动模式（会话里 /vk-auto 开的那个），是 Claude Code 自己的一种权限模式：有风险的命令先交给一个分类模型判断放不放。2.1.284 起没配过权限模式就默认进它。经网关用内网模型时它只添麻烦（2.1.289 实测）：

| 情况 | 结果 |
|---|---|
| `node -e`、`curl` 这类有风险的命令 | 每条多发一个分类请求，系统提示约 14 万字符，照常算用量 |
| 分类模型答得不合格式（内网模型多半这样） | 重试十次，再把命令拦下，说 "Auto mode could not evaluate this action" |

所以安装器在 `settings.json` 的 `permissions` 里写 `disableAutoMode: "disable"`，权限照原来的走。2.1.120、2.1.259 不认识这一项，不受影响。

- 想用它：配置页"保护"里"Claude Code 自带的自动模式"改成"不管它"，重新打开 Claude Code 生效。
- 你自己在 `settings.json` 里写过这一项的，套件不动，卸载时也不收回；你自己把 `permissions.defaultMode` 设成 `auto` 的，套件不加这一项，安装时提醒一句代价。启动时带 `--dangerously-skip-permissions` 的不受影响。

## IDEA 的 MCP

（原来的《IDEA 接入》，2026-10-30 并进这里。）

2026-10-28 起套件不再接 IDEA 的 MCP，也不再用 IDEA 的运行配置起服务。

### 变了什么

- 安装、更新不再把本机 IDEA 的 MCP 登记给 Claude Code，后台也不再探测。配置页"本机环境"里的"IDEA MCP"一节去掉了。
- 以前套件登记的 `vibe-idea-端口`：装新版时撤掉（重新打开 Claude Code 生效）。你改过那一项的，留着不动，安装时说一句；不用了在 Claude Code 里 `/mcp` 删掉。你自己登记的（比如叫 `jetbrains`）不动。
- 起服务只走 `tools/devserver.js` 照命令起，见[审查和自测](审查和自测.md)。你在 IDEA 里起着的服务套件不动：端口被它占着时说清是谁，要不要重启问你。以前用 IDEA 起、devserver 记着的那一份，`stop`、`status` 时说一句"到 IDEA 里停"，记录清掉，进程不动。
- `devserver.js start` 写了 `--idea` 的不报错，照 `--` 后面的命令起。

为什么去掉：要 IDEA 开着、项目在 IDEA 里打开、开了 brave mode、运行配置没错，缺一样就起不来或者挂住；IDEA 的 MCP 停不了普通 Run 起的服务；模型直接调运行配置和走 devserver 两个入口互相拦。用下来被拦、起不来比省下的事多。

### 自己登记的 IDEA MCP 走哪些检查

你自己在 Claude Code 里登记 IDEA 的 MCP 照样能用，套件只做和普通工具一样的检查：

- 终端命令（`execute_terminal_command`）按 Bash、PowerShell 的检查走：push 要确认、结束路由、整仓 add、串着 cd 这类。
- 改文件（`replace_text_in_file`、`create_new_file`、格式化、重构、批量补丁里点到的文件）按 Edit、Write 的检查走。
- 读套件的令牌文件、模型的 key、Claude Code 的用户配置（`.claude.json`）照拦。认不出是 IDEA 的 MCP，写明的路径参数读到这些也拦。
- 人工模式下，`execute_run_configuration` 算自测，先问你；`build_project`、`get_file_problems` 算快检，直接跑。
- 别的不拦：查库工具、整份运行配置、运行参数、调试表达式、新工具。返回的内容不遮口令。
