# 看页面

你不能凭想象说页面"应该没问题"。这个技能让你真的打开页面操作一遍，拿到页面上实际的值。

做法是：你写一个场景文件（JSON，几行声明式步骤），交给执行器跑，它用本机的 Edge 无头执行，把每步结果、读到的值、页面结构写成文本交回来。判断对错靠这些文本，不靠看图：读一张截图要花的 token 比读一份结构文本多得多，还不如数字准。

## 步骤

1. **确认服务在跑**：用 `node "$HOME/.claude/vibe-kit/tools/devserver.js" start --name <名字> --port auto --avoid <项目说明里的端口> -- <项目说明里的启动命令>`（vite 这类会热更新的它自己认得，改了代码不重启；Vite 不认环境变量 PORT，命令写 `npm run dev -- --port {port}`）。端口是它在 30000 到 39999 里挑的，离项目配置的远，和用户在 IDE 里起的不撞；起来之后最后一行说用的是哪个端口，后面 `--base` 就用那个。它记着以前起过的：已经在跑、跑的是现在的代码就直接用；改过代码就重启。起好（答了 HTTP）才返回。不是你起的、本来就在跑的服务（用户自己开的）不要动。
2. **写场景**到 `.vibe/scenarios/<名字>.json`。在壳子目录里干活的，这里的 `.vibe/` 指那个前端子项目里的，不是壳子根目录下的，场景跟着子项目走。格式见同目录 `scenario-format.md`，先读它。`.vibe/` 不用你管忽略的事：往里写文件时，钩子会自动把 `.vibe/` 加进那个仓库的 `.gitignore`。
3. **执行**：
   ```
   node "$HOME/.claude/vibe-kit/page/scenario-run.js" .vibe/scenarios/<名字>.json --base http://127.0.0.1:<devserver 起来时说的端口>
   ```
   结果放在当前目录的 `.vibe/out/<名字>/`（要放别处加 `--out <目录>`）。`--base` 是前端服务的地址，场景里 `goto` 写了相对路径就必须给，执行器不去猜端口。退出码 0 是全过，1 是有步骤失败（步骤名、选择器写错也算 1，报错里会写"不认识的步骤"），2 是参数或场景文件有错（JSON 不合法、没有 steps、没给 `--base`、忽略规则的正则写错），报错里写着原因。
4. **看结果**：控制台最后一行 `RESULT {...}` 有读到的值、失败的步骤、console 报错，以它为准。某一步失败后，后面的步骤不会执行。截图留在 `.vibe/out/<名字>/` 里给用户看；你自己只在一种情况下读图：某步失败了、报错文字又说明不了原因，这时读那张 `failed-step-N.png`。
5. **有问题就改代码再跑**，直到通过。场景文件留着，以后回归还能用。

## 写场景的要点

- 需要登录的系统，场景第一段就是登录。账号先看 `.vibe/login.json`，没有再问用户一次，问到就记进去；不要猜。**登录那一步要查返回的内容**（见 `scenario-format.md` 的"接口"一节）：很多系统登录失败也返回 200，只等它返回的话，没登录上场景照样往下走，后面全是 401。
- 场景文件做不了的操作：写探针到 `.vibe/tmp/<事由>/probe.js`，在被测项目目录运行 `node "$HOME/.claude/vibe-kit/page/probe-run.js" .vibe/tmp/<事由>/probe.js`。探针导出 `module.exports = async ({ page, context, assert }) => { /* 操作、读取并 assert 核对 */ return { 实际读到的值 }; };`。执行器提供系统浏览器，默认执行上限 120 秒，结束自动关闭。成功输出 `PAGE_PROBE {"ok":true,…}` 才算验过；断言失败、超时、后台未结束都不算。事由是变更名的留到归档，别的验完删掉。
- 探针例子：`module.exports = async ({ page, assert }) => { await page.goto('http://127.0.0.1:实际端口/页面'); const text = await page.locator('h1').innerText(); assert.equal(text, '订单'); return { 标题: text }; };`。原有独立脚本改为这个导出函数，复用传入的 page/context，不自行起浏览器。
- 自测前核对前端代理如何指向自测后端，包含项目上下文路径；统一认证回调和服务端 CORS 若限制固定端口，记录到项目说明。不能通过关闭浏览器安全检查解决服务端拒绝。菜单驱动的标签页要按真实菜单进入，不能假设改 hash 就能打开。
- 选择器优先用语义写法：`{"role": "button", "name": "保存"}`、`{"label": "用户名"}`、`{"placeholder": "请输入"}`。Element Plus 这类组件库渲染出来的类名和层级不稳定，少用长串 CSS。
- 加上 `"disableAnimations": true`，弹窗、下拉的过渡动画会让截图截到中间帧。
- **会产生数据的操作（提交、保存、删除）只做一次**。成功提示一闪就没了，很容易错过，错过了不要重新提交，去读列表里有没有多出那条数据来确认。
- 每个场景最后加一条 `{"expectNoConsoleErrors": true}`。开发态的噪音用 `"consoleIgnore": ["[Vue warn]", "[HMR]"]` 忽略（按字面匹配；要用正则就写成 `"/…/"`）。
- 一个场景只验一件事，十步以内。要验的多就拆成几个文件。

## 验后端接口

改了后端（接口、业务逻辑、SQL），光"编译通过"不算验过：写一个接口场景真调一次，查状态码和返回的字段。规格里的"当……则……"场景，结果在接口返回里的，就照着写成接口场景。

- 场景里全是接口步骤（`request`、`expectStatus`、`expectJson`、`readJson`）时不开浏览器，几秒就跑完；`--base` 给后端服务的地址。
- 要登录的：先 `goto` 登录页走一遍登录，或者直接 `request` 调登录接口；之后的 `request` 自动带着登录状态（同一份 cookie）。
- 页面上点按钮发出的请求：用 `waitResponse` 等它返回再查，比等提示文字准。
- 会写数据的接口只调一次；确认结果用查询接口，不要重复提交。
- 写法见 `scenario-format.md` 的"接口"一节。配置页（模型路由的地址）不是被测的项目，执行器不让打开。

## 还原原型、设计图

公司的规定：**还原度用工程手段解决，不靠看着截图临摹。** HTML 原型还原成 Vue，先按公司的流程把 HTML 标准化成 spec，再照 spec 写 Vue。这里做的是还原之后的**验收**：用数字说话，差多少像素、哪个颜色不对，一条条列出来改。

### 原型是 HTML（首选）

让执行器分别打开原型和你写的页面，各导出一份页面结构，然后对比两份文本。全程不用读图。

1. 原型导出结构。场景里 `goto` 可以直接写本地文件的地址（`file:///D:/…/login.html`，路径里的中文和空格要编码，用 `node -e "console.log(require('url').pathToFileURL('D:/原型/login.html').href)"` 生成）：
   ```
   {"viewport": {"width": 1440, "height": 900}, "disableAnimations": true,
    "steps": [{"goto": "file:///…/login.html"}, {"layout": "proto"}]}
   ```
2. 你的页面用同样的视口导出：`{"goto": "/login"}, {"layout": "page"}`。
3. 对比 `proto-layout.txt` 和 `page-layout.txt`。每行是一个元素：位置、宽高、文字色、背景色、字号、内边距。两边的类名和层级不一样是正常的，按**文本内容和先后顺序**对应元素，逐项比：位置和尺寸差 2 像素以内算一致，颜色和字号要完全一样。
4. 把对不上的列成清单（哪个元素、哪一项、原型是多少、现在是多少），改样式，重跑第 2 步，直到清单清空。

### 只有图片

1. 设计图放到 `.vibe/design/<名字>.png`，场景里把视口设成和它一样大。
2. 三步固定按这个顺序写，名字相同：
   ```
   {"screenshot": "page"}, {"layout": "page"}, {"diff": "page", "ref": "../design/<名字>.png", "max": 3}
   ```
   - `ref` 是相对**场景文件所在目录**的路径，`max` 是允许的差异百分比。
   - layout 必须在 diff 前面：diff 靠它指出差异落在哪个元素上；而且 diff 超过阈值会让场景停下，放在后面就不会执行了。
3. 会变的区域（时间、随机数据、头像）用遮罩盖掉：`{"screenshot": "page", "mask": [{"text": "更新时间"}]}`。比对时设计图的同一块也会被盖掉，不计入差异。
4. 看 `page-diff.txt`：它列出差异集中在哪些元素上。对照 `page-layout.txt` 里这些元素的数值改样式，重跑，直到差异降到阈值以下。
5. 差异明细看不出原因时，才读 `page-diff.png`（差异图）。

最后请用户看一眼，视觉上以用户说的为准。

## 收尾

- 你起的服务要停掉：`node "$HOME/.claude/vibe-kit/tools/devserver.js" stop --all`（接下来马上还要测就先留着，下次 start 会直接复用）。
- 告诉用户：验了什么、结果如何（读到的值、差异百分比）、产物在哪个目录。没验到的地方明说。
