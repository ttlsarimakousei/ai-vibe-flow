# 交接

公司规定上下文用到 70% 必须交接并开新会话。目的只有一个：新会话只读一个文件就能接着干，不用用户把事情重新讲一遍。

## 做法

1. **先查实际状态，不靠回忆**：
   - `git status --short`。在壳子目录里干活的，这次动过的每个子项目各查一次（`git -C <子项目目录> status --short`）。
   - 进行中的 OpenSpec 变更：读它的 tasks.md，数清做到第几项。
   - 你起过的服务：`node "$HOME/.claude/vibe-kit/tools/devserver.js" status` 看一眼。还在跑的，要么 `stop --all` 停掉，要么写进交接记录（新会话开头会被告知，再 start 时直接复用）。
2. **写 `.vibe/handover.md`**，放在启动 Claude 的那个目录下，覆盖旧的。按下面的格式，不超过 60 行。
3. `.vibe/` 不用你管忽略的事：写文件时钩子会自动把它加进那个仓库的 `.gitignore`。
4. 只回用户一句：交接记录写好了。输入 `/clear`，然后说一句"继续"，新会话会先读交接记录再接着干。不要再做别的事，不要总结。（`/clear` 只能用户自己敲；新会话里用户说"继续"，钩子会把交接记录接上。配置页开了"/clear 之后自动接着干"的，不用说话它也会接着干。）
5. **全自动模式开着时**（约定里有"全自动模式（已开）"一节）：用户不在，没人敲 `/clear`。上面第 4 步不做。写完交接记录**接着做手头的事**：不收工，不记经验，不写总结，不等用户。"下一步"里写清接下来做哪个变更的哪一项任务，写完就去做它。交接记录是给会话万一断了、第二天重开时用的。之后做完了一大步，覆盖更新一次这份记录，免得它过期（新会话发现记录里的事已经做完或归档，会当它过期、不照着做）。

## 格式

```markdown
# 交接记录（2026-09-19 16:40）

## 在做什么
一两句：目标是什么；属于哪个 OpenSpec 变更（名字、任务 3/7）；正在执行哪条指令（比如 /opsx:apply）。

## 已经做完并验证过的
- 做了什么（怎么验证的：跑了哪条命令、看了哪个页面）

## 做了一半的
- 哪个文件、做到哪、还差什么
- 没提交的改动在哪些仓库

## 下一步
1. 具体到文件和命令，新会话照着就能动手

## 这次会话里才知道的
- 用户纠正过的做法、明确提过的要求
- 试过但走不通的路（别再试一遍）
- 环境上的坑

## 没验证的、拿不准的
- …
```

## 不要写

- 代码里、git 记录里看得出来的东西。
- 对话经过、客套话、总结陈词。
- 账号密码。
