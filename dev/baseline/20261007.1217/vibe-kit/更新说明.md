## 升级怎么做

**装了 0928 晚上之后的版本，以后不用再拷压缩包**：维护的人发布到团队的 GitLab 仓库，你的电脑自己发现、自己装上（配置页"更新和上报"里能改成只提醒、不检查）。**没装过的人**也不用等人发包：仓库里放的就是解开的安装包，在仓库页面点"代码"下载 zip（或者 `git clone --depth 1`），解压后双击里面的 `安装（双击我）.bat`，见 README 的"安装"。下面是手动装的办法，第一次装、自动更新用不了的时候用。

1. 把新的压缩包**整个解压**出来，双击里面的 `安装（双击我）.bat`（在压缩包里直接双击会提示先解压）。
2. 装在原来的上面就行，不用先卸载。这些都原样保留：
   - 套件开关 `config.json`、本机环境 `local.json`
   - 路由里配好的模型和 key（`router-data`）
   - 问题反馈（`feedback`）、你自己加的规范
   - GitLab 的仓库地址和令牌（`gitlab.json`、`secrets.json`）
   - 你从 `settings.json` 里删掉的权限、环境变量，不会被补回来
3. **不用重开 Claude Code，也不用 `/clear`**：钩子立刻生效；约定和技能变了的部分，在你下一次发消息时由钩子带给它。路由会用新文件自动重启一次，正在跑的请求会断一下。

## 20261007.1217（最新）

用户用下来提的四件事。

### 让它出一份文档、生成个文件记东西：不算流程里的活，放哪照常问

起因：全自动开着，在流程里让它"生成一个文件记录一下"，钩子说全自动不问、让它自己定放哪。全自动只该在走 OpenSpec 流程时算数，可"正在流程里又说了一句话就还在流程里"把这种也算进去了。

- 现在：让它出一份代码之外的东西（说明、报告、清单、表格，或者"生成一个文件记一下"），这一轮不在流程里，放哪照常用提问框问你，全自动不作数。说"继续"接回流程。
- "做一个文件上传功能""加个导出接口"这类是代码的活，照旧算需求、进流程。

### 公共配置里被 dev 盖掉的库不再算开发库

起因：`db-crud.ini` 里混进了非开发环境的库。查下来是 `application.yml` 里写着一个库、`application-dev.yml` 用同一个键换成了开发库：跑开发环境时公共配置那一条被盖掉，留在那里的多半是测试、生产库，以前照样被算成开发库。

- 现在：公共配置里的连接，被同一处的开发环境配置（`application-dev.yml`、同一个文件里 `on-profile: dev` 那一段、`config/` 子目录里的）用同一个键换掉的，不算。多数据源只换了其中一个的，没换的那个照算。redis 一样。
- 已经写进 `.vibe/db-crud.ini` 的旧连接不会自动删：重新探索时它那一段上面会标一行"来源文件里已经找不到这个连接"，自己删掉那一段就行。

### 起服务的端口改成自动挑，离项目配置的远

起因：你自己在 IDE 里按配置的端口起服务验证，Claude 起的和你的撞上；这一类项目的端口还是顺着编的。

- 现在 `devserver.js start --port auto --avoid <项目配置的端口>`：在 30000 到 39999 里挑一个空着的，离 `--avoid` 的端口至少 1000。同一个服务每次挑到同一个端口。
- 端口怎么交给服务：命令里的 `{port}` 换成它；环境变量 `PORT`、`SERVER_PORT` 也设成它。Spring Boot、Vue CLI、Next、CRA 不用改命令；Vite、webpack-dev-server 要写 `npm run dev -- --port {port}`。项目说明里的"启动"一行会写明用哪种。
- 前端代理写死了后端端口的，前端打不到自动挑的后端：这种情况后端用 `--port <配置的端口>` 指定，或者把 vite 配置里的代理目标改成读环境变量。
- 约定、技能、起服务的拦截提示都改成这个写法；起来时那一行和 `status` 里标着"自动挑的"。

### 自动提交多了一档：一个阶段做完提交一次

每完成一件事就提交太碎，整个变更做完再提交又太大。中间那一档：tasks.md 里同一个大编号的任务（1.x、2.x……，写提案时按数据层、接口、页面这样分组，一组三五项）全部打勾了提交一次，信息写这一组做了什么；一组做到一半不提交。收工检查只在刚做完一个阶段（这一组最后一个勾打在仓库最近一次提交之后）时催。配置页"套件开关"里"验证过之后提交吗"选"一个阶段做完提交一次"。默认还是每完成一件事提交。

也想过别的办法，没做：每 N 项任务提交一次（N 和任务的大小没关系，分不出一组做的是什么）；每项任务照旧提交、归档时合并成一个（要改写 git 历史，套件不让模型动历史）。

## 20261005.0302

三件事：在当时最新的 Claude Code（2.1.289）上把套件验了一遍，查出一个要紧的问题并改了；全局约定加了官方那句"说话直说"；把套件自己审了一遍（安全一遍、1001 那一批新代码的逻辑一遍），属实的都改了。

### Claude Code 2.1.284 起默认进"自动模式"：套件默认把它关掉

这里说的不是套件的"全自动模式"，是 Claude Code 自带的一种权限模式（auto mode）：有风险的命令先交给一个分类模型判断放不放。2.1.284 起，没配过权限模式的话默认进这个模式。在 2.1.289 上实测，经网关用的时候：

- `node -e`、`curl` 这类命令，每条先多发一个分类请求，系统提示约 14 万字符，照常算用量。`echo`、`git status`、在项目里读写文件不发。
- 分类模型答得不合它要的格式，就重试十次，然后把这条命令拦下。内网的模型多半答不对。
- 没关它之前，套件的端到端测试在 2.1.289 上有 31 项不过（命令被拦、审查代理跑不起来）；关掉之后 190 项全过。

现在安装器在 `settings.json` 里写 `permissions.disableAutoMode: "disable"` 把它关掉，权限照原来的走。内网现在用的 2.1.120、2.1.259 没有这个模式，也不认识这一项，装上不受影响；以后升到 2.1.284 以上不会掉进去。

- 配置页"套件开关"那一页"保护"里多了"Claude Code 自带的自动模式"：关掉（默认）/ 不管它。改了要重新打开 Claude Code。
- 你自己在 `settings.json` 里写过这一项的、自己把 `permissions.defaultMode` 设成 `auto` 的，套件不动；后一种安装时提醒一句。

| 改了什么 | 说明 |
|---|---|
| 串着 cd 的命令一律拦下 | 拦的时候按后面跟的命令给出改好的写法，模型照着重跑一次就过了，不会停在确认框上。单独一条 cd 不拦 |

| 原来 | 改成 |
|---|---|
| `cd 子项目 && git status` | `git -C 子项目 status` |
