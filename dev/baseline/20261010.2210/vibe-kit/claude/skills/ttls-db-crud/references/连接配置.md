# 连接配置

## 放哪

**默认放在被操作项目的 `.vibe/db-crud.ini`。**
一个项目连哪几个库，跟着项目走才对得上。

从哪来：

| 来源 | 说明 |
|---|---|
| vibe-kit 后台自动探索 | 进到一个没探索过的项目，套件在后台扫项目的配置文件，把**开发环境**的库写进来。测试、生产环境的不写。项目的配置文件改了，这里跟着改 |
| `db.py init` | 手动扫一遍并逐个试连。和后台自动探索是同一套，也只配开发环境的；已有的配置是并进去，人改过的不动 |
| 手写 | 照下面的格式。测试、生产环境的库要用的话由人在这里加，加的时候标上 `readonly = true` |

没装 vibe-kit（技能单独拷出来用）时，`init` 用技能自带的扫描：认环境的办法简单，所以往严里判，
文件名、目录、profile 里看不出是开发环境的、连的也不是本机的，一律不配。

★ **这个文件里有账号口令，确认项目的 `.gitignore` 排除了 `.vibe/`。**
vibe-kit 的钩子会自动加；`db.py doctor` 会实地查一下到底有没有被忽略。

**`.vibe` 落在哪：写进真正拥有这份数据库配置的项目。**
外面套一层壳子（把前端后端装在一起的目录）时，落在里面那个后端下，不落在壳子上。
判断依据是 `pom.xml` / `build.gradle` 这类构建文件所在的最外层目录（多模块工程落在聚合根）。

完整的查找顺序（用第一个存在的）：

1. `--config` 指定的路径（指了却不存在会当场报错，不会悄悄换一份）
2. 当前目录的 `.vibe/db-crud.ini`
3. 往上找，最多 5 层，遇到 git 仓库根就停（在子模块里开 Claude Code 也能找到）。
   当前目录自己就是仓库根的不往上找：上面是别的项目
4. 往下找，最多 3 层（人在壳子根上，配置在里面的后端下）。
   找到多份会明确报错，让你用 `--project` 指定
5. `<项目>/.claude/urai-db-crud/connections.ini`（早期位置，仍然认）
6. `~/.db-crud/connections.ini`（多个项目共用一套连接时用）

**以前的文件名照样认**：`.vibe/urai-db-crud.ini`（这个技能并进 vibe-kit 之前的名字）。
新旧两个都在的，用最近改过的那一份。

## 长什么样

ini 格式，一个方括号一个连接。分号开头是注释。

```ini
; 达梦
[dev-dm]
dialect = dm
jdbc = jdbc:dm://localhost:5236
user = SYSDBA
password = 开发库口令

; MySQL
[dev-mysql]
dialect = mysql
jdbc = jdbc:mysql://localhost:3306/myapp?useUnicode=true&characterEncoding=UTF-8
user = root
password = ${ENV:MYSQL_PWD}
catalog = myapp

; Oracle
[dev-oracle]
dialect = oracle
jdbc = jdbc:oracle:thin:@localhost:1521:ORCL
user = app
password = ${ENV:ORA_PWD}
schema = APP

; 生产库这样标，写操作会被脚本直接拒绝
[prod-readonly]
dialect = mysql
jdbc = jdbc:mysql://prod-host:3306/app
user = readonly
password = ${ENV:PROD_PWD}
readonly = true
```

神通（`dialect = oscar`，`jdbc:oscar://…`）、人大金仓（`dialect = kingbase`，`jdbc:kingbase8://…`）同理。

## 各字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `dialect` | 是 | `dm` / `oscar` / `mysql` / `oracle` / `kingbase` |
| `jdbc` | 是 | JDBC 连接串，按各家自己的写法 |
| `user` | 是 | 登录用户 |
| `password` | 是 | 见下面「口令怎么放」 |
| `driver_jar` | 否 | 只给这一个连接用的驱动 jar。不填就用登记的，见下 |
| `driver_class` | 否 | 只有很老的驱动（ojdbc14、mysql 5.1）才需要，新驱动自带声明 |
| `schema` | 否 | 默认 schema，省得每条命令都写 `--schema` |
| `catalog` | 否 | MySQL 用这个放库名 |
| `readonly` | 否 | `true` 表示只读，任何写操作都会被脚本拒绝 |
| `forbid` | 否 | 这个连接上不许碰的表，逗号隔开，`*` 是通配（`SYS_*, T_AUDIT_LOG`）。语句里出现了就拒绝 |
| `hard_limit` | 否 | 影响行数的硬上限，到了就拒绝，确认也不给做。默认 10000000 |
| `confirm_above` / `warn_above` | 否 | 影响行数到了这么多就升到 DANGEROUS / WARN。默认 500000 / 50000 |
| `source` | 否 | 后台自动探索写的：这个连接是从项目的哪个文件里找到的。带着它的连接，来源文件改了会跟着更新；你手改过不想被更新的，把这一行删掉 |
| `notes` | 否 | 用这个连接踩过的坑，`db.py note` 写的 |

**`forbid` 和那几条上限是底线，由人在这里定。** 命令行上的 `--forbid`、`--hard-limit` 只能再收紧：
禁止名单是两边合起来，上限取更小的那个；给得比这里宽的不作数。配置里没写上限的，底线就是默认值。

## 口令怎么放

三种写法，**都是受支持的，不会因为用哪种被唠叨**：

```ini
password = 开发库口令            ← 直接写，内网开发库一般就这么配
password = ${ENV:DM_PWD}        ← 从环境变量取
password = ${FILE:C:/secure/dm.txt}  ← 从文件第一行取
```

**明文是默认做法。** 这个工具面向内网开发库，连接信息本来就躺在项目的
`application.yml` 里，扫出来的口令也是从那儿原样抄的。

真要用环境变量：`setx DM_PWD 你的口令`，**设完要重开 Claude Code 才读得到**。

口令从头到尾不会出现在命令行上：脚本解析完，经子进程的环境变量交给 Java。

## 驱动 jar 从哪来

**驱动不随技能带。** 达梦、神通、金仓、Oracle 的驱动是厂商的，只限内部使用，不能放进安装包。
每台电脑在 vibe-kit 的配置页「数据库驱动」里备一次：

- 点"自动搜索"：按「本机环境」里配的 Maven 本地仓库补登记，同一种数据库保留多个版本
- 或者点那种数据库那一行后面的"换驱动"，自己选一个 jar

命令行也能做（模型也可以跑）：

```bash
node "$HOME/.claude/vibe-kit/tools/drivers.js" list
node "$HOME/.claude/vibe-kit/tools/drivers.js" auto
node "$HOME/.claude/vibe-kit/tools/drivers.js" use <jar 的路径>
```

以前装过 urai-db-crud 的电脑：升级时它自带的那几个驱动已经自动挪过来登记好了。

不填 `driver_jar` 时按这个顺序找：

1. 被操作项目的 `lib/`、`WEB-INF/lib/`（它的版本和项目实际连的库对得上）
2. **配置页里登记的版本池**（`~/.claude/vibe-kit/drivers.json`），按当前项目 pom 和本地父 pom 声明的版本选择；没有声明才用默认
3. `~/.db-crud/drivers/`（以前的位置，照样认）
4. 本机的 Maven 仓库

同库登记第二个版本不会删除第一个；配置页可设默认或去掉单个版本。项目自己的 lib/ 有多个驱动时也按声明选，不能随便取第一个。明确声明的版本缺失、属性无法解析或多个文件匹配同一版本时，先添加驱动或用 `driver_jar` 指定，不拿另一版本代替。外部 BOM 和复杂 profile 不按完整 Maven 解析处理。

**Oracle 最容易需要换**：`ojdbc6` 往上能连到 12c 一带，连 19c 及以上要换 `ojdbc8` / `ojdbc11`；
反过来 21c 以上的驱动连不了 11.2。`conn test` 会打出实际用的是哪个 jar；任何命令连不上的时候也会打，先看那一行。

**连接串写成 `jdbc:postgresql:` 的**（金仓常这么配）：`dialect` 照样写 `kingbase`，但驱动要 PostgreSQL 的
（金仓的驱动不认这个前缀），在配置页里登记在"PostgreSQL"那一行。

## 对 java 的要求

这个技能靠 JDBC 连库，机器上得有 java，**JDK 8 及以上都行**，不需要 javac。
找 java 的顺序：环境变量 `DBCRUD_JAVA` → vibe-kit 配置页「本机环境」里的 JDK（默认的那个优先）→ 上次找到的那个（记在 `.vibe/db-crud.env.json`）→ `JAVA_HOME` → `PATH`。
找到的 java 太老（JDK 7）跑不了执行器时会明说，并把记下的那个去掉：在配置页里配一个 JDK 8 以上的就行。

执行器已经预编译好随包分发（`scripts/runner/` 里的几个 `.class`，用 `--release 8` 编的），
一份产物在 JDK 8 / 11 / 17 上都能跑。

## 后台执行器（开关，默认关）

默认每条命令起一次 java、连一次库。在 vibe-kit 配置页"数据库驱动"那一页的"查库快一点"里打开后台执行器之后，
第一次用的时候起一个 java 留在后台，连接留着，后面的命令省掉起 java 和连库的时间；几分钟没人用自己退出。

- 只听本机，端口随机，带口令牌。交请求之前先握手：对面答得上口令牌才把请求（里面有数据库口令）发过去。
  执行器被结束之后留下的状态文件、后来被别的程序占了的端口，拿不到口令。
- 看状态、停掉：`db.py daemon status`、`db.py daemon stop`。
- 走不通（起不来、连不上、握手对不上）时这一次自动退回老办法，不报错。
- **写操作交出去之后没等到回话（超时、连接断了）的不重发**，报"结果不明"：那一条可能已经执行了，重发就是执行两遍。
- 套件升级、执行器换了新的之后，旧的那个不再接新的请求，空闲到时间自己退。
