    后台自动探索

    OpenSpec 门槛

    提案、任务、归档各有一道门槛。过不去就拦下，提示里写着怎么改。

    提案、打勾、归档的门槛
    开着：提案写得含糊不让写，任务没验证不让打勾，代码没审不让归档。
    细节
    • 写提案：没在项目里读过代码不让写。不许写"待定、后续完善、视情况"，拿不准的写成决策项。设计里提到的文件要真的存在。
    • 写任务：每项要写改哪个文件、怎么验。
    • 打勾：这项任务的验法，要在改完它的代码之后跑过。验法里写了"本次不做（原因）"的那一部分不查。提案没审过不让开工。
    • 改产物：要在 revisions.md 记原因。
    • 归档：任务没全打勾、代码没审过不让归档。归档之后主规格里没有这个变更的需求会提醒。
    • 只查这次新加、改过的行，老内容不追究。
    多轮审查
    开着：审查报了问题、改了之后，再审改动点，直到它报"问题 0 条"。关着：提案、代码各审一轮。
    细节
    • 审查意见核实下来都不成立的，在 revisions.md 记下理由就算审完。
    • 轮数用完还有问题：有人在就问你。全自动模式下它选影响面最小的方案，记进 revisions.md。
    最多审几轮
    1 到 5。
    轮
    代码之外的产出先定位置
    开着：新建 DDL、说明文档、报告这类文件，放哪要是你定过的。没定过就拦下，让它先问你。
    细节
    • 你定了，它记进项目说明的"产出位置"，以后同类的不再问。
    • 全自动模式下不问，先放 .vibe/pending/，写进报告等你定。
    • openspec、.vibe、README、源码目录里的迁移脚本不管。
    起服务走 devserver
    开着：起后端、前端服务要用套件的 devserver.js。它不重复起，不换端口。
    细节
    • 直接敲 mvn spring-boot:run、npm run dev 会被拦下。
    • 服务已经在跑、代码没改过：直接用。代码改过：在同一个端口重启。
    • 端口被别的程序占着：说清是谁，不动它。
    • 停的时候把它起的进程都清掉，等端口空出来才返回。

    全自动模式

    你开会、下班的时候用。只在走 OpenSpec 流程时算数，而且只管做任务那一段：你说了开工，它不问你、不等你，任务做完、代码审过停下等你自测，收工时给你一份报告。探索、提案那一段和别的时候照常。

    全自动模式
    开着、又在做变更的任务：提问框用不了；被检查拦下它自己申请放行；做完审过停下等你自测，不归档。打开之后不用重开会话。
    细节
    • 什么时候算数：做任务那一段——你敲了 /opsx:apply，说了"开工""把 1.1 做了"，让它接着做某个已经打过勾的变更，或者接着上一轮说"继续"。探索、提案、审提案那一段（你提需求、敲 /opsx:propose、改提案）它照常问你：提案审过了停下给你看，你说开工才做。你问问题、让它检索、跑别的技能，这一轮也不算：做完你交代的事就收工，不会自己去接着做工作区里没做完的变更。做到一半才打开这个开关的，照那一轮开头你说的话算。
    • 只管自己做的变更：收工时只催这个窗口在流程里动手做过的变更。另一个窗口正在做的，它不碰。
    • 不问：它想用提问框问的问题会被拦下，记进报告。缺信息它先去查，查不到选影响面最小的做法。
    • 放行：被带拦截编号的检查拦下、照提示改不了的，它写明原因申请放行，不用你点。每次放行都记进报告。
    • 改库：不拦，条件是留得下备份。改、删留改前快照和还原脚本；新增记下表和主键，还原脚本是按主键删；建表、加列记下对应的 DROP。报告的"库里改过的"一节逐条列着，带还原的命令。备份不了的（没有 WHERE、没有主键、删表、清空……）查库的工具不执行，留给你。
    • 留给你：查库的工具不肯执行的改库操作、改 redis 里的数据、改公共配置、动 git 历史、push、要账号密码，这些它不做也不等。它在任务后面标上"留给用户"，接着做别的。
    • 照样拦：改套件、读令牌、结束路由进程、整仓 add、改非 UTF-8 的文件。这几样不能放行。
    • 报告：放在项目的 .vibe/reports/ 里，也写进它最后一条消息。七节：做了什么、留给你做的、库里改过的、自己定的事、没验证的、放行的检查、套件问题。
    • 下面"被检查拦住时"选了"不许放行"，全自动模式下也不放行。
    到交接线先写交接记录
    开着：到了交接线，先写一份交接记录再接着做，会话断了能接上。关着：不写，靠 Claude Code 自己的压缩。

    拉代码和提交

    开工前拉一次代码；只提交，从不 push。push 一律要你自己确认；全自动模式下直接拦下，留给你。不走 OpenSpec 的改动，提交前先问你。

    开工前拉代码
    开着：你提了需求、敲了 /opsx:… 命令、接着交接记录做的那一句话，先把会话所在的仓库（壳子里加上子项目）拉到最新，再开始分析、写代码。同一个仓库 2 小时里只拉一次。
    细节
    • 只快进：先 fetch，再 merge --ff-only 跟踪的远端分支。不做合并提交、不变基、不动你没提交的改动（配了 merge.autoStash 也不藏改动）。
    • 本地有没推的提交、远端也有新的（分叉了）：不拉，告诉 Claude，要合并先问你。没提交的改动和远端改的是同一些文件：git 自己拒绝，什么都不变。
    • 已经在流程里说"继续""好""不要停"不拉，做到一半不换底下的代码。中间插了一句问话再说"继续"也不拉。
    • 不是壳子的目录（一堆不相干的项目放在一起的上级目录）不带下面的仓库。壳子下面超过 12 个子项目的，一次拉 12 个，先拉最久没拉过的。
    • 连不上、没权限、连远端 15 秒没下完：没拉成，照本地的做。不弹登录框，登不上也不会拿别的东西当口令去试。全自动模式下没拉成的写进报告"留给你做的"。
    • 合并做到一半不结束它，等它做完：中途结束会留下 index.lock 和改了一半的工作区。合完了、只剩仓库自己的 post-merge 钩子在跑的，等 20 秒结束钩子。
    OpenSpec 的变更，验证过之后提交吗
    只 add 它这一轮改的和新建的文件。你工作区里原来就有的改动不会被带上。"一个阶段"是 tasks.md 里同一个大编号的任务（1.x、2.x）：每项太碎、整个变更太大时选它。
    不走 OpenSpec 的改动，验证过之后
    修 bug、改配置、改文案这类不用提案的活。选"先问我"：它交代改了什么、怎么验的，用提问框问你，你说提交了才提交；没点头就 git commit 会被拦下。
    提交检查
    开着：提交信息要写成"类型: 内容"；不许 git add -A、git add .、git commit -a；提交里像有密码的先让你看。
    细节
    • 提交信息的例子：feat: 新增修改页面。
    • 壳子里 add 子项目目录也拦，那样会提交成 gitlink。
    • 它新建的文件漏了 add 就提交，会点名拦一次。
    • 像密码的内容：有人在时弹框让你确认，框里写着哪个文件第几行。全自动模式下提交放行，记进报告。

    保护

    前两项和"全自动模式"只认在这个页面上改的。有程序直接改开关文件，不会生效。

    不许 Claude 改套件
    开着：~/.claude/vibe-kit、settings.json、全局 CLAUDE.md、装进去的技能和代理，它只能用不能改。
    细节
    • 用 Edit、Write 改会被拦。用 rm、重定向、sed 这些命令改也拦。直接调这个页面的接口也拦。
    • 只读的命令和套件自带的工具不受影响。
    • 令牌和模型的 key 不归这个开关管，什么时候都不给它读。
    被检查拦住时能不能放行
    只管带拦截编号的检查：OpenSpec 门槛、归档、产出位置、过程文件、起服务、提交信息格式、新文件没 add。
    细节
    • 要我点同意：它写清查过什么，再做那一步时弹确认框。通行证只对同一个文件或同一件事，用一次。每个会话最多 5 次。
    • 它自己放行：不弹框，记下就放。
    • 不许放行：被拦住就停下来告诉你。
    • 全自动模式开着时不弹框，直接放行并记进报告。选了"不许放行"的除外。
    • 放行记录在"更新和上报"那一页能看到。
    检查在哪里跑
    在路由里跑每次几十毫秒。用命令跑每次零点几秒，但不依赖路由。
    细节
    • 管的是五个检查：改文件、跑命令、提问框和调技能、搜文件内容、收工检查。会话开始、你发消息时的两个一直用命令。
    • 在路由里跑时，路由没在跑这几个检查会被跳过。所以你每次发消息会自检一次：收不到就把路由拉起来，还不行就自动切回命令方式。
    Claude Code 自带的自动模式
    新版 Claude Code 没配权限模式时默认进它：有风险的命令先发给一个分类模型审。内网的模型当不了这个分类器，默认关掉。
    细节
    • 它是 Claude Code 的 auto mode，和上面套件的"全自动模式"是两回事。2.1.284 起默认进，2.1.259 和更早的版本没有这回事。
    • 实测（2.1.289，经网关）：node -e、curl 这类命令每条多发一次请求给审查用的那个模型，系统提示有 14 万字符；它答得不合格式就重试，最多十次，然后把命令拦下。
    • 关掉：套件在 settings.json 里写 permissions.disableAutoMode，会话照以前的普通模式起（底下显示 manual mode），放行的还是套件装的那几条权限。
    • 不管它：套件把自己写的那一项去掉，照 Claude Code 的默认。
    • 你启动时带 --dangerously-skip-permissions，或者自己在 settings.json 里配了 defaultMode，不受这一项影响。改了要重新打开 Claude Code 才生效。
