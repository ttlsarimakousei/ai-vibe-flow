# 数据库读写

> 版本 1.1.1　｜　更新 2026-10-10　｜　变更记录见 [CHANGELOG.md](CHANGELOG.md)
> 原来叫 urai-db-crud，现在并进 vibe-kit，跟着套件一起装、一起更新。

## 这个技能在干什么

对开发库做**读**（看表结构、找表、查数据）和**写**（增删改）。

Python 脚本负责判断和留痕，真正连库的是一个只依赖 `java.sql` 的小程序，用机器上已有的 java 跑。
默认每条命令都是一个新进程，跑完就退。

**写操作分两步**：第一步算清影响面和风险但什么都不改，第二步带上确认串才真的执行。

## 脚本在哪

```
~/.claude/skills/ttls-db-crud/scripts/db.py
```

下面的 `<db>` 都指 `python "$HOME/.claude/skills/ttls-db-crud/scripts/db.py"`。
**跑命令时的工作目录是被操作的项目。** 这些命令都是你自己去跑的，不要甩给用户让他手敲。
`--conn`、`--timeout` 写在子命令**前面**：`<db> --conn dev peek --table T`。

连接配置在项目的 `.vibe/db-crud.ini`。vibe-kit 在后台自动探索项目时会把**开发环境**的库配进去，
**多数情况下直接就能用**。会话开头的项目说明里有"数据库"一行的，连接名照它写。

**只配开发环境的库。** 测试、生产环境的连接不会配进来，你也不要自己往连接配置里加。
用户要查那些库：告诉他连接没有配，由他来配。

驱动登记可保留同库多个版本。按连接所属子项目的 pom 声明版本选择，明确 driver_jar 优先；缺少版本、声明无法解析或多个文件有歧义时，照工具说明让用户添加或指定，不拿默认的另一个版本试连。

## 先挑最省事的命令

慢在连库：每条命令起一次 java、连一次库，要一两秒。所以**一条命令能问完的不要拆成几条，能不写 SQL 的不写 SQL**。

| 要做的事 | 用这个 | 不要 |
|---|---|---|
| 不知道表名，只知道业务词（"订单""密级"） | `find 订单` | 列出所有表再一张张看 |
| 看几张表的结构 | `columns --table A,B,C`（一次） | 一张表跑一次 |
| 看某张表里有什么 | `peek --table T` | 写 SELECT * |
| 按某个字段的值找数据 | `peek --table T --eq 字段=值` | 写 WHERE、加引号 |
| 数有多少行 | `peek --table T --eq 字段=值 --count` | 写 COUNT(*) |
| 要跑几条查询 | `query --sql "…" --sql "…"`（一次） | 一条跑一次 |
| 连表、分组、子查询 | `query --sql "…"` | —— |
| 值太长被截了 | 同一条命令加 `--width 0`；仍有 ★ 时先核对取数上限 | 按表格字符下标切列 |
| 要给脚本处理查询结果 | `query --sql-file q.sql --json` | 从对齐的终端表格里切列 |

`columns` 看过的表结构存在本地，再看不连库。输出里写着"来自本地缓存"的，是之前存的；
照它写的 SQL 报"列不存在"，加 `--fresh` 重新看。

## 执行前必读的五条纪律

**纪律一：能不写文件就不写文件。**

| 情况 | 用什么 |
|---|---|
| 一行能写完、没有中文字面量、没有嵌套引号 | `--sql "..."` |
| 多行、带中文字面量、带引号、或者超过一屏 | 用 Write 写文件 + `--sql-file` |

SQL 文件写在 `.vibe/tmp/<事由>/` 里：事由是变更名的留到变更归档（套件自己清），别的用完删掉。不要写在项目根目录、源码目录里。
`--sql` 遇到非 ASCII 字符会拒绝；LIKE 只剩 `%` 或 `%%` 时也拒绝，防止中文丢掉后变成全表匹配。中文写进 UTF-8 的 SQL 文件，用 `--sql-file`。
文本表格按显示宽度补齐，中文占两格，不能用字符下标切列。`query --json` 返回列和值，不补齐、不按显示列宽截断；值用字符串保留精度，NULL 用 JSON null。保留 `truncated_cell`、`truncated_rows`、`max_cell` 等标记；标记为真时结果仍不完整。
`--eq 字段=值` 里的值可以是中文，不用加引号。
shell 传中文参数报错时，`find --keyword-file <UTF-8文件>` 读查找关键字，`peek --eq-file <UTF-8文件>` 每行读一个 `列名=值`，不用在命令行拼中文。条件文件为空时直接报错，不会改成无筛选查询。
在 Git Bash 里，以 `/` 开头的值（`--eq URL=/system/user`）会被改成 Windows 路径、查出 0 行：
命令最前面加 `MSYS_NO_PATHCONV=1`。

**纪律二：★ 写操作的确认必须由人做出，不能由你代劳。**
第一步会打印连的是哪台库、影响面、风险和要执行的 SQL。**把这些原样给用户看，用提问框问他执不执行**，
用户明确同意了，才可以带 `--ack` 跑第二步。不要自己看一眼觉得没问题就补上确认串。
新确认串只含 ASCII，例如 `UPDATE-T_ORDER-3rows-12345678`；旧中文串可以写进 UTF-8 文件，第二步用 `--ack-file <文件>`。文件里只放一条串，这种写法仍需用户确认，仍核对影响面、指纹和一次性使用。
用户一开始就说了要改什么（"把这条改成 X"）也一样要走这两步：他说的是想要的结果，影响面是现在才算出来的。
**全自动模式（这个会话开着 /vk-auto、在做任务，用户不在）是例外**：第一步的输出里写着"全自动模式：这条留得下备份，不用等人确认"的，你自己看一遍影响面，
没问题就带 `--ack` 跑第二步，不用问。这时工具只做留得下备份的：改、删留改前快照和还原脚本，新增记下表和主键，
建表、建索引、加列记下对应的 DROP。执行完**把它打印的留痕目录写进最后的交代**（全自动报告的"库里改过的"一节也会列）。
它拒绝的（退出码 3：没有 WHERE、没有主键、INSERT … SELECT、删表、清空、改列删列……）不要换写法绕：
把那项任务标成"（留给用户：要改库）"，接着做别的。

**纪律三：确认串对不上、或者提示"没有执行"，就停下来。**
串里绑着连的哪台库、SQL、影响面、风险。对不上说明有东西变了。
**把新的影响面再给用户看一遍**，不要拿新串直接重试。
**一个确认串只能用一次**：执行过的命令再跑一遍不会再执行，会要求重新确认。
提示"结果不明"的（交出去了、没等到回话）：**不要重跑**，先查数据现在是什么样，告诉用户。

**纪律四：带 ★ 的提示必须转述，不能省略。**
结果里出现「还有更多行没取」「内容太长被截断」「快照没有取全」「没看完」这类带 ★ 的话，
说明你手上的不是全貌。原样告诉用户，不要当成完整结果去下结论。

**纪律五：口令不经你的手。**
口令写在连接配置里，脚本自己解析。
**不要打开连接配置文件，不要把口令拼进命令行，也不要在回答里复述它。**
要改连接配置的（口令不对、库名不对、要加连接）：告诉用户改哪一段的哪一项，由他来改。

## 用户怎么叫你，你就怎么做

| 用户说什么 | 你做什么 |
|---|---|
| `/ttls-db-crud` 后面没跟东西，或者「怎么用不了」 | 跑 `<db> doctor`，把 ✗ 的那几项和怎么补讲清楚 |
| 「配一下数据库」「这项目连了哪些库」 | `<db> conn list`；没有配置就跑 `<db> init`（只配开发环境的） |
| 「项目的配置文件里都写了哪些库」 | `<db> discover`（只看不写，各是哪个环境的都列出来） |
| 「哪张表存了 xx」「xx 字段在哪」 | `find` |
| 「看一下 xx 表的结构」 | `columns` |
| 「查一下 xxx」 | 先想能不能用 `peek`，不行再 `query` |
| 「把 xxx 改成 yyy」 | 走下面「写」那一节的两步流程 |
| 「刚才那个改错了，改回去」 | 走下面「留痕和还原」那一节 |

任何命令报「找不到连接配置」时，**不要把错误原样丢回去**：跑一次 `<db> init`，再接着做用户本来要做的事。
`init` 只把开发环境的库配进来并试连；它说"没配进来"的那些是测试、生产环境的，照上面说的告诉用户。

报「找不到驱动」时，照提示里的命令做（`node …/tools/drivers.js auto` 会到 Maven 本地仓库里找）；
还是没有，告诉用户去 vibe-kit 配置页的「数据库驱动」里选一个 jar。驱动是厂商的，不要到网上下载。

## 读

```bash
<db> --conn <连接名> find 订单
<db> --conn <连接名> columns --table T_ORDER,T_ORDER_ITEM
<db> --conn <连接名> peek --table T_ORDER --eq STATUS=待支付 --order "CREATED DESC" --limit 5
<db> --conn <连接名> peek --table T_ORDER --eq CUSTOMER_ID=1001 --count
<db> --conn <连接名> query --sql "SELECT ..." --sql "SELECT ..." --max-rows 200
<db> --conn <连接名> tables --schema <SCHEMA>
```

只有一个连接时 `--conn` 可以不写。

- **表名、字段名的大小写不用你操心**：达梦、Oracle、金仓的 Oracle 模式把标识符折成大写，
  神通和 PG 模式折成小写。`columns`、`peek` 会自己试原样、全大写、全小写，试出来和你给的不一样时会说一声。
- **没指定 schema 时只在当前登录的 schema（MySQL 是当前的库）里找。** 那里没有、别处只有一张同名的就用那一张；
  别处有好几张同名的会列出来，加 `--schema <名字>` 指定，或者把表名写成 `<名字>.<表名>`。
- `find` 在表名、表的注释、列名、列的注释里找。库很大时加 `--tables-only` 或 `--schema`。
- `peek` 的 `--eq` 可以写好几个，之间是"并且"；`--eq` 表达不了的（大于、like、in）写 `--where "…"`。
  `--where` 只能是条件，`--order` 只能是列名加 ASC / DESC：带分号、注释、写操作关键字的会被拦下（退出码 3）。
  `--cols a,b,c` 只看这几列。
- `columns` 会一并报主键。**没有主键的表要提醒用户**：改了之后还原不了（生成不了反向 SQL）。
- `query` 默认最多 200 行。**只跑查询**：里面有增删改、改结构、`SELECT … FOR UPDATE` 的语句会被拦下（退出码 3），那些走 `exec`。
- 每格默认显示 40 个字符。结果只有两三行、又有长的值时自动改成竖着排、不截；
  行多的时候被截了会有 ★ 提示，要看全就加 `--width 0`。

## 写

### 第一步：先看要发生什么（不改任何东西）

```bash
<db> --conn <连接名> exec --sql-file <文件>
```

它会打印：连的哪台库（地址、账号）、目标表、影响多少行、风险等级、要执行的 SQL，然后给出一串 `--ack ...`，退出码 4。

**把这些原样给用户看。** 尤其是影响行数——如果比用户预期的多，多半是 WHERE 写错了。

只想看不想做，用 `--dry-run`，它连确认串都不给。

### 第二步：用户同意之后

```bash
<db> --conn <连接名> exec --sql-file <文件> --ack <上一步给的串>
```

执行的那一刻会在同一个事务里再数一遍：和确认时的行数不一样就不执行，把现在的影响面打出来，要重新确认。
执行成功会报影响行数，以及留痕目录的位置。

### 一次只发一条语句

多条语句会被拒绝。拆开单独执行，这样每条的影响面和改前快照才是对得上的。

### 风险等级怎么来的

| 等级 | 什么情况 | 怎么处理 |
|---|---|---|
| SAFE | 建对象；数得出行数的插入 | 仍然要确认（凡是改库的都要） |
| WARN | 带 WHERE 的增删改；键撞上会覆盖已有行的插入；影响面较大 | 要确认 |
| DANGEROUS | 没有 WHERE、WHERE 恒真、连了别的表的更新和删除、影响面数不出来、清空表、删表、改结构、看不懂的语句 | 要确认，且要重点提醒用户 |
| FORBIDDEN | 删库删 schema；命中禁止名单；只读连接上的写；影响面超硬上限 | **脚本直接拒绝，退出码 3。不要绕过** |

禁止名单、影响行数的上限写在连接配置里（`forbid`、`hard_limit`），那是用户定的底线。
命令行上的 `--forbid`、`--hard-limit` 只能再收紧，放宽的不作数。
被判 FORBIDDEN 时**不要试图改写 SQL、加参数绕过去**。把拒绝原因告诉用户，让用户决定。

## 踩到坑就记一条

```bash
<db> --conn <连接名> note "一句话说清这个坑"
<db> --conn <连接名> note --list
```

记进连接配置里那个连接名下，**之后每次用这个连接都会先打出来**（最多 8 条，你记的排前面；`--list` 列全部）。

**该记的**（会重复踩的）：这个库跑在 Oracle 兼容模式，空串写进去会变 NULL；某张表数据量特别大，
查之前必须带条件；某个字段是加密存的；某个状态值的含义。表名要大写还是小写工具自己会记。

**不要记**：一次性的失误（SQL 打错字）、跟连接无关的事。

## 留痕和还原

每次写操作都会在 `~/.db-crud/journal/<连接名>/<时间>-<类型>/` 留下：

| 文件 | 是什么 |
|---|---|
| `op.json` | 这次干了什么：SQL、判定、影响行数、结果；新增的还记着表和每一行的主键（`inserted`） |
| `before.json` | 改之前那些行长什么样（和写操作在同一个事务里取的） |
| `undo.sql` | 还原脚本，生成的时候没有执行：删掉的插回去，改过的按主键改回去，新增的按主键删掉 |

要还原，拿那一次执行完打印的留痕目录：

```bash
<db> --conn <连接名> exec --undo "<留痕目录>"
<db> --conn <连接名> exec --undo "<留痕目录>" --ack <上一步给的串>
```

一样两步、一样要用户同意（全自动模式下不做还原，留给用户）。整份还原脚本在一个事务里跑，每一条都得正好动一行；有一条不是就全部回滚。
同一次只能还原一遍。

还原之前必须提醒用户：

1. 那一次之后别人改过这些行的话，那些改动会被一起盖掉。
2. 第一步的输出里带 ★ 的话（「快照没有取全」「有二进制列」）：**照它执行只能还原一部分**。
3. 还原本身不留改前快照。

新增的还原是按主键删：主键写在语句里的直接记得下来；主键是库里自己生成的（自增、序列），有人在的时候记不下来，
`undo.sql` 里会写明。清空表、改列删列、没有主键的表上的更新还原不了，`undo.sql` 里会写明原因。
建表、加列的 `undo.sql` 是对应的 DROP，工具不代做：要删得由人拿出来用 `exec --sql` 执行。

## 出错了怎么办

| 退出码 | 意思 | 你该做什么 |
|---|---|---|
| 0 | 成功 | —— |
| 1 | 参数或配置不对 | 按提示改；缺配置就跑 `init` |
| 2 | 连上了但失败了 | 把数据库原话告诉用户。语法错就改 SQL 重来。提示"结果不明"的不要重跑 |
| 3 | 被安全规则拦住；全自动模式下备份不了的写操作 | **不要绕过**，把原因告诉用户（全自动模式下留给用户） |
| 4 | 要确认 | 把影响面给用户看，等同意（全自动模式下自己看一遍，没问题就带确认串执行） |

连不上的时候输出里有"用的驱动"一行。像驱动问题的，工具已经按登记的顺序换别的版本试过（换成功会说换成了哪个）；还是不行的，照提示告诉用户在配置页加一个和库版本对得上的驱动。
遇到 `42S22` 或 Oracle `904`：先在本机核对完整错误，用 `columns --table <表名> --fresh` 重新读取 涉及的表或视图，核对 schema、真实列名、别名作用域和带双引号的大小写，再用最小只读查询确认；不要连续盲试原 SQL。神通的具体含义以对应版本错误详情为准。匿名汇总没有 SQL 和表结构，不能据此认定套件缺陷，也不要为排查上传原 SQL、真实数据或连接配置。Oracle 904 的含义见 [Oracle 官方错误说明](https://docs.oracle.com/en/error-help/db/ora-00904/)。
提示"工具自己出错了"的：那是这个技能的毛病，已经自动记成套件的问题反馈，交代里列进"套件问题"。

配置的格式、驱动从哪来、对 java 的要求，见 [references/连接配置.md](references/连接配置.md)。

## 这个技能不做什么

- **不自动回滚。** 只生成反向 SQL，还原与否由人决定。
- **不跨调用保持事务。** 每条命令自己开事务自己结束。
- **不翻译 SQL 方言。** 你写的 SQL 直接发给目标数据库，该按哪家的语法写就按哪家的。
- **不替用户保管口令。**
- **不配测试、生产环境的库。**
