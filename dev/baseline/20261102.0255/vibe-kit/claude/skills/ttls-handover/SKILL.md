# 手动交接

先运行 tools/workflow.js facts --project <项目> 核对当前 Git、任务、服务、有效验证和未完成审查。只有用户明确要求交接才写 .vibe/handover.md；不会自动 clear 或自动读历史记录。

写最少的接手必需信息：当前范围、用户已确认与未确认事项、下一项、未覆盖验证、审查状态、服务实际地址与归属。代码和 Git 能直接看出的不重复写，不写凭据、真实业务数据或对话经过。

新会话的“继续”不能选中旧交接。用户点名选择记录后先查文件时间、当前分支、任务和差异是否仍一致；过时部分明确标出。历史记录只能提供线索，不能恢复 apply、提交、归档、push 许可，开工范围重新确认。

默认 contextStrategy=compact，不自动读取历史交接。选择 handover 策略才使用旧交接线提醒，仍不自动 clear。网关拒绝大请求或 /compact 失败时说明真实错误，由用户决定手动交接与新会话。
