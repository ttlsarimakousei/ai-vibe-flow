# 模型路由和配置

路由怎么转发、怎么管、检查在哪里跑、各种配置放在哪、怎么加规范。回到[用户手册](../README.md)。

## 路由怎么转发

- 按请求里的模型名分角色：主会话 opus、审查 sonnet、后台小任务 haiku，各自交给配置页"角色分配"里指定的模型。
- 发给网关的请求不用 OpenAI 的认证方式（2026-10-28 起）：key 只放 Anthropic 的 x-api-key，不带 Authorization: Bearer；配置页"测试"也一样。
- 模型名照原样带着（网关要求必须有 model）：Claude Code 发来的是什么就带什么，这个模型配了"换成这个模型名再发出去"的换成那个名字。20261028.1834 去掉过模型名，更新后报"缺少必须的model参数"，下一版改回来了。
- 熔断（5xx）、key 失效（401/403）、连不上、300 秒没回应，自动换下一个模型。熔断和 key 失效冷却 30 分钟；连接层面的错误只避开 1 分钟（所有模型走同一个网关，多半不是那一个模型的问题）。
- **限流（429）、过载（529）、带 retry-after 的 503 先等再换**：在同一个模型上按它说的 retry-after 等（没说就 5、5、10 秒地试，总共不超过 20 秒，页面可调），等不到再换。换模型意味着另一个模型要把整个上下文从头算一遍，缓存全丢。
- **额度用完**（网关回"每日额度超限……将于 <时间> 重置"这类）：不等，直接换模型；这个模型停用到回复里说的重置时间（没说时间的每日额度停到本地明天 0 点），到点自动恢复，路由重启也不忘。配置页显示"额度用完，几点自动恢复"，你找管理员加了额度可以点"手动恢复"。所有模型都额度用完时直接回 429 并说清几点恢复。
- 所有模型都在冷却时，一个请求最多再多试一个（最快到期的那个），然后带着 Retry-After 回给 Claude Code，让它自己退避。
- 大请求（默认 30 万字节以上）慢是正常的：到 Claude Code 自己的超时之前、或者网关回 502 / 504，不换模型，回给 Claude Code 让它重试；同一个模型连续两次这样才当它卡住了。任何等待都封顶在 Claude Code 的超时减 20 秒。
- 你按 Esc 取消的请求不算模型的错，用量里记成"客户端取消"。同一个会话换过模型后 10 分钟内留在新模型上，不来回切；在页面上点首选模型的"现在就试"立即回首选。
- 回复边收边转；传到一半上游断了，把客户端的连接也断开让它重试，不把半截回复装成正常结束。413 翻译成看得懂的提示（见[上下文和 token](上下文和token.md)）。
- 只监听本机；配置页的接口只接受本机连接，网页发来的请求一律不转，免得网页借路由带着真实的 key 往网关发请求。
- 网关用 https 的默认不校验证书（内网常见自签证书）；证书是正规机构签发的，在模型设置里勾上"校验证书"更安全。

改配置改坏了也不会让 Claude 用不了：配置文件不是合法 JSON，路由继续用上一份好的；某个模型没填 key、地址不对、key 里混进看不见的字符，只跳过那一个，并在页面上标出来。保存前先测一次，测不通也能存。每次保存前自动备份，"配置备份"里能一键恢复。两个页面同时开着、或者你手改过 `config.json`，拿页面上的旧内容保存会被拒绝，不会把别处的改动冲掉。

## 路由在哪、怎么管

| | |
|---|---|
| 程序 | `~/.claude/vibe-kit/router/` |
| 数据（模型和 key、用量、日志、备份） | `~/.claude/vibe-kit/router-data/`，更新和卸载都不动 |
| 登录后自动启动 | "启动"文件夹里的 `vibe-kit-router.vbs`，删掉它就不再自动启动。不要管理员权限，不建计划任务 |
| 手动管 | `node "%USERPROFILE%\.claude\vibe-kit\router\service.js" status`，还有 start、stop、restart、autostart、no-autostart |

有的公司禁用 .vbs。安装器放之前先试跑一次，跑不了就不放，并告诉你。那种情况也不用管：打开 Claude Code 时，会话开始的钩子发现路由没在跑，会在后台把它拉起来；路由进程被杀了也一样兜底。

**配置页打不开**：先 `service.js status`。

- 说"没在运行"：`service.js start`。起不来它会把路由的输出打印出来；启动就崩的报错在 `router-data\router.out.log`，平时的日志在 `router-data\router.log`（满 5 MB 轮换）。
- 说"端口 15730 被别的程序占着"：在 `router-data\config.json` 里把 `listen.port` 换一个，再 `service.js start`；然后在配置页"断开"再"接上"一次，让 Claude Code 跟着换端口。
- 说"在运行"但浏览器打不开：地址用 `127.0.0.1`；浏览器或系统代理要对本机地址直连。

## 检查在哪里跑

套件的检查都是钩子。命令方式每个检查起一个 node 进程，每次 0.3～0.9 秒。装了路由时（配置页"保护"里"检查在哪里跑"选"自动"，默认），改文件、跑命令、提问框和调技能、搜文件内容、收工检查这五个在路由里跑，同一份代码、同样的判断，一次几毫秒到几十毫秒。会话开始、你发消息时的两个一直用命令方式，负责兜底：

- 路由没在跑，这五个检查会被 Claude Code 当成放行、悄悄失效。所以会话开始时发现路由没在跑，就在后台拉起来。
- 你每次发消息自检一次：上一轮改过文件或跑过命令，路由却没收到这个会话的检查 → 没在跑就拉起来；登记的端口和路由的端口对不上就重新登记；在跑也收不到，自动切回命令方式。三种情况都告诉 Claude"上一轮的改动没经过检查，自己核对一遍"。
- 装了新版，路由下一次调用就换新代码，不用重启。一个检查 25 秒没结果、或者出错，当放行，记一条问题反馈。

对这个不放心，改成"用命令跑"：每次慢零点几秒，但不依赖路由。

已知问题：Claude Code 2.1.259、2.1.263 在脚本方式（`claude -p`）下，SessionStart 钩子慢一点、同时配了命令方式的 Stop 钩子时，答完不退出。和套件钩子的内容无关，交互着用不受影响；检查在路由里跑（默认）时实测能正常退出。检查改成命令方式、又要在脚本里调 `claude -p` 的，给它加超时。

## 配置放在哪

| 内容 | 位置 | 进仓库吗 |
|---|---|---|
| 套件开关 | `~/.claude/vibe-kit/config.json`（配置页里改） | 不进 |
| 这台电脑的 JDK、Maven、Tomcat | `~/.claude/vibe-kit/local.json`（配置页里填），生成到全局约定 | 不进 |
| 模型、key、角色分配 | `~/.claude/vibe-kit/router-data/config.json`（配置页里填） | 不进 |
| GitLab 的仓库地址；令牌 | `~/.claude/vibe-kit/gitlab.json`；`secrets.json`（模型读不到） | 不进 |
| 子项目怎么编译、快检、启动，用哪个 JDK | 子项目的 `.vibe/project.md`（自动探索生成，`/ttls-onboard` 补） | 不进（`.vibe/` 自动加进 `.gitignore`） |
| 开发环境的数据库、redis 连接（带口令）；登录账号 | 子项目的 `.vibe/db-crud.ini`、`.vibe/redis.json`；`.vibe/login.json` | 不进 |
| 收工报告 | 项目的 `.vibe/reports/全自动报告-日期-时间.md` | 不进 |
| 审查报告和诊断 | 项目的 `.vibe/reviews/` | 不进 |
| 数据库驱动 | `~/.claude/vibe-kit/drivers/`，登记在 `drivers.json` | 不进 |
| 查库写操作的留痕 | `~/.db-crud/journal/` | 不进 |
| 查库命令的 Python 字节码缓存（删了会自己重建） | `~/.db-crud/pycache/` | 不进 |
| 问题反馈；对应的 issue | `~/.claude/vibe-kit/feedback/`；`feedback/issues.json` | 不进 |
| 下载的新版、更新日志 | `~/.claude/vibe-kit/update/` | 不进 |
| 拦截次数、放行记录、开关改动、使用情况、拉代码记录 | `~/.claude/vibe-kit/state/` | 不进 |
| 团队共同的约定 | 项目的 `CLAUDE.md`、`openspec/` | 进，团队维护（`/ttls-onboard` 问过你后会往 `CLAUDE.md` 写"项目说明（团队共享）"一节） |
| 项目的经验规则 | 出问题的文件所在仓库的 `.claude/rules/ttls-lessons-<类型>.md` | **进**，同事的 Claude 也能用上 |
| 经验的候选；用户级的经验规则 | 项目的 `.vibe/lessons/`；`~/.claude/rules/ttls-lessons-<类型>.md` | 不进 |

## 加规范

全局约定和规范每个请求都带着。想加一条自己的规范：在 `~/.claude/vibe-kit/rules/` 里放一个 `.md` 文件（文件名不要以下划线开头），然后运行

```
node "%USERPROFILE%\.claude\vibe-kit\install.js" --sync
```

文件名前面的数字决定先后顺序。想停用某条规范，给文件名加个下划线前缀再 sync；以后更新套件不会把它重新启用。注意每加一个字都是每个请求的成本。
