## Git 提交

{{AUTO_COMMIT}}
- 提交信息只写一行，格式固定：`类型: 内容`。类型后面是英文冒号加一个空格，然后直接写内容。例：`feat: 新增修改页面`
- 类型只用这七个：
  - `feat` 新功能、新页面、新接口对接
  - `fix` 修 bug
  - `docs` 文档、注释变更
  - `style` 代码格式调整，不影响逻辑
  - `refactor` 重构，既不是新功能也不是修 bug
  - `chore` 构建配置、依赖更新、脚手架调整
  - `release` 版本发布
- 内容用中文，简短明了，说清改了什么。不写正文，不加署名行，不加任何标记前缀。
- 修的是 OpenSpec 变更做出来的东西里的问题（审查、测试、用户发现的，归档了也一样）：内容末尾加上"（源自 <变更名> <任务号>）"，例：`fix: 导出时漏了表头（源自 add-export 2.3）`。任务号拿不准就只写变更名，查不到用 `tools/trace.js <文件>`。
- 一次提交只做一件事。类型不同的改动分开提交。
- 只 `git add` 你这一轮改过和新建的文件，一个个写出来：新建的 git 不会自动带上，提交前 `git status` 看一眼 `??` 开头的；工作区里原来就有的、不是你改的改动不要带上；为了测试临时加的不提交，测完删掉。`.gitignore` 里多出来的 `.vibe/` 那一行是工具加的，顺手带上。
- 在壳子里干活时（会话开头会提示），壳子和每个子项目各是独立的 git 仓库，各自提交（`git -C <目录>`）：代码在子项目的仓库里提交，openspec 的提案、tasks.md 在壳子的仓库里提交，类型用 `docs`。不管在哪，都不用 `git add -A`、`git add .`、`git add -u`、`git commit -a`。
- 在当前分支上提交，不要自己建分支、切分支，不要改写已有的提交（不 amend、不 rebase、不 reset）；我让你把没推的提交合并了再推的除外。
- 我说"推送""push"就直接 `git push`，几笔提交都一样，不出推送计划、不再问。我说"合并推送""合并成1条推送"这类，照我说的用 git 把还没推的提交合并了再推，不再问；只动没推上去的提交。不 force。
- 密码、key、token 不写进要提交的文件：配置里用占位符（`${DB_PASSWORD}`）或者本机不提交的配置。
