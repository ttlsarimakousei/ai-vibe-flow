## 升级怎么做

**装了 0928 晚上之后的版本，以后不用再拷压缩包**：维护的人发布到团队的 GitLab 仓库，你的电脑自己发现、自己装上（配置页"更新和上报"里能改成只提醒、不检查）。下面是手动装的办法，第一次装、自动更新用不了的时候用。

1. 把新的压缩包**整个解压**出来，双击里面的 `安装（双击我）.bat`（在压缩包里直接双击会提示先解压）。
2. 装在原来的上面就行，不用先卸载。这些都原样保留：
   - 套件开关 `config.json`、本机环境 `local.json`
   - 路由里配好的模型和 key（`router-data`）
   - 问题反馈（`feedback`）、你自己加的规范
   - GitLab 的仓库地址和令牌（`gitlab.json`、`secrets.json`）
   - 你从 `settings.json` 里删掉的权限、环境变量，不会被补回来
3. **不用重开 Claude Code，也不用 `/clear`**：钩子立刻生效；约定和技能变了的部分，在你下一次发消息时由钩子带给它。路由会用新文件自动重启一次，正在跑的请求会断一下。

## 20260930.1200（最新）

六件事：技能和代理的名字加 `ttls-` 前缀；查库、查 redis 两个技能并进套件；数据库驱动不随包带，配置页多一页来管；`/onboard` 改成后台自动探索；查库更快、少写 SQL；审查报的问题自动收进经验规则，工具的用量和毛病自动记。

### 改名：加 `ttls-` 前缀

别人的套件里也有叫 `onboard`、`handover` 的技能，装在一起会撞名。

| 以前 | 现在 |
|---|---|
| `/onboard` | `/ttls-onboard` |
| `/see-page` | `/ttls-see-page` |
| `/cross-review` | `/ttls-cross-review` |
| `/handover` | `/ttls-handover` |
| 审查代理 `vibe-reviewer` | `ttls-reviewer` |
| 经验规则的文件 `vibe-lessons-*.md` | `ttls-lessons-*.md` |

升级时安装器自己处理，你不用动手：

- 旧名字的技能和代理删掉。你改过的先备份，安装器会说备份在哪。不是套件装的同名技能不动。
- 会话记录、交接记录里的旧名字照样认。升级那一刻开着的会话不受影响。
- 经验规则的文件改名，旧文件里的规则并进新文件。**项目里的规则文件改了名，要提交一次**。

没跟着改的：项目里的 `.vibe/`、`~/.claude/vibe-kit/`、提示开头的 `[vibe-kit …]`。

### 查库、查 redis 并进套件

| 以前 | 现在 | 要什么 |
|---|---|---|
| `urai-db-crud`（单独装） | `/ttls-db-crud` | Python 3、java 8 以上 |
| `redis`（单独装） | `/ttls-redis` | 什么都不用装。客户端只用 Node 自带的模块，不要 redis-cli，不要 npm install |

- **装在用户目录里的旧技能**（`~/.claude/skills/urai-db-crud`、`redis`）：安装器删掉，删之前备份。`urai-db-crud` 自带的驱动挪进套件的驱动目录并登记好。
- **装在项目里的旧技能**（`<项目>/.claude/skills/urai-db-crud`）：安装器不动项目。会话开始时 Claude 会提醒你一次"旧的可以删掉了"，它自带的驱动套件先收进来。两个都在时 Claude 用 `ttls-` 开头的。
- 以前的配置照样认：`.vibe/urai-db-crud.ini`、`.claude/project.local.json` 的 redis 段。
- **redis 的连接信息不再上命令行**。以前主机、端口、口令拼成一段 JSON 放在命令行上，口令会进会话记录。现在写在项目的 `.vibe/redis.json` 里，命令行只给连接名。
- 查库的设计说明、维护须知、验证记录搬到了工程的 `dev/docs/ttls-db-crud/`。

### 数据库驱动：不随包带，配置页多一页

达梦、神通、金仓、Oracle 的驱动是厂商的，只限内部使用，不能夹在安装包里发。

配置页左边多了"数据库驱动"：

| 做法 | 说明 |
|---|---|
| 到 Maven 仓库里找 | 按"本机环境"里配的 Maven、`~/.m2` 的顺序找，每种数据库用最新的那个。认驱动看 jar 里面的驱动类，不看文件名 |
| 自己选一个 jar | Maven 仓库里没有，或者要指定版本 |

多数时候不用点：后台自动探索发现项目用到的数据库还没有驱动，会自己到 Maven 仓库里找一遍。卸载套件不删驱动。

### `/onboard` 改成后台自动探索（开关，默认开）

进到一个没探索过的项目，不用你说，套件在后台查清这几件事，几秒钟就好。**不用模型，不花额度，不挡你打字**。

| 查什么 | 写到哪 |
|---|---|
| 是什么工程、几个模块、怎么编译、启动命令和端口、什么编码 | `<项目>/.vibe/project.md` |
| **开发环境**的数据库连接 | `<项目>/.vibe/db-crud.ini` |
| **开发环境**的 redis 连接 | `<项目>/.vibe/redis.json` |

- **什么时候跑**：会话开始、你每次开口时看一眼。没探索过就探索；依据的文件改了（`pom.xml`、`application-dev.yml`…）就重新探索，只改变了的那几行；离上次整个扫一遍超过 6 小时再扫一遍。
- **探索好了怎么告诉 Claude**：夹在你的下一条消息里，只说一次。刚甩出去还没好的，你开口时最多等它一秒半。
- **只配开发环境的连接**。测试、生产环境的不配进来，项目说明里写一句"测试、生产环境的连接没有配进来"。
- **你和 Claude 改过的行不动**。命令是照工程结构推出来的，没实际跑过，标着"（没跑过）"；Claude 第一次用的时候跑一遍，通了把标记去掉，这一行以后就归它了。
- **项目说明是你写的、或者以前 `/onboard` 写的**：不动它，只在最后补数据库和 redis 两行。
- **壳子里套着几个子项目**：每个子项目各探索各的，壳子自己不建 `.vibe`。
- **查不了的不猜**：登录账号、代码之外的产出放哪、配置中心（Nacos、Apollo）里的连接。用到的时候 Claude 问你。
- 连接配置里有口令，探索完会把 `.vibe/` 加进那个项目的 `.gitignore`。

`/ttls-onboard` 还在，用在自动探索不够用的时候：认不出的工程、要实际跑一遍命令量时间、要补登录账号。

命令行：`node "%USERPROFILE%\.claude\vibe-kit\tools\onboard.js" status` 看探索得怎么样，`run --force` 重新探索。

### 查库更快、少写 SQL

慢在连库：每条命令起一次 java、连一次库，要一两秒。

| 做了什么 | 效果 |
|---|---|
| 一条命令只起一次 java | 以前看一张表的结构起 2 到 4 次，写操作的第二步起 3 到 5 次 |
| `find 订单` | 按关键字在表名、字段名、注释里找，不用先列出所有表 |
| `columns --table A,B,C` | 一次看几张表 |
| `peek --table T --eq 状态=待支付 --count` | 看数据、数行数不用写 SQL，值不用加引号 |
| `query --sql … --sql …` | 几条查询一次跑 |
| 表结构存在本地（12 小时） | 再看同一张表不连库；输出里写着"来自本地缓存" |
| 查库的后台执行器（开关，默认关） | 打开之后 java 不退、连接留着，后面的命令零点几秒。几分钟没人用自己退 |

三处比以前严：

- **`query` 只许跑查询**。里面有增删改、改结构的语句会被拦下，那些走 `exec` 的两步确认。以前不查，有的驱动用查询的接口也能执行写语句。
- **写操作的行数在事务里核对**。确认的时候是 3 行，执行的那一刻不是 3 行了就不执行。
- **全自动模式下不改库、不改 redis**。你不在，没人确认：写操作只算影响面，那项任务标成"（留给用户：要改库）"。

达梦、神通、Oracle、金仓、MySQL 的真库在这次改动之后**还没有验过**，这台电脑上只有 H2。第一次在真库上用，先让 Claude 跑一次 `conn test` 和一次完整的读写，有问题它会自动记成问题反馈。

### 审查报的问题自动收（开关，默认开）

以前靠 Claude 收工时自己记一条，它常常说"没有需要沉淀的经验"。现在脚本自己收：

- 审查代理报的每一条问题，收工时从它的回复里取出来。**审查之后那个文件确实改过，才算数**；没改的不收。
- 审查代理每条问题多写一行"以后怎么避免"（什么情况下：要怎么做），规则的文字用这一句。它写"无"的是一次性的疏忽，不收。
- 开着的时候收工检查不再催 Claude 自己记经验。
- 同一个问题在 2 个不同的变更里出现：自动变成规则。和以前手动记的走同一套上限、合并、过时。
- 同一类问题（同一种文件、同一个类别）在 3 个以上的变更里反复出现：多出一条"这一类要对照检查"的规则，带最近的例子。
- 已经是规则了还被审出来：记"没管住"。
- 配置页"经验规则"里自动收的带"自动"标记，能改、能删。**你删掉的不会再自动加回来；你改过的，脚本不再动**。
- 想回到以前那样，在配置页把"审查报的问题自动收"关掉。

### 工具的用量和毛病自动记

查库、查 redis 每跑一条命令记一行：哪条命令、多少毫秒、起了几次 java、出错的类别。**不记 SQL、数据、表名、key、地址、口令**。

- 配置页"数据库驱动"页的"用得怎么样"：哪条命令跑了多少次、多慢、哪种错多。
- 导出的问题反馈多了两节："工具用量"和"能优化的地方"。后一节只说数得出来的事，比如"查库的命令平均每条 2.1 秒，可以打开后台执行器"。
- 工具自己出的毛病（脚本崩了、执行器没有输出、找不到驱动、找不到 java）自动记成一条问题反馈，来源写"工具自动记录"，和别的问题一起上报。

### 发版前整个套件审了一遍

用 Opus 5.5 把整个套件从头审了一遍，报了 135 条，改了 132 条。你会感觉到的：

**查库**
- 找不到连接配置时，Claude 不再自己跑 init 把测试库、生产库配进来，缺连接就问你。
- `exec` 第二步执行的就是第一步分析过、给你看过的那一条。确认串只能用一次。
- 禁止名单和行数上限写在连接配置里，命令行只能改得更严。
- 带别名、JOIN 的 UPDATE、DELETE 数行数和改前快照不再拼坏；执行时核对实际动了多少行，比确认的多就回滚。
- 还原走得通了：`exec --undo <留痕目录>`，也是两步确认。
- 值被截了，同一条命令加 `--width 0` 看全。
- 报错里的口令、连接串里的口令遮掉。
- 后台执行器：写操作不会因为超时重发执行两次。

**查 redis**
- `set` 保留原来的过期时间。
- 二进制的 key 显示成 `hex:…`，原样当 key 给就能读、能删。
- `keys` 用游标翻，最多看 3 秒、返回 1000 个，没看完会说。
- 切库失败时写命令不发出去，不会写进 0 号库。

**后台自动探索**
- 认环境更准：`生产环境/`、`config-prod/` 这类目录，多数据源里叫 prod 的库，按 profile 分的配置，都认得出。测试、生产的不配进来。
- 连接串里带的口令不写进项目说明。
- 你补上的账号口令、你改过的行，下次探索不冲掉。
- 只放着一堆仓库的普通目录，不再挨个探索、挨个改 `.gitignore`。

**看页面**
- 记事本存的带 BOM 的场景文件也能跑。
- 整个场景默认最多跑 5 分钟，`--max 秒数` 可以改；`wait` 最多等 60 秒，`timeout` 最多 120 秒。以前页面一直转圈，命令就一直挂着。
- 读到的值太长的，输出里截断，全文在 `result.json`。

**起服务**
- 端口被你自己在 IDE、终端里起的服务占着：不再直接关掉，说清是你起的，要接管加 `--takeover`。带着调试器的一律当成你的。
- 电脑重启过、记录过期：不会把后来占着这个端口的别的程序停掉。

**拦截检查**
- 新加一条：Bash 里先 cd 到别的目录、再用相对路径 grep、cat、cp 的，拦下让它改用 Grep、Read，或者不 cd、把路径写全。这种命令 Claude Code 会停下来等人点确认，开着跳过权限模式也照样问，全自动时就一直挂着。
- 几种正常写法不再误拦：cd 进技能目录再跑脚本、外面包 `timeout` 或 `cmd /c`、在套件的文件里 grep `install` 这类词。
- 读令牌、改套件的几种绕法堵上了：PowerShell 的 `Join-Path`、管道传文件、heredoc 和 `eval` 里的命令、通配符。
- 新建的 `.ps1` 里带中文：拦一次，说清 PowerShell 5.1 会按 GBK 读。

**安装、更新**
- 放行里加了 PowerShell：默认模式下 PowerShell 命令不再一条条弹确认，git push 照样要你确认。你自己放行过的不重复加，卸载时也不收。
- 你删掉的"登录后自动启动"，装新版时不再加回来。
- 后台更新装到一半被打断，下次会重装。
- 卸载时说清令牌和 key 还在、保护已经收回。

**经验规则**
- 配置页删掉的自动规则不会再回来，改过字的不再被脚本改回去。
- 自动收的规则文字里的口令遮掉。

- 改文件、跑命令、收工这几个检查，改在路由进程里跑（HTTP 方式），每次约 5 毫秒。以前每次要起一个 node 进程，0.3～0.9 秒。
- 路由不在时这些检查会放行，所以用户开口时会自检：路由没在跑就拉起来；在跑也收不到就自动切回命令方式，并提醒核对上一轮的改动。
- 配置页可以选"钩子运行方式：自动 / HTTP / 命令"。

### 路由
- 你按 Esc 取消的请求不再让模型进冷却，只在用量里记"客户端取消"。
- 529、带等待时间的 503 也和 429 一样，先在原模型等一会儿再换；冷却多久按对方给的等待时间算；所有等待都不超过 Claude Code 的超时。
- 换过端口后点"断开"，能恢复成真正原来的网关地址。
- 配置页的选目录、自动探测、清点技能放到后台线程，碰到断开的网络盘也不卡转发。
- 按模型加"校验证书"开关（默认不校验，内网常见自签证书）。
- 两个页面同时开着保存，不会互相覆盖。

### 安装器和看页面
- 你从 settings.json 里删掉的权限、环境变量，升级时不再补回来。
- 技能目录里改过任何一个文件，覆盖前整目录备份；备份只留最近 20 份。
- 全局 CLAUDE.md 不是 UTF-8 时什么都不动，说清是哪几行、怎么转。
- `--no-router`：不装、不更新路由，以前装的原样留着。
- 看页面执行器：忽略规则默认按字面匹配；结果默认放项目的 `.vibe/out/`；用了相对地址没给 `--base` 直接报错说明；关浏览器偶尔卡死的问题修了。

### 约定
- 瘦身约一成。
- "审几次"统一成"提案一次、代码一次，开了多轮审查按轮数"。
- 提交节奏跟着自动提交开关生成。
