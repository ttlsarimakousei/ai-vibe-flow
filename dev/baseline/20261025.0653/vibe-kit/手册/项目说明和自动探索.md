# 项目说明和自动探索

套件怎么知道一个项目怎么编译、怎么启动、连哪个库，以及技能装了却不被用怎么办。回到[用户手册](../README.md)。

## 后台自动探索（默认开）

进到一个没探索过的项目不用你说。脚本在后台查，几秒钟就好，不用模型、不花额度、不挡你打字：

| 查什么 | 依据 | 写到哪 |
|---|---|---|
| 是什么工程、几个模块 | `pom.xml`、`build.gradle`、`package.json`、`.classpath` | 项目的 `.vibe/project.md` |
| 快检、全量、启动的命令，端口，上下文路径 | 构建文件加 `application*.yml`、`vite.config.*` | 同上 |
| 用哪个 JDK | `pom.xml` 里的 Java 版本，对上配置页"本机环境"里的 JDK | 同上 |
| 编码 | 抽查源文件，不是 UTF-8 的点出来 | 同上 |
| **开发环境**的数据库连接 | `application*.yml` / `.properties`、`jdbc.properties`、XML 里的数据源 | `.vibe/db-crud.ini` |
| **开发环境**的 redis 连接 | 同上 | `.vibe/redis.json` |

什么时候跑：会话开始、你每次开口时钩子看一眼（几毫秒）。没探索过的探索；依据的文件改了（`pom.xml`、`application-dev.yml`……）重新探索，只改变了的那几行；离上次整个扫一遍超过 6 小时再扫一遍。探索好了、更新了，随你下一条消息告诉 Claude 一次。

几条规矩：

- **只配开发环境的连接**。看文件名（`application-prod.yml`）、目录、YAML 的分段、数据源的名字；测试、生产的不写进去，宁可少找一个。公共配置里被 `application-dev.yml` 用同一个键盖掉的连接也不算。注释掉的地址不算。
- **命令没实际跑过**：项目说明里标着"（没跑过）"，Claude 第一次用时跑一遍，通了去掉标记。
- **你和 Claude 改过的行不动**，只换脚本自己生成、这次又变了的行。项目说明不是脚本生成的（你写的、以前 `/onboard` 写的），只在最后补数据库和 redis 两行。你手写的连接、记过的坑不动。
- **壳子里套着子项目**：每个子项目各探索各的，壳子自己不建 `.vibe`。会话开始在壳子里时，子项目只列路径，用到哪个读哪个。
- **查不了的不猜**：登录账号、代码之外的产出放哪、配置中心（Nacos、Apollo）里的连接、加密过的口令。
- **口令**：从项目的配置文件原样抄进 `.vibe/`，不进项目说明、不进日志、不发给模型。`.vibe/` 自动加进项目的 `.gitignore`。
- 用户目录、盘符根目录、套件自己的目录不探索。

命令行：`node "%USERPROFILE%\.claude\vibe-kit\tools\onboard.js" status`、`… run --force`。流水账在 `~/.claude/vibe-kit/state/onboard.log`。不想要，在配置页"自动探索"关掉；关掉之后没有项目说明的项目，Claude 会先跑 `/ttls-onboard`。

## /ttls-onboard 和团队共享的项目说明

自动探索不够用时用 `/ttls-onboard`：认不出的工程、要实际跑一遍命令量时间、要补登录账号。

`.vibe/project.md` 只在本机，每个同事都要各自查一遍。所以 `/ttls-onboard` 把团队都一样的部分（是什么工程、快检和全量命令、启动命令和端口、编码、哪些项不适用、产出位置、坑）问过你之后，写进项目根目录 `CLAUDE.md` 的"## 项目说明（团队共享）"一节，跟着仓库提交；本机的部分（JDK、用哪套 Maven、耗时）还在 `.vibe/project.md`。已经有这一节的项目，`/ttls-onboard` 只在本机把命令跑一遍、补本机的部分。

## 不是写代码的工程

开发技能的仓库、纯文档的仓库、一堆散装脚本的仓库，没有"编译""启动"这回事。自动探索和 `/ttls-onboard` 先判断是什么工程，只查该查的：

- 代码工程：类型、快检、全量、启动、编码。
- 技能工程（skills/、commands/、agents/、插件清单）：技能怎么组织、怎么验证、怎么装到本机试一次。快检是 `node "$HOME/.claude/vibe-kit/tools/skills-check.js" <仓库> --repo`，不查启动。
- 文档工程：快检、全量、启动都记"不适用"。
- 脚本工程：每个脚本怎么跑、语法检查命令、依赖、编码。
- 说不清的问你一句。

项目说明里标了"不适用"的项，收工时不再催：写了"快检：不适用"不催跑验证，写了"看页面：不适用"不催看页面。

## 普通的单个项目找哪个 openspec

不是壳子结构的单个项目：当前目录有 `openspec/` 就用它，没有就用所在 git 仓库根目录的；不会去仓库外面的上级目录找。

## 装了技能，Claude 却不用

Claude 并不"知道"自己装了什么，它只在每个会话开头收到一份技能列表，每个技能一行说明。先清点一下：

```
node "%USERPROFILE%\.claude\vibe-kit\tools\skills-check.js" D:\你的\项目目录
```

1. **列表超字数了**：整份列表默认最多占上下文窗口的 1%，超了所有说明都被压短，"什么时候用"那半句最先没。删掉不用的技能，或者设环境变量 `SLASH_COMMAND_TOOL_CHAR_BUDGET` 调大。
2. **说明只写了"它是什么"**：要写成"要知道表结构、字段，或者写 SQL、Mapper 之前使用"这种。模型是拿手头的任务去对这句话的。
3. **它以为手头的资料够用**：项目里有 DDL 文件，它读了就不会想到去查库。在项目的 `CLAUDE.md` 里写一句："表结构用 /ttls-db-crud 查真实的库，db/ 下的 DDL 是旧的"。
