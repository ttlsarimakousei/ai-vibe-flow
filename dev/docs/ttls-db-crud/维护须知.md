## 先知道这几件事

**这个技能会真的改数据。** 改它之前先想清楚：出错的后果是别人的业务数据，
不是一份报告写得不好看。涉及风险分级、快照、反向 SQL、执行器的改动，都要在真库上验证过再发。

**它带一个 Java 文件。** 理由和口径写在设计说明第八章。
改了 `DbRunner.java` **必须重新编译并把 `.class` 一起留在源码里**（带内部类，一共四个 class）：

```bash
javac --release 8 -encoding UTF-8 -d vibe-kit/claude/skills/ttls-db-crud/scripts/runner vibe-kit/claude/skills/ttls-db-crud/scripts/runner/DbRunner.java
```

漏了这一步，使用者拿到的还是旧行为，而且不会有任何报错。
打包脚本会查：class 比源码旧、不是按 Java 8 编的，都不让打包。

**它不带驱动。** 达梦、神通、金仓、Oracle 的驱动是厂商的，只限内部使用。
源码目录、安装包里都不能有 jar，打包脚本会查。测试用的 H2 放在运行环境的目录里，不进工程。

**源码目录里不能留 Python 的缓存。** `db.py` 开头把字节码缓存指到 `~/.db-crud/pycache/`（`sys.pycache_prefix`），
并盖掉 Claude Code 设的 `PYTHONDONTWRITEBYTECODE=1`：不缓存的话每条命令都要把标准库和技能的模块重新编译一遍（约 0.3 秒）。
这几行要放在别的 import 前面，在它前面载入的模块用不上缓存。源文件改了缓存自己作废（Python 按源文件的修改时间和大小核对）。
三个 `*_selftest.py` 只是手工跑，没改，照旧关着字节码缓存（`sys.dont_write_bytecode`）。
手工跑自测留下了 `__pycache__` 的话删掉，打包脚本会查。

**手工试的时候也要指假的用户目录。** `db.py` 会往 `~/.db-crud/` 写留痕和字节码缓存、往 `~/.claude/vibe-kit/state/` 记用量。
2026-09-29 手工跑了一次 `doctor`，在真实的用户目录下建出了 `~/.db-crud/journal`。
用 `dev/lib/harness.js` 的 `H.run`，或者自己把 `HOME`、`USERPROFILE`、`CLAUDE_CONFIG_DIR` 指到临时目录。

## 怎么验证

```bash
node dev/test-dbcrud.js <运行环境的目录>
```

```bash
node dev/run-all.js --rt <运行环境的目录>
```

运行环境的目录里要有 `python/python.exe`、`jdk/bin/java.exe`、`h2.jar`，都是便携版，不用装：
python.org 的 embeddable 包、Adoptium 的 JDK 压缩包、Maven 中央仓库的 `com.h2database:h2`。
目录放在工程外面，不提交。

`test-dbcrud.js` 拿 H2（MySQL 兼容模式）走完整的读写循环，最后照冒烟靶场把不连库的判断过一遍，三个自测都在里面。
`test-onboard.js` 测后台自动探索扫配置、并配置。`test-ttls.js` 测从旧技能升上来（删旧技能、挪驱动）。
`e2e-0930.js` 拿真的 Claude Code 走一遍：模型照技能说的跑 `db.py`，不被钩子拦。

改了 `discover.py` 的剥注释或落点逻辑，`discover_selftest.py` 必须过（在冒烟里）。
那两块错了不会报错，只会悄悄连到别的库上。Node 版的 `discover.js` 同理，看 `test-onboard.js` 的"扫配置"一节。

改了 `notes.py`，`notes_selftest.py` 必须过：它会往用户的配置文件里写东西，写坏了就是把人的连接配置弄没了。

**H2 测不出各家数据库的差异。** 改了会影响连库行为的东西（`DbRunner.java`、`journal.py`、`dbconf.py`），
要到有真库的机器上跑一遍完整读写循环，并把结果补进 `验证记录.md`。

最少要验的一轮：`conn test` → 建表 → 插入含中文、NULL、空串、时间戳的行 → `find` → `columns`（小写的表名）→
`peek --eq` → `query` 两条一起 → 带主键的 UPDATE 两步确认 → 用生成的反向 SQL 还原 → 确认数据回到原值 → 删表。

## 已知边界

- **DDL 不留痕**。`ALTER` / `TRUNCATE` / `DROP` 判 DANGEROUS，但改前快照救不回来，`undo.sql` 里会写明。
- **二进制列还原不了**。快照里标成 `<binary:类型>`，反向 SQL 会跳过这些列并留注释。
- **没有主键的表**，UPDATE 的反向 SQL 用整行做条件；表里有重复行时一条反向语句会改掉多行，会提示。
- **没有跨进程的锁**。两个 Claude 会话同时对同一张表操作，互相看不见。执行那一刻行数变了会被事务里的核对拦下，行数没变但内容变了的拦不下。
- **反向 SQL 不检查「这期间别人有没有改过」**，照跑会覆盖掉别人的改动，提示里说了这点。
- **`query` 的行数上限是取回来之后截断**，不改写 SQL 加 LIMIT。大表上流量该省没省。
- **表结构的缓存不知道别人改了结构**。12 小时的期限和 `--fresh` 是兜底。
- **后台自动探索只认文件里写着的开发环境连接**。配置放在配置中心（Nacos、Apollo）的扫不到，要手写。
