# 一页看懂 —— ttls-db-crud

> **这份是什么**：三分钟了解 ttls-db-crud 是干嘛的。给第一次接触的人看。
> 原来叫 urai-db-crud；2026-09-30 并进 vibe-kit，跟着套件一起装。章节级对照表在 [维护须知.md](维护须知.md)。

## 它解决什么问题

开发的时候经常要动数据库：看看这张表什么结构、这条数据现在什么状态、
把某个字段改回去。以前要么开数据库客户端手点，要么让 Claude 生成 SQL 再自己复制去执行。

让 Claude 直接连库当然更顺手，但也更吓人——它可能少写一个 WHERE，
一条 UPDATE 下去全表就都改了。

这个工具做的就是**让 Claude 能直接读写数据库，但改之前必须先把要发生的事摆出来给人看**。

## 它靠什么判断

先看 SQL 本身：是查还是改、动哪张表、有没有 WHERE。
再去数据库问一句「这条语句会碰多少行」，但**只问不做**。

两样凑齐才定风险等级，然后决定拦还是放：

| 等级 | 什么情况 |
|---|---|
| SAFE | 只读 |
| WARN | 带 WHERE 的增删改 |
| DANGEROUS | 没有 WHERE、WHERE 恒真、清空表、删表、改结构、看不懂的语句 |
| FORBIDDEN | 删库；碰了禁止名单上的表；在标了只读的连接上写 |

**看不懂的一律按最严处理。** 判严了最多多问人一次，判松了是数据事故。

## 用起来是什么样

对话里直接说「把 ID=1001 那条的状态改成 2」。Claude 会先跑一次，你看到的是：

```
目标表  SYSDBA.T_ORDER
影响面  3 行
风险    WARN
SQL：
  UPDATE SYSDBA.T_ORDER SET STATUS = 2 WHERE ID IN (1001,1002,1003)
```

这一步**什么都没改**。你说「可以」，它才真的执行。

要是影响面跟你想的不一样——比如你以为改 1 条，它说 3 行——那就是 WHERE 写错了，
在这一步就能拦住。

改完之后，改之前那些行长什么样会被存下来，同时生成一份**反向 SQL**。
真改错了，把反向 SQL 看一遍再跑一次，数据就回去了。

查的时候不用写 SQL 的就不写：「哪张表存了订单」是 `find 订单`，「看看待支付的有几条」是
`peek --table T_ORDER --eq STATUS=待支付 --count`。连接一般也不用配，套件在后台探索项目时把开发环境的库配好了。

## 它不做什么

- **不自动回滚。** 只把反向 SQL 摆出来，要不要执行由人决定。
  自动回滚看着省事，但「看起来撤回了其实没撤」比不撤更危险。
- **不跨命令保持事务。** 每条命令自己开事务自己提交，没有「先开着事务慢慢改」这回事。
- **不翻译 SQL。** 写给哪个数据库就按哪家的语法写。
- **不替你保管口令。** 口令放在你自己的配置文件里，工具只是去读。
- **不带驱动。** 厂商的驱动只限内部使用，在套件配置页的「数据库驱动」里管。
- **用户不在的时候不做留不下备份的写操作。** 套件的全自动模式下，改、删要留得下改前快照和还原脚本，新增要记得下表和主键，建表、加字段要写得出对应的 DROP；别的只算影响面，不执行。

## 三条核心理念

**一、改之前必须有人看过。**
不是弹个窗让人点「确定」，是把目标表、影响多少行、SQL 原文摆出来。
人真正要核对的是影响面——数字对不上，就是条件写错了。

**二、拦截要在代码里，不能指望弹窗。**
Claude Code 的权限弹窗在某些模式下会失效。所以删库、禁止名单、只读连接
这几条红线是脚本自己拒绝的，任何模式下都拦得住。查询命令里夹着写语句也一样。

**三、救不回来的事，要在救之前说清楚。**
快照没取全、表里没有主键、这一列是二进制存不进 SQL——
这些都会明说，而不是给一份看着能用、跑完才发现只还原了一半的反向 SQL。
