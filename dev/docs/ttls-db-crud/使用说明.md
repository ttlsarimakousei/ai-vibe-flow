# 使用说明 —— ttls-db-crud

> **这份是什么**：ttls-db-crud 的操作手册。怎么装、怎么配、怎么跑、出错怎么办。
> 这个技能原来叫 urai-db-crud；2026-09-30 并进 vibe-kit，跟着套件一起装、一起更新。
> 章节级对照表在 [维护须知.md](维护须知.md)。想先了解这工具是干嘛的，看 [一页看懂.md](一页看懂.md)。

---

## 一、装

装 vibe-kit 就装上了，不用单独装。以前单独装过 urai-db-crud 的：

- 用户目录下的（`~/.claude/skills/urai-db-crud`）：套件的安装器会删掉，删之前备份，它自带的驱动挪进套件的驱动目录并登记好
- 项目里的（`<项目>/.claude/skills/urai-db-crud`）：安装器不动它。会话开始时套件会提醒一句，自己删掉

**前提有两个**：

1. 机器上有 **Python 3**
2. 机器上有 **java**，JDK 8 及以上都行，不需要 javac

第二条是因为达梦、神通、Oracle、金仓都是私有的通信协议，Python 标准库连不了，只能走 JDBC。
执行器已经预编译好随包分发，一份产物在 JDK 8 / 11 / 17 上都能跑。

java 在哪，按这个顺序找：环境变量 `DBCRUD_JAVA` → 配置页「本机环境」里配的 JDK → `JAVA_HOME` → PATH。

不用装任何依赖包，不用联网。

## 二、配连接：一般不用配

在要操作的项目里开 Claude Code。套件发现这个项目没探索过，会在后台扫一遍项目的配置文件，
把**开发环境**的数据库写进 `<项目>/.vibe/db-crud.ini`，几秒钟就好。项目说明（`.vibe/project.md`）里会多一行：

```
- 数据库：连接 shop_dev（MySQL，jdbc:mysql://127.0.0.1:3306/shop_dev，来自 src/main/resources/application-dev.yml）。查库、核对表和字段用 /ttls-db-crud，连接名照这里写。测试、生产环境的连接没有配进来
```

项目的配置文件改了（换了库的地址、改了口令），下一次开口时它自己重新扫，连接配置跟着改。

扫的范围：

| 项目形态 | 扫哪些文件 |
|---|---|
| Spring Boot | `application*.yml` / `.properties`、`bootstrap*.yml`，含 Druid 多数据源 |
| Spring MVC 老项目 | `jdbc.properties`、`db.properties`，以及 XML 里的数据源 bean |

几条要知道的：

- **只配开发环境的。** 测试、生产环境的连接不配进来。要连的话自己在 `.vibe/db-crud.ini` 里加，记得写 `readonly = true`。
- **注释掉的地址不会被扫出来。** 老项目的配置里常年躺着一堆注释掉的旧地址，那些多半是别的环境甚至生产库。
- **你手写的连接、记过的坑，它不动。** 它只改自己写的那几段（带 `source = …` 的）。来源文件里找不到了的连接不删，加一行说明。
- **口令是从项目配置里原样抄来的，明文就明文。** 内网开发库一般就这么配。想用环境变量也行（`${ENV:变量名}`），`setx` 之后要重开 Claude Code。
- **加密过的口令（`ENC(...)`）抄不了**，那个连接要自己填口令。
- **配置落在真正拥有这个库的项目下。** 外面套壳子时落在里面那个后端，不落在壳子上；在壳子根或后端目录里开 Claude Code，两头都找得到。
- **配置放在配置中心（Nacos、Apollo）的扫不到**，要手写。

不想等它、想手动扫一遍：对 Claude 说「配一下这个项目的数据库」，它会跑 `db.py init`（扫、写配置、逐个试连）。
`init` 和后台探索一样只配开发环境的。测试、生产环境的库要用，照 `references/连接配置.md` 自己手写：
以前 `init` 把它们也配进来（生产的标成只读），这个命令模型自己会跑，等于把那些库交到了它手上。

后台自动探索不想要，在配置页把"后台自动探索"关掉。

★ **`.vibe/` 里有账号口令。** 后台探索写完连接配置会把 `.vibe/` 加进项目的 `.gitignore`；`doctor` 也会实地查一下。

字段全表、五种数据库各自的写法，见技能目录里的 `references/连接配置.md`。

### 驱动 jar

**驱动不随包带**：达梦、神通、金仓、Oracle 的驱动是厂商的，只限内部使用，不能夹在安装包里发。

在 vibe-kit 配置页的「数据库驱动」里管：

| 做法 | 什么时候用 |
|---|---|
| 点"自动搜索"（"刷新"旁边） | 项目编译过，驱动多半就在 Maven 本地仓库里。按"本机环境"里配的 Maven、`~/.m2` 的顺序找，每种数据库用最新的那个 |
| 点那一行后面的"换驱动" | Maven 仓库里没有，或者要指定版本。在弹窗里选一个 jar，也可以粘贴路径 |

后台探索发现项目用到的数据库还没有驱动，会自己到 Maven 仓库里找一遍。多数时候什么都不用做。

只给某一个连接用别的版本（最常见的是 Oracle：老的 `ojdbc6` 连不了 19c 及以上），在连接配置里指路径：

```ini
driver_jar = D:/path/to/ojdbc11.jar
```

## 四、跑

对话里直接说就行：

> 「看一下 T_ORDER 这张表的结构」
> 「哪张表存了订单」
> 「查一下昨天的订单有多少条」
> 「把 ID=1001 那条的状态改成 2」

**你不用敲任何命令。** 下面写的是 Claude 在底下跑的，列出来只是让你知道它在干什么；自己在命令行上跑也行。
`<db>` 指 `python ~/.claude/skills/ttls-db-crud/scripts/db.py`，工作目录是被操作的项目：

```
<db> conn list
<db> --conn shop_dev conn test
<db> --conn shop_dev find 订单
<db> --conn shop_dev columns --table T_ORDER,T_ORDER_ITEM
<db> --conn shop_dev peek --table T_ORDER --eq STATUS=待支付 --limit 5
<db> --conn shop_dev peek --table T_ORDER --eq CUSTOMER_ID=1001 --count
<db> --conn shop_dev query --sql "SELECT ..." --sql "SELECT ..."
```

只有一个连接时 `--conn` 可以不写。

## 四之二、为什么比以前快

慢在连库：每条命令起一次 java、连一次库，要一两秒。1.0.0 做了四件事：

| 做了什么 | 省了什么 |
|---|---|
| 一条命令只起一次 java | 以前看一张表的结构要起 2 到 4 次，写操作的第二步要起 3 到 5 次 |
| `find`、`columns` 一次看几张表、`peek --eq`、`query` 一次跑几条 | 少写 SQL，少来回 |
| 表结构存在本地（12 小时） | 再看同一张表不连库。输出里写着"来自本地缓存"；`--fresh` 重新查 |
| 后台执行器（开关，默认关） | 打开之后 java 不退、连接留着，后面的命令零点几秒 |

后台执行器在配置页「数据库驱动」页的"查库快一点"里开。几分钟不用它自己退。

### 表名大小写不用你操心

达梦、Oracle、金仓的 Oracle 兼容模式把不带引号的标识符折成**大写**，
神通和金仓的 PG 模式折成**小写**。你按代码里的写法敲 `t_order`，库里存的是 `T_ORDER`，
查元数据就是空的，而且不报错，只是「查不到」，很容易被当成表不存在。

`columns` 和 `peek` 会自己试三种写法。试出来和你给的不一样时会说一声，
并把这条记进配置，下次就直接按对的写了。

## 四之三、踩到坑记一条，别踩第二次

```
<db> --conn shop_dev note "这个库是 Oracle 兼容模式，空串会变 NULL"
```

记在 `db-crud.ini` 里那个连接名下，**之后每次用这个连接都会先打出来**。
有些坑工具会自己记：标识符大小写、某张表没有主键。

看已经记了什么：`note --list`。

值得记的是**会重复踩**的事：大小写、兼容模式、某张表特别大、某个字段是加密存的。
一次性的打字错误就别记了，记成流水账反而没人看。

## 五、改数据是两步

新确认串只含 ASCII，如 `UPDATE-T_ORDER-3rows-11fd6ccd`。旧中文串可以写进 UTF-8 文件，用 `exec --sql-file upd.sql --ack-file ack.txt`，文件里只放一条确认串。照样先把影响面给人看、得到同意，第二步仍核对指纹、行数和一次性。

`--sql` 只收 ASCII，带中文的 SQL 用 UTF-8 文件和 `--sql-file`；LIKE 只剩通配符也先拒绝，核对中文是否丢失。文本表格按显示宽度补齐，中文占两格，不要按字符下标切列。需要原值用 `query --sql-file q.sql --json`：保留 `truncated_cell`、`truncated_rows` 和 `max_cell`，这些标记说明数据是否取全，`--width 0` 只取消显示列宽截断。

查表关键字用 `find --keyword-file keyword.txt` 从 UTF-8 文件读入。按值条件用 `peek --table T_ORDER --eq-file eq.txt`，每行一个 `列名=值`，与 `--eq` 合并；条件文件为空时停止，不会改成无筛选查询。

第一步什么都不改，只算清楚要发生什么：

```
<db> --conn shop_dev exec --sql-file upd.sql
```

```
连接    shop_dev（MySQL）
语句    UPDATE
目标表  T_ORDER
影响面  3 行
风险    WARN
  · UPDATE 带 WHERE

SQL：
  UPDATE T_ORDER SET STATUS = 2 WHERE ID IN (1001,1002,1003)

这是写操作，要确认才能执行。把上面的内容给人看过之后，重跑一遍并带上：

  --ack UPDATE-T_ORDER-3rows-11fd6ccd
```

**重点看影响面。** 比你预期的多，多半是 WHERE 写错了。

看明白了再跑第二步：

```
<db> --conn shop_dev exec --sql-file upd.sql --ack UPDATE-T_ORDER-3rows-11fd6ccd
```

确认串里绑着 SQL、影响面、风险三样，任何一样变了旧串立刻失效。
所以**不能拿上次的串来确认这次的操作**。

执行的那一刻会在同一个事务里再数一遍。和确认时的行数不一样就不执行，把现在的影响面打出来，要重新确认。

只想看不想做，加 `--dry-run`，它连确认串都不给。

**`query` 只跑查询。** 里面有增删改、改结构的语句会被拦下（退出码 3），那些走 `exec`。

**全自动模式下不等你确认，但只做留得下备份的。** 只在走 OpenSpec 流程的会话里这样；别的会话照上面的两步来。

| 语句 | 做不做 | 留下什么 |
|---|---|---|
| UPDATE、DELETE | 影响几行数得出来、不超过快照上限、UPDATE 的表有主键、没有二进制列，就做 | 改前快照、还原脚本 |
| INSERT | 表有主键、新行的主键记得下来，就做 | 表名、每一行的主键。还原脚本是按主键删 |
| 建表、建索引、建视图、建序列、加字段 | 做 | 对应的 DROP 脚本 |
| 别的（没有 WHERE、连表改、`INSERT … SELECT`、改列删列、清空、删表） | 不做。Claude 把那项任务标成"（留给用户：要改库）"，接着做别的 | |

做过的每一条都列在全自动报告"库里改过的"一节：哪张表、几行、新增的主键、留痕目录、怎么还原。

## 六、改错了怎么办

每次写操作都在 `~/.db-crud/journal/<连接名>/<时间>-<类型>/` 留了三样东西：

| 文件 | 是什么 |
|---|---|
| `op.json` | 这次干了什么 |
| `before.json` | 改之前那些行长什么样 |
| `undo.sql` | 反向 SQL |

**`undo.sql` 生成的时候不执行。** 要还原，拿那一次执行完打印的留痕目录，和别的写操作一样走两步：

```
<db> --conn <连接名> exec --undo "<留痕目录>"
<db> --conn <连接名> exec --undo "<留痕目录>" --ack <上一步给的串>
```

整份反向 SQL 在一个事务里跑，每一条都得正好动一行，有一条不是就全部回滚。同一次只能还原一遍，还原本身不留改前快照。
以前 `exec` 只收一条语句，`undo.sql` 是好几条，这条路其实走不通。

还原前先看两件事：

1. 这期间有没有别人改过这些行。反向 SQL 会把那些改动一起覆盖掉。
2. 第一步的输出里有没有带 ★ 的「快照没有取全」「有二进制列」。有的话照它执行**只能还原一部分**。

INSERT 没有「改前的样子」；清空表、删表、改结构也还原不了。这些情况 `undo.sql` 里会写明原因。

快照里是真实业务数据，不用了就删掉整个目录。

## 七、出错了

| 退出码 | 意思 | 怎么办 |
|---|---|---|
| 0 | 成功 | —— |
| 1 | 参数或配置不对 | 按提示改 |
| 2 | 连上了但失败了 | 看数据库原话，多半是 SQL 语法或权限 |
| 3 | 被安全规则拦住 | 看拦截原因，别绕过 |
| 4 | 要人确认 | 看清影响面，带 `--ack` 重跑 |

几个常见的：

**「找不到连接配置」**：项目里没有 `.vibe/db-crud.ini`。让 Claude 跑一次 `init`（只配开发环境的），或者照 `references/连接配置.md` 手写。

**「口令要从环境变量 X 取，但这个变量没有值」**：`setx` 之后没重开 Claude Code。

**「找不到 XX 的 JDBC 驱动 jar」**：提示里列了找过哪些地方和三种补法。最省事的是配置页「数据库驱动」里点"自动搜索"。

**「没有驱动认得这个 URL」**：jar 挂上了但对不上号，检查 `jdbc` 串的写法。
很老的驱动（ojdbc14、mysql 5.1）没有自动声明，要额外配 `driver_class`。

**「机器上找不到 java」**：在配置页「本机环境」里配一个 JDK，或者设环境变量 `DBCRUD_JAVA` 指到 `java.exe`。

**「工具自己出错了」**：技能自己的毛病。已经自动记成套件的问题反馈，导出问题反馈时会带上。

## 八、几条别踩的

- **口令不要写进命令行。** 命令行会进进程列表，也会进对话记录。
- **长 SQL 写成文件再用 `--sql-file`。** Windows 命令行有 8191 字符上限，引号和中文经两层 shell 转义很容易坏。
- **一次只发一条写语句。** 多条会被拒绝，拆开执行，这样每条的影响面和快照才对得上。
- **连测试库、生产库，在配置里标 `readonly = true`。** 标了之后任何写操作都会被脚本直接拒绝，这层拦截在代码里，不依赖任何弹窗。
